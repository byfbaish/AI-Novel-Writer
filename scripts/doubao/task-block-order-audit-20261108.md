## 必须做的事

### 1. 实测块序（不许估）

用「行首标题」法（每行以 `【…】` 或 `# ` 开头视为块起点），从 trace 里 user 消息的正文中逐块输出：
**序号 / 起点字符偏移 / 字符数 / 占全篇百分比 / 标题原文**。两份 trace 各出一张表。

**硬要求：字符数必须是从文件里数出来的。不许写「约」「大概」「左右」。** 上一轮初稿用「任意 `【…】` 当块边界」切出了 52 块，其中大部分是行内 `【】` 与 bullet 中的加粗标题，属于切块伪影；这次只认行首标题。

### 2. 逐块定性

给每块判类型，**只许用这五类**：

- **系统合同**：身份 / 视角 / 不可变约束
- **材料型**：作者资料、前文事实、世界观、本书规则、上一卷交接、候选草稿
- **指令型**：文风、节奏、写作方向、去AI腔、平台硬指标
- **本轮任务**：篇幅合同、短细纲
- **输出格式**

### 3. 判偏差

作者定的原则：**材料型在上 → 指令型次之 → 输出格式最后**，另加一条硬约束：**短细纲唯一末位**。
逐块比对，列出**所有偏差**（现位置 vs 原则要求的位置）。

### 4. 每条偏差必须回答三个问题

- **动作**：现位置、建议位置、挪动的字符数（会改变多少百分比）
- **证据**：凡引用「U 形曲线」「context engineering」「lost in the middle」等结论，必须标明是**你直接读过原文**还是**转引设计稿**
- **风险**：挪了以后，**哪一类缺陷会变好、哪一类会变差**

**必须专门评估一条**：把内容型材料往末尾挪，是否增加照抄 / 逐字复现的风险。B1 之后 8 次对照里，覆盖率最高的一次（v6，7.7%）恰好出现在 B1 开臂，方向与「越靠近生成点越容易被续写式接续」一致；同章 B1 关臂最高只有 3.4%。这是噪声还是趋势还说不清，但任何往末尾挪的提议都必须先过这一关。

**答不上「哪一类会变差」的项，直接写「不建议挪」**，不要为了凑数给建议。

### 5. 「绝不能挪」清单

列出不该动的块 + 理由（一句一个）。
