## T9 · markers 二次误判修复（`scripts/doubao/markers.mjs`）

**背景**：`doubao.mjs markers` 会把**任务书正文里的格式示例行**当成真标记。已经修过一轮（`isTemplateMarker`：状态后紧跟 `|` 的枚举残片、note 只是 `<一句话说明>` 占位符），但仍然漏：

任务书里这样一行（是**给执行者看的模板示例**）：
```
## [QUEUE] EMPTY
```
以及任务书里引用的收尾格式：
```
## [T5] DONE <一句话>
```
在第一轮过滤后，`## [QUEUE] EMPTY` 仍被当成真标记读出来。

**真因（已定位，别重新调查）**：`doubao.mjs` 的切片起点是**最后一条用户消息的锚点之前**，任务书正文整体进了切片；而判据只过滤"有 note 的模板行"，`note` 为空的 `EMPTY` 行没有可过滤的字段。

**要做的改动**（只改 `scripts/doubao/markers.mjs`，不改 `doubao.mjs`）：

1. `extractMarkers(text)` 增加一个可选参数 `{ afterIndex }`（或等价的「只看最后一条用户消息之后」的入参），默认行为**保持不变**（老调用点不传就还是全量扫）。
2. 新增判据（**两个条件同时满足才算真标记**）：
   - ①它是**最后一行有效行**（之后没有非空内容）；
   - ②它之前至少有一条**已通过模板过滤**的真标记（`DONE`）。
   只满足一个就丢弃。为什么要第②条：任务书的「收尾」小节本身就以 `## [QUEUE] EMPTY` 结尾，且它的 `DONE` 行都是 `<一句话>` 占位符（已被模板判据丢掉）⇒ 只看「是否最后一行」仍然会在**助手还没回复之前**误报一次。加第②条后，任务书场景恒为「前面没有真 DONE」⇒ 不成立。
3. 判据写成纯函数（`isTerminalQueueMarker(markers)` 或同等命名，入参是已解析的标记序列），JSDoc 写清上面两个条件及理由。

**单测**：追加到 `scripts/doubao/__tests__/markers.test.mjs`，必须包含：

1. 真实回复样本：`## [T9] DONE xxx` 之后跟 `## [QUEUE] EMPTY` ⇒ 读出 2 条标记
2. **任务书整段**（含正文说明 + 中间一次 `## [QUEUE] EMPTY` + 末尾收尾小节再一次）⇒ **一条 EMPTY 都不读出**（这是本次要修的故障）
3. 任务书里 `## [T5] DONE <一句话>` 这种占位符行 ⇒ 不读出（已有判据，回归锁）
4. 空文本 / 只有空白 ⇒ 空数组
5. 只有 `## [QUEUE] EMPTY` 一行、前面没有真 DONE ⇒ **不**读出（条件②不满足）
6. 真 DONE 之后隔了几行文字再出现 EMPTY（不是最后一行）⇒ 不读出（条件①不满足）

**验收**：`node node_modules/vitest/vitest.mjs run scripts/doubao/__tests__/markers.test.mjs` 通过（**把 `Tests N passed` 那行逐字贴出来**）。
