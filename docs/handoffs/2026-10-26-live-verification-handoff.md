## 2. 本轮唯一主线：实机验证

### 2.1 开跑前必须确认的两件事

| # | 事 | 为什么 | 谁做 |
|---|---|---|---|
| **①** | 设置里有没有 **`world_building` 的全局覆盖版** | 有则**内置模板被静默遮蔽**（判据 AO：不报错、不提示）。N1 白改，A9–A12 验的是那份旧稿 | 作者查 → 恢复默认或手工同步 |

**②要挪的是哪几条**（`writingStyle` 槽里可数的那几条）：单段 ≤120 字、对话占比 25–40%、主叙述句 7–15 字。挪到「全局写作要求」，文风槽里删掉它们。**散文式风格描述不用挪**——那些本来就该被降权，挪过去反而有害。

### 2.2 日志在哪看 —— 清单里没写清，这里补上

- **位置**：底部状态栏**左下角**「日志」按钮 → 底部面板「日志」页（`StatusBar.tsx:11` → `BottomPanel.tsx` 的 `LogsView`）。

  ⇒ **一小时、几十次调用的流程足以把 A 区的日志挤出去。** 纪律：**A 区验完立刻抄读数，不要攒到最后统一看。**

### 2.5 跑的时候会看到的两个现象 —— 都不是故障，别记成缺陷

**① 侧栏那七个登记项，大部分不会自己长出来**

作者 2026-10-26 问「新项目的这些状态是不是都自动采集」。**不是**，按自动程度分三档：

| 侧栏项 | 数据来源 | 自动程度 |
|---|---|---|
| 资源登记 | 世界观生成后自动跑抽取 pass（`architecture.command.ts` 的 `attachWorldBuildingResourceCandidates`），面板上还能手动重跑 | **自动出候选，作者勾选才落库**（模型不能直接写） |
| 知情（谁知道什么） | 候选只来自**已定稿且投影有效**的连续性索引（`db:knowledge-fact-candidates`），且「事实只能引用、不能新写」 | **定稿后才有候选**，第一章之前必然是空的 |
| 能力（本书的能力规则） | 只从金手指文本里抽名称填进「名称」格（`abilityNameCandidates`） | **半自动，只预填名字**，机制要自己写 |
| 关键物品 | 作者侧唯一写入口 | **纯手填** |
| 制度（周期事件） | 作者侧唯一写入口（`CadenceRegistryPanel`） | **纯手填** |
| 卷末交接 | 卷末章定稿时自动生成初稿 | **自动生成** |
| 章节蓝图 | AI 生成（侧栏显示「待生成」= 还没轮到它） | **自动生成** |

⇒ **预期**：新项目跑到第一章时，写前查阅七节里的「关键物品」「制度」「知情」三节是**空的**，这是设计（作者侧 SSoT，不许模型推断直接成为事实），**不要记成「注入失效」**。要验这三节的内容，得先手工录几行。

**② 一键配置与单项生成是两份不同的 prompt，而且都是「扩写」不是「替换」**

作者 2026-10-26 问「一键和单项对同一字段是不是同一份 prompt，单项是不是用来抽卡的」。**两个答案都是否**：

- **不是同一份 prompt**：一键走 `generate_global_config`（一次调用返回整份 JSON），单项走 `generate_novel_config_field`；而且单项的字段要求**不在模板里**，是代码里的硬编码表 `generate-field.command.ts:259` 的 `fieldRequirements`。两处措辞已经漂移，且**各有对方没有的条目**（一键的 `goldenFinger` 没有「不能成为万能能力」，单项的 `coreOutline` 没有「爽点起伏」）。⇒ 同一个字段，两个入口抽出来的标准不一样。
- **单项不是抽卡**：两条路径都过 `preserveAuthorText`（`novel-config-expansion.ts:46`）——已有内容不覆盖，而是「作者原文 + 空行 + 生成」。**对某字段不满意点三次单项生成，该字段会变成三段拼接**，得手动删前两段。

⇒ **预期**：本轮验证**不要用单项生成去"重抽"**，会把配置写长。C1/C2 的重生成走**整章重生成**，与这条无关。

> 这两条都属「行为与预期不符」，但**不在本轮修**（要改就是结构变更：抽共享字段要求常量 / 重新定义两个入口的合并语义，都得上设计）。评估与方案对比已出 → [`../design/product/config-registry-write-paths-assessment.md`](../design/product/config-registry-write-paths-assessment.md)（含手填工作量分档、冲突风险三类、diff 组件能复用多少）。
>
> 其中一条值得记住：**「抽卡变成追加」的根因不是追加规则错，是缺一个显式的「这次我就要替换」动作**；diff 预览正好是这个动作的载体。所以「输入框看不清」和「越抽越长」是同一个缺口。

## 6. 环境与坑（本轮踩出来的）

1. **测试**：`pnpm test <paths>` 即可，全工程一份 ABI（走 `ELECTRON_RUN_AS_NODE=1`）。`pnpm dev` 开着也能跑——**这是 `36f8748e` 解决的**，不用再关 dev、不用再 `rebuild:electron`（`predev` 自动做）。真需要纯 Node 才用 `pnpm test:node`（它会切 ABI，必须先关 dev）。
2. **`pnpm` 在 Git Bash 里可能挂**（npm shim 的 node 路径损坏）⇒ 用 PowerShell 跑。
3. **跑 electron 全量一次不可信**：并行触发 safe-delete 阈值 50 与 10s hook 超时，栈落在 teardown 的 `fs.rmSync`（**不是断言**）。⇒ 按文件 / 按目录跑；必要时摘 `CODEBUDDY_SAFE_DELETE_BULK_STATE_DIR` + `CODEBUDDY_TOOL_CALL_ID`。
4. **既有红不等于本轮回归**：`src` 10 文件/29 例、`electron/controllers` 3 例、`project-migration-acceptance.mjs --run-synthetic` 2 例（`PROJECT_MIGRATION_UNSAFE_FILE`）都是**基线既有**。每期只与基线失败集比对。
5. **文档体检**：改完跑 `node scripts/check-doc-links.mjs` + `node scripts/check-doc-placement.mjs`（新增必须为 0，不许动基线）。
6. **改模板的两个静默陷阱**（N1 触及，下次还碰得到）：
   - **五维标题文字一个都不能动** —— 齐备性、规则抽取、空间约束三条链共用这个锚点，改了日志会变成「未能识别五维标题结构」；
