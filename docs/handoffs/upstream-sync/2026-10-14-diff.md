我方现状（`1c3d436`，2026-10-14）：

**判定：不吸收上游这一半。** 理由：上游是"整个弹框滚动"（会把标题栏和操作按钮一起滚走），我方是"进度区内部滚动 + 已完成项折叠"，**更精准**。两者目标相同（防撑破），我方方案更完备。
⚠️ 但保留一个观察点：若未来弹框其他区域（如错误提示）也会撑破，再考虑给 `DialogContent` 补 `max-h-[90vh]` 作兜底 —— 那是**增量改进**，不是吸收上游。

**(b) 章节卡「出场关键人」输入被打断 —— ★ 我方有同样的 bug，必须吸收**

上游改法：
```diff
                     <Input
-                      value={selected.characters.join('、')}
+                      key={selected.chapterNumber}
+                      defaultValue={selected.characters.join('、')}
                       onChange={e => updateField('characters', e.target.value.split(/[,，、\s]+/).filter(Boolean))}
```

**为什么是 bug**：受控 `value` 由 `characters` 数组 **join 后回写**，用户输入中间的顿号会被 `split(...).filter(Boolean)` **吞掉** → 输入框光标跳动、顿号打不出来。改用 `key` + `defaultValue` 后，输入态不再受重渲染干扰。

**我方现状（已核实）**：`src/components/editor/ChapterCardEditor.tsx:1136` 仍是 `value={selected.characters.join('、')}`，**bug 同样存在**。

**我方在此处的既有改动（`5ef5b214`）**：只改了 `Label` 文案（`（逗号分隔）` → `（顿号或逗号分隔）`），**与上游改动不同行、不冲突**。

⇒ **判定：吸收（手工应用上游那 2 行）**。不能直接 `cherry-pick`（该提交同时含我们不想要的 (a) 半），须手工改。

#### 2.1.2 `b5781975` 拆分与处置

含两个**相互独立**的修复：
- `fix(draft): retry the first eligible short-outline failure` —— 短细纲**首次**失败未重试（部分 Ⅱ）；
- `fix: initialize new project baseline in one transaction` —— 新项目基线初始化改为单事务（部分 Ⅰ）。

**为什么不能整体 cherry-pick**：它动的是 `generate-draft.command.ts`（**我方 P0-1 的核心落点，改动极大**），直接 cherry-pick 必然冲突。须**逐部分判断**。

##### 部分 Ⅰ：单事务初始化 —— ✅ 已吸收（`55122230`）

```diff
   database.pragma('foreign_keys = ON')
-  initializeLegacyBaselineSchema(database, importSourceSecret)
+  database.transaction(() => initializeLegacyBaselineSchema(database, importSourceSecret))()
```

**判据**：我方 `electron/database.ts:29` 与上游该行**逐字相同**、上下文也相同 ⇒ 干净应用、零冲突。

**碰不碰 schema 红线？** 不碰。红线 1 约束的是**不能改 DDL 内容**（`sha256(JSON.stringify(sqlite_master))`）。
这里是**同一段 DDL 包进事务**，语句、顺序、文本全不变 ⇒ 指纹一致。改的是**失败时的原子性**。

**真实风险面（比初评更大）**：`initializeLegacyBaselineSchema` 不是单个 `exec`，而是
`applyBaselineTables(db)`（一大段建表）+ 之后**多个独立的 `exec`**（若干 `ALTER TABLE` / `UPDATE import_runs`）。
⇒ 无事务时，「建表成功 + 后续某个独立 exec 失败」会留下 **20+ 张半成品表**。

##### 部分 Ⅱ：短细纲首次失败可重试 —— ⚪ **保留待评估**（本轮不动）

上游把「首次生成」**上提到 retry 分支之前**，并用外层 `let outlined` 汇聚两条分支的判定。

**我方现状**（`generate-draft.command.ts:1111-1137`）：retry 分支在前、首次生成在后，
**首次失败走 `:1133` 直接 throw**，不落成可重试记录 ⇒ **缺陷真实存在**。

**为什么不本轮修**：
1. 与 P0-1 的 `outlinePrompt` 逻辑**同段**，逐行对齐有回归风险；
2. 上层 `if (!recovery)` 里的 `outlined` 我方是块级 `const`，上游改成了外层 `let`，语义需重新对齐；
3. 性质是**失败体验问题**（用户须整章重跑），**不是数据损坏** —— 可以安全延后。
   本轮要求「不过重、低回滚风险」，故不纳入。

⇒ 登记为待评估；待单独开轮、出小设计稿后再动。
