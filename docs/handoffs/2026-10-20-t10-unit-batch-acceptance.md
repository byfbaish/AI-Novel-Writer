## 3. 项目 A · 新项目（按 A1→A6 顺序，改一个变量看一个结果）

### A0 准备

- [x] 新建项目，`pnpm dev` 里走完「故事前提 / 角色 / 世界观 / **弧光结构**」四个步骤
  - ⚠️ 弧光结构必须有 `### 单元一：` 或 `【小弧名】` 划界，否则单元模式**一步都跑不了**
- [x] 记下 `novelConfig.totalChapters` = \_*\_150\_*_（后面所有判据都拿它当分母）
- [x] 记下弧光结构里有几卷、每卷几个单元 =7 卷，第 1 卷 4 个单元；第 2 卷 5 个单元；第 3 卷 3 个单元；第 4 卷 4 个单元；第 5 卷 5 个单元；第 6 卷 4 个单元；第 7 卷 3 个单元
- [x] 确认 `.ai-novel/partial_arch.json` 里**没有** `synopsis_covered_to`（或为 0）

### A1 首单元

- [x] 打开「AI 生成故事架构」弹窗时，情节大纲那一块**不再出现章号输入框**，而是一行  
  `单元模式：第 k 个单元，从第 N 章起` + `本卷剩余 X 章，名义上界 Y 章`
  - 若仍看到「第 1 章 到第 5 章」的输入框，说明弹窗里的探针没拿到单元；下面一行灰字会写原因
- [x] 勾「情节大纲」→ 确认 → 日志 `正在写【单元 1：名】，从第 1 章起（全书 M 章）`
- [x] 完成 → 日志 `本单元实际写 N 章（第 1–N 章）`
- [x] `.ai-novel/partial_arch.json`：`synopsis_range.to` = **实际** N（不是名义上界）
- [x] 同文件 `synopsis_unit_cursor` 指向「**下一个要写的**单元」（不是刚写完的那个）
  - 判据只看 **A0 里记下的「本卷有几个单元」**，分两种情形，别混：
    - **本卷还有下一个单元**（本卷单元数 ≥ 2）⇒ `volumeIndex` **不变**，`unitIndex` = 2，`writtenInVolume` = 本单元实际章数  
      　首单元实测 5 章 ⇒ 应该读到 `{ volumeIndex: 1, unitIndex: 2, writtenInVolume: 5 }`
    - **本卷只有这一个单元**（本卷单元数 = 1）⇒ `volumeIndex` 进下一卷，`unitIndex` = 1，`writtenInVolume` = 0
  - ⚠️ 「全卷唯一单元」这个前提**只在本卷真的只有 1 个单元时**成立。本项目第 1 卷有 4 个单元，  
    所以首单元写完后仍然是**同一卷的第 2 个单元**，`volumeIndex` 不会变 —— 本轮实测即为 `{1, 2, 5}`。

### A4 卷末对账

## 4. 项目 B · 旧检查点项目（A 做完再做，别并行）

### B0 准备与自检

- [ ] 打开 `.ai-novel/partial_arch.json`，三项**同时**成立才算合格的「旧检查点」：
  - [ ] `synopsis_range` 存在

- [ ] `plotStructurePlan` 有 `### 单元一：` 或 `【小弧名】` 划界（没有 ⇒ 先重跑弧光结构，见 §6 风险 1）

### B1 迁移

- [ ] 点「生成情节大纲」→ 日志出现 `迁移情节大纲单元游标`（**只出现一次**）
- [ ] `partial_arch.json` 里出现 `synopsis_unit_cursor`
- [ ] 该游标定位到的单元与「含 `covered_to` 的单元」一致（`unitIndex` 对得上你记忆里正在写的那一个）

### B2 迁移后跑完

- [ ] 本次生成正常跑完，**不报**「无法由单元游标定位本次单元」

### B3 边界情况（命中就记，不要现场改）

- [ ] 若 `synopsis_covered_to` 正好停在某单元**最后一章**：记录实际 `unitIndex` 与 `from`
  - 预期现象：`from` 指向下一单元开头，但 `unitIndex` 仍是被写完的那个（滞后一位）。**这是 T7 迁移口径的已知缺口**，记为「待定」，不要在这里改代码

## 4C. C 组 · 连续单元（T12，在 A 上直接做）

> 设计见 `docs/design/architecture/e3-unit-batch-chain-design.md`。  
> 只验「连写 N 个 + 到本卷末停 + 中途可停」，**不验跨卷**（v1 明确不做）。

### C1 弹窗上限

- [ ] 打开生成弹窗，单元块下面出现「连写 [1] 个单元（本卷还剩 X 个，连写只到本卷末）」
- [ ] X = 第 1 卷的单元数（本项 A0 记的是 4 ⇒ 下拉最多 4 个）
- [ ] 下拉里**没有**超过 X 的选项（想选 5 也选不到）

### C2 连写 2 个

- [ ] 选 2 → 确认 → 大纲页出现横幅「连续生成中：第 1/2 个单元」
- [ ] 第 1 个单元写完后**自动**开始第 2 个（不用再点任何按钮）
- [ ] 第 2 批日志显示 `正在写【单元 2：名】，从第 N+1 章起`
  - 判据：`from = covered_to + 1`。**若从第 1 章重来，说明链发成了覆盖重写**
- [ ] 第 2 批的 prompt 里仍有作者的「补充指导」与「每章目标字数」（不是只剩默认值）
- [ ] 两批都完成后横幅变「连续生成已停止（2/2）：连写的单元已写完」

### C3 中途停止

- [ ] 再选 3 个单元跑起来 → 第 2 个单元**正在写**时点「停止连写」
- [ ] 期望：**当前这批照常写完**，之后不再有第 3 批（不该半路砍断）
- [ ] 横幅显示「已手动停止连写（当前这批会写完）」

### C4 卷末停下

- [ ] 一路连写到本卷最后一个单元 → 停止原因应&#x662F;**「本卷已写完」**，不是「连写的单元已写完」
  - 两者差别：到卷末时 `launched < total` 也可能成立（比如本卷剩 2 个但你选了 3 个，弹窗已封顶所以不会出现；主要看提示语是否指向卷）
- [ ] `partial_arch.json` 的 `synopsis_volume_deviations` 出现本卷一条记录（A4 的判据）

### C5 失败即停

- [ ] （可选，成本高）人为让某一批失败 → 链停下、toast 报「这一批失败了，已停止连写」
- [ ] 已完成单元的检查点与正文**完好**，重开弹窗能接着写

## 7. 已知风险（跑之前先知道，别当成新 bug）

1. **旧项目没有结构化骨架就定位不到单元。** `computeSynopsisUnitRange` 第一步是 `parseArcStructure(plotStructurePlan)`，为空直接返回 `null` ⇒ 「无法由单元游标定位本次单元」。先把弧光结构重跑成带「### 单元一：」的形态再验 B。
2. **旧检查点停在单元边界时 `unitIndex` 会滞后一位**（见 B3）。发射侧与命令侧同源，所以不会被拒绝，但语义错位。属 T7 迁移口径缺口，T10 只记录。
3. **中断态会退回按章区间。** `synopsis_incomplete = true` 且**盘上真有半成品正文**时，单元模式显式让位给旧的 `resumeSynopsis`，因为「中断续写是接着写同一单元还是算下一个」尚未定。日志里走 range 是预期。
   - 例外（2026-10-20 修）：`incomplete=true` 但 `synopsis_result` 为空、`covered_to=0` —— 这是批前预写留下的空标记，背后没有可续内容，**视同未开始**，照常进单元模式。
4. **章标题里章号两侧可能带空格**（`## 第 6 章：xxx`）。2026-10-20 实机整批因为这个被判「没写出章节条目标题」而丢弃（解析只认紧排的「第6章」）。现已修：`plot-outline-contract.headings`、`validPlotOutlineEntry` 与 `architecture.command` 的 `ZH_CHAPTER_TITLE_RE` 都容忍空格；`arc-node` / `synopsis-projection` 本来就容忍。**若再看到该报错，报错里会带上「能认出的最大章号」**，先看这个数：
   - `0` ⇒ 一个标题都没认出来（格式又漂了，把那段原文发我）
   - `> from` ⇒ 认出来了但起点不对（模型跳章或写成章组）
