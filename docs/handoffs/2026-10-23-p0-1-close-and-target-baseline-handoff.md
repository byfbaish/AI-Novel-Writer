### 这轮最重要的一个技术判断

期 1 的判据「快照代 < 全局 generation ⇒ stale」**在逐章修复时会错**：改第 22 章会让第 21 章已做的确认失效，可它根本不影响 21。
根因是全局计数器丢失了「变的是哪一章」。修法：M13 变更日志 + 判定改为
`max(快照代, 最新确认代) >= MAX(generation) WHERE change.chapter < 本章`。
**凡是"派生是否过期"的判定，都要问"影响方向"** —— 单向因果不能用一个标量表达。

## 3. 期 4 并入 P1-1（主 agent 判断，已写入台账）

**结论**：原 P0-1 期 4「波及扫描」不单独立项，**并入 P1-1（连续性四项宿体）**。

**理由**（查证，不是偏好）：

1. 扫描要产出「**冲突**清单」，必须先有可比对的 **canon**；四类宿体就是 canon。
2. 宿体不存在时，确定性档只能做「实体名 / 数值的字面检索」——产出的是「**命中**清单」（这名字又出现了），不是「这里自相矛盾」。
3. 而且**没有按章检索正文的通道**（`db:search-chapter-text` 不存在），要全量读几百章正文才有得比。
4. 所以先做扫描 = 造噪声源，与 W6 做账本同型（看起来聪明，没有判据）。

**合并后的顺序**：① 四类宿体 → ② 确定性档（宿体 + 正文检索）→ ③ 语义档（只扫命中章，全书语义扫默认关闭）。
**验收**：物品归属能答「刀在谁手里」；注入一处人造冲突（改数额/改单位/改归属）能被扫出并带引文；干净章节零误报。

## 5. 防目标漂移的规则（作者 2026-10-23 定）

1. **评审报告即事实依据**。施工目标从它派生，不从"我觉得应该"派生。
2. 要推翻任何一条结论，必须提供**新的行业标准**或**新的代码证据**，并在报告对应条目下写「何时、被什么推翻」。
3. 不得因为"做起来麻烦"或"想换个做法"而改目标。**目标漂移比做不完更贵**。
4. 加任何新机制前，先答四问（行业叫什么 / 谁消费 / 失败形态属哪类 / 已有产品做过什么）。
5. 收口一期时，**所有写着状态的位置**都要同步（顶部状态行、分期表、台账、交接稿）。
