#### 12.3.4 ⑤ D12 自动重跑一次

① **实际操作流程**：你让 App 批量写第 N 章，模型把上一章的剧情又写了一遍。落库前守卫命中，这一章**不保存**，界面报「新章节开头与上一章结尾存在大段重演，结果未保存」，你得自己再点一次生成；正文会进候选区，不至于白丢。

② **卡点**：失败即丢弃、没有自动纠正；你手点一次，而同一 prompt 直连复跑 10 次里只有 3 次干净 ⇒ 大概率再撞一次。更根本的是现在只比「上一章结尾 1000 字 × 本章开头 1200 字」，短章里开头就占 61%–73%，窗口之外一律看不见；「整章复用只换个开头」能绕过。

③ **想怎么改（产品意图）**：把「失败即丢弃」改成「失败 → 带具体纠正信息自动重跑一次 → 仍失败才丢弃并如实报出两次的重合率与重合段」。要保住的是你不必为一个已结案的 9B 模型弱点反复手点生成；**不重开 D12 结案结论**。

#### 12.3.5 ⑥ 同剧情判据

**去哪确认**：[`same-plot-check-20261109.md`](../design/product/same-plot-check-20261109.md) §三 是三条判据的成本 / 漏报 / 误报对照；界面侧看「AI 审稿 — 一致性检查」生成的报告；锚点硬约束在 `src/services/workflows/commands/review-chapter.command.ts:129`。
