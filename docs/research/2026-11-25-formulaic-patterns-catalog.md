## 0 这份文件不做什么

1. **不判「这段是真人还是 AI 写的」**。判真伪既不可靠也不该是产品目标（见课题总纲 §2「不追骗过检测器」）。
2. **不做 AI 词表拦截**。词表类全部进「不做」，理由在 §4，不是遗漏。
3. **不引需要 `logprobs` 的方案**。生成链不透传 logprobs，任何依赖它的判据在本仓不可实现（如 DetectGPT / Fast-DetectGPT / Binoculars 类）。
4. **不下载、不转载正文语料**。引用的都是方法与公开统计结论，二手仓库受 CC BY-NC 4.0 约束，**不复制其指标表与原文例句**，数值只作量级参考。
5. **不重复 11-04 已收的指标**（解释句密度、心理直陈、连接词密度、4-gram 自重复、句长方差），那些是「测量仪」，本清单只补**句式与篇章形态**。

## 1 判级与「可检」的定义

### 1.1 依据判级（沿用 `docs/design/prompt/d18-chapter-hook-contract-design.md:132-139`）

| 级别 | 本文件里的含义 | 能否作判据 |
|---|---|---|
| **一手·可核** | 论文原文（至少摘要全文）亲自取到，机构、日期、方法可指 | 可作硬依据 |
| **一手·题名级** | 只核到题名/摘要片段，方法细节未取 | 只作方向，不作依据 |
| **二手·可核** | 第三方实测文章/仓库 README 亲自取到，方法与数字连在一起 | 方向印证；**数值不作我方阈值** |
| **二手·不可复核** | 方法与结论公开，但语料因版权不入库，无法复算 | 只作方向与量级 |
| **内部既有** | 本仓已有文档已收（11-04 / 11-12） | 引用不重算 |

### 1.2 一个套路算「可检」的四个字段

负责人追加的验收尺：**「可检」= 能落到一条命令或一条规则，写得出「谁跑、跑什么、阈值多少」**。本文件每条都填这四格：

- **谁跑**：developer（写脚本）／QA（复算）／产品经理（只读结果）；
- **跑什么**：一条可执行命令（本轮**不建**脚本，只定契约）；
- **阈值**：判定式写死，不留空；
- **输出**：脚本必须吐出什么才可判。

统一判定式（四条 P17 候选共用）：

```
命中 ⇔ per1k ≥ max(P95_author, 绝对下限) 且 count ≥ 2
```

- `P95_author`＝作者库人类章（**≥ 20 章**）同特征每千字密度的 P95；**不足 20 章该特征只能进报告，不出判定**（这是已定决策，不再是开放项）；
- 绝对下限逐条给，防止「1 次 / 4000 字」被当作命中；
- 差值方向一律「本章 − 人类基线」，只报区间与命中率，不出点估计（沿用课题总纲 §3）。

## 3 四条 P17 候选的可检契约（写得出命令与阈值）

> 本轮**只写契约，不建脚本**。四条都落在同一个待建脚本上：`scripts/res/scan-formulaic.mjs`（S3 立项那轮由 developer 写，`src/` 零改动）。

### 3.1 F-05 否定式对举（S3-2，成本最低）

- **谁跑**：developer 写脚本；QA 用同一命令复算两遍，两次读数必须逐字相同。
- **跑什么**：
  ```bash
  node scripts/res/scan-formulaic.mjs --dir .runtime/res-corpus/author-v1 --feature neg-parallel --json
  ```
  输出每篇 `{chapter, count, per1k, hits:[{offset, text}]}`。
- **阈值**：`per1k ≥ max(P95_author, 0.3)` 且 `count ≥ 2`。作者库 ≥ 20 章才出判定。
- **为什么排第二**：它是二手实测里**唯一的纯写作信号**（Cliff's δ 两个模型族都过 0.7），且**一条正则就能实现**，误报只有「省略式口语对白」一类，可在命中样本上人工抽查 20 条校准。

### 3.2 F-09 结论提示冒号（S3-3）

- **跑什么**：同上脚本 `--feature conclusion-colon`。
- **阈值**：`per1k ≥ max(P95_author, 0.5)` 且 `count ≥ 2`。
- **关键限制**：判据是**冒号前的提示词**，不是冒号总量——二手件里冒号总密度人类反而更高（δ 为负），若用总量会得到反向结论。这条正好是「同一字符两种量法结论相反」的实例，写进判据时要连限制一起写。

### 3.3 F-01 段间跳转率（S3-1，我方唯一空白维度）

- **跑什么**：`--feature para-jump`；对每对相邻段算字符 2-gram Jaccard，输出**中位数**（越低＝越顺滑）与「≥ 0.30 的段对占比」。
- **阈值**：二值判定用占比，`占比 ≥ P95_author` 记命中（顺滑侧）；中位数只作报告值。
- **方向唯一（写死，2026-11-25 修）**：该占比**越高**＝相邻段重叠越重＝衔接越顺滑＝越像 AI。脚本、判据、报告三处都只认这个方向；出现「越低越像 AI」的表述一律按笔误处理、不得据其读数下结论。
- **为什么排第一**：四项指标全在句/段内几何，**篇章衔接我方零覆盖**（11-12 §4.1-P2 已点名为空白）；两个独立来源方向一致（AI 更少跳转），且不需要语义模型，纯字符统计就能做。

### 3.4 F-06 段首零回指评论（S3-4，量级有冲突，先采基线再谈条款）

- **跑什么**：`--feature zero-anaphora-claim`。
- **阈值**：`占比 ≥ max(P95_author, 0.06)`；作者库不足 20 章则**只进报告**。
- **必须写在判据里的冲突**：中文实测件给的是 4.4 倍（人类多带「这」字），另一个二手件给的是约 1.5 倍且已从自家脚本移除。**两源量级差近 3 倍、结论方向一致但不稳定**——所以它的排序在四项里最后，且**不许拿任何一方的倍率当阈值**，必须自采。

## 4 「不做」清单及理由（含被实测推翻的流行说法）

这一类要写清楚，因为它们最容易被当成常识再收一遍：

| 流行说法 | 实测/一手结论 | 我方处置 |
|---|---|---|
| 句长均匀＝AI 味 | 人机句长方差无差别；「AI 均匀 51 倍」是表格被切成一句的伪结果；另一手件也只在**小说之间**看到压缩，不是章内 | 不做；**禁止为像人而制造参差**（11-12 已定） |
| 删掉设问会更像人 | 正文设问人类是 AI 的 17 倍 | 不做（方向相反） |
| 删掉比喻会更像人 | 比喻人类是 AI 的 2.4 倍；只有「贴切度」AI 差，而贴切度机器判不了 | 不做（比例方向相反；质量归人审） |
| 黑名单词表（赋能/闭环/抓手/delve） | 配对后 δ≈0.10 无差；「首先/其次/总之」δ≈0.02 彻底失效；delve 在被点名后一年内自行下降 | 不做（词表拦截明令禁止，且它自己会过时） |
| 「这意味着」式复述是 AI 味 | 人类反而更多 | 不做（方向相反） |
| 概括替代具体信息是 AI 味 | 曾按 24.7% 判 AI，对称口径复查 26.0%，净差近零，已被源头标为永不据此删改 | 不做 |
| 破折号多＝AI | 分模型指纹：GPT 比人少、另一族 100% 使用；同一族跨版本差一个数量级 | 不做（无稳定方向；只作报告字段） |
| 序数小标题/空转开场 | 多出现在说明文、教程、问答体，网文正文几乎不出现 | 不做（我方体裁零触发面） |

**共同教训（写进 S3 判据清单顶部）**：流行的「AI 味」清单里，**过半是体裁混用造成的**——把说明文、问答体的特征套到叙事文本上。凡进入我方判据的特征，必须先证明它在**网文单章**里有变异，而不是只在「问答 vs 回答」里有差异。

## 7 结论

1. 市面上能收的「低层套路」里，**真正够格进我方判据的只有 4 条**（否定式对举、结论提示冒号、段间跳转率、段首零回指评论），其余 16 条要么被我方体裁结构挡掉（无小标题、无列表），要么方向被实测推翻，要么机器判不了。
2. **最有价值的产出是那张「不做」表**：它挡掉的都是会被当成常识再收一遍的条目（句长参差、删设问、删比喻、词表），省下的不是工作量，是**一轮错误干预**。
3. 我方缺的不是特征数量，是**人类基线**：20 条里 17 条卡在「未测」，唯一原因是没有中文网文人类对照语料。这一点不在本文件解决，但要写进 S3 立项前置——**没有 ≥ 20 章人类基线，四个候选全部只能进报告**。
