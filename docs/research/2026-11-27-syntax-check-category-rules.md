# 句法体检器（syntax-check）十类规则说明

本件说明 `scripts/syntax-check.mjs` 的判定口径：十类 A–J 各抓什么、哪些能出判定（`tier=verdict`）、哪些只作清单（`tier=report`）、为什么不落的类不落、各类已知误报形态。**器件只检不生成**：不调模型、不出改写稿、无新依赖，同一输入两次运行 `--json` 输出逐字节相同。

## 0. 三条底层口径（与仓内既有实现同源，不另造）

1. **单位**：汉字计 1；拉丁字母串按「词」计 1；其余可见码位各计 1；空白与标点不计。口径同 `src/shared/draft-units.ts` 的 `countDraftUnits`。
2. **断句**：`/[^。！？…；;!?]+[。！？…；!?;]*/gu`，与 `src/shared/prose-shape.ts` 的 `SENTENCE_PATTERN` 逐字相同。`.mjs` 不能 import `.ts`，故这是仓内第二份拷贝，两处改一处必须同步另一处。
3. **对白**：句中出现 `「『“"”` 任一即算对白句；A、B1 只对叙述句生效，B2 只对对白句生效。

另有一条实现层的边界：断句会把收尾的闭引号单独切出（`"…”`），零单位残片不算句，直接丢弃——否则 B2 会把同一个对白计两遍。

## 1. 十类定义与去处

层级：**判定**＝可对单章给「命中/未命中」且过了误报闸门的规则；**清单**＝只出候选行供人审；**读数**＝照常报数、不进判定集、不进 prompt；**不落**＝纯规则抓不到，在 `unsupported` 里留占位。

| 类 | 名称 | 规则 | 判什么 | tier | 依据 | 已知误报形态 |
|---|---|---|---|---|---|---|
| A | 断句切碎、句号错位 | A1/A2/A3 | 极短句紧跟长句、句末悬空功能词、单字叙述句 | report（读数，不判罚、不进 prompt） | 逐章密度两臂区间重叠，且「连排短句」方向相反（名家 0.29 vs 生成 0.00 每千字），当判据会系统误报人类稿 | 合法短句「他停住。」、人名单独成句、章末点题句、对白短应答（已排除对白） |
| B | 短句四不像 | B1/B2 | 无状语外壳的裸短叙述句、极短对白 | report（读数，不判罚、不进 prompt） | 逐章不判（名家最密 5.20 > 生成最疏 1.68）；语料级聚合才成立 | 干净动作句「他点头。」、合法简洁对白、拟声单句成段[示例·非语料] |

`unsupported` 占位带缺什么：E `needs-spatial-model`、I `needs-event-graph`、J `needs-syntax`。占位保留是为了下游 schema 不断档，不是「检过了」。

**去处一览**：判定项只有 H、F（`tier: verdict`）；C 维持出卡；D、G 出卡；A、B、C、D、G 一律不进判定集；E、I、J 不落。A、B 只报读数，与 C、D、G 的「清单」不是一个口径，也与「不落」不同——它们照常算数、照常打印，只是不参与判罚。

## 2. C / D / G 为什么出卡（判为清单，不给判定）

三类的共同点：**规则能出候选，但候选与「真问题」之间的距离是语义距离，阈值补不上**。

- **C 零区分度**：两臂每千字密度几乎相等（7.05 vs 6.74），密度比落在 1.00 附近。任何阈值都会同时切到人类稿。加上没有分词器，n-gram 会把人物名、地名一并抓进来，进一步污染。
- **D 比约 1.00**：只抓得住「比喻短且无落点」这一形态，而两臂各 2 条。真正的「生造搭配」要词义判断，本器件给不出。
- **G 需设定域输入**：系统提示式的说法（面板、数值、规则播报一类语汇）在玄幻里出戏，在都市/科幻里是白话。判定设定域等于让模型读全文，与「只检不生成、纯规则」直接冲突，所以输出强制带 `requires: setting-domain`，由人裁定。具体命中词条只在 `.runtime` 的实测词表里，本件不列。

C 在上一轮评审里已被判「零区分度、出卡」，因此分母口径（49 条）与门槛计算里不含 C/D/G 的判定贡献。

## 3. E / I / J 为什么不落

- **E**：矛盾的判定对象是「两个陈述在同一世界模型下不能同时为真」。纯规则只能枚举词对（很远 × 传不远），换场景立刻失效，写进规则就是把个别语料当规律。
- **I**：信息密度需要「事件」这个中间层——谁做了什么、推进了什么。没有事件抽取，规则只能数长度和复现，而长度与密度不等价。
- **J**：主语切换、词性错乱都以分词与依存句法为前提。本卡禁用新依赖（无分词器），所以只在设计上留了 0.20 置信的形态候选，本实现未启用，也不计入召回。

## 4. 词表与版本口子（判据 7）

- 仓内只提交零命中骨架 `scripts/lib/syntax/phrases.skeleton.json`（`version: v2`、`H: []`、`G: []`），保证默认运行不产生任何词表命中；骨架的 `version` 与实测词表对齐，避免两处版本号打架。
- 实测词表落 `.runtime/res-eval/phrases.v1.json`（不入库），`version: v2`；H 分三组共 12 条（生理反应 6、残缺比喻 3、表情与气场 3），G 共 4 条（系统腔术语）。逐条词条只在该 `.runtime` 文件里，仓内不出现。
- 扩词或扩规则必须同步改 `version` 并重跑 `--stats`，把覆盖读数一并更新。`--json` 会把 `tool.phrasesVersion` 写进输出，用来对账「这次读数是哪版词表跑的」。
- 词表正文不入库，是本器件的硬纪律：入库即等于把语料片段带进仓（`.runtime/` 之外一律视为泄漏）。

## 5. 本轮实测读数（`.runtime/res-eval/blind-eval-v1.md`，49 条可计片段）

**验收口径＝带 `--phrases` 跑**：判据 3 的数只有带实测词表时才成立，命令见 §6 第一条。下面第一组（带词表）是验收读数；第二组（无词表，默认骨架）只作对照——无词表时 H 被 disabled、判定集缩小，得 `covered=15/49`、`verdict_covered=3/49`，这两行**不是回归**，不能拿来对判据 3 的门槛。**判罚只看 `verdict_covered`（判定集＝H+F，`rules.mjs` 里唯二 `tier: verdict`）；`covered` 含 A/B，只是读数，不判罚、不进 prompt。**

带词表（`--phrases .runtime/res-eval/phrases.v1.json`）：

```
covered=30/49 (readings only, range=A/B/H/F)
verdict_covered=20/49
denominator: T=49 (51 quoted fragments - 2 summary-only, non-countable)
```

无词表（默认骨架，H 移出判定集）：

```
covered=15/49 (readings only, range=A/B/H/F)
verdict_covered=3/49
H: disabled (no phrase table)
```

逐类闸门（带词表，human/1k vs ai/1k）：A 0.59 / 3.09 pass-report；B 1.76 / 9.27 pass-report；C 7.05 / 6.74 FAIL-report；D 0.59 / 0.56 FAIL-report；F 0 / 1.4 pass-verdict；G 0 / 1.4 pass-report；H 0 / 4.78 pass-verdict。

两点必须写明：

1. **达标靠扩表，不是靠调阈值**。v1（8 条）时 `verdict_covered` 只有 9，不到 0.28 线；扩到 12 条才到 20。增益主要来自一条「动作套话」类词条（去表即回落，读数回到 12 附近，词条原文只在 `.runtime` 词表里）。这是词表覆盖面问题，与阈值无关——门槛、分母口径、C/D/G 的归类一个都没动。
2. **`--stats` 读数与「零命中默认」是两件事**。判据要求的两组读数分别取自带词表与不带词表的两次运行，不能互相顶替。

## 6. 复算命令

```
node scripts/syntax-check.mjs .runtime/res-eval/blind-eval-v1.md --stats --phrases .runtime/res-eval/phrases.v1.json
node scripts/syntax-check.mjs .runtime/res-eval/blind-eval-v1.md --stats
node scripts/syntax-check.mjs .runtime/res-eval/blind-eval-v1.md --json --phrases .runtime/res-eval/phrases.v1.json
node scripts/syntax-check.mjs .runtime/res-eval/blind-eval-v1.md --extract-rejects .runtime/res-eval/syntax-rejects-v1.json
```

`--extract-rejects` 的目标路径解析后不在 `.runtime/` 之内即退出码 2、不写文件（语料纪律）。
