# T1 · 字数失守根因：1751 字是怎么被允许落库的

**根因一句话**：不是模型偷懒，是**唯一的自动化补救开关（续写）被接到"退回线"而不是"合格线"上**——模型按蓝图自然收束（合理），而代码在 1750 处松手（不合理）。

## 2. 口径核对：1751 是"汉字数"，不是"判定数"

对 trace:852-1008 正文复算（draft-units.ts:46-56 逐行等价实现）：

| 口径 | 值 | 说明 |
|---|---|---|
| 汉字（\p{Script=Han}） | **1751** | 与基线一致；= 2500 的 70.0%，= aimLow 2125 的 82.4% |
| 数字码点"17/19" | +16 | 数字不匹配 \p{L}，按 otherVisibleCodePoints 计入(draft-units.ts:51-54) |
| 英文/Unicode 词 | 0 | 正文无外文单词(:50) |
| 标点/空白 | 排除 | :53 排除 P/S/空白，这部分与"不含标点"一致 |
| **countDraftUnits 判定值** | **1767** | 而文案写的"按汉字计"→ 模型若真按汉字理解，会低估 16 |

三点误导：
1. **"按汉字计"与实际判定不符**：判定含数字码点，这份正文差 +16；对白里金额、编号多的章差得更多。"按汉字计"会让模型以为数字/外文不算，它的内部估算和判定器永远对不上。
2. **文案给的是模型无法测量的量**：模型不能可靠自数 2500 个汉字，只能感知"写了几件事/几场戏"。给一个它测不准的数，等于没给。
3. **"少于 1750 字会被退回"把地板写成了目标**：模型读到的是"过 1750 就安全"，而 1750 恰好是本次落点。判定余量实际是 **+17 而非 +1**（1767 vs 1750），说明它不是"险过"，是"稳过而无人管"。

## 3. 三个候选修法

### 修法 A（首选，一行改动）：续写触发线 minimum → aimLow
- 位置：`generate-draft.command.ts:1536-1549` `shouldAutoContinue`
- 改前：`if (finishReason === 'stop') { return currentChars < draftTargetUnitRange(targetChars).minimum }`
- 改后：
    const aimLow = Math.round(targetChars * 0.85) // 与 chapterLengthContractText:448 同源
    if (finishReason === 'stop') return currentChars < aimLow
- 效果：1767 < 2125 → 立即触第 1 轮续写；:1616 remaining = 2500-1767 = 733、:1618 allowance = 733，按 :1629-1634 的 lengthInstruction 补足后落点约 2500，稳进 2125–2500。
- 风险：1750–2125 区间的章每章多 1 次调用（成本+1 次）；若模型已在收束段，续写可能写出"注水尾"——需配修法 C 的差额指令，把"补足差额"落在"推进下一事件"上而非空转描写。

### 修法 B（文案去刹车）：把"硬后果"从 1750 挪到 2125
- 位置：`chapterLengthContractText` `generate-draft.command.ts:451`，以及 `builtin-prompt-templates.ts:1066`
- :451 改前：`…少于 ${minimum} 字会被退回。` → 改后：
    …少于 ${aimLow} 字视为篇幅未达标，会自动继续续写直至超过 ${aimLow} 字；低于 ${minimum} 字整章退回。
- :1066 改前：`接近目标篇幅时按本章结束状态收束，不要超过目标` → 改后：
    写满 ${aimLow} 字之后才允许按本章结束状态收束；未满 ${aimLow} 字不得收束，需要继续推进本章蓝图内已安排的事件与对话。
- 效果：把唯一"有代价的线"提到 2125，模型不再把 1750 当安全区；与 :824/:828 的"不要超过目标"也不再与 floor 混读。
- 风险：措辞硬化后可能集中冲到 2500+；上限 3250 只提示不退回(:1338-1339 只查 minimum)，可接受。项目覆盖 first_chapter_draft.zh-CN.json:27 的"控制字数，不依靠景物细节扩写篇幅"需同步放宽，否则反向拉扯。

### 修法 C（续写注入差额，可行性=通道已具备）：让模型"补差"而不是"数数"
- 通道已存在：`extendDraftIfNeeded` 在 :1605-1660 组装 continuationPrompt，:1608 已算 `currentChars = countDraftUnits(draft)`，:1610 日志已打"当前约 X/Y 字"，:1641 复用篇幅合同，:1654 已把合同塞进续写 prompt。**缺的只有一句差额指令**——续写轮天然拿到准确计数，这是整个系统里唯一可靠的字数反馈点。
- 位置：`generate-draft.command.ts:1629-1634`，在 `- 本次续写补足约 ${allowance} 字即可…` 之前插入：
    const aimLow = Math.round(params.targetChars * 0.85)
    const deficit = Math.max(0, aimLow - currentChars)
    // 中文串（插入 lengthInstruction 最前）：
    - 本章已写约 ${currentChars} 字，距合格线 ${aimLow} 字还差 ${deficit} 字。请把差额写满：推进本章蓝图内尚未落地的事件、动作或对话，不要用总结句、心理旁白或景物堆砌凑数。
- 效果：模型不需要会数汉字，只需把"还差 358 字"写满，这是可执行的相对量；配合 A，一轮即可从 1767 → ≥2125。
- 风险：deficit(358) 与 allowance(733) 口径不同，需明确"至少 deficit、不超过 ceiling"，否则可能只补到 2125 就收；续写段仍受 :1652"不提前写后续章节"限制，事件源必须由蓝图提供。

## 4. 一句话结论

**最该改的一处是 `generate-draft.command.ts:1545-1546`：`shouldAutoContinue` 在 finishReason=stop 时用 `minimum`(1750) 而不是 aimLow(2125) 判断是否续写——它让一次语义上完整的收束在 1767 字处被直接放行，这是 1751 落库的唯一开关。**

## 二、本稿最不番茄的 5 处

1. **trace:869–873（连续 4 段内收心理）**——「他还躺着…他想再躺三分钟」「然后胃先凉了」。番茄写法应把「额度已烧」的后果**外化为可见代价**（房东把门砸开、邻居当场指认他是 19 号），而不是让他继续躺着感受。
2. **trace:883–885**——「窗外巷子里一声短促的狗叫，接着没了。／他得出去看看。」空转景物+过渡句，两端都没信息。番茄会砍掉，把字数让给对话。
3. **trace:939–961（回声棚整场）**——400 余字里主角只说「嗯。」两次，靠耳机、波形、降噪沉默完成。这是**反番茄的典型场**：对话占比 0、信息量近 0、只服务氛围。
4. **trace:983–985**——「手写的不算。／本子上写的字，世界不认。」规则用旁白直接告诉读者，而非让读者从一次失败的行动里推出来。番茄写法：他写下一句话期待成真，结果什么都没发生，读者自己得出结论。
5. **trace:1007**——「感觉到那扇门上铁皮门牌后面那颗新钉子，被他的重量一点点往木头里推。」章末最后一句是**体感隐喻**（重量推钉子≈命运压身），而非对话或行动。番茄章末要硬钩子，不要余韵。

## 三、番茄味没兑现的结构性原因（落到槽位）

1. **KPI 全部躺在 global_guidance（trace:738–779），位置太靠前、权重太低**。全文 15067 字符里，这段埋在 trace 588–700 的设定池之后，距生成点（trace:848）还有黄金法则+去 AI 腔+不可偏离事实 100 行。番茄 KPI 的**末位有效权重近乎 0**。
2. **番茄 KPI 与「真人叙事·最高优先级」正面打架**。trace:774–779 明确要「叙事跳跃与省略」「不先铺白景再写人」「能用动作体现心理就绝不直说」，而番茄要「对话 25%–40%」「爽点轮换」「情绪写出来」。本稿显然是**真人叙事那一派赢了**（对话 6%、零爽点、通篇内收）——两条都标注最高优先级的指令互斥时，模型选了后者。
3. **writingStyle 槽位被 systemSuffix 降权**。trace:816–818【文风适用边界】逐字写「文风仅用于选择表达方式，不是新增事实或事件要求；无需逐条强行兑现」（来源 builtin-prompt-templates.ts:1055）。项目级覆盖 first_chapter_draft.zh-CN.json 的 content（:24）把 {{writing_style}} 放在倒数第三位，任何写进文风槽的番茄要求都会被这句**主动豁免**掉。
4. **去 AI 腔约束（trace:793–799）反向优化短文风**。约束集中在「禁超短单句切割」「禁细节特写」「克制造句」，模型把它理解成「少写、短写、留白」，于是段长更短（70% <30 字）、对话更少。**降 AI 味与番茄 KPI 被优化成了同一个方向**，没人让它往反方向补偿。
5. **无任何自检/回退机制**。trace:836–837 篇幅合同有硬断言（<1750 退回，generate-draft.command.ts:1338-1339），但对话占比、段长、钩子密度**没有对应校验器**——只有字数被机器管，所以只有字数被认真对待（1751，贴着下限）。
6. **taskGuidance 用的是「尽量」措辞**。first_chapter_draft.zh-CN.json:27 的「文风要求：真人叙事…克制有呼吸感」，而番茄 KPI 只在 global_guidance 里以「■」分节陈述，无强制性词汇。**在没有强制语气的槽位里放硬指标 = 不生效**。

## 四、可直接粘贴的番茄风格补丁（建议放 taskGuidance 末尾）

> 【番茄平台硬指标（优先级高于文风）】
> 1. 对话占比 25%–40%，按汉字计；每段对白之间最多 2 段叙述。闭嘴式沉默场景每章不超过 1 处。
> 2. 段落 60–110 字，单段不超 120 字。禁止连续 3 段短于 30 字。
> 3. 每 800 字一个钩子；前 300 字内必须出现一次**他人对主角的直接质问或揭穿**。
> 4. 本章必须落 1 个爽点，且是五类型之一（打脸/收获/揭秘/升级/被认可）；只准用「收获」或「揭秘」，不得写成纯压抑。
> 5. 章末最后一句必须是对白、动作或威胁，不得以体感/景物/心理收尾。
> 6. 情绪必须外化：每章至少 2 处可见外化（喊、骂、摔、逃、笑），不得只用生理反应代替。
