# 「故事弧」环节设计提案（作者设想的具体化）

> 缘起：作者指出「我觉得就是在现在的故事架构里，少了这一个环节」，
> 并给出初步设想：**世界观里设 L5 地图空间信息（大区域 + 副本）；故事弧据其他信息生成；情节大纲受故事弧约束**。
> 本文把该设想**落到确切的数据流与改动点上**，供讨论。
> 日期：2026-10-11 · 分支 `dev_byf`

---

## 0. 先纠正我自己：作者对"声明式 vs 命令式"的反驳是对的

我在 `seven-layer-skeleton-assessment.md` 里把这件事框架成"声明式 vs 命令式"的范式之争。
**作者指出这不是重点**：

> 「剧情弧的层级在大纲之上，是用来约束大纲的，**只要大纲按照剧情弧的内容来设计，跟现在的命令式一脉相承**」

**→ 接受。** 我的框架错了，因为：
- 大纲**继续用现有的做法生成**（AI 逐章产蓝图，命令式不变）；
- 弧的作用是**给大纲一个上游输入**，而不是替换它的生成方式。

**弧的价值 ≠ 换范式，弧的价值 = 给大纲一个它现在没有的依据。**

前文说"命令式不可维护、要改成声明式"是**过度推论**；
作者说"跟现在一脉相承"才是准确的——**弧只是往上游又加了一层输入**。

## 1. 作者设想的数据流（转述）

```
L1 世界观（现有环节，扩展）
    ├─ 核心规则 / 阶层断层 / 深层危机      ← 现有三维度
    └─ ★ 空间结构（大区域 + 副本）          ← 新增，作者说的"L5 地图空间信息"
              │
              │  弧引用空间节点
              ▼
★ L3 故事弧（新增环节）
    ├─ 名称 / 起止章节
    ├─ space: 引用 L1 的空间节点（如"无声公寓"）
    ├─ 目标 / 冲突 / 高潮位置
    ├─ 活跃角色 / 退场角色
    └─ 伏笔埋收（可与现有 narrative_thread_plans 关联）
              │
              │  大纲受弧约束
              ▼
L5 情节大纲（现有环节，加约束）
    └─ 生成时知道"本段处于哪条弧的什么位置"
              │
              ▼
L4 章节蓝图（现有，不变）
    └─ 逐章命令式生成，但上游多了弧的依据
```

**关键：整条链上唯一"新"的实体是弧。世界观是扩展，情节大纲是加输入，蓝图完全不动。**

## 3. 设计细节：三个必须定清楚的问题

### 3.1 ★ 世界观加"空间结构"——但它不像其他三个维度

**现状**：世界观模板（`builtin-prompt-templates.ts:508-520`）明确要求**三个维度，每个"自带冲突点"**：

```
1. 【核心规则与体系漏洞】
2. 【阶层断层与资源战场】
3. 【隐喻与深层危机】
（要求）每个设定都必须"自带冲突点"，能直接驱动情节。
```

**问题**：**空间结构是"客观地点"，不该"自带冲突点"**。
"无声公寓在第三层"是一个地理事实，不是冲突。

**两个选项**：

| 选项 | 做法 | 代价 |
|---|---|---|
| **A. 作为第 4 维度**（并入世界观文本） | 在世界观末尾加 `### 4.【空间结构】`，写明大区域与副本清单 | 与世界观的"每项自带冲突"要求**语义冲突**；且它会被 `worldbuilding` 的一段文本承载，**难以被弧结构化引用** |
| **B. 独立为结构化清单**（推荐） | 空间节点作为**结构化数据**（名称/类型/父节点/描述），存 DB | 需要新表；但**弧可以直接外键引用**，且地图可视化有天然数据源 |

**→ 我倾向 B**，理由是作者自己的诉求：分析里说"P5 地图是弧的 space 字段可视化"——
**如果空间只是世界观里的一段散文，地图就无从可视化。**
（这条需要作者确认：你要的"大区域和副本"是**散文描述**还是**可选清单**？）

### 3.2 ★ 弧"根据其他信息生成"——具体是哪些信息？

作者说"故事弧根据其他信息来生成"。**需要明确"其他信息"是什么。** 我的理解是：

| 弧字段 | 来源 |
|---|---|
| `space` | ← L1 空间结构（**引用**，非自由填写） |
| `active_characters` / `exit_characters` | ← L2 角色图谱 |
| `goal` / `conflict` | ← L0 故事前提（核心冲突链） |
| `climax` / 起止章节 | ← L0 故事前提（悬念骨架）+ 作者指定 |
| 伏笔埋收 | ← 可与现有 `narrative_thread_plans` **关联**（`弧 ⊃ 伏笔`） |

**→ 即：弧 = 把 L0/L1/L2 的信息"按时间切片"，切成若干段。**
**这正是它作为"中间层"的意义**：不是新造信息，而是**把已有信息组织成阶段**。

### 3.3 ★ 情节大纲"受弧约束"——怎么个约束法？

**现状**（已核实）：`synopsis` 是**按批次分章生成**的（`architecture.command.ts:52-57` 的
`synopsisRange` + `PLOT_OUTLINE_PROTOCOL`），**当前不以任何"段"为前提**。

**加弧之后的两种做法**：

| 做法 | 说明 | 风险 |
|---|---|---|
| **a. 生成时注入弧** | 生成第 N 章大纲时，告知"本段属于 arc X，目标是 Y，高潮在 ch10-12" | ⚠️ 触碰生成侧契约（与 P3 同源的收据校验问题） |
| **b. 生成后校验** | 大纲照旧生成，之后**检查它是否覆盖弧的起止章、是否在弧范围内** | 零运行时风险，但只是"报错"不是"引导" |

**→ 建议先做 b（校验/提示），验证弧的价值后再考虑 a（注入）。**
理由与 P3 的教训一致：**先做零风险的只读检查，再动生成管线。**

## 4. 与既有实体的关系（避免重复造轮子）

| 既有实体 | 与"弧"的关系 | 处置 |
|---|---|---|
| `narrative_thread_plans`（伏笔台账） | **弧 ⊃ 伏笔**：一条弧内可有多条伏笔 | 保留，可选加 `arc_id` 外键 |
| `characters.arc`（角色弧光） | 角色弧光应"跟随大纲"，而大纲受弧约束 → **弧是它的正确归属** | ★ 建议迁移为"弧内的角色变化"（见评估 §6.4） |
| `blueprints`（章节蓝图） | 不变，逐章生成 | **不动** |
| `project_core.worldbuilding` | 若选 3.1-A 则并入；选 B 则并列 | 待定 |
| 剧情树（只读快照） | 不变，未来可增加"按弧分组"的视图 | 不动 |

**→ 弧的引入**不会与现有任何实体冲突**，反而是它们缺失的上游。**

## 6. 一句话总结

**作者的纠正成立：这不是"范式之争"，弧只是给大纲加一个上游依据，大纲的生成方式不变。
落地的最小形态是——世界观加"空间结构"、新增"故事弧"环节（弧 = 把 L0/L1/L2 信息按时间切片）、
情节大纲加弧约束。整条链上唯一的新实体是弧，蓝图完全不动。**
