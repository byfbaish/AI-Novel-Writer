# 文档放置要有入口与反馈：常驻 AGENTS.md + 章程 + 体检脚本

2026-10-24 的核查发现：这个仓库**不缺规则**——`docs/README.md` 已有 §2.5 文档纪律（改代码同提交同步文档、收口一期要改所有状态位、提交前跑断链检查）、§3 放置决策树、§3.3 命名约定、§4 索引（75 篇），`docs/agents/delivery.md` 也有交付规则。缺的是**两个闭环**：

1. **入口闭环**。规则写在 `docs/README.md` 里，但那个文件只在"我要找文档"时才被打开；根目录没有常驻指令文件（`/AGENTS.md` 被 `.gitignore:58` 忽略，`.gitignore:57` 的注释是 "Never publish internal agent instructions"）。于是新会话的 agent 开工前**从不读规则**，按习惯把设计稿写进 `docs/plans/` 或根目录。
2. **反馈闭环**。唯一检查脚本 `scripts/check-doc-links.mjs` **只查断链**。实测首跑：**33 份** `docs/design/` 设计稿没有 `> 状态：` 行、**8 篇**设计稿未进 README §4 索引（而该节自称"这是查找设计文档的唯一清单"）、`docs/README.md` §2.5③ 指向的 `docs/design/archive/` **目录根本不存在**。规则是否被遵守，没有任何东西知道。

因此决定三件事。

**一、常驻入口：本机 `AGENTS.md`（不入库）+ 入库的章程。** 根目录 `AGENTS.md` 限 60 行，只放项目地图、命令集、8 条硬规则、以及「要做什么 → 先读什么」。它**保持被 `.gitignore` 忽略**——仓库不发布内部 agent 指令，这条发布卫生规则不因本次改动推翻；权威内容入库在 `docs/agents/documentation-charter.md`（四层模型、单一事实源、完成定义、开工五步、反例库、脚本用法）。两边各写一行 `charter-version`，脚本比对，不一致即报 C7。这样既解决"新窗口不读规则"，也不把内部指令推到公开仓库。

**二、体检脚本先报告、后阻断。** 新增 `scripts/check-doc-placement.mjs`，七类检查：C1 缺状态行、C2 未进索引、C3 命名不合规、C4 链接的相对目录不存在、C5 放在禁放区（根目录白名单外的 md、`plans/` 下的设计稿）、C6 断链（与 `check-doc-links` 同源）、C7 章程版本不一致。存量违规写进 `docs/agents/doc-placement-baseline.json`，默认只报「新增」（退出码恒 0），`--strict` 才判红。**基线只允许缩小，新增违规不得写入基线**——写进去等于把违规洗白。

**三、不新建第四套东西。** 不新建第二个台账（`docs/plans/prompt-assembly-backlog.md` 仍是唯一）、不新建 `docs/conventions/`（与 `docs/design/` 的评估稿职责重叠）、不把规则复制到多处（单一事实源表见章程 §3）。也**不引入**外部上下文检索工具（context-router 等）：当前规模（298 份 md）用索引 + 基线足够了。

## Consequences

- 新会话有明确入口：`AGENTS.md` 常驻 → 章程 §4/§6 → 台账顶部表 → 1–2 份相关设计稿。不再需要"整目录通读"来猜规则。
- 违规从"无人知道"变成"增量可见"：清理存量是可选的，**新增违规必须当场修**。
- 基线成为一份需要维护的账：每次修复都要重跑 `--update-baseline` 收窄，否则脚本会持续提示"已修复 N 条"。这条手续成本是刻意的。
- 文档改造被纳入完成定义（章程 §6），与"测试通过"并列；`tsc` 通过不再等于任务完成。
- 本次未改任何生成行为、未动 schema、未改 prompt 文案；对产品零影响。
- AGENTS.md 在**新克隆的机器上不存在**（不入库）。章程 §7.1 给出重建方式；这是"不发布内部指令"的代价，已显式记录而非静默接受。
