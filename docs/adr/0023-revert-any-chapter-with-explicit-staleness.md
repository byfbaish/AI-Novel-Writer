# 退回草稿不限链尾：失效必须显式，而不是靠禁止

ADR-0021 规定「只有定稿链尾部可以退回或删除」，理由是中间章退回会让后续章节静默失去前提。这个理由是成立的，但**手段选错了**：它用"禁止操作"回避了一个本可以显式表达的状态。

2026-10-23 查证：**"失去前提"这件事系统一直在算，只是算完就扔**。退回或改写任意一章都会调 `invalidateContinuityProjectionFrom`，使 `continuity_projection_meta.generation` +1、`stale_from_chapter` 取最早失效章；每章派生快照记录自己生成时的 `projection_generation`；角色投影只采信"代 ≤ 当前"的章。失效数据是完整的，**缺的是消费**：渲染层零消费、正文生成链不检查。于是系统知道"谁旧了"，作者却看不见，生成时也照用。

现在把链路接上，退回不再限链尾（ADR-0023 收窄 ADR-0021 的范围，不是推翻它）：退回任意章后，其后各章的派生相对新世代落后，判定为 `stale`（`src/shared/chapter-staleness.ts`，判定只看三件事：有无快照、快照代是否追平当前世代、是否有针对**当前世代**的人工确认；**不看 `stale_from_chapter`**，那是单调水位，用它判会把整本书永久判脏）。`stale` 章在正文列表与草稿箱显示「前提已变」；正文生成要求前章定稿来源可信，前章 `stale` 即拒绝并指出处置入口；处置有三条，全复用既有机制——重新定稿（正文改过）、修复后处理（正文没改但重建派生）、确认无需改动（写 `chapter_staleness_acknowledgements`，理由必填）。确认绑定世代：下次任何一章再退回，generation 变，旧确认自动失效。

**删除正文仍只限链尾**：它连正文一起删，后续章没有可复核的东西，失效无法靠界面表达。这条边界不随本次放开。

## Consequences

- 「改早期章节」从禁止变成"可做但会亮灯"。改稿的代价从"做不到"降为"要逐章确认/重建"，与长篇创作的真实成本一致。
- 失效不再可能静默：任何退回都会让受影响章进入 `stale`，而 `stale` 会挡住下一章生成。
- 逐章处置是刻意的手续成本，不做批量重定稿工作流（作者 2026-10-23 裁定）；列表徽标保证几百章待处置能被一眼看见。
- 判据 CX 在此成立：每条 `stale` 都有确定的三选一处置，不存在"永远无法应用的待办"。
- ADR-0021 的"只能动链尾"对**删除**继续有效；对**退回**由本文取代。
