# DSH 文件监控唤醒插件 · 开源版产品方案（P1.5）

> 状态：待裁定（2026-11-12） · 日期：2026-11-12

## 一、背景

产物落盘后叫醒会话，目前靠人看或定时唤醒。P1 探针（`scripts/dsh/wakeup-plugin/`，`index.js` 225 行 / 零依赖 / `index.test.mjs` 5,599 字节）已证明「`fs.watch` → 稳定判定 → `agent.followup()`」这条路成立，但它的配置是 `watchDir` + `targetSessionId` 两条，只够我们内部用。

主人定：**开源到单独一个仓库**，不与 AI-writer 混在一起；**配置界面走官方插件管理界面，不单独设计**；**监控目录与监控规则开放成接口，可同时监控多个目标**；**核心功能很简单，不要臃肿**。

硬约束（大肥鱼 4 条 + 总负责人加宽 3 条）：

1. 参数只进 `cordis.patch.yml` 的 `config`，不写 UI、不自建设置页。
2. 多目标一次到位，单目标 = 长度 1，不做先单后多的两套形态。
3. 脱敏：字面量（内部路径 / 项目名 / Bot 名 / 卡号 / `.batch/night`）与**背景叙述**（「为多 agent 派卡流程做的」）都不进开源物。
4. 插件只做「文件稳定 + 标记 → 投递到 session」，不内置任何卡面格式。
5. 许可证与仓库归属由主人拍板，Bot 不代选（先例：去 AI 味仓库选错不可逆）。
6. 不引用本仓任何脚本或路径，插件要能独立 `npm i` 起来。
7. 开源前必须有一次真实投递成功；顺序锁死：代码级 PASS → 重启 → 真实投递成功 → 出开源物。

本稿只定**开源版 v1 的产品边界与配置契约**；改码与搬运派 WorkBuddy / 豆包，经联络人。

## 二、目标

装进任意 DSH profile、在 `cordis.patch.yml` 写一段配置，就能让「目录里写完的文件」叫醒指定会话，且使用者不需要读我们的任何内部协议。

**不做什么（这一节可直接搬进 README 的「不做什么」段）**

- 状态机、重试队列、历史记录、UI / 设置页、日志系统、卡号或看板映射、文件内容解析、轮询、「全部产物齐全才投递」的编排——都能由外层脚本或官方插件管理承担。
- 不做 `ignore`：`include` 写细即可表达排除。
- `include` 不做正则：路径匹配用 glob 够用；正则只允许出现在 `done` 规则里（见 §3.1）。
- 不做 message 模板：模板等于把我们的卡面格式搬进去。
- **不做多播**（11-13 定稿，二期不做、不留待议）：一个 watch 投多个目标 = 让 N 个 agent 同时独立开跑，而插件不认识群、也不知道谁该串谁，做进去就是把编排责任塞进投递层。同一目录要多目标，配多条 watch（`dir` 相同、`targetSessionId` 不同、各带 `done`），语义更清楚，哪条失效也能单独看见。「一个被唤醒带动全群」属 agent 层，由被唤醒方在群里 @ 下一个。

**四条尺子**：① 质量优先于行数——职责单一、判定逻辑逐行保留且有测试、零新增依赖、配置面无冗余；行数只作软参考（当前 `index.js` 约 256 行，收到 ≤200 行是整理目标，不是门），**禁止为凑行数砍注释、并函数**；② 配置只留 5 个字段；③ 上列不做项一律不加；④ 删行测试——删掉任意一段若说不清它挡住哪个已知故障，就删掉。

**唯一不许动的段落**：「稳定判据」（记 `(size, mtimeMs)`、静默计时、到期复读、变了重新计时）。那是插件唯一真正难的地方，砍掉等于砍掉功能。

## 三、功能描述

### 3.1 配置结构（11-13 定稿，唯一形态，无继承链）

全局一个 `stableMs`，其余逐条 watch；每条 watch 自身闭合：目录、目标会话、完成规则都在同一条里，不设「全局默认 + 条目覆盖」，也不做逐条覆盖。

| 位置 | 字段 | 必填 | 默认 | 语义 | 非法时 |
|---|---|---|---|---|---|
| 全局 | `stableMs` | 否 | `5000` | 静默窗口，整数 ≥1000 | 非整数或越界 → 用默认值 + warn |
| watch[] | `dir` | 是 | — | 监控目录，绝对路径，加载时必须存在且可读 | 一条 warn 说明字段与当前值，跳过该条，profile 不崩 |
| watch[] | `targetSessionId` | 是 | — | 单个会话 id（多目标 = 多条 watch，各写各的） | 缺失/空串 → 跳过该条 + warn |
| watch[] | `done` | 否 | `{ text: "<!-- DONE -->" }` | **四态**：省略 = 默认 `text: "<!-- DONE -->"`；`{ text: "…" }`；`{ regex: "…" }`；`done: null` = 关闭完成规则。只在文件尾部 4 KB 内求值 | 两种对象形态同时给 / 正则编译失败 / 超长 / 含嵌套量词 → 只跳过该条并 warn |

**`done` 四态**（11-13 定稿）：省略 → 默认 `text: "<!-- DONE -->"`（加速判据）；写 `{ text }` 或 `{ regex }` 覆盖默认；写 `done: null` → 关闭完成规则、只按 `stableMs` 投。不新增 `enabled` / `mode` 键。

**`done` 为什么进每条 watch**：同一个 DSH 会同时监控异构产物——报告用 `<!-- DONE -->`、正文用 `## 章末`、机读文件用 `"status": "done"`。全局单值会逼使用者把不同的东西塞进同一个标记。`doneMarker` 已删、不留兼容（还没发出去）。

**`done` 只是加速判据**：命中 → 立即投递（不等静默窗口）；未命中 → 照常按 `stableMs` 稳定投递。**不是「必须命中才投」**——这条是硬约束，否则一个写错标记的文件永远不投。

**为什么 `done` 支持正则**：只在「尾部变化」时对尾部 4 KB 求值，文本有界；`include`（路径匹配）不接正则——路径每事件都跑，代价不同。正则固定按 `m` 标志编译、不给 flags 开关。文本形态是精确子串、区分大小写。

**用户配置的正则不可信**（大肥鱼口径）：限长（超出即拒）、禁嵌套量词（`(a+)+` 这类直接拒绝）、只扫尾部 4 KB。V8 回溯失控会卡住事件循环，插件会跟着一起卡住。

**为什么不做 `ignore` / `include`**：路径过滤没有进入定稿 schema；需要收窄范围时，一条 watch 指向一个更小的目录（目录即边界），比再引入一套匹配语法便宜。

同一 `dir` 只配一条 watch；配两条会重复投递，README 写明（不写校验）。

### 3.2 判据（加速路径 + 稳定兜底）

- 尾部命中 `done` → **立即投递**（`reason=done`），不等静默窗口。
- 未命中 → `size`+`mtime` 连续 `stableMs` 不变即投（`reason=stable`）。
- 两者是「先到先投」，不是合取：`done` 是加速器，不是闸门。
- 每个（文件，签名）只投一次；文件再次变化并重新稳定 → 再投一条。
- 进程重启**不回扫、不重放**已存在文件（只对加载后的事件生效），README 明写；代价是停机期间写入的文件不会补投——这条**不做状态落盘**是刻意的（状态文件=历史记录+幂等对账，与「不臃肿」冲突）。需要补投的使用者自己 `touch` 一下或在外层脚本里做。

> 口径变更记录：我上一版稿写的是「marker 命中且静默 `stableMs` 才投」的合取；11-13 负责人定稿改为「加速判据 + 稳定兜底」，理由是合取会把一个写错标记的文件变成永远不投。按定稿执行。

### 3.3 投递语义

- 一条纯文本消息，固定文案 `File ready: {file} ({size} bytes, {reason})`，`reason` 取 `done` / `stable`。**不提供 message 模板**（模板等于把我们的卡面格式搬进去）。
- 实现约束（已核实）：投递只需构造一条 user 消息交给 `agent.followup()`，与官方 `dsh-schedule` 同款写法（`dsh-schedule/lib/index.js:828-835`）；watcher 自己持有 `(size, mtimeMs)` 与 `done` 规则命中结果，`followup` 不查文件、不参与判定、不持久化、不打断当前 turn。
- `targetSessionId` 每条 watch 一个；多目标 = 多条 watch，各投各的（不合并成一条消息）。
- target 找不到会话：**warn 一次**，附带当前可用会话 id 列表便于填配置；不重试、不排队、不静默。
- 不做投递确认、不做回执。

### 3.4 配置界面（二期；一期只做日志校验）

**一期（已定，并入 P4，不单开卡）**：不做界面，零新增依赖。Host 加载配置时把每个 `targetSessionId` 解析成会话标题记一条 info；只有解析不到时记一条 `warn`，并带上该 watch 的 `dir`。这样「失效」至少落在日志里，不需要任何人打开界面才能发现。

**三种状态必须分开**（我原稿只写「解析不到才 warn」，没说清「会话在但还没折叠出标题」算哪一种——P4 因此把两种都报成 warn，属我稿子的缺口）：① 解析到标题 → info，附标题；② 会话在、但暂无标题 → info，写「会话存在，标题待生成」，**不 warn**；③ 该 id 在 `get` 与 `roots` 里都找不到 → warn，带 `dir` 与可用 id。判据是「会话是否存在」，不是「有没有拿到标题」。

**二期（未来形态，本文档描述的目标，不在本期交付）**：官方插件管理**不读**插件自带的配置声明——配置页只枚举 Host 上已有的 settings namespace，再按 namespace key 去槽位找**插件自己上贡的 React 卡片**（`lib/client.js:400-403` 只 `renderSlot`，注释原文 *the tab enumerates settings namespaces but never interprets one*）。所以界面一旦存在，就已经是 client 侧，React + 打包省不掉：「只做只读展示」并不比「做选择器」更便宜。

二期可选会话的数据来源（已核实）：Host 侧 `ctx.agents.list()` / `roots()`，浏览器侧 `SessionSummary.displayTitle`（持久标题 > 项目目录名 > session id）与侧边栏已有的 `searchSessions(query, signal)` RPC。交互：每个 watch 一行三列 = 目录 / 目标会话 / 完成规则，「选择目标」弹层按 `displayTitle` 模糊搜索，列表显示标题 + cwd + 运行中状态，选中回填，点保存才写入。

三条 watch 字段（`dir` / `targetSessionId` / `done`）与卡片一行一一对应，UI 不引入第二套概念。UI 细稿见 `.batch/night/reports/file-watch-ui-requirement.md`（豆包出，我已按定稿 schema 吸收完成规则）。

## 四、验收标准

执行交 QA；判定线里的状态与 run id 按 G7 / G12 口径记录。

| # | 场景 | 判据 |
|---|---|---|
| G1 | 配置校验 | 一条 watch（`dir` + `targetSessionId`，`done` 省略走默认）加载成功，日志一行给出 dir/targetSessionId/stableMs/done 形态；缺 `dir`、缺 `targetSessionId`、`dir` 非绝对路径三种各自 warn 一条且跳过该条，profile 不崩；`done: null` 合法（关闭完成规则）；`done` 正则编译失败 / 超长 / 嵌套量词 → 只跳过该条并 warn |
| G2 | 判据 | 文件持续写入时不投；写完静默 `stableMs` 投 1 条（未命中 done 也投）；尾部出现 done 立即投 1 条不等静默窗口；文本与正则两种规则各验一次 |
| G3 | 去重 | 同一文件不再变化不重复投；再改一次并稳定 → 再投 1 条；重启后不重放 |
| G4 | 多目标 | 两条 watch 指向两个会话 → 各 1 条、不合并；其中一条 id 失效 → 另一条照投，且失效那条有一条 warn 带 `dir` 与可用 id 列表 |
| G5 | 多 watch | 两个不同 `dir` 并行 → 各自触发互不影响；一个非法配置被跳过，另一个照常工作；两条 watch 用不同 `done` 规则互不串 |
| G6 | 脱敏 | 全库 grep 内部路径 / 项目名 / Bot 名 / 卡号 / `.batch` 均 0 命中；README 无背景叙述（人工判读，QA 复核） |
| G7 | 质量 | 职责单一、稳定判据逐行保留且每条判定都有测试、dependencies 为空、配置面无冗余字段、`node index.test.mjs` 通过并附输出原文；行数只记录不设门 |
| G8 | 独立可用 | 全新空目录装包后可跑测试，不出现本仓任何脚本或路径引用 |

G1/G2/G4/G5 需实机（真 DSH 加载 + 真会话）；G3/G6/G7/G8 可静态。

## 五、交付给 P1.5 的三件

### 5.1 README 可写 / 不可写对照表

| 能写 | 不能写 |
|---|---|
| 通用问题：「目录里的文件什么时候算写完、写完通知谁」 | 内部路径、项目名、Bot 名、卡号、`.batch/night` |
| 字段语义、默认值、已知限制（目录即边界，不做路径过滤） | 「这插件是为多 agent 派卡流程做的」这类背景叙述 |
| 占位符示例（`/srv/jobs/outbox`、`<SESSION_ID>`） | 真实会话 id、真实目录、真实产物名 |
| 判据与边界（done 加速、稳定兜底、去重、不回放、不重试） | 我们的卡面格式、首段四行制、看板联动 |
| `done` 两种形态与正则三条约束（只扫尾部 4KB / `m` 标志 / 禁嵌套量词） | 具体的正则示例绕过约束去教人写 |
| 许可证（由主人填）与安装 / 卸载步骤 | 本仓脚本引用、内网地址、私有约定文件 |
| 中文 + 英文两份说明（`README.md` 与 `README.zh-CN.md` 互链，字段表两边同构） | 只给一种语言；两边字段或默认值不一致 |

### 5.2 最小示例（脱敏）

```yaml
- insert:
    - id: file-watch
      name: dsh-handoff-relay
      config:
        stableMs: 5000
        watches:
          - dir: /srv/jobs/outbox
            targetSessionId: "<SESSION_ID>"
            done:
              text: "<!-- DONE -->"
          - dir: /srv/jobs/inbox
            targetSessionId: "<SESSION_ID>"
```

正则形态（同一位置二选一）：

```yaml
            done:
              regex: "^\\s*status:\\s*done\\s*$"
```

`done` 整行省略 = 默认 `{ text: "<!-- DONE -->" }`；`done: null` = 关闭完成规则、只按 `stableMs` 投。

反例（不该被接受）：缺 `targetSessionId` 或空串 → 跳过该条并 warn；`dir` 用相对路径 → 跳过该条并 warn；`done: { text: "…", regex: "…" }` → 两者都给，跳过该条并 warn；`regex: "(a+)+b"` → 嵌套量词，跳过该条并 warn。

### 5.3 第一次跑起来几步

1. 装包（`npm i <包>`，或放进 profile 的 `node_modules`）。
2. 在 `cordis.patch.yml` 里加 `insert` 段 + 上面那段 `config`（**一期命令行/配置文件；图形卡片属二期**）。
3. 重启 DSH（Host 侧配置变更必须重启才生效）。
4. 看启动日志：每条 watch 一行，`targetSessionId` 已解析成标题；解析不到会有一条 `warn` 带该 watch 的 `dir` 和可用 id 列表。
5. 往 `dir` 里写一个文件：写完静默 `stableMs` 应收到 `File ready: …`；若先写完成标记，应立刻收到（不等静默）。

## 六、待拍板与风险

- **许可证**：主人定。`package.json` 现写着 `"license": "MIT"`，是合理默认但不是主人拍的，**开源前必须由主人确认或替换**。
- **开源前必须改的两处打包字段**：`"private": true` 会挡住发布；`"os": ["win32"]` 会让 macOS / Linux 装不上（`fs.watch` 跨平台可用，Windows 的 `filename=null` 兜底可保留，但 `os` 要放开）。
- **名字已定（11-13）**：`dsh-handoff-relay`（弃 `dsh-file-watch`、`dsh-handoff-trigger`）。`relay` 点到点转达，不暗示能起构建/跑命令。本文档文件名沿用旧名以免索引抖动，正文与配置示例一律按新名写。改名必须五处同批（仓库 `package.json` name、仓库目录与 `profiles\desktop\node_modules` 的 junction、`profiles\desktop\package.json` 的依赖项与 `bundles`、`cordis.patch.yml` 的 `id`/`name`、两份 README 互链），少一处重启后插件挂不上。
- **client 半边的验收归属**：二期。React 卡片不适用 core 的零依赖尺子，但要有自己的判定线（能加载、能保存、搜索能出结果、失效 id 有提示），交 QA 补。
- **与现实现不是照搬**：配置层从「平铺全局」改成「全局 `stableMs` + 每条 watch 三字段（`dir`/`targetSessionId`/`done`）」，判据改成「done 加速 + stableMs 兜底」；「稳定判据」那一段一个字都不许砍（记 `(size, mtimeMs)`、静默计时、到期复读、变了重新计时）——这是插件唯一真正难的地方。
