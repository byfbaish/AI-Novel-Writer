## 6. 根因复核（2026-11-04，作者三问之后）

作者三问把这份清点的口径改了：**三条都不该以「事后拦截」为主修法**。逐条复核如下，其中 D15 与 D18 各推翻了本稿前面的一处说法。

### 6.1 D5：根因在模板的两处 `<…>`，而「重试」在这里没有粒度可选

模型两种抄法都出现了，两种都指向同一件事 —— 格式本身就是填空壳：

| 模型输出 | 抄自 | 表现 |
|---|---|---|
| `拍子：<七点>` | `builtin-prompt-templates.ts:772` `拍子：<名字>` | **连壳带填**（`<` 加自己选的名字，`>` 也留着） |
| `落位：<钩子>→单元一` | `:773` `落位：<拍名>→单元<几>｜…` | 保留 `<拍名>` 的尖括号，把 `<几>` 换成中文数字 |
| `逼法：<赵铎用律条锁人> → …` | `:828` 输出示例段 | 括号内确实填了本书专名，但整段仍包在尖括号里 |

两处来源：**格式要求段**（`:771-773` / `:789-791`）与**输出示例段**（`:814-830`，`## 卷一：<有画面的事实>` 起）。后者是本稿之前没注意到的那处 —— 它既是一个「例子」，也是一个「填空壳」，正撞在既有的「给判法，不给例子」红线上。

**「别全量重试」这句话在这里是硬约束，不是偏好**：卷纲是**一次生成整本**（D5 的 trace `ioCalls[0].output` 6,706 字符），当前没有任何按卷 / 按单元重生成的入口。所以一旦带占位符，唯一的"重试"就是整本重跑 —— 这正是前置引导必须做、机检只能是兜底的原因。

前置修法（不锁实现）：**保留字面前缀**（`- 拍子：` 是解析锚点，必须逐字），值位置不写 `<…>`，改成一句「这一格写什么」的判据；输出示例段整个删掉（它与「每一卷写六格」重复，且正是例子的形态）。

### 6.2 D15：章号从来不是卷纲给的 —— 重叠只能来自模型自报的归属

先回答现象。**卷纲确实不含章号**：模板 `:748` 明确写着「不要写章数、字数、篇幅占比，也不要在名字或标题里写"第 1–6 章"。折算是系统的活」。`planned_first / planned_last` 有两个来源：

| 来源 | 位置 | 会不会重叠 |
|---|---|---|
| 折算 `scaledBoundaries()` | `arc-position.ts:430-442`（边界 `Math.max(prev+1, …)` 严格递增） | **数学上不可能** |
| 观测 `observeHeadings()` | `volume-structure.ts:113-135`（扫大纲章标题的 `第V卷第U单元第C章（全书第N章）`，按单元取 `min/max`） | 会 |

`buildUnits()`（`:235-243`）**观测优先**于折算。我拿一份构造数据跑了探针：

```
观测优先   → 卷2 单元 [[1,7,9,headings],[2,8,9,headings],[3,10,10,headings]]   ← 正是 D15 的形状
同一份 plan，不看 synopsis → [[1,6,7,even],[2,8,8,even],[3,9,10,even]]          ← 连续不重叠
```

⇒ **D15 100% 来自观测路径**，即「模型把同一章标给了两个单元」（或两批大纲的单元标记叠在一起），平台 `min/max` 一聚合，区间就糊了。范围核对：`volume-structure.ts:238` 注释自己写着观测值「只覆盖已经写出来的部分，所以只当区间用，不当边界推导」—— 但它被直接写进了 `planned_first/planned_last`，而下游（`volumeEffectiveRanges`、卷末判定、交接单）当计划边界用。**这与 D19「`actual_last` 冒充计划边界」是同一类错误**：一个让进度冒充边界，一个让观测冒充边界。

与「动态反馈收敛」的关系：观测天然只覆盖已写部分，所以已写部分的边界会随大纲漂移 —— 而计划区间本应由卷纲权重决定、不随落稿进度变。当前实现让后者跟着前者走。

三档修法（不锁实现，可叠加）：

| 档 | 做法 | 代价 |
|---|---|---|
| **甲（推荐）** | 大纲章标题**由平台拼**，模型只写章名 + 事件。`chapter-position.ts:39-56` 的 `chapterPositionLabel()` 已经能拼出正确前缀；E3 逐单元生成时卷 / 单元 / 起始章全在游标里 | 改模板格式段 + 拼装处；观测从此恒可信，甚至可删回退分支 |
| 乙 | 保留模型自报，但观测值**不再当单元区间**，只用于卷边界锚点（那才是它唯一精确的用途） | 单元区间永远走折算，已写部分与结构表可能对不上（但这本就是「计划 vs 进度」的差别） |
| 丙 | 机检 + 前置报（生成批落库前），只报不拦 | 兜底，不解决根因 |

### 6.3 D18：本稿 §4-3 那句「要定阈值」是错的 —— 现状没有阈值

看过实现（`suspense-hook-alignment.ts:56-65`）后必须更正：`verdict` 的判据是 **bigram 交集非空**。中文双字词撞车概率极高（"执事" / "墨迹" / "笔尖" 这类通用词全算命中）⇒ 实际几乎恒判 `aligned`。**问题不是阈值高低，是判据没有区分度。**

取样标准（作者问的那件事）：

| 项 | 建议 |
|---|---|
| 样本单位 | 一对（该章大纲「收尾：」行, 该章蓝图 `suspense_hook`） |
| 来源 | 实库全部已提交蓝图；按卷分层取首 / 中 / 末章，外加所有已知 D18 章（5 / 6 / 7 已有标注） |
| 标注三档 | **A** 照搬 / 近逐字照搬 · **B** 同义改写 · **C** 另起悬念或自造设定（应判 drifted） |
| 指标优先级 | **precision@C 优先于 recall** —— 只报警不阻断时，误报多了作者会关掉告警；漏报则退化为现状，不会更差 |

判据改造建议（两条，只有一条需要标定）：

1. **新造词判据（不需要阈值）**：钩子里的汉字 bigram 在**整本大纲**（不只是收尾行）里从未出现 ⇒ 高置信 drift。背景语料是全本大纲，判据是「有没有见过」，不用定数字。D18 的「寿元」「因果纹」正是这一类。
2. **落点覆盖率（需要标定）**：钩子 bigram 能在收尾行找到的**比例**（不是有没有），低于阈值 ⇒ 低置信 drift，只记日志。阈值初值 0.2，用上面样本回测。

但前置修法已经定位了：`builtin-prompt-templates.ts:1165` 两条条款正面互斥（「必须落在收尾行」vs「钩子不是事件」）。**拆互斥是主修法**，上面的判据只是兜底 —— 只做判据会把「模板自相矛盾」变成「每章都报警」。

### 6.4 D15 更正（作者 02:53 追问后）：甲档「平台拼标题」撤回，改成批内 + 跨批两级校验

作者把生成期的信息边界说清之后，§6.2 的甲档站不住了。核对代码，**当前设计的式样正是作者描述的那套**：

| 环节 | 谁做 | 代码 |
|---|---|---|
| 本批卷 / 单元 | 平台定 | `architecture.command.ts:3049-3052`（`unitContext.cursor.volumeIndex` / `range.unitIndex`） |
| 本批起始全书章号 `from` | 平台定，= 已覆盖章 + 1 | `:300` `const from = coveredTo + 1` |
| 本批**最多**写几章 | 平台给上限（剩余章数 ÷ 剩余单元 + 容差） | `:306-310` `maxChapters` |
| 本批**实际**写几章 | **模型规划** | 请求期不存在 `to`：`:3051` 注释「`boundTo` 只参与指纹与预算核对，不写进检查点，完成时按实际章数回填」 |
| 单元内序号 / 全书章号 | 模型写，两者同步 +1 | `synopsis-unit-heading.ts:60-66` 的格式段（给两个完整标题示例，`第<单元内序号>章（全书第<全书章号>章）` 是说明串） |

⇒ 作者说的「发请求之前算不出这个数值」是**设计事实**，不是缺陷：`resolveUnitContext` 只能给上限，`to` 由生成后数标题行数回填（`:319` 注释：「请求期没有 `to`，生成后由正文数出实际章数」）。

**因此甲档撤回。** 平台拼标题意味着生成后要改写正文（模型出 `## 章名` → 系统替换成三层归属），而：

- 续写批次已知会漂回旧格式（`bounded-completion.ts:214-217` 就是为这个加的纠偏），说明正文形态靠 prompt 约束 + 解析兼容，不靠事后改写；
- 更要紧的是 **平台拼救不了 D15**：单批内「序号 +1、全书章号 +1」是恒等式，模型在这一批里自洽，重叠只可能发生在**跨批边界**，而 `from` 本身就可能错（回退 / 续写的 `coveredTo` 不同步）。

改后的建议：**保留模型写，加两级零猜测校验**。判定不需要任何猜测，因为 `chapter - from + 1 === chapterInUnit` 是恒等式：

| 级别 | 判据 | 何时跑 | 失败意味着 |
|---|---|---|---|
| 批内·恒等式 | 每行 `chapter === from + chapterInUnit - 1` | 单元批解析后、落库前 | 模型算错（可只重跑**这一个单元批** —— 这是最小生成单位，不像 D5 整本卷纲） |
| 批内·连续性 | `chapterInUnit` 为 1..N 连续、`chapter` 连续无跳号 | 同上 | 模型跳章或漏章 |
| 跨批·不相交 | 本批 `from` > synopsis 里已有章号的最大值（或 = 上一单元结束 + 1） | 同上 | 回退 / 续写后游标不同步 —— **D15 的最可能真因** |
| 观测·连续段 | 某单元观测到的章号必须是连续段（7,9 缺 8 ⇒ 报）；相邻单元首尾相接 | `observeHeadings` 内 | 现在静默取 `min/max`，把「缺一章」和「重叠」都糊成区间 |

第四行是必须改的：`observeHeadings` 现在对「某单元章号不连续」零防御，`min/max` 一聚合就把 7–9 / 8–9 生成出来了 —— 而实际数据是 7、8、9 / 8、9 两段。**只要改成连续段校验，D15 的区间根本不会出现**，因为 7..9 与 8..9 里有一段是重叠的重复章号。

### 6.5 D18 的「收尾：」行：它的本职不是给蓝图当钩子

查定义（`builtin-prompt-templates.ts:962-1005`），这条行的本职有两件，**都不面向蓝图**：

| 本职 | 条款 | 原文要点 |
|---|---|---|
| **章际承重** | `:973` | 「上一章的收尾行点明了某个仍未决的东西；本章正文必须**从它接着写** —— 要么推进它，要么明确交代它为什么不再悬着」 |
| **未决项声明** | `:983` | 「章末仍未决的是什么 —— 就是 ③ 的收尾行，两处必须是同一件事」 |

而它的三条硬约束（`:965` / `:967` / `:969`）把它定死成**零新增信息的承接件**：原材料必须全部来自本章正文，不得引入正文里没有的新事实、新人、新事件；不得与正文矛盾；不得提前写下一章才发生的事。

⇒ 它的**首要消费者是下一章的正文**，而 `:1083` / `:1165` 把它指定成「蓝图 `suspenseHook` 的唯一权威来源」，是**派生的第二用途**，且这个用途与它的设计前提冲突：一个只许复述本章正文、不许新增的句子，被要求承载「下一章的悬念」。

第 6 章就是冲突的现场：收尾「赵铎的尸身已化作灰骨散在风里」按 `:965` 只能来自本章正文 ⇒ 它必然是**已完成事件的结果**；而蓝图条款 2 说钩子「不是事件，不得复述 keyEvents」。两条正面撞，模型选了后者，于是造出「寿元」「因果纹」 —— 这两个词全书大纲里根本不存在，恰好违反了收尾行「零新增」的精神（只不过它是在蓝图里造的）。

⇒ 修法比 §6.3 写的更明确：把「唯一权威来源」降级为「**锚点**」。钩子必须承接收尾行点名的那件事，但**允许写它造成的后果**，哪怕那个后果是事件性的。判定口径也随之变简单：问「钩子是不是在回答收尾行提出的那个问题」，而不是问「钩子是不是事件」
