## 0. 先说结论

四份稿已分别盘完：**生产链**（会不会自相矛盾）、**创作侧**（读者会不会追）、**工程侧**（prompt 有没有接上）、**外部包**（别人的做法能不能搬）。加起来覆盖了「做得对不对」和「别人怎么做的」。

**四份都在回答「怎么做得对」，没有一份回答「做对了又怎样」。** 缺的是两个属于第一性的前提：

1. **这个工具替谁解决什么问题。** 现有定位原文只描述**形态**（桌面工作台 / 本地优先 / 不提供什么）。全库检索 `目标用户`、`用户画像` **命中 0**。
2. **什么叫「写得好」。** 这一条不是没人提，而是**被绕过**了：外部包里唯一能判「好不好看」的那套东西（22 类风格 lint + 双轴定级）在 2026-10-25 被裁定**降级**，理由原文是「用外部完结书做校准的标准很难定」。

第 2 条是本稿的核心发现：**A1 降级的根因不是成本，是没有质量标准可校准。** 只要「什么叫写得好」没有答案，**「好不好看」里的语义层**判据都会得到同一个降级结论 —— 这解释了为什么 C8（创作侧零测量）挂 P2 不动，也解释了为什么三层盘完只有一致性结论、没有一条好看结论。

**但这句话不能推广到形态层。** 2026-10-25 裁决时纠正过：对话占比、段长、句长、钩子间隔、复读率全是纯计数，阈值可先跑起来，误报率是**调参**问题而非「基准不存在」问题。语义层（爽不爽、情绪拉力）才是死结。分界见 §7.5。**阈值从哪来后来又有更正：见 [`prose-shape-measurement-design.md`](./prose-shape-measurement-design.md) §1——不用外部口径，直接取作者自己的 v7 正文规则。**

### 2.3 结论：定位回答的是「我是什么形态」，不是「替谁解决什么」

## 4. 「好不好看」这条路：已评估过，结论是走不通（根因分析）

### 4.1 现状：不是没人试过，是试过并降级了

外部包里唯一能判「文字好不好」的资产是**风格 lint 检测器**（22 类 AI 味特征 + 按千字密度双门槛 + blocking/advisory × mechanical/semantic 双轴 + 字面量白名单 + 退出码语义）。2026-10-25 逐条过了三闸，结论是 **A1 降级**，理由原文：

> **裁定**：成本太高。已定稿量少；用外部完结书做校准的标准很难定，还可能把污染语料带进语料库——这不是个人团队负担得起的研究。它现有的七猫/黑岩只能当**平台扩展的参考材料**，置后。
> —— [`assessment.md`](../../research/2026-10-25-oh-story-absorption/assessment.md) §3「A1」

同批还有一条更值得注意：**B2 评测脚本方法论**（预注册协议 → 冻结 fixture → 真实 CLI 跑 → LLM 评委 → 非劣效门槛）被记为「方法论确实是我方 C8『创作侧零测量』缺的那一环，**但成本高**，等真要改 prompt 质量时再立项」。

### 4.2 根因：拦路的不是成本，是「校准基准不存在」

A1 的裁定理由里，真正致命的是中间那半句：**「用外部完结书做校准的标准很难定」**。

顺着查了配套的前置调研（[`2026-10-25-threshold-calibration-corpus/`](../../research/2026-10-25-threshold-calibration-corpus/)），结论是：起点有 3 条合法语料来源（全限非商业研究）、**番茄零**、公开世界**不存在**「AI 句式每千字频次 / 误报率」可对标数据。

于是形成闭环：

```
要用 A1  →  必须先定"多少算多"  →  这需要一个基准（哪批文本算好、哪批算坏）
         →  基准只能来自"本书目标读者的验收标准"
         →  该标准不存在（§3 第 2 行）
         ⇒  A1 无法校准  ⇒  降级
```

**这不是 A1 特有的问题。** 任何「好不好看」型判据（爽点密度、钩子强度、节奏快慢、对话自然度）都要先回答「按谁的标准」。所以：

- C8（创作侧零测量）挂 P2 不动，不是优先级问题，是前提缺失；
- C5（情绪极性 / 钩子类型）之所以只能做「记录」不能做「拦」，同一原因（craft-alignment §5 已判）；
- craft-alignment 关于爽点密度的「2–3 章 vs 3–5 章」两套数字打架，本质是两个不同平台基准混在一轮 prompt 里。

### 4.3 所以本稿不主张「重新搬 A1」

那份裁定没有错，且已经写明是作者裁定。**本稿要指出的是它的推论**：先把 Q2（什么叫写得好）定下来，A1/B2 才有重启的前提；否则任何重提都只是重复一次同样的降级。

## 6. 已论证但未施工的三条设定层判断（摘要，非方案）

2026-10-25 至 26 论证过三件事，**都还没进任何正式稿，也都没施工**。登记在此仅为防丢；**是否开工须等 §7 的定位问题有答案**。

| # | 判断 | 一句话依据 | 为什么现在不施工 |
|---|---|---|---|
| 1 | **五维问句严重不均，第 1 维只有 2 问** | 第 1、2 维来自上游初始提交、从未被审；第 4、5 维是后来做的，有成体系的可判定问法（正反例 + 反面词表 + 宁缺勿编）。第 1 维标题承诺「体系漏洞」，问句从未要求写漏洞 | 改内置模板会改所有项目的世界观生成口径；且「该问什么」取决于这本书为谁写 |
| 2 | **升级体系缺一等公民** | 网文最硬的是「他凭什么赢、下一关怎么过」。现状只有第 1 维一句散文 + `power_abilities.stage_note` 自由文本（无顺序、无可比）；`abilityStageState` 判的是**时间轴**（到没到可用章号）不是**序数轴**（第几境、能否越阶） | 需先裁定「升级体系做到哪一层」，且题材缺省（种田/言情明确无阶梯）要先有答案 |
| 3 | **五维是三种用途混在一张表** | 冲突引擎（1、2 维）/ 叙事悬置（3 维，判据 DP 规定永不注入）/ 机读坐标（4、5 维）。齐备性检查要求五维全在，而规则注入刻意永不给第 3 维 —— 两函数口径相反却都成立 | 属分类学整理，不改任何行为；优先级低于定位 |

**三条共同前提**：它们都在答「怎么让模型写得对」，而 §3 指出真正缺的是「什么叫写得好、给谁写」。**顺序不该反过来。**

| 平台在本项目里**已经是一等属性**，但只覆盖**节奏**（卷数 / 单元数 / 兑现频率） | `project_core.rhythm_profile`（M09，`m09-rhythm-profile.ts:11`，`TEXT NOT NULL DEFAULT ''`）；`src/services/prompts/rhythm-profiles.ts:13` 只有 `qidian` / `fanqie` 两档，正文见 `:17-40` |
| 形态指标（对话占比 / 段长 / 句长 / 钩子间隔）**零代码** | `src/` 全库检索 `对话占比\|dialogRatio\|段长\|句长\|sentenceLength` **命中 0** |
| 冲突是实测过的，不是推测 | P8 把番茄 KPI 写进 prompt 后，对话占比只从 **6.40% → 9.34%**（`p8-fanqie-flavor-draft-quality-design.md` §1），复验仍是 **20.60%，跌回 25% 以下**（同稿状态行）。番茄目标 25–40%，起点向允许更低对话、更长段 |

三条设计定则（本节的产出）：

1. **阈值只挂在 `rhythm_profile` 上，不得写成全局常量。** 空值 / 未知值 ⇒ **不判**。这不是新规矩：`rhythm-profiles.ts:10-11` 已明写「空串 = 中性……**不要**给空值一个『默认起点』」——同一姿态直接复用。
2. **`rhythm_profile` 现在是「已知 id 或自定义文本」二义**（`resolveRhythmProfile` 对未知值原样返回）。形态判定只能对**已知 id** 生效；自定义文本一律不判，否则判定规则会随作者随手填的字漂移。
3. **形态结论不落库为 finding。** 平台是可变属性，改成起点后旧 findings 全部失效。只作为**当次生成的即时报告 + 定向重写指令**，不写进 `review_findings`。

一条连带限制（容易被漏）：**平台目标进不了续写/压缩轮**。台账 P16-2 已确认「续写/压缩轮不重渲染模板正文，平台节奏块也到不了那里」；P9 §1 的结论是「每轮都注入且不被豁免」的通道只有写作 Skill。所以形态目标要么走 Skill 通道，要么由重写指令显式携带——**不能指望模板变量**。

### 7.3 约束二：语料从哪来，以及三条边界

作者原话：**「目前没有可用的，不过可以扒排行榜，那这就涉及到文风拆解和真人指纹了，本工程是有该模块的，只是一直没有启用，不知道边界。」**

先纠正事实，要分两半说（2026-10-25 当日二次取证后修正）：

- **「真人指纹」确实不存在。** `src/` 全库检索 `指纹\|fingerprint\|styleProfile` 命中的全部是**内容哈希**（稿本指纹、引文指纹、冻结输入指纹），无一是**结构化**风格指纹——没有句长分布、词频、句式模板这类可对标字段。
- **但「文风拆解」存在，而且一直在启用**（原稿此处写作「没有」，已作废）：入口是「小说拆解与仿写」对话框（`ImportNovelDialog.tsx:533`）的 `style` 阶段，落到 `AnalyzeWritingStyleCommand` + `analyze_writing_style` 模板。它不是「没接线的模块」，是每天能点到的功能。

六个「看起来像」的东西，边界各不相同：

| # | 存在的东西 | 位置 | 它是什么 | 边界（关键） |
|---|---|---|---|---|
| 1 | **退化指纹检测器** | `src/shared/visible-text-integrity.ts:270` / `:293` | 三类：复读 / 占位拒绝语 / 写作工序词；阈值 12 / 3 / 8；有 5 例单测 | **已接线，且是阻断级**——2026-10-25 复核推翻了此前「生产链零调用点」的说法（见 §7.5 第 4 条）。正文链五处调用：首稿 `assertNotDegenerateVisibleText`（`generate-draft.command.ts:1422`，抛错阻断）、终稿同函数（`:1512`）、短细纲 `findVisibleTextDegeneracies` 只跑复读+占位（`:1342`，命中则丢弃细纲但不阻断）、自动续写增量（`:1938`，命中则丢弃本轮）、压缩修订结果（`:2114`，不接受则保留原稿） |
| 2 | 参考作品 | `project_core.reference_works` | 自由文本，作者手写笔记，须带作用域标签（`text-scope-tags.ts:208` 的三键之一） | 进提示词的是**原文**，不经过任何分析；不带标签会被无差别全局注入 |
| 3 | 文风要求 | `project_core.writing_style` | 自由文本 | `refine` 链**被显式豁免**（`review-revision-generation.ts:168` 把 `writingStyle` 置 undefined），不是每条链都生效 |
| 4 | 写作 Skill 容器 | `src/shared/writing-skills.ts` + `injectWritingSkillIntoSession` | P9 认定的「每轮注入且不被豁免」唯一通道 | **P9 平台文风层待裁定、未编码**，目前只是个空容器 |
| 5 | 拆文 / 扫榜方法论 | 外部 skill 包 `story-long-analyze` / `story-long-scan` | 提示词资产，不是本工程代码 | 不进产品运行时，只指导人怎么读 |
| **6** | **文风拆解（真·启用）** | `ImportNovelDialog.tsx:533` 的 `style` 阶段 → `AnalyzeWritingStyleCommand` + 内置模板 `analyze_writing_style`（`builtin-prompt-templates.ts:1431`） | 从 **5 章样本 / 每章截 2000 字**（`analyze-style.command.ts:213-218` 前 3 + 后 2）提炼「风格档案 + 仿写指南」，输出**纯文本 3-6 条**，写进 `writing_style` 单字段 | 三处硬边界见下。**关键：它替代不了形态统计器** |

**为什么第 6 行不能拿去当「平台形态统计器」用**（这是最容易踩的坑：以为既有功能改改就能用）：

| 卡点 | 事实 | 后果 |
|---|---|---|
| 样本量 | `representativeChapters()` = 前 3 章 + 最后 2 章；文风每章只截 `slice(0, 2000)` ⇒ 模型最多看到 **1 万字** | 1 万字能听出「腔调」，建立不了**分布**。段长分位、对话占比这种统计要几百章才有意义 |
| 产物形状 | 输出**纯文本**，模板写明「总计提炼 3-6 条简短建议，各字段最多一条」 | 无可解析字段，进不了任何阈值比较。想量化只能再加一层解析，等于重写 |
| **模板是反向护栏** | 模板原文：**「不得把样本剧情事件、动作或物件的出现次数、每幕配额或样本文长转成写稿要求」** | 这不是「漏了量化」，是**故意禁止量化**——防过拟合到样例的正确设计。要它吐数字就是跟护栏打架 |
| 样本来自哪本 | knowledge 阶段把**整本**原文逐章落知识库（`kb:import-reference-text`） | 拿自己的书没事；拿榜单上别人的书跑这套 = §7.3 三层风险里最高的那一层 |

所以 P17-2 的形态统计器必须**自己写纯代码数数**（不调模型、不产生 token），与第 6 行是两个不同工具：一个给「写起来像不像人」，一个给「符不符合平台形态」。**不要试图把 `analyze_writing_style` 改造成统计器。**

另外发现一处成本口径缺陷（既有，不新增项）：`estimateImportCost(_totalWords, chapterCount)` 第一个参数**完全未使用**，预估算的是章数不是字数；「全局推演 ~15K」是写死常量；**`style` 那一步的成本没算进预估**。300 章实估 ≈ 1.215M tokens（15K + 4K×300）。

三条边界，风险从低到高：

| 层 | 做什么 | 风险 | 判断 |
|---|---|---|---|
| **只要聚合统计量** | 形态校准最小只需要几十个数字：对话占比、段长分位、句长分布、钩子间隔 | 极低——统计量不构成对作品的复制，甚至可以先人工抽查十几章手记 | **建议走这条**。它也正好是 §7.4 期 1 需要的东西 |
| **原文切片进提示词** | 把真人作品片段塞进 `referenceWorks` 或 Skill | 中——涉及复制。但**产品不内置语料、只提供槽位、内容由作者提供**，责任从「产品分发他人作品」降为「用户自行输入」 | 现状已如此，保持即可 |
| **整本抓取入库** | 扒排行榜全书落库 | 高——同时触碰平台用户协议（起点/番茄均禁止自动抓取）、著作权（TDM 不在《著作权法》第 24 条列举的合理使用情形内）、《生成式人工智能服务管理暂行办法》第 7 条对训练数据来源合法的要求 | **这三条我不替你定**，需要你或律师确认 |

**一条关键推论：Q3 的「编辑挑不出 AI 感」不需要先扒榜。** 可判定的一半全是自有指标——A3 三类退化（已实现）+ 形态统计（对话占比/段长/句长/钩子间隔）+ P8 已写死的结构性禁令。只有「像不像某个平台的真人作者」那一层才依赖外部语料。**先做不依赖语料的那一半，Q3 就能拿到大部分收益，且不欠任何法律债。**
