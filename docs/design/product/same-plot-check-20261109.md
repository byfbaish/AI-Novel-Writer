## 结论（一段话）

现有一致性检查是**一次 LLM 审稿**（不是一组确定性判据），它现在能判「本章任务有没有兑现、与前文事实是否冲突、时间精度是否错位」，判不了「本章和上一章是不是同一个剧情」；而手里唯一的结构化事件数据是**蓝图里的 `key_events`**（`BlueprintKeyEvent { id: 'ch{N}:E{i}', event, … }`），它记的是**计划**、不是正文实际发生的动作。所以推荐的做法是：**先把判据落在「相邻两章蓝图事件清单」上（规划期就拦），正文写完后的「实际同剧情」留给审稿模型按同一口径抽事件再比**，并且为这类 finding 单开一种**以事件 id 为锚点**的 finding 形态 —— 因为现有审稿合同强制要求证据必须是「正文中逐字连续、且全文仅出现一次」的摘录，而「两章写了同一件事」根本不存在这样的单句可引。逐字判定器（`ratio`）在这件事上是 0 能力，不是阈值问题（组 C/D 实测全 0），调参只会制造误报。

## 一、现有「一致性检查」是什么，能查什么

**入口两处**（同一件事的两个壳）

- `src/components/editor/DraftEditor.tsx:792` `title={text('AI 审稿 — 一致性检查，生成审稿报告', 'AI review — run a consistency check and create a review report')}`
- `src/services/workflows/chapter-workflow.ts:397` `'一致性检查（角色/剧情/世界观），生成审稿报告'`

**实现是提示词合同，不是判据集合**

- `src/shared/review-execution-contract.ts:45`–`:50` 定义判定口径：【任务兑现】【可推进范围】【已定稿事实优先】等；`:48` 原文 `计划、决定、承诺、保证、签字认责、单纯否定翻转，都不等于结果已经发生。`
- `src/services/workflows/commands/review-chapter.command.ts:136` `'【时间一致性检查】只核对正文实际表达的时间精度。…'`
- 两个确定性 helper：`reviewTimeContinuity()`、`reviewFarTermSettingRule()`（出处 `review-execution-contract.ts:18`–`:19` 自述「时间承接：审稿侧已有…」「远期设定边界：已有…」）。

**它现在能查的**：本章是否把作者要求的事件写成「具体行动及其实际后果」（`:48`）；是否与前文定稿事实矛盾（`:49` 身份/物品/知情/时点）；时间表达精度是否与事实冲突（`:136`）。**它现在查不了的**：本章与上一章是否**同一个剧情**——合同里没有任何一条把「与邻章的相似性」写成判据，而且下面这条硬约束使它连发现都表达不出来。

**真正的拦路石：证据锚点格式**

`review-chapter.command.ts:129` `'【证据锚点硬约束】每个 error/warning 的 items[].quote 必须是待审正文中逐字连续、且全文仅出现一次的单一摘录；不得拼接多个位置、改写原文或包含省略号。'`

⇒ 「第 7、8 两章写了同一件事」没有单句可引：要么引第 8 章那句（可它单独看没问题），要么拼接两章（明令禁止）。**这条规则要不改锚点形态，要么这个类别的 finding 根本发不出来。** 这是本草案的核心结论，也是最该先裁的一点。

**逐字判定器与它无关，且已证明无效**

- `src/shared/chapter-reuse-coverage.ts:17` `export const REUSE_RATIO_BLOCKING = 0.45`、`:19` `export const REUSE_RATIO_ADVISORY = 0.15`；判据门槛是 16 字连续逐字重合（实验报告 `docs/experiments/reuse-coverage-threshold-calibration-20261109.md:15`「16 字连续逐字重合的门槛下…连续 ≥80 字判重演」）。
- 实测：`同报告:136` `ch10-v2 与 ch10 是**同一段剧情、同一批人物、同样援引…措辞高度相似**的两种写法，判定器仍给 ratio=0`；`:150` `16 字连续逐字重合使 ratio 对「改写式复用」完全无感…只调阈值不够`。
- 生产调用点：`analyzeChapterReuse` 全仓仅 `src/shared/chapter-reuse-coverage.ts:66`（定义）与 `src/shared/__tests__/chapter-reuse-coverage.test.ts`（13 处）⇒ **生产调用点 0**（与 D12 结案时「零接线」一致）。

## 三、候选判据（三个，含成本与误报来源）

### 判据甲 · 相邻两章「蓝图事件清单」重合度（**推荐首发**）

- **怎么判**：取 `ch(N-1)` 与 `ch(N)` 两章的 `keyEvents`，两端 `event` 文本两两做相似度匹配（字面 + 轻量语义，如字符 n-gram / 同义合并），得到匹配对集合；当**匹配对 ≥1 对且两章的事件覆盖率都 ≥50%** 时报「疑似同剧情」。附条件：同一事件在上一章若只作为**埋点/预告**出现，而本章才写「发生」，不算重复。
- **能抓**：规划阶段就把同一事件排进两章（最常见的同剧情来源）；且能给出**可锚定的证据 id**（如 `ch7:E2` vs `ch8:E1`），不需要引正文单句。
- **漏**：正文偏离蓝图（蓝图不同、写出来却一样）；纯粹的「换场景换人物但事件骨架相同」（事件文本不同、结构相同）。
- **误报来源**：合法的跨章续写（第 7 章埋、第 8 章收）、卷末收束章复用同一场危机、系列性仪式（每章都「过一遍关卡」）。对策：只认「两章都写成已发生」+ 覆盖率高门槛，不做单对匹配即报。
- **落地成本**：**2–4 小时**（纯函数 + 复用现有 `keyEvents`，零模型调用、零新表）。可放在蓝图提交后、正文生成前。

### 判据乙 · 场景 + 人物 + 目标三元组重合

- **怎么判**：从两章大纲段各抽 `(主要场景, 核心人物, 本章目标/障碍)`，三元组完全命中即报。
- **能抓**：换措辞、换叙述顺序但「同场景、同人、同一个目标」的重复——这正是作者说的「同剧情换措辞」的典型形态。
- **漏**：同一目标换了实现方式（目标相同但过程不同，本该允许）；纯动作/氛围章节三元组空。
- **误报来源**：日常过场（同一间屋子、同一批人、同一个待办）；连续两章同一场审讯的两面（合法）。
- **落地成本**：**6–10 小时**（抽取口径要先定义，且实际抽取只能靠模型，得做稳定性验证）。

### 判据丙 · 对话重放检测

- **怎么判**：把两章正文切成「发言-回应」对，比较语义重合（同一方说了同一件事、同一方给出同一反应）。
- **能抓**：同一场对话被写两遍——改写式复用最常见的落点（比事件更具体、更好抓）。
- **漏**：无对话的动作章；独白型章节。
- **误报来源**：角色口头禅、反复出现的仪式化对白（「你又迟到了」这类）。
- **落地成本**：**8–12 小时**（切分 + 语义比对 + 口头禅白名单）。

### 一句话对比

| 判据 | 抓得到 | 主要漏 | 误报主因 | 成本 |
|---|---|---|---|---|
| 甲 蓝图事件 | 规划期同事件 | 正文偏离蓝图 | 合法跨章续写 | 2–4h |
| 乙 三元组 | 换措辞同场景同目标 | 目标同过程不同 | 过场章 | 6–10h |
| 丙 对话重放 | 同一场对话两遍 | 无对话章 | 口头禅/仪式对白 | 8–12h |

## 四、边界与推荐

**边界（必须写死，否则会有人拿它去调阈值）**：逐字判定器覆盖的是「逐字照搬」，不覆盖「改写式复用」；组 C（同题材同人物剧情不同）3 例、组 D（真实改写 4 对）实测 `ratio=0`（`docs/experiments/reuse-coverage-threshold-calibration-20261109.md:119`–`:136`）。**这不是漏报，是判别范围之外**（`:136` 原话）。⇒ 这条规则**必须新指标**，任何对 `REUSE_RATIO_ADVISORY/BLOCKING` 的调整都不可能让它生效。

**推荐：先落判据甲，判据丙作为第二阶段。** 三条理由：

1. **唯一有结构化输入**：`keyEvents` 已在库、带稳定 id（`blueprint-key-events.ts:13`），可复算、可解释、可逐条对账；乙、丙都得靠模型抽取，先落它们等于在没有 ground truth 的情况下引入新的不稳定源。
2. **时点更早**：甲在蓝图提交后即可判，能在写正文前拦下一次返工（这符合项目一贯的「多报一次可用就是界面撒谎」之外的另一种节约：别让错的先写完）。
3. **成本最低**（2–4h），且失效面清楚：甲的漏（正文偏离蓝图）正好由丙/乙在第二阶段补，两层不重叠。

**建议口径（写进判据说明，供作者裁）**：「相邻两章」= 同一卷内的 N-1 与 N，跨卷交界不判（跨卷换单元本就允许重开同一事件）；命中后**只报不阻断**（与现有审稿 finding 的 error/warning 一致，不新增拦截）。

## 遗留问题

1. **锚点格式要改到什么程度（最关键）**：`review-chapter.command.ts:129` 要求 quote 逐字唯一。若为「同剧情」这一类开一条「以 `{chapterNumber, eventId}` 作锚点」的新形态，等于在证据合同上开口子；若不开，这个判据只能做成**审稿前的独立预检**（不进 finding 列表）。两条路径的产物形态完全不同，需作者裁。
