# Q4 交付计划：以「已实施未实机清零」为唯一硬指标

> 状态：待裁定（2026-11-12 用户已同意入库，工期按用户「太慢」意见压缩）· 日期：2026-11-12 · 修订依据：`docs/design/product/2026-11-12-author-now-what-works.md`（四处人接手）、`docs/agents/acceptance-gates.md`（15 条闸门）

## 0. 一句话

**本季度不再按「做了几个新功能」排期，只按「台账里『已实施』的卡有几张真正过了实机」排期；目标是 12/31 前把「已实施未实机」清零。**

理由：现在作者一动手就撞上的四处（相邻章重演、卷单元区间重叠、批次终态、钩子与 AI 味只报不拦）**都不是没实现，是实现完了没验证**。继续堆功能只会让「已实施未实机」这张欠账表更长。

## 1. 排期（压缩版）

| 期 | 时间 | 内容 | 出口（可判） |
|---|---|---|---|
| **1a 清噪声** | 11/13（1 天） | ① `public-repository-hygiene.test.ts` 与 ADR-0025 的规则冲突 ② 剩 7 条 `ENOTEMPTY` 同族 ③ 脏树断言定性 ④ `641/642` 缺口 | 全量失败数 **62 → ≤30**，且新增红为 0 |

| **2 实机复验** | 11/18–11/22（5 天） | D1 / D2 / D4 / D5 / D13 / D20 逐张补实机 | 每张要么给出 run id 证据，要么写明「不可行 + 原因」 |
| **3 架构一致性** | 11/24–11/28（5 天） | D9 超时三态（先裁 `capMs` 归属）+ AC2/S2 | 超时三态在界面上可区分（不是日志里可区分） |

**与初稿的差别**：初稿 11/25 才出第一张成绩单，现压到 11/17。压缩依据是 1a 全是机械修（改一个断言、5 个文件换 cleanup、核一批测试），不需要设计讨论；1b 的 D12 判定器已入库，只缺接线。

## 2. 短期节奏（每轮必须交三样）

1. **基线**：隔离 worktree 跑一次全量，落日志（不在 develop 主区跑，见 2026-11-12 事故）
2. **复验**：≥2 张「已实施未实机」卡补上实机证据（run id / 导出文件 / 截图）
3. **账**：本轮新增红几条、关掉红几条

## 3. 红线与判据

- **红线：no new red。** 改动不得让全量失败数上升；上升则本轮回滚，不计入进度。
- **基线双轨**：browser 按 G7（`≤1 条且必须是 B11`，2026-11-12 用户裁定从 `2 failed` 下调）；全量按 G12（首跑建基线，此后只许减不许增）。
- **三个数字**（任一恶化即停新功能先还账）：红数趋势 / 实机复验率 / 未结算卡数。
- **全量只在隔离 worktree 跑**；修复后必须真跑一次全量才算验证，单跑不算。

## 4. 人力节奏

- **白天**：改码 + 实机 + 提交（需换身份复核，执行者不给自己 `done`）
- **夜间（00:00–08:00）**：只派只读卡（对账 / 审查 / 溯源），不跑全量，不碰 `electron/`
- **派活纪律**：经 workbuddy联络人 / 豆包联络人 派给 WorkBuddy / 豆包，禁止私自调动；命令带 `CODEBUDDY_SAFE_DELETE_ENABLED=0`

## 5. 不做什么

- 不按功能数排期
- 不开新区块（E 计划层 UI 除外，且期 1–3 未清完则顺延）
- 不把「单元测试通过」当实机证据
- 不为赶期把红数藏进 `skip` / 排除项
