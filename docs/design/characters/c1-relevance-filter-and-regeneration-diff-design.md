## 0. 一句话结论

角色卡是**固定字段的表格**，不是自由文本：所以「直观对比」不必做逐字 diff，只要**按字段并排 + 只高亮有差异的字段 + 差异可逐字段回退**；筛选则给三档可组合的**命中原因标签**，只标不自动勾选。

## 1. 背景（现状，均给文件:行）

| 现状 | 位置 | 缺什么 |
|---|---|---|
| 角色列表只有**按名字搜索 + 分页**，全选按「当前筛选结果」 | `src/components/panels/sidebar/CharactersView.tsx:26`（`CHARACTER_PAGE_SIZE = 50`）、`:29`（`searchQuery`）、`:62-70`（过滤 + 分页）、`:97-101`（按可见结果全选） | 没有「有没有剧情」这一维；无法筛出「从头到尾没进过正文的卡」 |

| 架构重建是**整批替换语义**：同名即同一人，旧批被替换 | `src/shared/character-proposal.ts:80-92`（判据与作者 2026-10-29 裁定）、`:92`（`isArchitectureRebuildBatch`） | 语义已确定，但**覆盖前没有任何"要覆盖什么"的呈现** |
| 提案面板已说明「整册重建会覆盖同名卡的资料：候选为空的字段保留现有值」，同名候选折叠在下方，逐项可选 建卡／映射／功能配角／暂不采用 | `src/components/characters/CharacterProposalSelectionPanel.tsx:44-51`（文案）、`:57`（同名折叠组）、`:108-125`（逐项动作） | 只有一段**文字说明**，作者看不到「这张卡具体哪几个字段会变」；也没有回退入口 |

结论：C1 的两项不是"加功能"，是把**已经存在的语义**（重建即替换、同名即可比）变成**作者能看见、能反悔**的界面。

## 2. 目标 / 非目标

**目标**
1. 角色列表能按「有没有剧情」筛，且每张卡标出**为什么算有剧情**（命中原因），不自动勾选、不默认隐藏任何人。
2. 重生成（架构重建批次）确认前，作者能看到**旧卡 vs 候选**的字段级并排差异，并能对整批做三选一、对单张做逐张确认。
3. 覆盖发生前自动留**旧卡快照**；覆盖后能**逐字段回退**（总负责人加的硬约束）。

**非目标**
- 不做逐字文本 diff（主人已否）。
- 不做角色卡的自动合并、自动退休判定（退休语义沿用重建批次现有规则）。
- 不新建角色事实源：所有字段仍来自 `CharacterRosterEntry`（`src/shared/character-roster.ts:75-103`）。

## 3. C1-① 相关性筛选三档判据

### 3.1 三档定义（可组合，默认全开＝不筛）

| 档 | 名称 | 判据（事实源，文件:行） | 命中原因文案 |
|---|---|---|---|
| ① | 有关系对象 | 该卡的 `relationships` 非空（`src/shared/character-roster.ts:90`） | 「有 3 条关系」 |
| ② | 被蓝图声明 | 名字出现在蓝图角色同步记录里（`src/shared/ipc-channels.ts:1076-1088`：`db:blueprint-character-sync-list-pending` / `-list-all`） | 「蓝图声明过（第 12、37 章）」 |
| ③ | 名字出现在大纲/世界观正文 | 名字出现在项目核心的 `synopsis` / `plot_structure_plan` / `worldbuilding` 三串之一（字段清单见 `src/shared/plot-outline-contract.ts:163-181`） | 「出现在大纲／世界观」 |

### 3.2 判定规则（可机判，不引入模型）

1. 名字匹配：中文按**逐字子串**；英文按大小写不敏感子串。**v1 不做别名与代称匹配**（容易假阳性，且会让"命中原因"变成猜）。
2. 每行最多显示 **2 条**命中原因，多余收成「+N」；点击展开完整原因。
3. **只标原因，不自动勾选**：三档只决定"显示哪些"，勾选仍是作者动作（沿用 `:97-101` 的"按当前筛选结果全选"，但全选只在作者点按钮时发生）。
4. 三档是**并集**（任一命中即"有剧情"），不做交集选择器；默认全开。
5. 全部未命中的卡显示「无剧情线索」，仍在列表里（不隐藏）——这是作者真正要清理的目标集合。

### 3.3 产品上改了什么 / 体验差异 / 不选最坏后果 / 代价

- **改了什么**：列表头部加一组三档勾选（默认全开）＋每行原因标签；不新增页面。
- **体验差异**：120 张卡里"40 张从没进过正文"从"肉眼扫"变成"一眼筛"。
- **不选的最坏后果**：批量清理只能盲删；删错一张会连带丢掉关系引用，作者信任成本高。
- **代价**：③ 是全文匹配，必然有假阳性（同名配角、代称）——所以**只标原因、不默认勾选**；② 依赖蓝图已生成，新项目早期②恒为空（不报错，只是这一档筛不出东西）。

## 4. C1-② 重生成弹窗：字段级并排 + 三选一

### 4.1 弹窗形态

触发点：架构重建批次的确认前（现有入口 `src/components/characters/CharacterProposalSelectionPanel.tsx:44-51`），把现在的"一段说明"升级为一屏对比。

```
┌ 本次重建会覆盖 7 张同名卡 ─────────────────────────────┐
│  [全部覆盖]  [保留旧卡（跳过同名）]  [逐张确认]          │
├───────────────┬──────────────┬──────────────┬──────────┤
│ 字段           │ 现有卡（库）  │ 本次候选      │ 差异      │
├───────────────┼──────────────┼──────────────┼──────────┤
│ 名字           │ 程实          │ 程实          │ —        │
│ 身份           │ 主角          │ 主角          │ —        │
│ 背景           │ 清平里租客…   │ 清平里租客…   │ ● 高亮    │
│ 关系           │ 周德胜(债主)  │ 周德胜(债主)  │ —        │
│               │               │ 老陈(邻居)    │ ● 高亮    │
│ 当前状态       │ 第 12 章·受伤 │ 第 12 章·受伤 │ —        │
└───────────────┴──────────────┴──────────────┴──────────┘
```

### 4.2 对齐字段（固定 5 组，按此顺序，不做自定义）

名字 / 身份（`role`）/ 背景 / 关系 / 当前状态。映射到既有字段：`name`、`role`、`background`、`relationships`、`currentState`（`src/shared/character-roster.ts:75-103`）。
- **背景组**吸收 `gender` / `age` / `appearance` / `personality` / `abilities` / `motivation` / `arc` / `notes`：这些字段各自成行会变成 12 行噪音，故合成一组「背景资料」，组内逐字段列差异（例如「性格：新增一句」）。
- **关系组**按"关系对象名 + 关系词"配对比较，不是字符串比较：新增／消失／关系词变化分别标色。
- **当前状态**只读展示，标明"候选不提供状态时保留现值"（与 `:49-51` 现有文案一致）。

### 4.3 差异高亮规则（可机判）

1. 逐字段做**去空白后相等比较**；相等＝灰行不展开。
2. 不等＝该行高亮，并在组内列出"新增句／删除句／改写"，**按句切分**（中文按 `。！？；`，英文按 `. ! ? ;`）——这是轻量结构化 diff，不是逐字 diff。
3. 候选为空字段：标「候选为空·保留现值」，不计入差异数（避免"全红"）。
4. 顶部数字：`本次重建会覆盖 N 张同名卡` + `其中 M 张有实质差异`；M=0 时按钮降级为「无差异，仍要覆盖？」。

### 4.4 三选一（批次级）

| 选项 | 行为 | 适用 |
|---|---|---|
| 全部覆盖 | 沿用重建语义，所有同名卡按候选更新（空字段保留现值） | 默认、也是现状行为 |
| 保留旧卡（跳过同名） | 同名项一律 `keep-unresolved`，不建新卡、不改旧卡 | 作者只想补新名字 |
| 逐张确认 | 展开为逐卡动作（映射／新建／功能配角／暂不采用），沿用 `:108-125` 现有选择器 | 差异多、需要一张张看 |

**重要**：三选一只改**默认选择**，不新增决策类型——仍产出 `CharacterProposalDecision`（`src/shared/character-proposal.ts:60-72`）。

### 4.5 逐张确认的字段级回退（总负责人约束 · 落点已裁定）

**快照落点＝新 lane 表 `character_regeneration_snapshots`，不挂既有提案表**（项目总负责人 2026-11-24 裁）：

- 为什么不挂 `character_identity_proposals`：它自带 `resolved_character_id` / `approval_id` 的审批语义（`electron/migrations/m02-character-identity.ts:18-21`），角色卡重生成塞进去会把两套审批搅在一起。
- 为什么不能改基线表：M00 的 DDL 已冻结，指纹就是那段文本的哈希，加一行注释都会让旧项目 `probeSchema` 报 `UNRECOGNIZED_SCHEMA`（`electron/migrations/baseline-schema.ts:10-15`）⇒ 只能新增 lane 步骤。
- 照 M08 先例建表（`electron/migrations/m08-structured-refs-and-cast-decisions.ts:9`、`:17`、`:26-38` 的 `character_cast_decisions` 形状：`source_revision` / `operation_id` / `created_at` + 一条按名索引）：

| 列 | 语义 |
|---|---|
| `operation_id` | 本次重建批次的操作号（回退时按它取快照；**一次覆盖一个 operation 一组行**） |
| `character_id` | 被覆盖的卡 |
| `source_revision` | 覆盖前的 roster `revision`（回退时校验"自那以后有没有被人手改"） |
| `field_json` | 覆盖前该卡整卡字段快照（`appearance`/`personality`/`background`/`abilities`/`motivation`/`relationships`/`arc`/`notes`/`currentState`） |
| `created_at` | 落盘时间 |

- 覆盖后：弹窗每行提供「回退这一字段」；回退按 `operation_id` 取快照写回旧值、自增 roster `revision`，**不触碰其他卡**。
- `source_revision` 与当前 revision 不一致（已被人手改）：**拒绝回退并显示"该字段在此后被手改，请人工比对"**——不强制覆盖。
- 快照读不到时（功能上线前产生的旧批次）：该批不显示回退按钮，只显示只读差异——**不猜、不伪造**。

### 4.6 产品上改了什么 / 体验差异 / 不选最坏后果 / 代价

- **改了什么**：确认前多一屏对比；批次记录多一份快照；覆盖后多一个逐字段回退入口。
- **体验差异**：从"盲赌"变成"看清这个人变了哪三处"。
- **不选的最坏后果**：重生成＝盲赌；一旦覆盖掉手工改过的背景，**没有撤销入口**（roster 只有 `revision`，无内容回滚），作者只能重写。
- **代价**：中。一个字段级 diff 纯函数 + 一个对比弹窗 + 一份快照落库 + 双语文案；回归面集中在架构确认弹窗与 roster 写入路径，**与 P6 档 1 争同一块 UI，必须串行**。
