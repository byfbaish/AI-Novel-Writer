## 0. 三句话结论

1. **不是模型不听话，是提示词内部三套任务定义互相打架**：内置基座要「细节填充 / 五感强化 / 给足爽感 / 词汇升级」，作者的 `systemRole` 覆盖要「只做最小改动的校对，不做主动修饰」，作者的 `taskGuidance` 要「只润色表达，不重写故事」。弱模型在多目标冲突时必然抓最保守的一方 → 实测退化成「删助词校对」。
2. **「精修」的输入也比输出更糟**：`refine-draft.command.ts:75-76` 把同一个 `historySummary` 喂给 `global_summary` 与 `short_summary` 两个变量，渲染成两段**逐字相同**的上一章全文（各 4575 字符，约占该次请求 27%），而标签写的是「全书摘要 / 近三章」。
3. **重构口径：基座只描述「改写这个动作本身」和「什么不能动」**，题材、章位、爽点类型、金手指、钩子一律不由基座假设 —— 它们来自 `chapter_info`（蓝图）、`writing_style` 与 `global_guidance`（作者事实）。

## 2. 病灶分层

### 2.1 指令互斥（最致命）

```
systemRole（作者覆盖）: 「只做克制精准的修改，只做最小改动的校对，不做主动修饰」
content（内置基座）    : 「【精修与细节填充】」+ 第1条五感强化 + 第3条给足爽感 + 第4条词汇升级
taskGuidance（作者覆盖）: 「只润色表达，不重写故事」
```

一个请求里出现两个方向相反的任务定义。**同类症状在 `next_chapter_draft` 也发生过**（见 `chapter-prompt-pileup-triage.md` §三问题4 的「字数四重指令打架」误判反面：这里是**真的**多重指令打架）。

### 2.2 不可执行条目污染整块可信度

| 条目 | 为何第 4 章无法执行 |
|---|---|
| 第 2 条「金手指的使用细节融入战斗或博弈」 | 本章是「管事翻账本要画押」，全程无金手指、无战斗 |
| `global_guidance` 里的「黄金三章 part1（第1/2/3章必须…）」 | 第 4 章不是黄金三章 |

模型看到的是一整块「一半以上要求与本章无关」的指令，学到的结果是：**【精修要求】这块可以整块跳过** —— 于是第 1/3/4/5 条一起被降权。

这不是新问题。`first_chapter_draft` 早就用「仅当【本章信息】明确要求时才展现主角的金手指」处理过同类风险；精修基座缺这一层。

### 2.3 文风层与精修层正面冲突

| 基座要求 | 作者文风要求 |
|---|---|
| 通过「五感」细节**强化环境描写** | 环境描写**仅服务于氛围渲染**、**不得用景物描写凑篇幅**、少比喻少通感 |
| 用更**具镜头感**的词汇 | **禁止参数式摄像头描写**、装饰性精确→**降维或删除** |
| 强化反派压迫感、高潮**给足爽感** | 叙述语气克制、不煽情不升华；本章 purpose 是「他选择拖」 |

「五感强化环境描写」这句话本身就**不抽象** —— 它是一条具体的、与作者文风相反的写法命令。基座层不该有这种东西。

### 2.4 字数条款是反向激励

「目标字数控制在 {{word_number}} 字左右」= 2500，原稿 2531。模型读到的是「已经超了，只能减」。而字数条款写了具体数字、「画面感」只有形容词——**具体的赢**，所有「强化/升级」被抵消。

### 2.5 同源摘要注入

`refine-draft.command.ts:75-76` 同一字符串喂两个变量；且这两个变量原本是定稿历史**唯一**的入 prompt 通道，本行把 `finalized-history` 从材料块里 filter 掉了。三者叠加 = 27% 的请求体重复 + 标签语义造假。

### 2.6 taskGuidance 引用不存在的条款

`【动态豁免清单】内容不计入异常。` —— 全库无实现、无数据来源。另有语病：「黑名单模板…同章≥2处」阈值含义不明（允许还是违规？）。

### 7.2 对 §1 的一处**诊断更正**

`143750` 那份 trace 里 **没有**「去精确堆砌」「段落密度上限」「去AI机械化」任何一条（grep 计数均为 0），

### 8.2 合并时必须动的 5 处（都是冲突消解，不是润色）
