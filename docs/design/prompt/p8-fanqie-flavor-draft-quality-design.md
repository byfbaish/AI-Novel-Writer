## 0. 一句话结论

用户在首章 trace 上抱怨的三件事——**字数不够、AI 味重、番茄味淡**——不是三个独立的调参问题，而是**同一个病灶的三张脸**：

> **这份 prompt 里所有"可判定"的约束都没有判定权；唯一有判定权的是字数下限，而那个下限接错了线。**

- **字数**：`shouldAutoContinue` 在语义收束（`finishReason='stop'`）时比的是**退回线** `minimum`(1750)，不是**合格线** `aimLow`(2125)。实出判定值 1767 ≥ 1750 ⇒ 判定"够了" ⇒ 不续写 ⇒ 静默落库。**整条链上没有任何一环以 2125 为条件**。
- **AI 味**：真正生效的去 AI 腔禁令只有 4 条**举例式黑名单**（点名"这一切才刚刚开始"这类短语），模型换个措辞就通过；替换成**可机械判断**的结构性禁令才有约束力。
- **番茄味**：番茄 KPI（对话 25–40%、段长 60–110、爽点轮换、每 800 字一钩）**全都写进了 prompt**，但位于 `global_guidance`、距生成点约 100 行，且**没有任何校验器**；唯一承载调性的【文风要求】槽因 `writing_style` 为空被**整段裁掉**。

**所以本稿的处方不是"把要求写得更狠"**——要求已经够狠了（篇幅合同白纸黑字写着 2125–2500，模型给了 1751）。处方是**给要求装上判定权**：把续写开关接回合格线，把模糊禁令换成可判定的，把番茄 KPI 挪到不受豁免的位置。

## 2. 三个抱怨的根因（逐条带证据）

### 2.1 字数：续写开关接在退回线上

```
src/services/workflows/commands/generate-draft.command.ts
:1536-1549  shouldAutoContinue(currentText, targetChars, rounds, finishReason)
  :1542  if (rounds >= MAX_AUTO_CONTINUE_ROUNDS) return false        // = 7（:74）
  :1543  const currentChars = countDraftUnits(currentText)
  :1544  if (currentChars > draftTargetUnitRange(targetChars).maximum) return false
  :1545-1546  if (finishReason === 'stop') {
                return currentChars < draftTargetUnitRange(targetChars).minimum   // ← 1750
              }
  :1548  return finishReason === 'length'
:1605  while (this.shouldAutoContinue(draft, params.targetChars, rounds, lastFinishReason))
```

`minimum = floor(2500 × 0.7) = 1750`，`maximum = ceil(2500 × 1.3) = 3250`（[`src/shared/draft-units.ts:10-11`](../../../src/shared/draft-units.ts)）。本次 `finishReason='stop'`，`countDraftUnits` 判定值 **1767**（汉字 1751 + "17/19" 等 16 个数字码点），≥ 1750 ⇒ 不续写。

两处退回断言（`:1337-1339`、`:1787-1789`）同样只比 `minimum`。**全链路零处引用 2125。**

判定值的精确口径（`draft-units.ts:46-56`）：汉字（`\p{Script=Han}`）+ Unicode 词 + 其余可见码点（先剔词、再剔空白/标点/符号）。所以篇幅合同文案里的"按汉字计"**与判定器不一致**——本稿差 16，对白里数字/编号多的章差得更多。

### 2.2 番茄味：KPI 写在被降权的位置，且无校验器

| 特征 | 番茄基准（trace:755–763） | 本稿实际 | 缺口 |
|---|---|---|---|
| 对话占比 | 25%–40% | **6.40%**（24 组引号 / 21 段含汉字对白 / 112 汉字） | 差 4–6 倍 |
| 段落 60–110 字 | 目标形态 | 78 段中仅 **4 段**达标（5%），70% 不足 30 字 | 反形态 |
| 爽点 | 每章至少 1 个且类型轮换 | **0 个**（门牌、排班单都是纯压力） | 全缺 |
| 前 300 字立张力 | 冲突+钩子 | 第 300 汉字落在 trace:879，是内心复盘 | 延后 |
| 章末钩子 | 具体型（揭示/行动/威胁/疑问） | 威胁型达标，但末句是体感隐喻 | 半达标 |

三条结构性原因：

1. **位置**：番茄 KPI 全在 `global_guidance`（trace:738–780），距生成点约 100 行。
2. **互斥且对方称"最高优先级"**：【真人叙事·最高优先级】（trace:774–779）要求"叙事跳跃与省略""能用动作体现心理就绝不直说"；番茄 KPI 要求"对话 25–40%""情绪必须外露"。两条都自称最高时，本稿选了后者——**这正是"压抑内收、零爽点"的直接来源**。
3. **唯一承载调性的槽位是空的**：`project.db → project_core.writing_style = ''`，导致模板里的【文风要求】段被空段裁剪规则整段删掉（[`builtin-prompt-templates.ts`](../../../src/services/builtin-prompt-templates.ts) 的空变量裁剪）。而**即便填了也没用**——它会被【文风适用边界】`:1055`"无需逐条强行兑现"豁免。

第 4 条更关键：**对话占比、段长、钩子密度没有任何校验器**。只有字数有硬断言，于是只有字数被模型当真（而且只当真到退回线）。

### 2.3 AI 味：禁令不可判定 + 零惩罚

实际生效的去 AI 腔条款只有 trace:830–834 四条：

```
- 禁止段尾总结句（如"他知道，这一切才刚刚开始"、"命运的齿轮开始转动"）
- "仿佛"、"犹如"、"宛如"全章合计不超过3次
- 对话必须区分角色语气
- 禁止在结尾添加与正文无关的哲理感悟或旁白总结
```

四条里三条是**举例式黑名单**：只点名具体短语，模型换一个同功能的措辞就通过。本稿两处最刺眼的 AI 腔恰好都是"换过措辞的版本"：

- trace:935「两件事同时立着：门上挂"19"的是他；排班单上排着"程实"的，也是他。」——冒号归纳 + 对称复述，读者刚在 891–921 看过这两件事。
- trace:985「本子上写的字，世界不认。这是程实唯一敢说真话的地方。写什么都不会落地，不会改门牌，不会改排班单。」——定性解释 + 三连排比 + 全称断言。

项目 `taskGuidance` 里其实有一套更锋利的五条（trace:793–799，含"禁止连续 3 句以上均等超短单句""禁止直白概括式心理总结"），**确实进了 prompt**，但：位置在更前面、措辞是"尽量避免""无作用微小细节一律不写"这类不可判定表述、且**没有任何后果**。夹在「★最高优先级★」（trace:821）和「篇幅合同（带硬罚则）」（trace:837）之间，它的竞争位次最低。

## 3. 方案

### 3.1 设计原则：从"要求"转向"闸门"

本稿**不增加任何新的创作要求**。现有 prompt 的要求密度已经过高（15067 字符里 75.5% 是背景材料，真正的本章任务信息仅 8.6%）。新增措辞只会加剧稀释。

三步处方：

| 步骤 | 做什么 | 为什么这样能生效 |
|---|---|---|
| **① 接回判定** | 续写开关改用合格线；续写轮注入差额 | 让"没写够"这件事**在代码里**有后果，而不是靠措辞恳求 |
| **② 换成可判定** | 把举例式黑名单换成结构性禁令（冒号解释句 / 三连同构 / 情绪短语配额） | 模型无法靠"换同义词"绕过结构特征 |
| **③ 挪到有效位** | 番茄 KPI 从 `global_guidance` 挪到 `taskGuidance`；并解掉【文风适用边界】的豁免 | 脱离被降权的槽位，进入 recency 更强、且不被 `:1055` 管辖的位置 |

### 3.2 落点分工（为什么是这三个文件）

| 改什么 | 文件 | 能否被项目覆盖 | 为什么必须是这里 |
|---|---|---|---|
| 续写判定 | `generate-draft.command.ts` | 否（代码） | 唯一的判定处；prompt 改多硬都不影响这个 if |
| 刹车文案 | `builtin-prompt-templates.ts` `:1061-1072` / `:1143-1154` | **否**（覆盖只能改 content/taskGuidance/systemRole） | "切忌注水/不要超过目标"在这里，项目覆盖改不到 |
| 番茄 KPI | 项目 `first_chapter_draft.zh-CN.json` 的 `taskGuidance` | 是（作者自己的项目） | 写进 `writing_style` 会被 `:1055` 豁免；taskGuidance 不受 `{{writing_style}}` 直接管辖 |

> **明确不动的**：内置 `content`（`:1022-1049`）。项目的 `content` 与之**逐字相同**（520 vs 520 字符，校验员程序化比对确认），覆盖优先 ⇒ **改内置 content 对这一章完全无效**。

## 4. 具体改动

### 4.1 P1 · 续写判定接回合格线（必做）

**文件**：`src/services/workflows/commands/generate-draft.command.ts`

**① `shouldAutoContinue`（:1536-1549）**

```ts
private shouldAutoContinue(
  currentText: string,
  targetChars: number,
  rounds: number,
  finishReason: LLMCompletion['finishReason'],
): boolean {
  if (rounds >= MAX_AUTO_CONTINUE_ROUNDS) return false
  const currentChars = countDraftUnits(currentText)
  const range = draftTargetUnitRange(targetChars)
  if (currentChars > range.maximum) return false
  // 语义收束（stop）时用「合格线」而非「退回线」判断是否续写：
  // 退回线只是「不许落库」的底线，不是「写到这里就够」的目标。
  const aimLow = Math.round(targetChars * 0.85)
  if (finishReason === 'stop') return currentChars < aimLow
  return finishReason === 'length'
}
```

> `minimum` 仍由 `:1338-1339` 与 `:1788-1789` 的退回断言使用；本函数内不再引用，故只取 `maximum`，避免未使用变量。

**② 续写轮注入差额（:1629-1634 的 `lengthInstruction` 之前）**

续写循环已经具备全部原料：`:1608` 算了 `currentChars`、`:1616` 算了 `remaining`、`:1617` `ceiling`、`:1618` `allowance`、`:1641` 复用篇幅合同、`:1642-1659` 拼 `continuationPrompt`。**只缺一句"还差多少"**。

```ts
const aimLow = Math.round(params.targetChars * 0.85)
const deficit = Math.max(0, aimLow - currentChars)
const deficitInstruction = deficit > 0
  ? promptLanguageText(
      params.writingLanguage,
      `- 本章已写约 ${currentChars} 字，距合格线 ${aimLow} 字还差 ${deficit} 字。请把差额写满：推进本章蓝图内尚未落地的事件、动作或对话，不要用总结句、心理旁白或景物堆砌凑数。\n`,
      `- About ${currentChars} units are written; ${deficit} more are needed to reach the qualifying line of ${aimLow}. Fill the gap by advancing events, actions, or dialogue still unrealized in the chapter blueprint; do not pad with summary sentences, inner monologue, or scenery.\n`,
    )
  : ''
```

然后在 `continuationPrompt` 里把 `${lengthInstruction}` 改成 `${deficitInstruction}${lengthInstruction}`。

**为什么必须先做这一步**：只要判定还比 1750，prompt 里写多硬都不会触发第二轮。本次就是活证据——篇幅合同明文写着"少于 1750 会被退回"，模型给了 1751，代码判定"过线了"。

**风险**：1750–2125 区间的章每章会多 1 次续写调用（成本 +1 次）。若模型在收束段续写，可能写出"注水尾"——所以 ② 的差额指令必须落在"推进未落地事件"上，而不是"多写描写"。

### 4.2 P2 · 拆掉刹车 + 把 AI 味禁令换成可判定

**文件**：`src/services/builtin-prompt-templates.ts`

**① 【具体生成要求】（`:1061-1066`，next_chapter 对应 `:1143-1148`）**

现状是两句配合的刹车：`:1062`"切忌注水！不要为了凑字数"与 `:1066`"接近目标篇幅时按本章结束状态收束，不要超过目标"。模型读到的是"够了就停"。

改为（first_chapter 版；next_chapter 同构改写，文案须保持一致）：

```
- 体量与节奏控制：本章目标 {{word_number}} 字，合格线为其 85%。写到合格线之前不得收束；
  不足合格线时，继续推进【本章信息】中尚未落地的事件、对话与动作，把事件写满而不是把句子写长。
  同样禁止为凑字数撰写旁白科普、重复复述或无关日常对话。按【本章信息】约定的结束状态收束；
  未明确要求时自然断章，绝不可提前泄露后续情节。
- 写满合格线之后才允许按本章结束状态收束，且不得超过目标上限；不要写"继续生成""点我继续"之类的界面提示。
```

**② 【AI 味反制】（`:1068-1072`，next_chapter 对应 `:1150-1154`）**

保留现有 4 条，追加可判定的 3 条（合并自取证 03 报告 L1/L2/L3/L4）：

```
- 禁止归纳式收束：段落末尾不得出现「X：Y」式冒号解释句（Y 是对 X 的复述或结论），
  也不得出现 3 个及以上结构相同的并列短句（如"不会改A，不会改B，不会改C"）。
  该段的结论应当由读者自己得出，不得由叙述者说出。
- 禁止由叙述者给世界规则下定义：规则只能通过至少两处可观察的事件后果呈现；
  不得出现"什么都不会/从来不/唯一……的地方"这类全称判断。
- 同一情绪外化短语（呼吸停了一拍/喉咙发紧/胸口一松/后背一僵/指节发抖）全章各不得超过 1 次；
  不得连续三段只写生理反应而不给外部动作或对话。
```

**会撞的既有测试（必须同批修）**：

|---|---|---|
| `src/services/__tests__/prompt-local-qwen-contract.test.ts` | `:533-550` 逐字断言 `:1066`/`:1148` 原句；断言 `{{word_number}}` 恰好出现 2 次 | P2 ① |

> 已核对**安全**的用例：`:4053-4072`（2600 单位上限，2600 > aimLow 仍不续写）、`:2180`（2000 stop + 1700 续写，2000 < 2125 仍触发）。

### 4.3 P3 · 番茄 KPI 挪到有效位

**文件**：项目 `first_chapter_draft.zh-CN.json` 的 `taskGuidance`

**为什么放 taskGuidance**：写进 `writing_style` 会被 `:1055`"无需逐条强行兑现"直接消解——这正是本稿番茄 KPI 全线失效的槽位级原因。taskGuidance 不是 `{{writing_style}}` 变量，不受那条豁免直接管辖。

**改为**（替换原 taskGuidance 中【正文生成约束｜去AI腔】之后的部分，同时删掉原第 5 条里的"控制字数"——它与 P1/P2 的字数硬化正向对抗）：

```
参考以上材料，撰写第一章完整正文。
开篇快速切入主角现状，立刻抛出核心冲突/危机，亮出钩子与核心卖点；结尾留下强悬念。
人物行为、世界观规则必须和整体架构、后续蓝图保持一致，杜绝提前剧透。
只输出第一章小说正文，不附带额外说明。

【番茄平台硬指标（以下为可判定要求，优先级高于任何文风描述）】
1. 对话占比 25%–40%（按汉字计）。每段对白之间最多夹 2 段叙述；闭嘴式沉默场景全章不超过 1 处。
2. 段落 60–110 字，单段不超过 120 字。不得连续 3 段短于 30 字。
3. 每约 800 字安排一个推进或钩子。前 300 字内必须出现一次「他人对主角的直接质问、揭穿或施压」。
4. 本章必须落 1 个可辨识爽点，且属于以下五类之一：打脸、收获、揭秘、升级、被认可。
   本章只准用「收获」或「揭秘」，不得把全章写成纯压抑。
5. 章末最后一句必须是对白、动作或威胁；不得以体感、景物或心理活动收尾。
6. 情绪必须外化：每章至少 2 处可见的外化反应（喊、骂、摔、逃、笑、怼），不得只用生理反应代替。

【正文生成约束｜去AI腔（可判定，禁用形容词式要求）】
```

### 10.4 缺陷 D6（本稿新发现，建议单独修）

`extendDraftIfNeeded` 的续写 prompt 由 `draftAuthorMaterialBlock` 手工拼装，**只复刻了"材料"，没有复刻"规则"**：

- 模板正文（`{{...}}` 渲染的那一大块）
- `taskGuidance`（作者可覆盖的创作指导）
- `systemSuffix`（内置的具体生成要求 / AI 味反制）

三者在续写轮全部缺席。后果：

1. 任何写在上述三处的**风格类规则，在"首稿失败 → 续写重写"这条路径上全部丢失**——而这条路径并不罕见（本次就是）。
2. 越依赖 prompt 做风格控制，越会在续写轮被静默降级。
