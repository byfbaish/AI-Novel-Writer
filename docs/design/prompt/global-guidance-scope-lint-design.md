# 全局写作要求「章节越界」静态校验（AGL）小设计稿

> 状态：**搁置（2026-10-14 作者裁定，暂不实施）** —— 作者原话：「三个拆开手动分别放进大纲和正文微操入口（大纲生成界面不叫这个名字，节奏/风格指导），**这是使用上的问题，框架就不兜底了**」。故本设计（编辑期静态提示）**不进框架**，保留本文件备查。本文件不含任何代码改动。
> 附注：作者明确「黄金三章的特点也是要落实到大纲上的」，其正确工具是 **P0-2 段级标签**（`【适用：大纲】`，写稿也要看就 `【适用：大纲,正文】`）或直接写进前几章蓝图；`userGuidance`（作者微操指导）**只在正文模板被引用**，大纲阶段读不到。详见 §4.1 / §9.5。

> 关联：`docs/design/prompt/free-text-scoping-design.md`（段级标签分区）、`docs/design/prompt/prompt-payload-scoping-design.md`

## 1. 背景：这不是机制 bug，是「字段语义错配」

`globalGuidance`（书籍配置 · 全局写作要求）的语义是 **「每一章、每一步都注入」**。因此写进它的内容天然是全局约束。

实测（ch2 trace `20261014-002323-116-正文-ch2-77463622.md`）作者当前 globalGuidance 共 **701 字 / 8 个 `■` 块**，逐块判定：

| # | 块 | 判定 | 处置 |
|---|---|---|---|
| 1 | `■ 红线·命中即作废` | 全局 | 保留 |
| 2 | `■ 设定禁忌` | 全局 | 保留 |
| 3 | `■ 爽点` | 全局 | 保留 |
| 4 | `■ 钩子` | 全局 | 保留 |
| 5 | `■ 黄金三章` | **章节限定 · 跨层**（规划层要设计、正文层要执行） | 用段级标签 `【适用：大纲】`（或 `【适用：大纲,正文】`）就地收窄 —— **不能只移到 userGuidance**，理由见 §4.1 |
| 6 | `■ 段落与对话` | 全局 | 保留 |
| 7 | `■ 弹幕` | 全局 | 保留 |
| 8 | `■ 修稿／精修时适用` | **阶段限定**（仅精修） | 精修模板已内含同义条款 → 作者可直接删除 |

结论：**字段被误用，非引擎缺陷**。引擎行为（无条件注入每章）是正确且必须的。

⚠️ 第 5 块是**跨层**的典型：作者 2026-10-14 明确「黄金三章的特点也是要落实到大纲上的」。也就是说它既要影响**前三章的规划**（大纲层），又要在**正文**里落地执行 —— 这决定了它的正确落点不是「某章的作者微操指导」（那是写稿专属），而是**段级标签收窄作用域**（P0-2 已交付的机制）。

因此本设计的定位 = **「段级标签的智能提示」**：P0-2 给了作者收窄作用域的工具，但作者可能忘了用；lint 负责在编辑期把「这段看起来只对某层/某章生效，但你还没打标签」说出来。

本轮**不改注入逻辑**，只加一层**编辑期静态提示**（作者第 1 条建议）。

---

## 2. 目标与非目标

**目标**：在作者编辑 `globalGuidance` 时，实时指出「这段只对某几章成立」，并指引作者**择一**处置：

- ① **只约束该章正文**（怎么写） → 移到该章卡片的「作者微操指导」（`Blueprint.userGuidance`）；
- ② **需要影响该章规划 / 大纲**（要规划成什么样） → 用段级标签 `【适用：大纲】`（或 `【适用：大纲,正文】`）就地收窄作用域。

> 作者 2026-10-14 补充「黄金三章的特点也是要落实到大纲上的」属情形 ②。故 lint 必须给出**标签**这条路径，不能只推 userGuidance。

**非目标（明确不做）**：
- ❌ 不自动迁移、不自动改写、不自动截断作者文本（红线：不擅改作者资产 / 避免多源真相）。
- ❌ 不阻塞保存、不阻断生成。
- ❌ 不改变任何 prompt 注入行为。

## 3. 方案：纯函数 + 编辑期提示条

沿用段级标签已有的成熟套路（`src/shared/text-scope-tags.ts` 纯函数 + `ScopeTagBar` 提示条）：

1. **纯函数**：`src/shared/global-guidance-scope-lint.ts`
   ```ts
   export interface ChapterScopeIssue {
     line: number        // 1-based 行号
     excerpt: string     // 命中行原文（截断到 ~60 字）
     kind: 'chapter' | 'stage'
     matched: string     // 命中的字面（如「第 1 章」）
   }
   export function lintGlobalGuidanceScope(text: string): ChapterScopeIssue[]
   ```
   纯函数 ⇒ 可单测、无副作用、不进主进程、不碰 ESM 红线。

2. **UI**：`NovelConfigEditor.tsx` 的「全局写作要求」Section（现 `:518-529`，Textarea + `ScopeTagBar`）内，`ScopeTagBar` 下方追加一个提示条，样式复用 `ScopeTagBar` 中 `unknownTags` 的黄条（危险色，`AlertTriangle` 图标）。

3. **触发时机**：随 `value` 变化即时计算（纯函数，文本量小，无需防抖/无性能顾虑）。

## 4. 检测规则

### R1 — 章节限定（本次实现，用户第 1 条）

命中即提示：

| 形态 | 正则要点 | 示例 |
|---|---|---|
| `第 N 章` / `第 N 回` | `第\s*[0-9一二三四五六七八九十百零两]{1,3}\s*[章回]` | `第 1 章：前 300 字…` |
| `前 N 章` / `开篇 N 章` | `(?:前\|开篇)\s*[0-9一二三四五六七八九十]{1,2}\s*[章回]` | `前三章` |
| 成词 | 词表 | `黄金三章`、`开篇三章` |

#### 4.1 落点判定（关键，决定提示文案）

实测：`userGuidance`（作者微操指导）**只在正文模板被引用** —— `builtin-prompt-templates.ts` 中 `user_guidance` 仅出现于 `first_chapter_draft`（:983）与 `next_chapter_draft`（:1050）；蓝图 / 大纲类模板（`chapter_blueprint` / `chapter_blueprint_chunk` / `infer_single_chapter_blueprint` / `plot_structure` / `synopsis`）**均不含该变量**。`generate-draft.command.ts:262 toWriterChapterInfo` 亦只在写稿链路透传它。

⇒ 结论：**`userGuidance` 的生效范围是「写稿层」，大纲阶段看不到它。**

因此 lint 的提示必须按内容意图分流：

| 内容意图 | 正确落点 |
|---|---|
| 这一章**怎么写**（语气、节奏、桥段执行、字数） | 该章「作者微操指导」（`Blueprint.userGuidance`） |
| 这一章**要规划成什么样**（章型特征、必须出现的能力展示、闭环/钩子设计要求） | **留在会注入大纲步骤的字段**，用 `【适用：大纲】` 收窄；若写稿也要看到，用 `【适用：大纲,正文】` |

第 5 块 `■ 黄金三章`（「第 1 章必须有…」）属后者：它是**规划约束**，若只移到 userGuidance，大纲阶段就再也读不到，与「要落实到大纲上」直接冲突。

**误报白名单（必须排除，实测作者文本已出现）**：

- 泛指词不含「第」：`每章`、`本章`、`该章`、`各章`、`逐章`、`上一章`、`下一章`、`前一章`、`后一章`、`章末`、`章节` ⇒ 天然不匹配 `第N章`，无需特判。
- `每章至少 1 个` / `每约 800 字`：数字后不接「章/回」⇒ 不命中。
- **`第N章`（N 为字面字母）⇒ 显式不警示**：作者用它表达「任意一章」的泛指占位，警示即误报。（引擎内部的 `【定稿原文 · 第N章】` 属代码生成文本，本就不经此函数。）

### R2 — 阶段限定（**可选**，用户第 2 条，默认是否开启待裁定）

| 形态 | 正则要点 |
|---|---|
| `修稿时适用` / `精修时适用` / `审稿时适用` / `仅修稿` 等 | `(?:修稿\|精修\|审稿)\s*(?:时)?\s*(?:适用\|生效\|专用)` |

⚠️ 与 R1 的差别：R1 建议的落点是**「某章」**（蓝图微操指导），R2 建议的落点是**「某步骤」**（提示词设置里的精修/修稿模板）。提示文案不同，故作为独立 kind。

**建议**：R2 默认开启（同一函数一并返回 `kind: 'stage'`），文案改为「这类内容只在精修步骤生效，建议放到『提示词设置 → 章节精修』模板里」。

## 5. 提示文案（草案）

```
⚠ 检测到 1 处疑似「只对特定章节成立」的指导：
  第 70 行  第 1 章：前 300 字必须有冲突＋钩子…
  「全局写作要求」会注入每一章。请二选一：
  · 只影响该章正文（怎么写） → 移到该章「作者微操指导」
  · 需要影响该章规划/大纲（要规划成什么样） → 给它加【适用：大纲】标签
  [复制该行]  [插入【适用：大纲】]
```

- 多处时列表展开（上限 5 条 + 「等 N 处」）。
- `[复制该行]` 仅复制原文到剪贴板；`[插入【适用：大纲】]` 在**该块首行上方**插入标签行 —— 迁移/收窄动作仍由作者确认。
- 黄条**不阻塞保存**，与 `unknownTags` 提示同待遇。

## 9. 为什么不做「前 N 章」档位（辨析：首章/后续章分野 ≠ 章节范围机制）

**作者提问（2026-10-14）**：「在提示词模板里首章和后续章节本来就是分开的，如果将范围扩大到前三章合理么？」

**结论：不合理。** 那个分野**不是"章节范围"机制**，不能推广成"前 N 章"。

### 9.1 分野的判据是「有无前驱」，不是「第几章」

`generate-draft.command.ts:625-626`：

```ts
const isFirstChapter = this.chapterInfo.chapterNumber === 1
const templateKey = isFirstChapter ? 'first_chapter_draft' : 'next_chapter_draft'
```

判据是**布尔**（是不是第 1 章），且两模板的差异**全在"前驱类材料"**：

| | `first_chapter_draft` | `next_chapter_draft` |
|---|---|---|
| 输入材料 | `architecture`、`novel_config`、`chapter_info`、`future_blueprints` | `global_summary`(章节要点时间线)、`character_states`、`short_summary`(近期三章)、`previous_ending`(上章结尾800字) |
| 职责 | **破冰**：从零建立世界与主角 | **承接**：接上章结尾、保持连续性 |
| 结构前提 | **无前驱** | **必有前驱** |

⇒ 第 2、3 章与第 4 章在**结构上完全同构**（都有上一章、都有时间线）。「前三章」这个集合内部**不存在可依附的机制边界**；要把它变成一档，只能硬编码一个数字。

> 旁证：P0-1 的短细纲也按同一判据分支 —— ch1 = 1,336 字（无前驱块），ch2 = 5,565 字（含"上一章定稿原文"3,534 字）。差别来自**前驱的有无**，与"第几章"无关。

### 9.2 N=3 是方法论数字，不是引擎常量

黄金三章是**流派写法**（也有黄金五章 / 七章 / 十章）。引擎固化 3，等于把某个流派塞进通用机制，与作者 00:51 的裁定「这个是由作者自己控制的」直接相悖。

### 9.3 段级标签的坐标系是「步骤」，混入章号会让语义崩坏

`projectScopedText(raw, step)` 的唯一维度是 **step**（架构/大纲/正文）。要支持"前 N 章"需：

1. 投影函数加 `chapterNumber` 维度；
2. **7 处注入点全部**传章号 —— 其中架构/大纲步骤的章号是**批次章号**（`declareTraceScopeChapterRange` 支持多章批次），语义立刻混乱；
3. 收益近零 —— 见 §9.4，正文侧本就不该读"规划原则"。

### 9.4 ★ 反证：黄金三章写进全局，会与内置首章纪律**打架**

内置 `first_chapter_draft` 的【网文"黄金第一章"创作法则】第 2 条：

> 仅当【本章信息】明确要求时才展现主角的金手指；不得为满足通用套路擅自新增事件。

作者 globalGuidance 的「第 1 章：…金手指能力首次显现…」**无条件进每章** ⇒ 与上面这条**直接冲突**（一个说"仅当本章信息要求"，一个说"全局必须有"）。

**改成落进第 1 章蓝图就自洽了** —— 它变成了【本章信息】里的明确要求，与内置第 2 条完全一致。

⇒ 这是「黄金三章属于大纲/蓝图层」最硬的证据：它不是"正文阶段要再读一遍的原则"，而是"**规划阶段要消化成章级设计**"的约束。

### 9.5 落地建议（给作者）

| 想要的效果 | 正确做法 |
|---|---|
| 前三章的**规划**体现黄金三章特征 | ① 给 `■ 黄金三章` 块加 `【适用：大纲】`；**或** ② 直接把要求写进第 1/2/3 章的蓝图（`keyEvents` / `suspenseHook` / `userGuidance`） |
| 首章破冰的特殊要求 | 内置已内建【黄金第一章法则】，无需重复；要改就用覆盖版改 |
| 想在第 1–3 章**正文**额外强调 | 写进那三章各自的 `userGuidance`（逐章，写 3 次） |
