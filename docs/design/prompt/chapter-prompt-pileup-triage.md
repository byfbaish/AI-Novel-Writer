## 0. 三句话结论

1. **报告的问题描述基本成立，但根因八成不在它指的位置。** 它指"正文/提示词"，实际根因大多在**章节蓝图阶段**与**槽位选择**。
2. **"一锅乱炖"的感觉是准确的，且可定位。** 拆解只发生在**步骤边界**（短细纲→初始→续写；弧光→大纲→蓝图→正文），没有发生在**载荷边界**——每一步仍把手上所有材料倒进同一个 user 消息。
3. **报告最严重的三个判断（字数四重指令打架 / 短细纲材料里有已写正文 / 对话占比应豁免）都不成立或方向相反**；而它没看到的两个真问题（**蓝图与正文字数基准不一致**、**硬规则被放进文风槽位并被框架主动降权**）才是当前最该修的。

## 2. 报告没看到的框架级根因（优先级高于报告全部条目）

### 2.1 ★★★ 硬规则被放进「文风槽位」，被框架主动降权

实机 trace：作者把 **【黄金三章】【爽点轮换】【钩子轮换】【段落与对话·对话占比25%–40%】【弹幕·每条≤20字／每段≤5条】【情感线】【世界关系】** 全部写在 **`writingStyle`**（`NovelConfigEditor.tsx:522` 的文风槽位）。

而 `first_chapter_draft` / `next_chapter_draft` 的内置 systemSuffix（**用户覆盖不到**，硬编码）写着：

> 【文风适用边界】
> - 文风仅用于选择表达方式，不是新增事实或事件要求；**无需逐条强行兑现**。
> - 作者明确事实与指导、实际前文、本章关键因果和本章篇幅优先。**不得用文风改写这些内容或仅为兑现文风增加场景、动作或事件**。

→ **框架在结构性地告诉模型"文风这几条可以不当真"。** 于是"前300字必须……""对话占比25–40%""弹幕≤5条/段"被模型合法忽略。这不是模型问题，也不是作者问题，是**槽位语义与规则语义不匹配 + 框架主动降权**。

这条与已登记的未修缺陷完全吻合：`NovelConfigEditor.tsx:525`"严格遵循风格要求"与 systemSuffix"无需逐条兑现"矛盾 → 诱导作者把硬指标错放进文风槽位（见 `MEMORY.md` 已知文案缺陷）。

**修复方向（三选一或组合）**
1. **文案纠偏**（最小成本）：把 `NovelConfigEditor.tsx:525` 的"严格遵循风格要求"改为写实描述，并在文风槽位旁标注"放表达方式；放硬性格式/结构指标请用『全局写作要求』或『节奏/风格指导』"。
2. **硬规则槽位**：给"可计数、可判定"的规则（字数/条数/占比/首句类型）一个不受【文风适用边界】约束的落点。候选=扩展 `pacingGuidance` 语义，或新增 `globalGuidance` 内的**结构标签段**。
3. **取消无差别降权**：把【文风适用边界】的"无需逐条强行兑现"限定为"仅适用于主观风格描述"，对**含数字指标/可二值判定**的条目改为"必须兑现"。

> ⚠️ 注意红线：这条改动影响 11 个模板的生效语义，须先确认 `prompt-variable-usage` 与相关测试基线。

### 2.2 ★★ 蓝图与正文的**字数基准不一致**

- 蓝图容量合同：`directory.command.ts:191/248/401` 用 `normalizeChapterWordsTarget(novelConfig.wordsPerChapter)` → **项目配置值**。
- 正文篇幅合同：`generate-draft.command.ts:700` 用 `normalizeChapterWordsTarget(chapterInfo.wordsTarget, novelConfig.wordsPerChapter)` → **本章覆盖值优先**。

实机：`novel_config.wordsPerChapter = 3000`，而本轮 `word_number = 1000`、篇幅合同 `目标 1000 字`。→ **蓝图按 3000 字规划事件容量（`章节容量合同` 会算出 2100–3900），正文按 1000 字生成。** 两者互不校验、互不告知。

后果链：
- 蓝图 `keyEvents` 塞进 3000 字容量的事件量；
- 正文只有 1000 字目标，却被要求"落实全部必需事件，不得删除、改写或截断"；
- → 事件被压扁、铺垫挤占冲突、观感"前 300 字没冲突 / 节奏赶 / 收束仓促"。

**这是报告"前300字无冲突"和"字数不足"的共同物理原因**，比"四重指令打架"更接近真相。

**修复方向**：①把本章 `wordsTarget` 一并传进蓝图容量合同（`buildCompactBlueprintTask` 增加字段）；②或在两处取值不一致时**在运行日志与 trace 里显式告警**（"蓝图按 X 字规划、正文按 Y 字生成"）。

### 2.3 ★★ 载荷无作用域：一步一锅

实机 assembled prompt（续写请求）= **11,279 字**，13 个区块：

```
system:  systemRole + 不可变系统合同 + 本章执行合同(6 子条款)
user:    [注入的写作 Skill]
       + 续写指令
       + 本章篇幅合同
       + 本章蓝图(JSON)                     ← 计划层
       + 全局写作要求(=作者 24 组规则)        ← 含弹幕/对话占比/黄金三章…
       + 文风要求(红线/禁忌/精确度/真人叙事10条/爽点/钩子/黄金三章/段落对话/弹幕/情感线/世界关系)
       + 文风适用边界                        ← 又把上面降权
       + 小说配置事实
       + 作者资料(2 张角色卡原文)
       + 后续计划边界(第2–5章蓝图全文 ≈2000 字)
       + 有来源的历史与候选
       + 生成短细纲块(计划)
       + 本章已写正文全文
```

**分层在"数据来源"上做了**（`readArchitecture()` 把章级段挡在正文外），**但在"注入内容"上又摊平了**：续写同时收到"计划（蓝图＋短细纲）"和"成品（已写正文）"和"5 章远景全文"和"24 组规则"。

**修复方向（框架侧，按收益排序）**
| # | 动作 | 落点 |
|---|---|---|
| A | 给每个步骤定义**允许出现的区块白名单**：正文步骤不注入完整情节大纲；蓝图步骤不注入正文格式规则（弹幕/段落/对话占比） | `prompt-builder.ts` / `draftAuthorMaterialBlock` |
| B | `globalGuidance` **按用途分层注入**：架构链只取"基调/主题/视角/设定禁忌"；正文链才取"段落/弹幕/对话/爽点/钩子" | `builtin-prompt-templates.ts` 的变量出口 + `BasePromptBuilder` |
| C | 短细纲 → **结构化要点**（带编号，并标注"初始生成写哪几条 / 续写写哪几条"） | `draft-short-outline.ts` |
| D | 初始生成结束后，**由代码**算出"已落实/待落实事件"并注入续写（**不让模型自报**） | `generate-draft.command.ts`，可复用 `arc-position.ts` 的"解析上位→累积求和→注入位次"范式 |
| E | 续写补"**本章不可写事件**"具体清单（材料已存在=第2章蓝图，只需提炼） | `draftAuthorMaterialBlock` |

## 4. 建议实施顺序（待审核）

- **P0-1** 蓝图容量合同带上本章 `wordsTarget`（或至少在基准不一致时告警）——小改动，消除最大的物理性偏差。
- **P0-2** 短细纲加**格式契约 + few-shot 示例**（每变体一个，写"示例不代表上限"），并把它从"整份初始 prompt"里改成**只喂该步需要的材料**。
- **P1-1** 文风槽位与硬规则的语义纠偏（§2.1 方向 1，最小成本先落地）。
- **P1-2** 续写补"本章不可写事件"清单 + 明确停止点。
- **P1-3** 载荷作用域白名单（§2.3 A/B），先只做"正文步骤不注入完整情节大纲"这一条。
- **P2** 蓝图阶段加**设定时点预检**（物品/知情提前出现的机器可读标记，落点可挂在 `consistency-preflight.ts`）。
- **P3** prompt-trace 的**片段归因按 call 归属**（见 `MEMORY.md` 追踪红线 ⑤）。
