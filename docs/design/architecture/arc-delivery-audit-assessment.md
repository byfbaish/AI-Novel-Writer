# 弧光兑现度审计：已生成的情节大纲 vs 弧光设定

> 状态：待裁定
> 日期：2026-10-18
> 范围：项目《如果我的能力是每天第一句谎言都会成真》（150 章），产物取样 `project_core.synopsis`（第 1–5 章）、`plot_structure_plan`（3931 字）、`characters_arch`（4498 字）
> 说明：本稿是**现状审计**，不含实施项；需要动手的部分进台账。

---

## 0. 一句话结论

**情节弧（plot_structure_plan）机制健全，但第 1–5 章已把中弧 2 的转折位提前用掉；角色弧（characters_arch）只有 3/7 个角色的起点落地，且整条角色弧没有任何逐章义务载体。**

---

## 1. 弧光设定本身是完整的

`plot_structure_plan` 是一份合格的三层嵌套：

| 层 | 数量 | 章号 |
|---|---|---|
| 大弧 | 3 | 1–52 / 53–103 / 104–150（Σ=150，差额 0） |
| 中弧 | 6 | 1–26 / 27–52 / 53–78 / 79–103 / 104–127 / 128–150 |
| 小弧 | 16 | 每个 8–14 章 |

每个中弧都写了 `类型 / 目标 或 因果 / 尝试 / 转折 / 结束状态`，且**明写了章号区间**——这意味着它是**部分可判的**（见 §4）。

### 1.1 注入机制是健全的（不是「没喂」）

- 弧光结构步骤 `architecture.command.ts:1812` 吃 `premise + charactersArch + worldbuilding + genre + …`；
- 情节大纲步骤吃 `charactersArch`（`character_dynamics`）+ `plotStructurePlan`（经 `withProjectedArcGuide`）；
- `src/shared/arc-position.ts:374` 会按 `from/to` **裁剪弧光正文**，并追加【本批所处弧位】硬规则块，其中第 2 条明写：

> The goal / attempts / turning point of any mid arc AFTER this batch must NOT happen in this batch.

⇒ 判据 ⑩（「没喂」≠「喂了没看见」）：**材料齐了，缺的是服从。**

## 2. 情节弧：不是没兑现，是**超额兑现**

大纲本次只生成了第 1–5 章（`synopsis` 共 1760 字，章锚点 = 1,2,3,4,5；这是**有意的分批**，代码里有 `synopsisRange`）。而第 1–5 章全部落在**中弧 1「门牌错位」（1–26）**的小弧 1「睁眼十秒」（约 9 章）内。

| 大纲章 | 内容 | 归属 | 判定 |
|---|---|---|---|
| ch1 | 睁眼十秒「我马上到」+ 门牌 17→19 + 排班单 + 「第一句是敷衍，不是真话也算」 | 小弧 1 | ✅ 命中 |
| ch2 | 纸门牌交涉 + 额度耗尽 + 黑市报价 + 望海桥 + 新版作息表 | 小弧 1 尾 / 小弧 2「纸门牌」 | ⚠️ 小弧 2 提前 |
| ch3 | 搅格 + 「这格废了」+ 19 号门牌 + 「周三别来桥上」 | 小弧 2 | ✅ |
| ch4 | 鲁传福「桥的事别问」+ 借庞大勇嘴放消息 + 沈砚出场 | **中弧 2 的转折位** | ❌ **超额** |

### 2.1 具体对不上的两处

**（a）中弧 2「三方上门」（27–52）的尝试 2** 是「利用『写下来的不算』，用记事本和纸条跟人笔谈」。
→ 大纲 ch2 已经写了「不张嘴也能把话说完」，等于**把 27 章之后的尝试提前到第 2 章**。

**（b）中弧 2 的转折** 是「他第一次主动说了一句精心设计过的谎，把姜小满的镜头引到街对面——成了，但代价记在**鲁传福**头上，他写下第一笔『欠』」。
→ 大纲 ch4 的爽点是「他一句没说，却把消息放了出去，把盯他的人往桥墩下引。留的隐患是，**庞大勇**转头就会把这事当笑料讲给整条巷子」。
→ **功能位完全相同（设计一次引导 → 成功 → 代价落在别人头上），承重角色从鲁传福换成庞大勇。** 而鲁传福本人在这 5 章里只落了「桥的事别问」四个字，中弧 1 要求的「替程实挡电话 + 挨第一笔登记」**没有出现**。

### 2.2 后果

中弧 2 到第 27 章时，它的「尝试」和「转折」都已经被消耗过一遍——要么重复，要么失效。**偏差也不会自收敛**：`previous` 取的是 `existingBlueprints`（旧蓝图），后续章节基于偏差继续推。

## 3. 角色弧：7 个角色，3 个起点落地

`characters_arch` 给每个人都写了「从 A 到 B」。第 1–5 章（占全书 3.3%）只应呈现 A 段，这里逐人核对：

| 角色 | 弧光起点 A | 第 1–5 章 | 判定 |
|---|---|---|---|
| **程实** | 被动挨打、把生活压到最小；闯祸就跑、代价记在别人账上 | ch1 惹祸跑处理 / ch2 闭嘴写字 / ch3 反击 / ch4 借嘴转嫁代价 | ✅ **A 段完整且准确**。但 ch3 已「主动设计反制」，接近 B 段，略快 |
| **庞大勇** | 不知情地帮着圆谎 | ch4 被借嘴捎话 | ✅ 起点落地（他确实不知情） |
| **沈砚** | 只登记不追问的归档人 | ch4 结尾「卷宗比昨天厚」+「你住还是不住？」 | ✅ **很准**（只登记、不追问） |
| **鲁传福** | 用老交情替程实遮丑 | ch4「桥的事别问」 | ⚠️ 只落一半；中弧 1 要求的「挡电话 + 挨第一笔登记」缺 |
| **韩九畴** | 稳坐江对岸收货 | ch2 座机报价「晚场比早场低两成」 | ⚠️ 机制在、**人未点名**、无对岸场景 |
| **姜小满** | 把程实当纯素材（跟拍逼他开口） | ch4 仅被「捎话」提及，**未出场** | ❌ 起点未建立 |
| **蒋慕之** | 躲在巷子深处只丢半截话 | **完全未出现** | ❌ 未出场（弧光结构安排他在中弧 5，104–127 章，故不算结构违约，但**「教招」的坑先被主角自己填了**） |

### 3.1 一个真实的多义点：「三条铁律」从未被定义

`三条铁律` 在设定里出现 4 次，**没有一处给出清单**：

- `characters_arch` 程实备注：「**三条铁律永不解除**」
- `characters_arch` 蒋慕之能力：「**三条铁律**的边角经验拥有者：知道刚醒十几秒最致命，知道成真走最省事路径，知道第二句抢位会打架」
- `plot_structure_plan` 大弧三结束状态 / 中弧 6 转折：「**三条铁律**仍在 / 永不解除」

而大纲自己归纳了**另一组三条**：

| 章 | 大纲自造 | 与蒋慕之版重合 |
|---|---|---|
| ch1 | 「第一句是敷衍，不是真话也算」 | ✗ |
| ch2 | 「后面说的不算数」 | ≈「第二句抢位会打架」 |
| ch3 | 「坐到零点翻篇，今天的额度重新空着」 | ✗ |

⇒ **全书承重术语没有唯一权威定义，且大纲与设定的三条只有一条勉强重合。** 这是纯文本可查的缺口，不需要任何语义推断。

### 3.2 两份弧光互不对齐

- 情节弧终点（中弧 6「自担的那一句」）= 「程实必须用一次代价自担的引导…不能再让周德胜、庞大勇、鲁传福替他挨登记」
- 角色弧终点（程实）= 「站在被牵连的人身边自己认账」

**这是同一个终点，但两份产物由不同步骤生成，彼此零引用。** 改其中一份不会提醒另一份。

### 3.3 结构缺口：角色弧没有「义务载体」

角色弧以整段散文（`{{character_dynamics}}`）进入大纲 prompt，**没有任何机制要求「本章推进谁的哪一步」**；章节蓝图链、审稿链也都不查弧光推进。

对比：`keyEvents` 会被 `freezeChapterGoals` 冻成审稿核对目标（`ch1:keyEvents:N`）——**弧光没有对应的冻结物**。它只能靠模型自觉。

## 4. 可判 / 不可判的分界（决定该不该上代码）

| 检查项 | 可判？ | 怎么判 |
|---|---|---|
| 大纲章号 ∈ 所属小弧区间 | ✅ | 要求每章标注「小弧：<名>」，比对 `plot_structure_plan` 里的章号区间 |
| 中弧 2 的转折是否被提前 | ❌ | 「转折」是散文，要判就变成通用语义理解 |
| 两份弧光终点是否一致 | ⚠️ 半可判 | 可做**关键词对齐提醒**（如「自担」↔「自己认账」），不宜硬判 |
| 「三条铁律」是否被定义 | ✅ | 术语表存在性检查（一次性） |
| 角色弧是否被推进 | ❌ | 除非要求每章显式声明，否则不可判 |

## 5. 建议（按性价比）

| 优先 | 动作 | 类型 |
|---|---|---|
| **1** | 给「三条铁律」加**唯一权威清单**（落 `worldbuilding` 或设定区），各层引用同一份 | 数据订正，一次性 |
| **2** | 章级大纲条目增加「**小弧：<名>**」+「**弧光推进：<角色> — <哪一步> / 本章不推进**」两个字段 | prompt 合同 |
| **3** | 两份弧光建立交叉引用：中弧「结束状态」必须点名它对应哪个角色的哪一段弧 | prompt 合同 |
| **4** | 大纲生成加一条硬约束：「本章只能使用**当前小弧**的转折；后续中弧的转折不得提前」并附章号区间 | prompt 合同（不可代码判） |
| 不做 | 弧光推进的自动检测 | 不可判，会上通用语义检测的无底洞 |

> 第 2 条的价值不在「自动检测」，而在**让它可见**：一旦每章都要写「本章推进了谁」，空白就会自己暴露。
