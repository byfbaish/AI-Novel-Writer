## 0. 这份东西测什么

只测一件事：**同一份结构，只改「配给状态」那一段，模型写出的章数会不会跟着变。**

- 会变 → 说明"鼓励"这个提示词有效，E2 通过，可以进 E3（改分批机制）
- 不会变 → 说明提示词没说服力，**先改提示词再谈机制**，不要反过来

不需要跑真实项目：三份 prompt 都用虚构数据，每份 < 1,500 字，网页模型几十秒出结果。

---

## 1. 怎么用

1. 新建三个**互不相关**的对话（同一对话里连续跑会串上下文，三份就全废了）
2. 各贴一份，要求"只输出单元 2 的章节大纲"
3. 数每份里 **## 第N章** 的个数，以及每章正文的行数
4. 填进 §4 的判读表

## 3. 判读表

| 版本 | 状态 | 期望章数 | 期望形态 | 实测 |
|---|---|---|---|---|
| A | 不足 | **2–3 章** | 事件压缩，少开新线，四行要点偏"结果" | |
| B | 均衡 | **3–4 章** | 每章一个完整小局面 | |
| C | 充足 | **5–7 章** | 有过程、有支线、有旁观者反应 | |

通过标准（三条都成立才算通过）：

1. **C > B > A**，且 C 至少比 A 多 2 章；
2. A 里没有丢单元 2 的任何一项规格（叙事任务 / 离开状态 / 逼法换代都要在）；
3. 三份都没有提前写单元 3 的"旧账"。

---

## 4. 判定之后怎么办

| 结果 | 结论 | 下一步 |
|---|---|---|
| 三条全过 | 提示词有效 | 进 E3（改分批机制） |
| C > B > A 但差距 < 2 章 | 有效但力度不够 | 把"收紧/扩充"的具体动作写得更狠（给出可数的操作：合并场面、删支线、加旁观者视角），再测一轮 |
| A/B/C 章数几乎一样 | **提示词无效** | 不要动机制。先改状态块的写法：把形容词换成动作清单，再测 |
| A 丢了必要情节 | 收紧被理解成"删内容" | 补一句"删的是过程，不是结果"，再测 |

---

## 5. 为什么用虚构数据

真实项目的材料有 1 万多字（世界观 + 角色 + 全部单元），一次跑几分钟、还占上下文；而这里要验的只是**一句话有没有说服力**。

结构、单元规格、输出格式三样在真实链路里都存在，虚构版只是把它们压到最小。**如果最小版都不生效，真实版不会因为材料多而生效。**

## 6. 第一轮实测与 v2 修正（2026-10-19）

### 6.1 第一轮结果

| 版本 | 状态 | 实测章数 | 期望 |
|---|---|---|---|
| A | 不足 | **11–15** | 2–3 |
| B | 均衡 | 8–15 | 3–4 |
| C | 充足 | **4–12** | 5–7 |

**方向反了**：最该收紧的 A 写得最多，最该扩充的 C 写得最少；三份区间还大幅重叠。

### 6.2 两个原因

**① 测试有混淆变量。** 三份的"单元 1 已写章数"不同（10 / 7 / 3），导致起始章号也不同（第 11 / 8 / 4 章）。模型看到"从第 11 章开始"会默认自己在故事中段，倾向写细；看到"第 4 章"会默认还在开篇。**状态块的效果被起始章号盖住了。**

**② 设计缺陷：状态块没有锚点。** 原文只说"收紧/按节奏/扩充"，但没告诉模型"一个单元大概几章"。20 章 ÷ 3 单元 = 6.7 章这个数，模型并不知道。没有基准时：

- "收紧"被理解成"别漏东西"→ 反而拆得更细、写得更多；
- "按节奏发挥"没有落点 → 区间最宽（8–15）；
- "可以展开"只是**许可**，不是**要求** → 模型没有动力多写。

### 7.1 v2 判读

| 版本 | 状态 | 期望章数 |
|---|---|---|
| A2 | 不足 | **3–5** |
| B2 | 均衡 | **5–7** |
| C2 | 充足 | **8–10** |

通过标准：`A2 < B2 < C2`，且 **C2 − A2 ≥ 3 章**；三份都不丢单元 2 的三项规格；都不提前写单元 3。

若仍不通过，说明问题不在"有没有锚点"，而在于**模型不接受"写多少章"这类指令**——那时要换机制（改用分批硬边界，而不是靠模型自律）。
