## 0. 三句话

| 问题 | 回答 |
|---|---|
| 「分形 + 切片」方向对不对 | **对**，而且它是当前架构唯一能通向长篇的路：模型写不好几百万字，但能写好一个个闭环的十万字单元，前提是**接力时交得清** |
| 切片交什么 | **不是交设定，是交「可判定的状态」**。判定标准一句话：*下一个项目写第 1 章时，手里必须有它，否则第一句就在撒谎* |
| 现在能交吗 | **只能交一半**。资源有账本（能交），角色状态是自由文本（交不准），伏笔**根本没有「已回收」状态**（交不了），能力/制度无宿体（交不出） |

**一句话**：W8 的第一件工作不是写导出按钮，是**先把「下一部第 1 章必须知道的东西」逐项找到宿体**；找不到的，必须显式降级成「作者手写摘要」，不许假装能自动提取。

## 1. 为什么只做线性（作者 2026-10-23 裁定）

线性升级流 = 人界 → 灵界 → 神界，**单向向上，不回头**。这是本稿唯一的建模对象。

**不做多图往返，不是因为技术上做不到，而是因为语义上定不下来**：

- 一旦允许「回天南」，就必须先回答：离开期间那张图**冻结**还是**按规则演变**？
  - 冻结 ⇒ 十年后回去，世界一动不动，读者不信；
  - 演变 ⇒ 需要一套「离线演化规则」，而模型演出来的东西没人核对过，等于给正文埋一片无法验证的背景。
- 两种选择都会造出**作者看不见的第二套真相**（这正是 W3/W4 一路在防的形态）。
- 而在线性流里这个问题**根本不存在**：旧图已经"结算完毕"，只以背景设定与遗产的形式存在。

**重新评估的条件**（满足两条再谈）：① 作者真的写了「回旧图」的剧情，不是设想；② 线性版的跨部伏笔账（§4）已经能自动算出「哪一层还欠几个坑」。

> 附：Q2 方案里的 `region_id` / 蓝图 `region_tag` / 焦点切换，在**线性流里全部不需要**。
> 线性流只需要一个维度：**当前处在第几层**，且它单调递增。

## 2. 切片包的必需集 —— 逐项过现状（这是本稿的核心）

判定标准：**下一个项目写第 1 章时，须有它才能不撒谎。** 逐项核对现有宿体：

| 要带走的东西 | 现有宿体 | 能自动带走吗 | 处置 |
|---|---|---|---|
| **资源余额**（手里还剩多少上品灵石） | `resources` + `resource_movements`（W6） | ✅ 能（余额是纯算术） | 作为新项目的**起点 movement**，但**必须换成本部单位重新声明**（§5） |
| **资源定义与量纲**（1 枚 = 多少、日结月结） | `resources` | ⚠️ 能带格式，**语义不可复用** | 旧定义只作参考，新项目**强制重新登记**，不许直接继承 `anchor_value` |
| **角色状态六槽**（境界/伤势/物品/位置…） | `cs_*`（自由文本） | ⚠️ 能带字符串，**带不准** | 照抄进新项目角色卡；显式标注"上一部末状态，需作者核对" |
| **关键物品**（那把刀、那张欠条） | **无结构**（在 `cs_key_items` 一句话里） | ❌ 带不了 | 只能走作者手写摘要（W6 §6.1 已承认是真空） |
| **未回收伏笔** | `NarrativeThreadStatus` 五态（planned/planted/progressing/**resolved**/abandoned）+ `dormantChapters` + `overdue` | ⚠️ **能算出"未回收"，但只在项目内** | 缺的是**跨项目作用域**（id 是项目内自增）⇒ §4 新建跨部伏笔池；在此之前只能人工列清单 |
| **金手指/能力触发次数、冷却、代价** | **无宿体** | ❌ | 手写摘要，或先立 12.x 的能力槽 |
| **制度进度**（月例发到第几月、差事轮次） | **无宿体** | ❌ | 同上 |
| **故事日序** | `summary_snapshots.story_day_offset`（整数） | ✅ 能 | 新项目起点直接写整数 |
| **世界观本体**（法则、势力） | `worldbuilding` 长文 | ⚠️ 能带，但**必须降维** | 旧图压缩成"背景设定"段，不整篇搬运（搬运会把已死的人物、已灭的门派当成现役） |

**结论（也是给作者的实话）**：所谓"状态固化已经让跨项目切片变得可能"，**目前只对资源这一类成立**。
其余五项里，两项带不准、两项带不了、一项压根没有宿体。W8 若直接做导出按钮，导出的会是一份
**看起来完整、实则一半是猜的包** —— 那比不做更危险。

**因此 W8 的排序是**：先补齐「下一部必须知道」的宿体（能力槽 / 关键物品 / 伏笔回收状态），
再谈导出与导入。

## 3. 切片包的形态

一份包 = **两个人能读、机器也能读**的两份文件（同源生成，作者可改）：

```
handoff-<项目名>-<层名>.md      # 作者读、可编辑（最终以它为准）
handoff-<项目名>-<层名>.json    # 机器读（导入用；与 md 不一致时以 md 为准并高亮差异）
```

内容分区（**每区都必须标 `来源：结构 / 手写`**，让作者一眼看出哪些是机器算的、哪些是猜的）：

1. `identity` —— 层名、本层结束时的章节号、总字数、故事日序
2. `world_compressed` —— 世界观降维段（法则 / 势力 / 已结算事件），**明确写"旧图已结算，以下均为背景"**
3. `characters` —— 角色终态六槽 + 所在位置 + **显式标注未结构化项**
4. `resources` —— 每项：名称 / 单位 / 期末余额 / **是否跨层通用** / 旧层口径
5. `threads_open` —— 未回收伏笔（`来源：手写`，直到 §4 落地）
6. `scale` —— 本层量纲表（境界上限、货币单位、兑换关系），供下一层重写时对照
7. `warnings` —— 生成包时自动跑的体检结论（如"3 项资源未登记单位""本层还有 2 个 target 已过期未回收的伏笔"）

> **不做「自动写进新项目正文」**。导入只做三件事：填入 `world_setting` 的"前情"段、写一条起点 movement、生成资源定义草稿（待作者确认）。其余一律进"参考区"，由作者决定要不要用。

## 4. 跨部伏笔池（唯一必须新增的持久层）

**为什么不能塞进项目库**：伏笔的"欠账"属性跨项目存在。第 1 部埋的坑，第 2 部要还；如果池子住在本部库里，第 2 部根本看不见它。所以它必须是**项目外的用户级资产**（与 `.vela-pack`、作者级 prompt 同级），而**不是**任何一本项目库里的表。

**现状核对（2026-10-23 实测该表）**：

```
narrative_thread_plans => id,title,type,target_start_chapter,target_end_chapter,author_intent,created_at,updated_at
```

- **计划表没有 status** —— 但**线索状态是有的**：`NarrativeThreadStatus` = `planned / planted / progressing / resolved / abandoned`，
  另有 `dormantChapters` 与 `overdue`（`src/shared/narrative-thread.ts`）。状态由事件（`narrative_thread_confirmations`）推导，
  所以「哪些坑还欠着」**能算出来**；
- **没有** 「预期回收层级」（在哪一部回收）；
- **没有** 跨项目身份（id 是项目内自增，换项目就重号）。

所以缺的**不是**"回收状态"，而是**跨项目作用域 + 层级归属**：
「第 1 部还欠几个坑」这件事，在第 2 部里查不到，因为池子住在第 1 部的库里。

**最小可行形态**（W8c）：

| 字段 | 说明 |
|---|---|
| `thread_uid` | 跨项目稳定键（ULID），**不复用项目内自增 id** |
| `title` / `intent` | 原文照抄，不改写 |
| `planted_in` | 哪个项目、哪一章（`projectId` + 章号） |
| `due_layer` | 预期在哪一层回收（层名，手填） |
| `status` | `open` / `resolved` / `abandoned`（作者显式变更） |
| `resolved_in` | 实际回收的项目与章（作者确认后写） |

**纪律**：**不做自动注入蓝图**。自动把"本层该回收的坑"塞进蓝图，会立刻变成判据 **CX** 那类
「永远无法应用的待办」—— 作者既不能确认也不能拒绝。只做**只读汇总 + 手动勾选继承**。

## 5. 通胀控制：不是汇率，是「每层重写量纲」

上一部「满级神装」到下一层变白板，是网文铁律；直接继承资产会让主角在新图财务自由、张力归零。

**规则（硬性）**：

1. **新项目的 `resources` 必须作者重新登记**，不复用旧项目的定义与 `anchor_value`。
   `anchor_value` 的相对性只在本项目内成立（W6 §3.2 的"虚拟基准"假设了同一套体系）。
2. **余额不许直接搬**。新项目的起点必须是 `chapter_number = 0`、`source = 'author'` 的一条
   movement，且单位是新项目的单位。旧余额只作为**参考数值**出现在导入包里。
   （这条与 W6「起点是一条 movement，不是一个字段」天然契合。）
3. **必须显式声明跨层通用性**：每项资源在导入时勾一个「跨层仍有效」。
   - 勾了 ⇒ 允许按作者给的换算率写起点；
   - 没勾 ⇒ 新项目里**不出现**（灵界的灵石在天南不通兑，反过来也一样）。
4. **量纲体检（W8d）**：新项目写第 1 章之前跑一次——若资源余额是从上一部数字直接搬来的、
   且没有换算说明，给出**建议级**提示（不进矛盾计数，判据 DL 同源）。

## 6. 分期

| 期 | 内容 | 依赖 | 验收 |
|---|---|---|---|
| **W8a** | 切片包生成（只读，md + json 双份，每区标来源） | 无 schema 改动 | 用真实项目生成一份包，作者能读懂、能改；`warnings` 区能指出"未登记单位的资源""已过期未回收的伏笔" |
| **W8b** | 新项目导入（前情段 + 起点 movement + 资源定义草稿，全部需确认） | `project_core` 缺「前情提要」字段 ⇒ 复用 `world_setting` 前缀段，或新增字段（需迁移，先讨论） | 导入后新项目第 1 章能读到前情，且 `resources` 有一份待确认草稿 |
| **W8c** | 跨部伏笔池（用户级新表 + 手动勾选继承） | 新持久层（项目外） | 第 2 部能看到第 1 部未回收的坑，且**不会自动进蓝图** |
| **W8d** | 量纲体检 | W8a/b | 直接继承余额且无换算说明 ⇒ 给出建议级提示 |

**前置（不属于 W8，但 W8 依赖）**：能力槽 / 关键物品结构化 / 伏笔回收状态 —— 这三项没有宿体，
切片包里就只能写"手写摘要"。

## 7. 不做（写清楚，防止范围蔓延）

- ❌ **多图往返 / 回旧图**（含 `region_id`、蓝图 `region_tag`、焦点切换、世界总控面板）
  —— 见 §1，语义定不下来；线性版跑通且真有往返剧情再评估
- ❌ **多图并行**（同一本书里两条时间线各在一张图）
- ❌ **自动把旧世界整篇当新世界世界观**（已死人物、已灭门派会被当成现役）
- ❌ **自动跨层换算汇率表**（每层重写量纲，不做汇率网络）
- ❌ **自动注入伏笔到蓝图**（判据 CX）
- ❌ 把切片包做成"只能导入不能编辑"的黑盒

## 8. 与既有判据的关系

- 判据 **DI**（权威值唯一）：跨层后 `resources` 是**新的一套**，旧项目 `resources` 冻结为历史，
  不得让两个项目的资源定义互相"覆盖"。
- 判据 **DJ**（中断必须显式）：新项目的余额起点若来自导入，必须是一条可追溯的 movement，
  不许直接写一个余额数字（否则中断语义失效）。
- 判据 **CX**（不得产生永远无法应用的待办）：伏笔只做只读汇总 + 手动继承。
- 判据 **DL**（体检不进矛盾计数）：量纲体检只出建议。
