## 0. 一句话结论

**指纹是 4 元的（源事实 / 步骤指导 / 批次范围 / 生成模板），报错只认 1 元（源事实），而且是断言式的认。**

判定处拿到的信息只有一个布尔值「不等」——组合哈希是单向的，**比对的那一刻已经不可能知道是哪一项变了**。文案却写了「项目源事实自上次生成后已变化」，`:3135` 还补了一句「（故事前提/角色/世界观/总章数等）」，把读者的视线钉在恰恰没变的字段上。

作者原话即本条的验收标准：

> 「模板变化不应该影响到原事实变更，这完全是错误的说法。开发者倒是可以调查到真实原因，但对于使用者来说，抠破脑袋都找不到这个真实的原因，只会以为自己的写作材料变化了，但其实根本没有变化。」

**修法不是改文案，是让判定侧有归因能力**（§4）——文案只是这个能力的出口。

## 1. 现象：一条有代码级证据的误诊

### 1.1 复现记录（D17 实机复验，2026-11-05 20:05）

| 步骤 | 实测 |
|---|---|
| 动作 | 复制作者真实项目到 `.runtime/d17-verify/`，隔离数据根（`AI_NOVEL_APP_DATA_HOME`），走 UI 触发「单元批大纲生成」（第 18–19 章） |
| 结果 | 续批被拒，报文：「项目源事实自上次生成后已变化，既有大纲不能与新的源事实拼接。请从「AI 生成故事架构」从第 1 章重新生成。」 |
| 诊断 | 临时打印（已删）：`stored=13sbmpn  expected=tkj9w7` |
| **核对** | **12 个源事实字段逐字段 sha256 与原库完全一致**：`premise` / `characters_arch` / `worldbuilding` / `genre` / `total_chapters` / `words_per_chapter` / `writing_language` / `plot_structure` / `plot_structure_plan` / `narrative_pov` / `global_guidance` / `synopsis` |
| 真因 | 换了数据根 ⇒ `resolvePromptTemplate('synopsis', …)`（`:3020`）解析出的模板不同（原环境有全局覆盖版 `~/.vela/prompts/synopsis.zh-CN.json`，新环境走内置） |

**换数据根 = 换机器 = 换项目覆盖设置，三者等价。** 也就是说：作者把项目换个目录打开、重装一次、或者只是同事那边也开了同一个项目，旧检查点就可能续不上，而界面告诉他「你的写作材料变了」。

### 1.2 指纹里到底有什么

`synopsisInputsFingerprint`（`architecture.command.ts:1124-1150`）把 4 段拼成一个 32 位 djb2 哈希（`synopsisFactsFingerprint`，`:1033-1040`，base36 ≈ 7 字符）：

```ts
return synopsisFactsFingerprint([
  JSON.stringify(sourceInputs),   // ① 11 个源事实字段（:1130-1143）
  stepGuidance,                   // ② 作者步骤指导
  `${range.from}:${range.to}`,    // ③ 批次范围
  JSON.stringify(template),       // ④ 解析后的生成模板（整对象）
])
```

④ 是**整个模板对象**，包含 `systemSuffix`（三层结构的完整输出合同，`builtin-prompt-templates.ts`）、`taskGuidance`、以及渲染期不生效的字段。**它不在任何 UI 上显示，作者无法查看也就无法联想到这里。**

### 1.3 报文与代码的错位（逐处）

| 位置 | 报文 | 实际可能的原因 |
|---|---|---|
| `:3135`（续写） | 「项目源事实（故事前提/角色/世界观/总章数等）自上次中断后已变化」 | 4 项里任一项；括号里那 4 个字段**恰好是最不可能变的那几个**（变了会被 §1.1 的核对直接查出来） |
| `:3242`（续批） | 「项目源事实自上次生成后已变化，既有大纲不能与新的源事实拼接」 | 同上 |

**同一个文件里，世界观链写对了**——`architecture.command.ts:2334`：

> 「故事前提、小说配置或**世界观模板**自候选保存后已变化，旧候选不能续到新上下文；候选仍可查看或复制。」

它把 4 个组成项（`premise_result` / `config` / `stepGuidance` / `template`，见 `:2326-2331`）**点名列了出来**。所以这不是「作者不知道要写全」，是**同一个文件里两处写法不一致，而错的那两处正好在用户最常撞上的路径上**（大纲是每个项目必跑、且是最长的一条链）。

## 2. 为什么"改文案"不够

把 `:3242` 改成「输入（源事实 / 步骤指导 / 批次范围 / 生成模板）之一已变化」——诚实了，但**没解决问题**：作者仍然不知道该查哪一项。他的可选动作还是只有「从第 1 章重新生成」这一个，代价是全书大纲重写。

作者的判据写得很清楚：**「抠破脑袋都找不到这个真实原因」**。所以要求是**归因**，不是**免责**。

归因的前提是判定时能逐项比较，这需要写入侧多存一点东西（§4.1）——这是本条真正的工程量所在。

| 文件 | 自述 |
|---|---|

顺带说明一点边界：这两处 override **不是纯为躲指纹**而存在的（两级 vs 三层结构本来就换了套输出合同）。所以修好 D20 **不等于可以把 override 删掉**，但可以让「能不能直接改内置模板」重新成为一个可选项，红线 19 也就该随之重新评估（§7 第 3 条）。

## 4. 修法

### 4.1 必做：把「一个哈希」扩成「分项哈希」，组合值保持不变

**不动现有字段语义**（`synopsis_facts_fingerprint` 仍是那 4 段的组合哈希，老检查点照旧能读），**新增一份分项明细**：

```ts
// 新增纯函数，与 synopsisInputsFingerprint 并列
export function synopsisInputFingerprintParts(
  expected, stepGuidance, range, template,
): { source: string; guidance: string; range: string; template: string; combined: string }
// combined 必须 === synopsisInputsFingerprint(...) 的返回值（单测钉死）
```

写入侧（`:3750` 完成落盘 / `:3916` 中断落盘 / `:4102` 逐章路径）一并落 `synopsis_input_fingerprints`：

```ts
partial.synopsis_input_fingerprints = { source, guidance, range, template }
```

判定侧（`:3133` 续写 / `:3240` 续批）改为调 `parts`，逐项比较，得出

```ts
type SynopsisInputDrift = Array<'source' | 'guidance' | 'range' | 'template'>
```

**为什么存 4 个短哈希而不是存原文**：每个 ≈ 7 字符（`synopsisFactsFingerprint` 是 32 位 base36），总量约 30 字节；存原文会让 `partial_arch.json` 把模板整份复制进去（`systemSuffix` 就 70 行），且模板里一旦有作者自定义内容就变成第二份真相。

**`range` 一项天然不会误报**：两处判定都用检查点自己的 `synopsis_range` 重算（`:3130` / `:3237`），与写入侧一致（中断落盘用请求范围、完成落盘用实际章数，见 `:3261-3265` 的注释）。但既然要逐项比，就把它一起比出来——否则将来范围迁移出 bug 时，又会退化成"反正有一项变了"。

### 4.2 报错按 `drift` 生成（文案表）

| `drift` | 报文（中） | 可继续？ |
|---|---|---|
| `['source']` | 现有的 `:3242` **一字不改**——这时候它是对的 | 否 |
| `['template']` | 「大纲**生成模板**自上次生成后已变化（源事实、步骤指导、批次范围均未变）。已写的 N 章大纲仍然有效。模板变了，续写会按新模板产出后续章节。」 | **允许继续（裁定 A）**，但必须显示这条提示，不静默 |
| `['guidance']` | 「作者步骤指导已变化。」（`:3125` 已有独立检查，这里只是兜底） | 否 |
| `['range']` | 「批次范围变了（检查点记 A–B，本次算 C–D）。」 | 否 |
| 多项 | 逐项列出，例如「源事实与生成模板均有变化：…；…」 | 否 |
| 旧检查点（无 `synopsis_input_fingerprints`） | 「输入自上次生成后已变化，但这个检查点写于旧版本，**无法判断是哪一项**（可能是源事实 / 步骤指导 / 批次范围 / 生成模板）。请从第 1 章重新生成。」 | 否 |

**最后一行是必须有的诚实兜底。** 存量检查点全是没有分项明细的，一次会话里就可能撞上——它至少不再说"源事实变了"。

### 4.3 顺带修掉的三处预告文案

§3.1 那三处（`:792` / `:610` / `:166`）按新报文改写。其中 `ArchitectureConfirmDialog.tsx:792` 是**用户可见**的，且它在清空架构这个场景下预告的确实是 `['source']` 分支——改写后应写成「这样生成会提示源事实已变化」，不再逐字引用报文全文（引用全文的文案一定会再次过期）。

## 5. 行为裁定：只有模板变时，允不允许续？

**这是本条唯一需要作者拍板的地方。** 三种取法，我不替作者选，但把证据摊开：

| 方案 | 做法 | 支持它的证据 | 反对它的证据 |
|---|---|---|---|
| **A 允许续写** | 模板不进"有效性"判定，只提示"后续章节按新模板写" | 项目**事实上早就这么判了**：红线 19 与三处 override 的全部存在理由，就是"模板变化不该作废大纲"。若现在说不许续，等于承认三处绕行是白付的 | **模板变化可能是结构性的**。`synopsis-two-level-suffix.ts` 就是活证据：两级结构换掉 `systemSuffix` 后，输出合同的格式要求整段不同。第 1–20 章按合同甲写、第 21 章起按合同乙写，大纲文件里会并存两套格式 |
| **B 如实说明 + 作者确认后可续**（我倾向） | 拦一次，报文说清"只有模板变了、已写的都有效"，给一个「仍用本检查点继续」 | 保留作者的判断权；不静默混格式；也满足作者"我要知道真实原因"的诉求 | 多一次点击；且需要想清楚"确认"要不要记忆（记了就不再问，不记就每批都问） |
| **C 拦且不给旁路** | 现在的行为，只把文案改对 | 最保守，改动最小 | **正好是作者这次抱怨的那一半**——知道原因了却仍然只能全书重写 |

**若选 B，还需要定一条**：确认记到哪一层——记在检查点（`synopsis_template_ack: "<hash>"`，模板再变就再问一次）还是每次会话都问。记在检查点更省事，且天然带版本绑定。

### ✅ 裁定（2026-11-05 20:57，作者）：**选 A —— 允许续写**

| 项 | 内容 |
|---|---|
| 裁定 | 只有模板变化时**不拦**，旧检查点继续可用；原事实/步骤指导/批次范围真的变了才拦 |
| 落地形态 | `drift === ['template']` ⇒ 放行 + 一条不阻塞的提示（「生成模板已变化；已写的前 N 章大纲仍然有效，后续章节按新模板生成」）。**不是静默放行**——归因仍要显示出来，否则又是"什么都不说" |
| 为什么这条与 D8 的 A 是同向的 | D8 裁定 A 的道理是「单元化之后整批重来的代价可接受」；本条的道理是「模板不构成事实变化」。两者都指向同一个口径：**只有内容层面的真实变化才该让已完成的成果作废，工具链的差异不该** |
| 与 §5 表里"反对 A"那条的关系 | 反对意见（模板变化可能是结构性的，会让同一份大纲并存两套格式）**被知情接受**，不再作为拦截理由。**但仍要写进提示文案**：模板变化时明确告知"后续章节会按新模板的格式写"，让作者自己能判断要不要手动重来 |
| 裁定 4（B 的确认记在哪） | **随之作废**——不拦就不需要确认记录 |

## 7. 明确不做什么

1. **不改 `synopsisFactsFingerprint` 的算法、不加长哈希**。32 位碰撞概率对本用途足够；换算法会让所有存量检查点一次全失效，等于手工制造一次本条要治的故障。
2. **不改 `synopsisInputsFingerprint` 的签名与返回值**。它是导出函数、被 `plot-outline-batch.command.test.ts:72` 复用（那份测试刻意要求"不得复写算法"）。新增并列函数，不改旧的。
3. **不顺手删 `systemSuffixOverride` 机制**。它的第一用途是换输出合同，不是躲指纹；本条只在 §6 里记一笔"限制可解除"。
4. **不把模板复制进 `partial_arch.json`**。存哈希，不存原文（理由见 §4.1）。
5. **不给 `world_building` 单独开一条**。同病同治，§4.1 做成共用件。
6. **不动 `:3125` / `:2315` 那两处「作者步骤指导已变化」的独立检查**。它们是对的，且比指纹更早拦住、报文更准。
