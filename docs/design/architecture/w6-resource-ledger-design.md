## 0. 三句话

| 问题 | 回答 |
|---|---|
| 资源能不能塞进角色六槽？ | **不能。** 六槽全是自由文本（`cs_key_items` 是字符串），没有单位、没有周期、没有加减。资源是**独立的状态类别**，不是角色属性 |
| 谁说了算？ | **`resources` 表**（作者登记的权威值），不是散文、不是模型输出。正文与世界观里的数字只是**引用**或**冲突证据** |

**一句话**：把「灵石有多少」从散文里拎出来，变成一张有单位、有周期、有余额、能算中断的表 —— 与 W2 把「今天第几天」变成整数是同一种手术。

## 3. 权威值 SSoT

### 3.1 放哪

**新表 `resources`（项目级），入口仍在世界观页面**（第 2 维【阶层断层与资源战场】旁边一块「资源登记」）。理由：

- 表格：可校验、可引用、可被账本 join、可以被作者逐个确认；
- 散文：模型每次重生成就重写一遍，且改一个字就可能让整条链失效；
- 入口放世界观页：作者不必记两个地方，且"资源"本来就属于第 2 维的语义范围。

### 3.2 字段（草案）

**先明确一件事：`resources` 是「资源」这一整类的表，不是灵石专用表。** 一条记录 = 一种可计数的资源，
可以是下品灵石、中品灵石、仙晶、人民币、美元、军功、声望、丹药、人情。见 §3.3。

| 字段 | 语义 | 约束 |
|---|---|---|
| `resource_id` | 稳定键（ULID/UUID） | 永不复用 |
| `family_id` | **资源族**（可空）：同一族的多个品阶共享它，如 `灵石` | 可空；单例资源（如「军功」）留空 |
| `name` | 显示名（逐字键，如「下品灵石」/「人民币」/「军功」） | **项目内唯一** |
| `tier` | **族内品阶**（0 = 基础/单例，1、2、3… 递增） | 默认 0；同族内不重复 |
| `unit` | 记账单位（枚 / 元 / 点 / 份） | 必填；**同一条资源只能一个单位** |
| `anchor_value` | **换算锚**：1 本条资源 = 多少个虚拟基准值 | 可空；**空 = 不可通兑**（灵石↔军功通常为空） |
| `period` | 数额口径（日 / 月 / 副 / 次） | 必填；这是「30 倍 bug」的死因（AC5 §5 表第 ③ 类） |
| `earn_note` / `cost_note` | 收入 / 支出速率的**说明文本** | 可空；**仅展示，不参与算术**（算术只认账本变动） |
| `scarcity_note` | 设计意图（为什么要稀缺） | 可空；进「设定体检」区，不进矛盾计数（判据 **CM/DL**） |
| `anchor_note` | 换算说明（如「按开篇 1 美元 = 7.2 元，本书不浮动」） | 可空；汇率是否随剧情变化由作者声明 |

> ★ **起点余额不在本表**（2026-10-22 评审补）：§5.3 要求「起点必须有值」，但这里**故意不加 `initial_value` 列** —— 起点就是一条 `source='author'` 的 movement（§5.1），`chapter_number=0`。于是余额 = `Σmovements(≤n)`，**一个公式、一个数据源**（判据 DI）。加一列就等于造了第二个起点真相。
>
> ★ **`earn_note` / `cost_note` 故意不参与算术**。账本的唯一数据源是**逐章变动**（§5），设定里的费率只用来做「合理性体检」（§4.4）。混用会让"设定写的"和"正文发生的"两套数打架。
>
> ★ **换算用「虚拟基准」而不是两两配对**：`下品灵石 anchor=1`、`中品=100`、`上品=10000`、`仙晶=1000000`，
> 任意两者互换率 = `anchor_a / anchor_b`，不需要 N×N 的汇率表；`人民币=1`、`美元=7.2` 同理。
> `anchor_value` 为空的资源（军功、人情、声望）**各自独立成链，永不合并**。

### 3.3 资源是类别，不是灵石（这一节回答「资源项会不会太单薄」）

**定义**：资源 = 任何**可以计数、会被获取或消耗、且影响人物处境**的东西。判据是「有没有数量的增减」。

| 算资源 | 不算资源（归物品槽 12.13） |
|---|---|
| 下品/中品/上品/极品灵石、仙晶 | 欠条（只有"签没签"，没有数量流动） |
| 各国货币（人民币/美元/欧元…） | 草刀（在谁手里 = 归属状态，不是余额） |
| 丹药几副、粮草几石、军功几分 | 药包（丢了没丢是状态，不是数量） |
| 声望、人情、信用额度 | — |

**必须支持的四种形态**（都落在同一张表上，不是四套系统）：

1. **单例资源**：`family_id` 空、`tier=0`。例：「军功」「声望」。
2. **同族多品阶**：`family_id='灵石'`，`tier` 0/1/2/3，`anchor_value` 逐级放大。例：下品/中品/上品/极品。
   **账本永远记在具体品阶上**（`下品灵石 +120`），族级余额是**派生展示**，不单独存 ——
   否则「族余额」与「品阶余额」就是两套真相（判据 DI 的延伸）。
3. **跨族可兑换**：两族都给了 `anchor_value` ⇒ 可换算。例：人民币 ↔ 美元；灵石 ↔ 仙晶（若作者设定仙晶可兑）。
4. **跨族不可通兑**：任一 `anchor_value` 为空 ⇒ 各自独立。例：灵石 ↔ 军功 ↔ 人情。
   **「并行抢夺多种资源」正是这种形态** —— 读者能同时感到"钱不够"和"人情欠多了"，两者不能相抵。

**多资源并存是默认状态**，不是特例：一本都市书可能同时有 4 种货币 + 2 种隐性资源（人脉、信用），
每条独立账本、独立中断状态、独立余额；W6c 资源页按 `family_id` 分组展示。

**边界（仍然只做一类）**：一张表能表达"有数量的东西"，但**表达不了"状态机"**。
欠条从"没签"到"签了"不是加减，是状态跃迁 ⇒ 归 12.13（关键物品），不在本表。

> ★ **`earn_rate` / `cost_rate` 故意不参与算术**。账本的唯一数据源是**逐章变动**（§5），设定里的费率只用来做「合理性体检」（§4.4）。混用会让"设定写的"和"正文发生的"两套数打架。

### 3.4 谁能写

| 角色 | 权限 |
|---|---|
| 作者 | 增删改（唯一权威） |
| 模型（生成期） | **只能提议**：生成世界观时输出"我认为本书有这些资源：灵石（枚/日）" 的提案，**落库前必须确认**（照 W4a 的「先生成后 stage」，不允许模型直接建行） |
| 定稿后处理 | 只读 SSoT，写**变动**（§5），**永不改 SSoT** |

判据 **DI**（权威值唯一且不进散文）：资源名/单位/周期只允许在 `resources` 表定义一次；正文与散文里的"新定义"只能作为冲突证据，**不得被采纳为权威值**。

## 4. 生成期自检（W6a）—— 「防下一本」的那一半

### 4.1 三层，从确定性到判断

| 层 | 谁来做 | 能抓什么 | 是否阻断 |
|---|---|---|---|
| **A 规则层**（纯函数） | 代码 | 量纲上限、相对量缺分母、同资源双单位 | ❌ 只提示 |
| **B 模型自审** | 生成后追加一次 pass | 规则抓不到的语义矛盾（"劳作换取" vs "签到即得"） | ❌ 只提示 |
| **C 设定体检** | 纯算术 + 阈值 | 结余率、稀缺度、张力 | ❌ **只建议，永不进矛盾计数**（判据 DL） |

**A 层是本次立项里性价比最高的一块**：不需要 schema、不需要新表、不需要模型配合，纯正则 + 常量表就能拦住本项目的两个硬伤。

### 4.2 A 层规则（先做前两条，后两条要等 SSoT）

| # | 规则 | 命中样本 | 依赖 `resources` 表？ | 判据来源 |
|---|---|---|---|---|
| A-1 | **量纲上限**：工时类数值 ≥ 24 小时（常量表：1 时辰 = 2h，1 日 = 12 时辰） | 「每日劳作**十二时辰**」= 24h ⇒ 零睡眠 | ❌ 不依赖 | AC5 N-b 的合法复活 |
| A-2 | **相对量缺分母**：`[一二三四五六七八九十百]+分之一` / `%` 且同句无「收入/支出/月例/总收入」之一 | 「药钱大概占据**五分之一**」 | ❌ 不依赖 | 判据 **CK** |
| A-3 | **同资源双单位**：同一段内同一资源名后跟两个不同单位词 | 「灵石（枚）」之后又写「灵石（块）」 | ✅ **需要资源名清单** | AC5 N-c 的合法复活 |
| A-4 | **资源名疑似重复定义**：「灵石」与「下品灵石」在同一维内各自被定义 | 修为体系常见的层级混淆 | ✅ **需要资源名清单** | 新（DI 的前置检查） |

> ★ **为什么 A-3/A-4 要等 M11**：没有 `resources` 表时，「资源名」只能靠"单位词 + 前文名词"猜。
> 猜错就产出一批**假问题**，而假问题会直接变成作者要一条条处理的待办 —— 这正是判据 **CX**
> 要防的形态（待办队列不得产生永远无法应用的项）。有表之后这两条变成精确比对，成本还更低。
> **所以 W6a-1 只做 A-1 / A-2。**

**A-1 的判定条件（纯句式 + 纯算术，不依赖任何动词表）**：

1. 句中出现日常量词：**每日 / 每天 / 一日 / 一天** 之一；
2. 同句（或紧邻下一分句）出现时间量：数字 + **时辰 / 小时 / 更 / 刻**；
3. 换算后合计 **≥ 24 小时**。

> **判定的是数值，不是语义**：这句话声称「每日」的时间总量 ≥ 24 小时 —— 一天装不下。
> 不管那十二时辰是劳作、打坐、赶路还是自创的「炼气」，都不影响结论。
> 「每日炼气十二时辰」命中（不需要知道"炼气"是什么）；
> 「打坐十二时辰」不命中（没有日常量词，不构成日常作息声称）；
> 「一夜十二时辰」「每月初一劳作十二时辰」同样不命中。

**为什么不用动词表**：「哪些词表示工时」是**这本书的世界观特征，不是通用规则**。
作者写「每日炼气/守阵/喂灵兽十二时辰」，写都市「每日搬砖」、写异界「每日挖矿」，词表永远追不上；
而**漏报（真问题抓不到）比误报更糟** —— 你永远不知道漏了什么。枚举法在泛用性上必输。

**已知误报（接受，不为它引入词表）**：「一月三十日，每日十二时辰」这类历法换算说明会命中。
措辞中性（"请确认是否为设定"），作者扫一眼即判；这种句式在设定里出现频率极低。

**兜底**：产出级别固定 **`undecidable`**，不阻断、不判 error、**不给"应该改成什么"**（判据 CJ）；
每条 finding 带稳定 `key`（`worldbuilding-numeric:<kind>:<hash>`），可直接复用既有
`consistency_exemptions.stable_fact_key` 表做豁免 —— 每一项都可"确认或豁免"，不是悬空待办（判据 CX）。

> **备选（未采纳）**：把 A-1 整体挪到 B 层模型自审，让模型区分「打坐是设定」与「劳作是矛盾」。
> 代价是"防下一本"依赖模型判断、确定性弱一档。已裁定：**保留在规则层**。

**A-2 的实现收窄（记录在案）**：分式（`五分之一`）直接算相对量；百分数（`30%` / `百分之三十`）
只有出现在**份额语境**（占 / 比例 / 份额 / 抽成 / 分成 / 提成）里才算，否则「成功率百分之三十」
这类句子会被全部报一遍。

> A 层**不猜、不补**：命中即报「这句话现在不可判定 / 物理不成立」，并给出原文片段与位置，
> **不给出"应该改成什么"**（判据 CJ）。

### 4.3 B 层：生成后自审 pass

- 时机：`GenerateWorldBuildingCommand` 产出文本后、写库前（若现有流程没有确认面，则落库后立即跑并把结果附在完成提示里，见 4.5）。
- 输入：本次生成的世界观全文 + 已登记 `resources`（若有）。
- 输出（严格 JSON）：`{ findings: [{ severity: 'conflict'|'undecidable'|'suggestion', category, quote, why }] }`
- **硬约束**：只允许引用原文，**不许做任何算术**（判据 **DK** 的生成期版本）；不许改正文。

### 4.4 C 层：设定体检（与一致性分栏，判据 CM/DL）

按 SSoT 的 `earn_rate`/`cost_rate`/`period` 与账本余额算出：

- 月结余率（`(收入-支出)/收入`）；
- 一次性支出相对月结余的倍数；
- 若账本显示"余额长期单调上升且无门槛支出" ⇒ 提示"稀缺性可能不足"。

**措辞固定为建议句**，进独立的「设定体检」区，**永不进 warning 计数、永不阻断生成**（AC5 §4.5）。

### 4.5 结果落在哪（低成本起步）

| 阶段 | 呈现 |
|---|---|
| 立即可用 | 落库后一行日志（照 §11.7 的先例）+ 架构页顶部一条**可见但不阻断**的提示条（`conflict` 用警示色、`suggestion` 用次要色） |
| 可选升级 | 若后续给世界观生成加确认面，把 A/B 层结果移到确认前 ⇒ 作者能在落库前决定是否重生成 |

**不做**：自动重生成、自动改世界观正文、把体检结论写成 error。

## 5. 账本（W6b）

### 5.1 表：`resource_movements`

| 列 | 类型 | 说明 |
|---|---|---|
| `id` | INTEGER PK | |
| `chapter_number` | INTEGER NOT NULL | 变动发生的章；**`0` 专表「开篇起点」**（§5.3，且只允许 `source='author'`） |
| `resource_id` | TEXT NOT NULL | 外键 → `resources` |
| `delta` | INTEGER NOT NULL | **整数**增减（正负）；带小数先乘到最小单位再存。**不许 `DEFAULT 0`** —— 缺失就是没有这条行 |
| `unit` | TEXT NOT NULL | **记账当时的单位快照**（2026-10-22 补）。理由见下方 ★ |
| `evidence` | TEXT NOT NULL | 正文逐字引文（判据 DJ 的核对依据） |
| `source` | TEXT NOT NULL | `finalized-extract` / `author`（作者手工补登、含起点行） |
| `created_at` | TEXT | |

- **一条 movement 必须有 `delta` 和 `evidence`**。抽不到就不写行 —— 「没有行」表示"本章没有明确变动**或**没抽到"，两者由 **§5.2 的扫描记录**区分。
- 索引：`(chapter_number, resource_id)`。

> ★ **为什么存 `unit` 快照**（2026-10-22 评审补）：`resources.unit` 是作者可改的。若不快照，作者把「枚」改成「块」之后，**全部历史 `delta` 的语义会被静默重解释** —— 这是「30 倍 bug」的同一类形态（改了定义，历史不报错地变了意思）。所以：写行时快照当时的 unit；读账本时若 `movement.unit ≠ resources.unit`，**判为显式冲突**（与 A-3 同类处理），**不静默合并、不自动换算**。
>
> ★ **必须幂等**（2026-10-22 评审补）：`runPostProcessPipeline` 用 `withRetry(…, retryCount=2, …)` 包住 `step.executor`（`workflow-utils.ts:307`），同一段抽取代码**最多会跑 3 次**。所以写库前必须
> `DELETE FROM resource_movements WHERE chapter_number=? AND source='finalized-extract'` 再整章重建。
> 漏了这条不会报错 —— 只会让余额越滚越大，而账本看起来一切正常。

### 5.2 抽取：定稿后处理新增一步 `resource-ledger`

挂在既有 `runPostProcess`（`src/services/workflows/workflow-utils.ts:259`）的 steps 里，`critical: false`。

| 项 | 约定 |
|---|---|
| 输入 | 本章定稿正文 + 本章可见的 `resources` 列表（**只给名字与单位，不给费率**，避免模型顺手算） |
| 输出 | `movements: [{resource, delta, unit, quote}]`；`scanned: boolean` |
| 硬约束 | **只认明确的数量变化**（"取走一百二十枚" → +120 / "花掉六枚" → -6）；模糊表述（"损失惨重"）**不产生行**；**不许输出余额**（判据 DK） |
| 中文数字 | 由纯函数 `parseChineseNumber` 归一（一百二十 → 120）；归一失败 ⇒ 丢弃该条并计入 `unreadable` |
| 扫描记录 | 复用 post-process step 的记录，但**不是三态枚举** —— 见下方 ★ |

> ★ **「已扫 / 未扫」的真实判定**（2026-10-22 评审改正）：原文写的是「`passed` = 已扫；`failed`/`skipped` = 未扫」，但 `post_process_steps` 只有 `ok INTEGER`（`baseline-schema.ts:292`），而且**没跑过的步骤根本没有行**。所以判定是：
>
> | 库里的样子 | 判定 |
> |---|---|
> | 行存在且 `ok=1` | **已扫**（抽到行，或确认本章无变动） |
> | 行存在且 `ok=0` | 未扫 |
> | **没有这一行** | 未扫 |
>
> 后两种 ⇒ `余额(≥该章) = unknown`，UI 文案「第 n 章起账本中断」，**不是「0 枚」**（判据 DJ）。

### 5.3 纯算术：`resource-ledger.ts`

```
余额(章 n) = 余额(章 n-1) + Σ movements(章 n)
```

**三条硬规则**：

1. **中断即停**（判据 **DJ**）：若章 n 的扫描状态不是「已扫」（§5.2 的判定表），则 `余额(≥n) = unknown`，**不得跨过中断继续累加**，也不得填 0。UI 显示「第 n 章起账本中断」，不是「0 枚」。
2. **起点是一条 movement，不是一个字段**：起点 = `chapter_number=0` 且 `source='author'` 的那条行。没有这一行 ⇒ 第 1 章余额 = `unknown`（**不得假定 0**）。作者补一条 `下品灵石 +30` 就是「开篇有 30 枚」。这样「起点」和「变动」共用一张表、一个公式（判据 DI）。
3. **单位不混算**：`movement.unit ≠ resources.unit` ⇒ 显式冲突，各自独立成链；**不静默合并、不自动换算**。

### 5.4 判据（新增，接在 D 系列 DH 之后）

| 编号 | 判据 | 违反症状 |
|---|---|---|
| **DI** | **权威值唯一且不进散文**：资源名/单位/周期只在 `resources` 定义一次；散文里的新定义只能作冲突证据 | 两处定义 ⇒ 每章各算各的（AC5 灵石案原样复发） |
| **DJ** | **账本中断必须显式**：未扫描的章之后余额一律 unknown，不得跨越累加、不得填 0 | 漏一章，后面全错**且看起来正常** |
| **DK** | **模型只读数、不做算术**：抽取产物只能有「整数 + 引文 + 资源名」，任何模型给出的余额一律丢弃 | 模型口算错一次，账本与正文一起错，且无法定位 |
| **DL** | **设定体检不进矛盾计数**：稀缺度/结余率/张力只在「设定体检」区、措辞为建议，不得计入 warning、不得阻断 | 作者以为有 3 个 bug，其实只有 2 个（AC5 §4.5 的复述） |

## 6. 并入世界状态（W6c）

**左栏分类从 5 个变 6 个**（空间检查已于 2026-10-22 占了第五位）：
`归位表 / 时间线 / 角色 / **资源** / 连续性事实 / 空间检查` —— 资源插在「角色」之后，
因为设计语义是「人（角色）/ 物（资源）/ 事（时间线）」并列（原先写的「第五类」是空间落地前的说法）。

| 区 | 内容 |
|---|---|
| 资源页 | 每个资源一张卡：当前余额（取最近一个可算章）+ 逐章余额走势（小条形）+ 异常标记（骤增/骤降）+ **中断提示**（"第 n 章起账本中断"）+ 引文展开 |
| 时间线章卡 | 加一行「资源变动」摘要（`灵石 +120 / 药钱 -6`），点开看引文 |
| 角色卡 | **不放资源**（资源不是角色属性；角色持有量若需要，是"角色×资源"的第三张表，本轮不做） |
| 硬边界 | 仍是只读；唯一写入口是「作者手工补登一条变动」（照 orphan 补齐的模式：可写但必须显式确认） |

**为什么给资源一个独立位置**：作者的原话是「资源作为社会运转的基本基石」。归位表管**人**，时间线管**事**，资源管**物** —— 三者是并列的世界状态维度，塞进任何一边都会变形。

### 6.1 W6 覆盖到哪：六个状态槽里只活了一个半

**这一节必须写清楚，否则会被读成「世界状态问题解决了」。** 世界状态要盯的是六类东西，
W6 只动其中一类的一半：

| 槽 | 谁管 | 现状 | 缺什么 |
|---|---|---|---|
| **物品 / 资源** | 资源 → **W6（本文）** | 📋 立项，W6a-1 已落地 | **关键物品仍是真空**：欠条签没签、药剩几副、草刀在谁手里 —— 仍在 `cs_key_items` 自由文本里，无结构、无校验、**未立项** |
| 时间 | 未立项 | W2 只有「日序整数 + 单调性」（可算术）、A-1 只查量纲 | 「昨儿夜里」vs「当天」这类**跨章时间承接**没有归属 |
| 空间 | 第 4 维机读行（生产口径待确认） | 有数据 | 没有消费方，W6 不校验 |
| 人物 | W4b → 已移交 W6 的 M11（**只补字段**） | 字段有 | **知情边界**（"记的是四副"越界）、伤势单调等**转移规则校验**，一个都没做 |
| 能力 / 金手指 | 未立项 | 无结构 | 触发次数、冷却、代价累计 |
| 制度 / 流程 | 未立项 | `resources` 的 `earn_rate`/`cost_rate` 只是展示文本，**不参与算术** | 签到轮次、月例发放、差事派单、送账日 |

```
六槽
├─ 物品/资源
│   ├─ 资源 → W6（本文）：SSoT + 账本 + 中断 + 判据 DI/DJ/DK/DL
│   └─ 关键物品 → 未立项（欠条/药包/草刀），仍在 cs_key_items 自由文本
├─ 时间  → 未立项（"昨儿夜里"无归属；A-1 只查量纲，不查承接）
├─ 空间  → 第 4 维机读行（生产口径待确认）
├─ 人物  → W4b 补字段（已并入 M11）；知情边界 / 伤势单调无校验
├─ 能力  → 未立项（触发次数 / 冷却 / 代价累计无结构）
└─ 制度  → 未立项（签到 / 月例 / 差事 / 送账日无状态）
```

**两条容易误解的边界，单独说明**：

1. **W4b「六槽补齐」补的是字段存在，不是转移规则校验。** W6 落地后：资源这一个槽是**活的**
   （有权威值、有账本、有中断、有判据）；另外几个槽即使字段补齐，**写了也不等于会被查**。
2. **W6 是「账本」，不是「生成时输入」。** 正文生成时模型手里仍然没有「当前资源余额 + 本章适用规则」
   的快照 —— 状态快照 / 本章规则子集 / 本章任务 / 风格这四件套属于**前置注入**，
   **已单独立项为 [`W7`](./w7-world-state-injection-design.md)**（2026-10-22 作者裁定：世界状态必须闭环）。
   校验（W6）与注入（W7）是两件事，**两者拼起来才闭环**；只有账本而没有注入，就是「事后能查出、
   写的时候照样不知道」。

> **本文射程一句话**：W6 只解决「资源」这一类状态的**可登记、可校验、可中断**。
> 其他五槽的转移规则校验不在本文范围 —— 见 §10。

## 8. W4b 现状与合并裁定

**W4b 现在什么情况**：⏸ **后置未开工**，定义是「六槽补齐 + 设计意图栏」（主稿 §18.1）。后置理由是"六槽里三槽已有宿主（`cs_location` / `cs_power_level` / `cs_key_items` + `cs_provenance`），再定一遍不产生新能力，先落 schema 会把'现在能写的'和'新加的槽'混成两套真相"（判据 CU 的教训）。前置条件「拿 W4a 真实数据」**现在已满足**（归位表已并入 W5 并在跑），但还缺一段真实使用数据。

**它与 W6 的关系（需要作者裁定）**：

| 方案 | 做法 | 代价 |
|---|---|---|
| **甲 分开做** | W4b 保持后置、独立一次迁移；W6 自己建 `resources` + `resource_movements` | 两次迁移（M11、M12）；"设计意图"出现两处载体（W4b 的意图栏 vs W6 的 `scarcity_note`） |

**建议乙的理由**：W4b 的「设计意图栏」本质是「**期望值 vs 实际值**」的对照，而资源是这个对照的**第一个真实实例**（"设定说该稀缺" vs "账本显示余额一路涨"）。分开做，必然出现两套"期望"，最后还是得合并一次 —— 与 W4a「先生成后 stage」同一个道理：**先做会造出第二事实源的那一半，等于白做。**

> ✅ **2026-10-22 作者裁定：走乙** —— W4b 并入 W6 的 M11，一次迁移同时落 `resources` + `resource_movements` + 六槽补齐 + 设计意图栏。W4b 在 W 线主稿里标记为「已移交 W6」。

- ❌ **关键物品的状态结构化**（欠条签没签、药剩几副、草刀在谁手里）—— 这一半**目前是真空**：
  仍在 `cs_key_items` 自由文本里，没有任何结构与校验。本文明确承认这个缺口，但**不认领**它
- ❌ **前置注入（状态快照 / 本章规则子集 / 本章任务 / 风格四件套）** —— **已移交 [`W7`](./w7-world-state-injection-design.md)**（2026-10-22 作者裁定单独立项）。W6 是账本，告诉你在第 4 章算错了；它**不会**在生成第 5 章时把余额递给模型

## 11. 风险

| 风险 | 缓解 |
|---|---|
| **抽取假阳性**（把"三人"读成"3 枚灵石"） | 必须带逐字引文；作者可删条目；`parseChineseNumber` 失败即丢 |
| **账本中断频繁**（模型漏抽） | 中断显式可见（判据 DJ）；先只对"明确声明数量"的章记账，宁可少记 |
| **单位换算错误** | 不声明 `conv` 就不合并；同资源多单位直接判冲突（A-3） |
| **设定费率与账本打架** | 费率只进体检、不进算术（§3.2） |
| **把体检当 bug 修** | 分栏 + 固定建议措辞 + 判据 DL |
