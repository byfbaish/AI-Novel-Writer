# 弧光层的工间交接（2026-10-18）

> 用途：**换会话 / 换人接手前读这一份**。它不讲规则细节，只回答三个问题：
> 这一层当初为什么存在、现在该干什么、为什么会长成现在这样。
> 细节在 `arc-generality-and-ending-design.md`（判据）与 `arc-tree-expansion-design.md`（改造方案，待重写）。

## 0. 定位：这是一层**后加的、可剥离的**层（2026-10-18 核实）

弧光层不是管线的前提，而是**替换掉一层硬编码**的可选增强。证据以代码为准：

| 事实 | 证据 |
|---|---|
| 原始架构只有枚举 | `electron/migrations/baseline-schema.ts:33` 只有 `plot_structure TEXT DEFAULT 'three_act'`；**基线 DDL 里没有** `plot_structure_plan` |
| 自由弧是后加列 | `electron/migrations/m07-plot-structure-plan.ts:9`：`ALTER TABLE project_core ADD COLUMN plot_structure_plan TEXT NOT NULL DEFAULT ''`；同文件注释——基线已冻结，新增列必须走 lane，不能改 baseline |
| 空值即回退 | `architecture-workflow.ts:366-368` `resolveStageStructureGuide`：`plotStructurePlan` 为空 → `getPlotStructureGuide()` 枚举模板；注释写明「保证老项目与"不想用自由弧"的作者行为完全不变」 |
| 投影失败也回退 | `arc-position.ts:621`：`span && plan ? 裁剪 : guide` —— 结构不可解析 / 本批越界 → 原样返回，不抛错 |
| 体检不拦 | `architecture.command.ts:318-346`：`summarizeArcDensity` / `summarizeArcCoverFindings` 注释均写「只报告，不阻断」 |
| 下游不读它 | `plotStructurePlan` 的非测试消费点只有三处：`synopsis` 生成（`architecture.command.ts:2058 / 2249 / 2534`）、编辑器预填（`editor-store.ts:84`）、仓储与导出。**正文与审稿链路零引用** |

**所以「剥离」的真实含义**是：删掉 `plot_structure` 生成步骤 + 弧光 UI + 两个体检函数，列保留（DEFAULT `''`）→ 大纲照样出，只是退回「三幕 20/55/25」这类**硬编码比例分段**。不是「没有分段」，是「分段重新由枚举常量给」。

**它存在的意义**：把「全书切几段、每段从哪到哪」从常量变成按本书生成的数据，于是**大纲不必自己发明全书节奏**，只需管章级局面。这既是它值钱的地方，也是它的边界——见 §2 / §3：一旦它开始替大纲写「事件好不好看」，就是上游代偿下游，必然补不到位。

## 1. 初衷（作者 2026-10-11 原话）

> 「现在的架构**其实就是五层架构**，只不过**有一层被隐藏起来了**，而且是**固定编码**。
> 现在要做的就是**把这一层显现出来变成可被管理的状态**，在故事架构生成阶段**动态生成并可调整**，
> 接下来就是**复用现在的管线**。」

被隐藏的那一层，代码里是 `getPlotStructureGuide(structure, totalChapters, language)`——
一个**纯函数**：输入 5 个枚举之一（三幕 / 英雄之旅 / 救猫咪 / 起承转合 / 多线）+ 总章数，
`switch` 出一段硬编码文本，内容是**阶段划分**：第一幕几章到几章、每阶段该写什么、各占多少比例。

所以弧光层的初衷只有三条，一条都不涉及"写好事件"：

1. **显性化**：把"阶段划分"从枚举硬编码变成按本书动态生成的数据；
2. **可管理**：有自己的数据落点（`plotStructurePlan`）、能看能改；
3. **复用管线**：不改动大纲与正文的既有链路，只是喂给它们一个真实的分段。

## 2. 职责范围

**只该回答三个问题**（对应 `getPlotStructureGuide` 原始的三个信息）：

| 该答 | 形式 |
|---|---|
| 全书切成几段 | 个数（篇幅只用来算这个） |
| 每段从什么处境到什么处境 | 入口 / 落点（状态，不是事件） |
| 每段里必须发生什么 | 极少的必发事件，防空转 |

**不该答**（每一条都曾经被塞进来，又被迫撤回）：

| 不该答 | 为什么 | 该由谁答 |
|---|---|---|
| 每段多少章、多少字 | 篇幅一旦进内容，模型就开始凑（1500 字下限→到字就停） | 代码按个数折算 |
| 事件好不好看（四态、三型、对手失手位） | 这是"这一章怎么写"的判断，弧光没有这一章 | 大纲的章级局面 |
| 结局怎么收 | 全书问题是第 1 层的事 | 核心种子 + 最后一段落点 |
| 故事过了多久 | 没有来源，模型只能编（`P19` 已改成"时间密度"） | 核心种子（如果要约束）。**能写密度（压缩选择 + 理由），不能写跨度（几章/几年）** |
| 主角的"目标/赌注" | 见 §4：这是补丁，不是职责 | 大纲 |

## 3. 它是怎么长到 10,629 字的

实测（2026-10-18）：`plot_structure` 提示词 **10,629 字符**，25 个 ★ 块，19 条自检，
其中输出格式示范 **3,411（32%）**、自检 **1,627（19%）**。
同期 `synopsis`（真正写内容的那层）只有 **3,759**。

**上游比下游重 2.8 倍** —— 这就是"承上启下"失职的量化证据。

增长机制是一个正反馈，每一轮都一样：

```
大纲写出来不好看
  → 我判断"弧光没给够材料"
    → 在弧光加规则（P13 信息量递增 / P15 四态+收尾 / P16 赢回位 / P17 目标赌注+位置行）
      → 上游把细节写死
        → 大纲只能抄，抄完没料
          → 再加规则
```

**正确的因果链应该是反的**：大纲不好看，多半是大纲层的"章级局面"不够，
不是上游材料不够细。上游代偿的代价是永远补不到位——因为 8 章需要的是
"同一目标上的第 2、3 次失败"，那只可能在大纲层生成。

## 4. 已被证伪的假设（别再捡回来）

| 假设 | 谁证伪的 | 现在成立的版本 |
|---|---|---|
| 差异越大/时间跨得越久，越能展开 | 作者（陈佩斯吃面 25 分钟；一天写十章） | 容量来自**阻力与边界数量** |
| 用强因果约束弧间关系 | 作者（重生小学生→全国首富，没有必然因果） | 只需**可达**：说得出怎么走过去 |
| 篇幅是内容预算 | 作者（1500 字下限一到就收笔） | 篇幅**只算个数** |
| 时间跨度是一个事实 | 作者问"这个数字从哪来" | 它是**叙事密度选择**（量级+理由），不约束大纲 |
| 砍掉小弧能减负 | 作者问"罩得住 20–30 章吗" | **层级不是负担，字段才是**。中弧 20–30 章 ÷ 3–5 章 = 5–7 段，一个 want→result 只撑一段 |
| 加"目标/赌注"能治"重量不足" | 尚未证伪，但它是补丁：治的是事件质量 | 待验收；若大纲层能自己长出，就删 |

## 5. 现在该是什么样（未落地，待重写方案）

三层保留，每层只写三格；**落点用"选择变少"来判，不用句式判**：

```
## 大弧：<名>
- 从 <入口> 到 <落点>：世界和他各自变成了什么样
- 这一段必须改变的是：<一件具体的事>
- 中弧个数：N
- 时间密度：把读者压在 <几天/几个月/几年> 里，因为 <理由>

### 中弧：<名>
- 从 <入口> 到 <落点>：他的路从 <几条> 收到 <几条>
- 小弧个数：N

#### 小弧：<名>
- 他要办成 <…>，办不成失去 <…>
- 从 <还有哪些路> 到 <少了哪一条>
```

删掉：三型分类、8 个位置字段、四态、位置行点名、Σ/±10%、19 条自检里的 16 条。

**为什么"选择变少"能防住"他想要吃饭，结果饭店关门了"**：那是**一场戏**，
一条路都没少；而一段弧的定义就是"他少了一条路"。这个判据同时把认知型事件
（发现 / 确认 / 意识到）挡在落点之外——认知砍不掉路。

生成方式：**逐节点展开**（大弧一次 → 每个大弧展开中弧 → 每个中弧展开小弧）。
一次性生成的病不是"重"，是逼模型在同一个上下文里同时做 27 个决定，于是只能套格式。

## 6. 交接禁忌

1. **不要在上游加质量规则**。想加之前先问：这条在大纲层能不能用一行解决？
2. **不要给没有来源的数字**。写进提示词的数（章数、字数、天数）要么来自作者，要么由代码算；
   否则它会变成假权威，还会反过来否决下游。
3. **不要砍层级来减负**。层级是内容结构，不是负担；负担是字段与自检。
4. **不要用褒贬词当规格**（"不要写他用了什么招"）。模型判不了语义褒贬，只判得了结构位置。
5. **不要用禁词解决问题**。`目标/赌注/起点/落点` 是普通中文词，禁了会误伤正文；
   要管的是"标签+冒号"的**字段语法**，而大纲 ⑤ 早已禁止字段列表。
6. **不要在方案未获裁定时直接改代码**（作者 2026-10-18 明确要求：结构类改动先讨论再落地）。

## 8. 附：我这轮被污染的具体表现

写进交接是为了让接手的人知道**失败模式**，不是自责清单：

1. 提出"小弧不拆"，理由是"少一层轻一半"——这是**工程直觉**（减行数），不是内容判断，被 20–30 章一问就露馅。
2. 把"目标/赌注"当成弧光必须的字段，因为**我刚加了它**，不是因为这一层需要它。
3. 用"他想要→结果"的句式去治"事件质量"——而事件质量根本不该在这一层判。
4. P15 加"时间跨度"，P19 论证它没来源，中间隔了三轮，且期间它一直作为硬约束在跑。
5. 判据编号排到 `CF`（第 84 条），几乎每一条都是某次补丁的收据。

**共同点：每次都在回答"怎么把眼前这个症状修好"，没有一次先问"这一层该不该管这件事"。**
