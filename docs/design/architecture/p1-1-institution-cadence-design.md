# P1-1 期 2 · 制度槽（周期事件 / cadence）

> **状态**：✅ 已落地（2026-10-23，M15 · 独立登记页 · 写前查阅第四小节）
> **行业名**：periodic obligations / recurring events —— story bible 里属于 world rules 与时间线的交叉格；
> 它在 ConStory-Bench 的「时间线与情节逻辑」下表现为**周期性事件错位**（该发生的没发生、连发两轮）。
> **它解决的不是数量问题**：`resources.period` 是口径说明，这一格是**判定轴**，两者不共用字段。

---

## 0. 四问

| 问 | 答 |
|---|---|
| 行业里叫什么 | recurring event / periodic obligation。网文侧的实例是「月例哪天发」「签到几轮」「送账日」——世界观写了规则，正文每次重述各写各的 |
| 谁消费产出 | ① 写前查阅（生成第 N 章时告诉模型「这一章该不该发生」）② 作者扫表（哪条该发了）③ 将来的 findings（漏发/连发） |
| 失败形态 | 时间线连续性 · 周期事件错位（**不是**数量矛盾，所以不用账本） |
| 已有产品做过什么 | story bible 的时间线分区通常只列事件，不做「该不该发生」的判定；写作软件普遍没有 cadence 概念。我们的差异是**需求差异**：长篇里作者自己会忘，模型更会忘 |

---

## 1. 形状（M15 `institution_cadences`）

一条记录 = **一个周期事件**。

| 列 | 说明 | 可空 |
|---|---|---|
| `name` | 制度/事件名（月例 / 巡夜 / 送账日），**UNIQUE** | 否 |
| `axis` | 判定轴：`chapter`（每 N 章）/ `story-day`（每 N 日） | 否（CHECK 限两值） |
| `interval` | 每 N 章 / 每 N 日（> 0） | 否 |
| `anchor_chapter` | **上次真的发生**在第几章 | ✅ 空 ⇒ `unknown` |
| `anchor_story_day` | **上次真的发生**在第几日 | ✅ |
| `fallback_interval_chapters` | 日序轴不可用时的按章降级间隔 | ✅ |
| `note` | 作者原话（发给谁、凭据是什么） | ✅ |
| `chapter_number` | 这条**制度**写在哪一章 | ✅ |
| `evidence` / `source` | 出处引文 / `author` | 引文可空 |

**锚是「上次真的发生」，不是起算点 t0**：用 t0 必须做模运算，中间漏写一轮会被悄悄吞掉，此后永久错位；
用「上次发生」则错位只影响一轮，作者更新一次锚就恢复。

**`chapter_number` 与 `anchor_chapter` 不是重复**：第 3 章登记了「月例」，但上次月例发生在第 12 章，这是最常见的情形。

## 2. 四态判定（`evaluateCadence`）

| 轴 | 条件 | status | basis / reason |
|---|---|---|---|
| chapter | 锚空 | `unknown` | none / anchor-missing |
| chapter | 锚 > 本章 | `unknown` | none / anchor-in-future |
| chapter | `elapsed ≥ 2N` | `overdue` | chapter |
| chapter | `N ≤ elapsed < 2N` | `due` | chapter |
| chapter | `elapsed < N` | `not_due` | chapter |
| story-day | 锚空 | **`unknown`（绝不降级）** | none / anchor-missing |
| story-day | 本章日序已知 | 日差套三档 | story-day |
| story-day | 本章日序不可知，且有降级轴 | 章差套三档 | chapter-fallback |
| story-day | 本章日序不可知，无降级轴 | `unknown` | none / story-day-missing |

- `overdue` = **至少漏了一整轮**（`elapsed ≥ 2N`），与 `due` 分开：作者要处理的不是「该不该写」而是「中间漏了」。
- `unknown` 与 `not_due` 在类型、渲染、测试三处分开（判据 DN 同型：缺失就说缺失，不折成「未到」）。
- **只判「该不该发生」，不判「应发多少」**（ADR-0022：派生数值不进上下文）。`note` 因此也不进提示词。

---

## 3. 注入口径

```
【制度（周期事件：到没到点）】
以下每条只回答「该不该发生」，不回答「应发多少」；没有锚的标「未知」，不得按章号推算。
- 月例 — 每10章一次；上次：第12章（作者登记）⇒ 本章：到期
- 送账日 — 每7日一次；上次：第12章（书中第9日，作者登记）⇒ 本章：未知（本章日序不可知）
- 巡夜 — 每3日一次；上次：第12章（书中第9日）⇒ 本章：到期（按章降级：每3章）
```

- 位置：`【关键物品】` 之后、`【本书规则】` 之前（顺序 facts → items → **cadences** → knowledge → abilities → rules）。
- 上限 6 条 / 480 字；排序 `due → overdue → unknown → not_due`（作者最该处理的排前面）。
- 「本章日序」取**最近一个日序已知的已定稿章**；新章本身尚未定稿，日序必然未知 —— 这正是 `unknown` 的合法来源。
- 空数组 ⇒ 整节不出现，材料块逐字节不变。

## 4. 验收

| 项 | 结果 |
|---|---|
| 登记「月例 / 每10章 / 上次第12章」→ 写第15章 / 第22章 / 第32章 | 未到 / 到期 / 逾期（至少漏了一轮） |
| 日序轴只填锚、不填降级轴 | 写任何章 ⇒ **未知（本章日序不可知）**，不出现「未到」 |
| 补填降级轴 | 出现「到期（按章降级：每3章）」 |
| 未登记 | 零字节；三条旧哈希不变 |
| 续写轮 | 同一份材料块 ⇒ 同样有 |
| 单元与集成 | 纯函数 10 · M15 lane 6 · 仓储 6 · 渲染并入 prewrite 18 · 面板 7 · 生成链集成 |

## 5. 不做（防下一轮发明）

- ❌ **数量/金额**：不判「该发三枚」、不算「累计欠了几轮」的金额。
- ❌ **历法换算**（2026-10-22 已否决）：不做「第几天 → 几月初一」，只用整数差。
- ❌ **复用 `resources.period`**：那边是口径说明，`prompt-builder.ts:318-330` 类型上只收 `name/unit`。
- ❌ **自动推进锚**：模型说「发了」不等于记账；锚必须作者更新（面板标红提示）。
- ❌ **结算历史表**：只保存当前锚。要历史先回答「谁消费这份历史」——W6 的死法就是从「留历史」开始的。
- ❌ **世界状态只读区**：要动 7 处，与「只读视图」一起另立项。
