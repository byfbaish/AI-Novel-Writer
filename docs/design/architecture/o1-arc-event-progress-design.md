## 0. 一句话结论

**不新增请求、不改批次大小、不改 cursor。**

弧起点那一步不用让模型"先排一张分章表"——**表可以由代码算**：把每个小弧的必发事件按 `→` 切成有序步（`E0…En`），再按「本章是弧内第几章」算一条**进度线**（本章水位允许落在哪个区间）。模型只要在既有的 `覆盖：` 行后面写一个 `#E3`。

于是三件事同时被锁住：

| 要保证的 | 靠什么 | 违反时的形态 |
|---|---|---|
| **事件完整** | 弧末水位必须 = 末项 | 有事件从未落地 |
| **不提前兑现** | 水位不得超过进度线上界 | 第 3 章就写掉落点 |
| **分配不失衡** | 水位连续多章不涨、或早早顶到末项 | 8 章写 1 件事 |

> ⚠️ **第三行原来是「不注水」，2026-10-18 作者裁定后改为「分配不失衡」。** 章数一个都不减；「水位不涨」不等于注水，它可能正是展开一章的机会。**「撑不起」是内容形状的问题，本稿只负责把它变成可见的失衡，不负责减章。** 配套药方见 [`synopsis-expansion-design.md`](synopsis-expansion-design.md)。

## 1. 用作者这个真实小弧走一遍

`M1-1/小弧:错位门牌`，覆盖第 **1–8 章**，`text` 原文：

> 程实被周德胜敲门催租，迷糊中想敷衍 → 程实对周德胜说"我马上到" → 清平里三户门牌与租客记忆错位 → 老陈记常客争论谁住几号 → 程实发现记事本写"今天不说谎"不算数 → 他确认第一句已消耗，巷里出现第一处对不上的门牌

**第一步：按 `→` 切成有序步，由代码编号（不要求模型写 ID）**

| 步 | 内容 | 类型 |
|---|---|---|
| `E0` | 程实被周德胜敲门催租，迷糊中想敷衍 | **起点**（弧的入口状态） |
| `E1` | 程实对周德胜说"我马上到" | 事件 |
| `E2` | 清平里三户门牌与租客记忆错位 | 事件 |
| `E3` | 老陈记常客争论谁住几号 | 事件 |
| `E4` | 程实发现记事本写"今天不说谎"不算数 | 事件 |
| `E5` | 他确认第一句已消耗，巷里出现第一处对不上的门牌 | **落点**（弧的出口状态） |

> 首项与末项**照样占编号**，只是标注类型。理由：P13 的弧位硬约束 5 已经规定「落点不得在弧的前段提前兑现」——它是一个**必须被兑现、且必须最后兑现**的步，不是装饰。给它编号，才能机械判定"有没有提前"。

**第二步：算进度线**（`N` = 弧长 8 章，`M` = 末步号 5）

```
第 k 章（弧内序号）末，水位应落在 [ floor(k·M/N) , ceil(k·M/N) ]
```

| 弧内第几章 | 全书章号 | 期望 | **允许水位** | 含义 |
|---|---|---|---|---|
| 1 | 1 | 0.63 | `0–1` | 至少写起点，最多到 E1 |
| 2 | 2 | 1.25 | `1–2` | |
| 3 | 3 | 1.88 | `1–2` | 可以是反应章（不推进） |
| 4 | 4 | 2.50 | `2–3` | |
| 5 | 5 | 3.13 | `3–4` | |
| 6 | 6 | 3.75 | `3–4` | 可以是反应章 |
| 7 | 7 | 4.38 | `4–5` | 不得越过 E5 之前冲顶 |
| 8 | 8 | 5.00 | `5–5` | **必须到落点** |

**这个公式的副作用正好是我们要的**：因为 `上界 − 下界 ≤ 1`，它天然写成「**每章最多推进一个事件步，允许 0 步**」。

- 8 章 / 5 步 ⇒ 有 3 章是「水位不涨」的**反应章**——它们不是注水，任务是展开上一步的后果（谁的反应、代价、误判）；
- ~~如果一个小弧只有 1 条事件（`M=1`）却给了 8 章 ⇒ 自动暴露「配额超载」~~
  **[已失效 2026-10-18]** 作者裁定**小弧章数是给定条件，不是估计值**（陈佩斯吃面：零时间跨度也能撑 25 分钟）。水位不涨的章**不是**配额超载的证据，而是展开的机会。`M` 小、`N` 大时，EV-3 的下界自动贴近 0，不会误报。见 [`synopsis-expansion-design.md`](synopsis-expansion-design.md)。

**第三步：模型只在 `覆盖：` 行报一个水位**

```markdown
## 第5章：谁把三号记成了四号

覆盖：M1-1/小弧:错位门牌#E3

（正文……）

收尾：……
```

`#E3` = 本小弧已推进到 E3（**累计语义，不是"本章兑现了 E3"**）。累计语义是关键：它同时容忍
**合并**（`E1+E2` 同一场景，水位直接跳两格吗？不行——上界只允许 +1，所以第 2 章报 E1、第 3 章报 E2，两章分别写这一场的前半/后半）与**拆分**（一件事跨两章，第 4、5 章都报 `#E2`）。

## 2. 为什么不做「弧起点先让模型排一张分章表」

这是上一轮提的方案，核完代码后**降级为不必要**，三个理由：

1. **多一次请求 = 多一次失败面**，而且它是**规划**而不是**产物**——失败了没有可恢复的中间态（`plot-outline-contract` 的 `recover` 只认章级产物）；
2. **承诺没有约束力**：模型先写一张漂亮的分章表，生成时照样可以偏离；真正起作用的是**每章都被对账**，而不是开头有一段声明；
3. **进度线是代码算的，天然一致**：同一份弧光，任何时候算出来的线都一样。而模型排的表，两次跑可能不一样。

> 判据 AO 的应用：**代码生成的合同 ≥ 模板 `systemSuffix` > `content`**。进度线属于第一档。

## 3. 三件套的落点

### 3.1 事件切分与编号（`arc-position.ts`）

`parseMinorArcs` 现在已经把 `text` 整串收下（`MINOR_ITEM_ZH` 的第三捕获组），**没有切 `→`**。新增：

```ts
export interface MinorEventStep {
  /** `E0` 起；末项是落点 */
  id: string
  index: number
  text: string
  kind: 'start' | 'event' | 'end'
}
export function splitMinorEvents(text: string): MinorEventStep[]
export function minorEventLine(parsed: ParsedArcStructure, chapter: number, total: number): string | null
```

切分规则（都按 `→`/`->`，并容忍 `⇒`）：

| 段数 | 解释 |
|---|---|
| 0 | 没有 `→` ⇒ 返回 `[]`（**不做**"整串算一步"的兜底——那会把一段没有事件的小弧伪装成有 1 条事件） |
| 1 | 只有一段 ⇒ 同样返回 `[]`（无法判断起点/落点，不猜） |
| ≥2 | 首项 `start`、末项 `end`、其余 `event` |

⚠️ 这一条与 `MINOR_CONTENT_FLOOR = 20` 的体检**互相独立**：`auditArcDensity` 查的是"有没有内容"，事件切分查的是"内容能不能分步"。两个都可能单独失败。

### 3.2 水位声明解析（`arc-node.ts`）

关键事实：`COVER_SEPARATOR = /[、,，;；]/u`，**不按 `/` 切**，也**不按 `#` 切** —— 所以 `M1-1/小弧:错位门牌#E3` 会被当成**一个完整字符串**收下，现有解析不会碎。

因此在 `splitCoverValue` 之后加一步**剥离后缀**：

```ts
export interface ChapterArcCover {
  chapterNumber: number
  title: string
  /** 结构位 ID（已剥离 #E 后缀）—— 语义不变，INV-1/2/3 完全不受影响 */
  covers: string[]
  /** 新增：本小弧推进到第几步。解析不到 `#E<n>` 时为空数组（fail-open） */
  progress: { nodeId: string; reached: number }[]
  coverLine: number | null
}
```

剥离是**非破坏性**的：`covers` 里的 ID 被还原成 `M1-1/小弧:错位门牌`，`auditArcCovers` 一行都不用改。

### 3.3 章级注入块（`arc-position.ts` + `architecture.command.ts`）

**这是「弧位块按章定位」的具体形态。** 现在是 `withProjectedArcGuide(guide, plan, total, from, to, lang)` —— 传批范围，不传章号。要加一个 `chapter` 参数，并追加一段：

```
【本章弧内定位】（系统按弧光与已写大纲算出，不是建议值）
- 所在小弧：M1-1/小弧:错位门牌（第 1–8 章；本章是第 5 章）
- 本小弧共 6 步：E0 起点 → E1 → E2 → E3 → E4 → E5 落点
- 已推进到：E2（由前 4 章的「覆盖：」声明推出）
- ★ 本章允许推进到：**E3–E4**（不得跳到 E5 —— 那是落点，最早第 7 章）
- 若本章是反应章、没有新事件发生，写 `#E2`（水位不动）是允许的；
  但**连续两章水位不动**必须确有值得展开的后果，否则说明这一段在注水。
```

要点：
- **`已推进到` 从上文 synopsis 解析**，不引入新存储 —— 账本就是大纲本身（与"两轨不通"一致）；
- 跨批时同样成立：`confirmedPrefix` 里已有前文全部 `覆盖：` 行，第 11 章能接着第 10 章的水位；
- 跨弧边界时水位从 `E0` 重新开始，块里要明说"本章是新小弧的第 1 章"。

### 3.4 模板

`synopsis` 的格式段里，`覆盖：` 那一行加一句：

```
- 覆盖：<结构位 ID>#E<步号>
  步号是小弧里「→」分隔的第几段（从 E0 起），表示本弧**已推进到**第几步，不是本章新发生的事。
  不写步号视为「未报进度」，不会报错，但这一章的进度无法被核对。
```

**⚠️ 红线 3**：改内置 `synopsis` 前必须先 `getPromptSource('synopsis')` 并检查作者覆盖目录，否则改了内置是白改。P13 刚改过同一模板的 `systemSuffix`，需要一并复核。

## 4. 四条不变量 + 一处已知上限

在 `auditArcCovers` 之外新增一组（**只报告，不阻断**，与 INV-3 同策略）：

| ID | 判据 | 报告形态 |
|---|---|---|
| **EV-1** | 终态完备：弧写完后，最大水位必须 = 末步号 | 「`M1-1/小弧:错位门牌` 已写满 8 章，但水位停在 E3 —— E4、E5 从未落地」 |
| **EV-2** | 不得超前：水位 ≤ 进度线上界 | 「第 3 章水位到 E4，进度线上界是 E2 —— 提前了 2 章兑现」 |
| **EV-3** | 不得拖后：水位 ≥ 进度线下界 | 「第 6 章水位仍是 E1，进度线下界是 E3 —— 连续 3 章没有推进」 |
| **EV-4** | 不得回退：水位单调不减 | 「第 5 章报 E2，第 4 章报 E3 —— 水位倒退」 |

**已知上限（必须明说）**：这套机制只核对**声明**，不核对**内容**。模型完全可以写 `#E4` 而正文只写了 E1。

不做语义比对的原因：那是纯语义判断，代码无解；而且会引入大量假阳性（同一事件的措辞可以完全不同）。缓解手段是**结构性**的：

1. EV-2 限制了一章最多涨一步 ⇒ 造假也不能一章冲到顶；
2. 落点（末步）必须与 `收尾：` 行一致 —— 收尾已经从本章正文取材（P13 的四硬约束），两处对不上就是线索；
3. 最终仍是人看。**这一层不要假装能自动化。**

### 4.1 EV-5：骨料容量的探测器 —— 大纲正文字数

2026-10-18 实测（作者 150 章项目，第一个小弧「刚醒的第一句」8 章）：

| 章 | 覆盖 | 大纲全文 | 正文（去覆盖/收尾行） |
|---|---|---|---|
| 1 | 小弧:刚醒的第一句 | 274 | ~250 |
| 2–8 | 同上 | 260–316 | 205–243 |
| 9–10 | 小弧:机器故障 | 306–354 | 249–290 |

`planningTargetInstruction` 的目标是 **600 字/章**，实际 **200–290**，连续 **10 章**都不到目标的 45%。

这不是模型偷懒——**是它没有内容可写**。而且第 1 章就把该小弧的 6 段事件**全部**写完了（拍门催租 → “我马上到” → 门牌错位 → 翻记事本 → 解释不通 → 老陈记吵架 → 写下“已用掉”），第 2–8 章写的是**下一个小弧「机器故障」的素材**（回声棚、鲁传福、“设备检修”），但覆盖行仍写着小弧 1 —— 这就是**越弧取材 + 提前兑现**，而且 INV-1/2/3 全绿（它们只查形式）。

⇒ ~~判据 BF：大纲正文字数持续显著低于目标，是「骨料不足」的直接症状。~~

> **[改归因 2026-10-18]** 探针保留，结论改了：「短」不是料不够，是**这一章没有被赋予一个可能失败的目标**（章级局面缺失）。字数本身没错，错的是把它读成"配额太多"。详见 [`synopsis-expansion-design.md`](synopsis-expansion-design.md) §2、§4.6。

**体检**：连续 ≥3 章正文 < `target × 0.6` ⇒ 报「这 N 章都没有可失败的目标」。不需要解析时间词、不需要语义判断，纯字数统计，可离线跑、可回放历史库。

> 这条与 EV-1..4 互补：EV 查「水位有没有按约定推进」，EV-5 查「这段水位本身是不是虚高」。两个都报，才分得清「模型不听话」和「大纲没给这一章任务」。

## 5. 与既有机制的关系

| 模块 | 关系 |
|---|---|
| `plot-outline-contract.ts` | **不动**（批次、cursor、重试、恢复、作者手改全不变）—— 本方案最大的好处 |
| INV-1/2/3（`arc-node.ts`） | **不动**。`covers` 剥离 `#E` 后语义不变 |
| `auditArcDensity`（P13） | 不动，但它与 EV-1..4 互补：P13 查"材料够不够"，本稿查"材料用没用掉" |
| `arc-budget-engine-design.md` §3.2「配额 × 骨料」 | **由本稿给出确定算法**：`M` 与 `N` 的比值直接体现为「有几章必然是反应章」；`M=1, N=8` 时 EV-3 会从第 2 章起连报到弧末 |
| 弧光覆盖对账 `summarizeArcCoverFindings` | 新增一组 `EV-*` 的汇总出口，同策略：`callbacks.log`，只报不拦 |

### 5.1 与伏笔（叙事线索）机制的关系 —— 现在零冲突，将来更好接

**核实结论：伏笔机制不读情节大纲。** 它的两个入口都是别的材料：

| 入口 | 实际输入 | 位置 |
|---|---|---|
| 线索**计划**候选 | `blueprint`（本章蓝图 JSON）+ `totalChapters` | `narrative-thread-generation-pure.ts:20-26`、`narrative-thread-candidate-generator.ts:26-31` |
| 线索**事件**候选 | `plan` + `drafted/finalized` 正文 | 同文件 `:28-36` |

⇒ 本稿只在 `synopsis` 的 `覆盖：` 行加 `#E<n>`、只在**大纲请求**里加「本章弧内定位」块，**不触碰蓝图与正文的任何输入**，因此伏笔机制**不受影响**。

**将来要接，这个改法反而给了它缺的东西。** 伏笔当前的结构性短板是**只有单章视角**（计划按章生成），拿不到「这条线该在第几章埋、第几章收」的跨章坐标。而进度线正好产出这个坐标：`E3` 落在哪几章，可以由 `[floor(k·M/N), ceil(k·M/N)]` 反推出**章号区间**。

⚠️ **但有一条必须守住**：**不要让伏笔去复用 `#E` 这个字段。** 如果伏笔把「埋/收」直接锚到 `#E3` 上，同一个标记就同时承载两个语义（弧事件进度 + 伏笔锚点），这正是 `arc-budget-engine-design.md` §4 里「一张表两个消费者」的问题，而且更糟——那是同一个**字段**两个语义，任何一侧改动都会静默改变另一侧的行为。
**正确做法**：伏笔只消费**由 `#E` 推导出的章号区间**（纯函数输出），不消费 `#E` 本身。

### 5.2 容错与向后兼容（实施时必须逐条满足）

作者明确要求这一层不能忘。五种失败模式，各自的姿态：

| # | 失败模式 | 姿态 | 依据 |
|---|---|---|---|
| F1 | 小弧 `text` 里没有 `→`（或只有一段） | `splitMinorEvents` 返回 `[]` ⇒ **整条 EV 链对该弧静默关闭**，只报一句「本小弧未切出事件步，进度不可核对」 | 与 `parseArcStructure` 失败姿态一致：宁可不判，不可错判 |
| F2 | 大纲里没写 `#E<n>`（旧大纲 / 模型漏写） | `progress: []` ⇒ 水位视为「未知」，**不视为 0**。EV-1..4 全部跳过，不报「停滞」 | 把「未知」当 0 会立刻误报倒退 |
| F3 | 作者手工改了大纲、删掉了 `#E` | 同上（F2）。**不阻塞保存、不弹窗、不清空历史水位** | 作者手改是最高优先级，代码不得与之竞争 |
| F4 | 水位倒退（`#E2` 出现在 `#E3` 之后） | 报 EV-4，但**以「已出现的最大水位」为准继续推进**，不中断后续章节的进度计算 | 一次手误不应让后面所有章都失去参照 |
| F5 | 跨批 / 跨小弧边界 | 跨批：水位从 `confirmedPrefix` 解析恢复，**不需要新存储**；跨小弧：新弧从 `E0` 重新起算，注入块明说「本章是新小弧的第 1 章」 | 账本 = 大纲本身 |

**总原则**：EV 系列与 INV-3 同策略——**只报告、不拦截、fail-open**。这不是偷懒，是 P12-1 已经确立的立场：结构对账的价值在于「让偏差异见」，一旦变成闸门，作者会为了过闸而改声明，信号反而失真。

## 6. 待裁（5 条，全部影响实施粒度）

| # | 问题 | 建议 |
|---|---|---|
| 1 | 首项与末项是否占编号（`E0`/`E5`） | **占**。否则"落点最后兑现"这条无法机械判定 |
| 2 | 水位写 `#E<n>` 是否接受（模板改动） | **接受**。这是唯一低成本的可核对信号；不写也不报错（fail-open） |
| 3 | 进度线容差用 `[floor, ceil]`（每章最多 +1） | **用**。副作用正好是"一章一件事"，不需要另立配额规则 |
| 4 | 「连续 2 章水位不动」是否单独报 | **暂不**。EV-3 已经覆盖"落后"，单独报会与它重叠（P13 已踩过"两条并列导致报告翻倍"） |
| 5 | 反应章是否要在注入块里显式点名 | **不点名**。点成"第 6 章写反应"会让节奏变成模板；只给上下界，让模型自己决定哪一章收气 |

## 7. 不做

1. **不改 `PLANNING_ACTION_CHAPTER_LIMIT`**（抬到 15 章能让"按弧圈范围"成立，但那是 A3 的事，且会放大单次失败面）；
2. **不做弧起点分章表**（§2）；
3. **不做正文语义比对**（§4 已知上限）；
4. **不做自动重写/自动补章**——EV-1 只报告；
5. **不给小弧强加"必须几章一个事件"的规则**（那会把节奏模板化，与判据 `AW` 的教训相反）。
