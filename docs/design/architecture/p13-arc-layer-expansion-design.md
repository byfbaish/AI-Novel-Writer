# P13 · 弧光分层的信息量递增（小弧从「标签」变成「材料」）

> 状态：✅ 已实施（2026-10-18，提交见文末「实施记录」）
> 分支 `dev_byf` · 关联：`p12-arc-node-anchoring-design.md`（结构位 ID / 覆盖声明）、`arc-nesting-design.md`（层级语义）、`arc-proportion-calibration.md`（篇幅比例，另一立项）

## 1. 问题：三层里有一层是**信息倒置**的

作者提出（2026-10-18）：

> 中弧1 + 中弧2 的信息量应该 > 大弧。理想情况下，小弧1 + 小弧2 + 小弧3 的信息量 > 中弧1，这样才做到了剧情扩张切分……我怀疑中间剧情提前兑现就是因为大纲拿到了不属于自己的内容导致的。

实测（作者 150 章弧光的真实数据，字数 = 去空白后计）：

| 层 | 覆盖 | 该层总字数 | **密度（字/章）** |
|---|---|---|---|
| 大弧 | 50 章 | ~177 | ~3.5 |
| 中弧 | 25 章 | 125–225 | **5.0–9.0** |
| 小弧 | 8–13 章 | 9–18（三个合起来） | **0.36–0.72** |

- 中弧 → 大弧：**递增** ✅（5–9 字/章 vs 3.5 字/章）
- 中弧 → 小弧：**坠落 10 倍** ❌（0.72 vs 5.0）

小弧层是整条链上唯一**信息量下降**的一层。三个小弧加起来 18 字，要撑 25 章大纲
（约 5,000 字）—— 放大比 1:280。

## 2. 机制：越层取材不是模型跑偏，是唯一可行的解

大纲模板对弧光做**分级裁剪**（`projectArcStructureText`）：本批覆盖到的中弧保留全字段，
同大弧内其他中弧降级为「标题 + 一句话定位」，其他大弧只留「接续理由」。

所以 ch1–10 的模型实际看到的是：

```
大弧一的 4 个字段（含「结束状态」全文）        ← 全量
中弧1 的 因果 / 时序 / 转折 + 三个小弧的名字  ← 全量
中弧2 的 目标（一句）                          ← 降级
【本批所处弧位】块：小弧 ID + 章号区间          ← 定位
```

它要在 25 章里写出「错位门牌」这一段，但本层只有 4 个字。可用的材料只有两处：

1. **中弧1 的「转折」**：`他发现漏洞物证同时被三家抢，围猎从偶然变系统` —— 这实际上是
   第 3 个小弧「三家人抢一张排班表」（第 17–25 章）的内容，却被当成整段 25 章的氛围；
2. **大弧一的「结束状态」**：`…鲁传福背上第一笔登记账，韩九畴拿到作息表并首次报价…`
   —— 那是第 50 章才成立的验收标准。

实测结果正是这两处：第 3、4 章写「鲁传福报信 / 让鲁传福拿着检修牌去堵门 / 横在门口说设备检修」，
把「鲁传福替他挡」这件事写在**第 35 章左右才该发生的位置**（中弧2 的尝试 1）。
审计一条都没报 —— 覆盖声明写的是 `M1-1/小弧:错位门牌`，落在 `[1,8]` 内，形式完全合规。

**判据 AY**：层级不是空间，是信息。每下一层的对应切片必须**严格多于**上一层；
某一层若只是上一层的同义改写（甚至更短），它就没有展开能力，下层必然越层取材。
**这不是提示词措辞问题，是结构问题。**

## 3. 修法

### 3.1 小弧：从「名称 + 章数」改为「起点 → 必发事件 → 落点」

```
- 小弧：
  - 错位门牌（约 8 章）：17 号换成 71 号 → 街坊说法不一 → 找周德胜对质 → 拿到排班单 → 手里有物证但不知能证明什么
  - 第一页报告（约 8 章）：观察科递来登记回执 → 沈砚上门问话 → 回执被拍照 → 被写进第一页报告
```

- 必发事件 3–5 条，约每 2 章一条；只写「谁做了什么 / 拿到了什么」，**不写因果推理**
  （因果已在中弧字段说过，重复等于零新增信息）；
- 落点状态 = 下一个小弧的起点状态；
- 明确禁止两种不合格形态：只有名字（零信息）、逐章流水（那是大纲的事）。

### 3.2 大弧：补「中弧推进」

原来的大弧三件套（接续理由 / 核心冲突 / 结束状态）**与类型无关**，于是「类型」是空标签：

- 实测大弧二声明 `B 目标驱动型`，却没有「目标」这一行；
- 而中弧1 的「目标：从被动拖到零点 → 学会以最小代价说谎…」正是大弧二该有的那个目标。
  **大弧缺字段，中弧越位替它说了。**

补一行「中弧推进」，与中弧的「因果」同构（双功能：接上一层 + 交代本层内部）：

```
- 中弧推进：因为 中弧1 的 <结果>，所以 中弧2 的 <动作>
```

并硬性要求：大弧「结束状态」的每一条都必须**点名由哪个中弧兑现**。
实测大弧一 4 条结束状态里有 2 条没有任何中弧承接。

### 3.3 模板：新增第 2.5 步「信息量递增自检」

把判据 AY 写进生成流程，含**反向禁止**（不要把更细一层的内容提前写进上层）：

> 上层越权写细节，下层就没有可展开的余地，只能靠猜 —— 而猜的方式就是去借下一层的材料，
> 剧情因此提前兑现。

### 3.4 弧位块：补两条防提前硬约束

```
4. 大弧的「结束状态」是本卷第 N 章才成立的验收标准，不是本批可用的材料
5. 一个小弧跨好几章：本批只落在前段时，不要提前兑现它的「落点状态」
```

第 4 条直接对着第 3、4 章那次越层取材（材料来源就是大弧结束状态）。

### 3.5 代码：`auditArcDensity` + 生成时体检

弧光生成完成后立即跑一次分层体检（`summarizeArcDensity`，只报告不拦截），四类发现：

| code | 判据 |
|---|---|
| `MAJOR_NO_MID_PROGRESSION` | 大弧缺「中弧推进」 |
| `MAJOR_END_STATE_UNASSIGNED` | 大弧「结束状态」没点名任何中弧 |
| `MINORS_NAMELESS` | 有 N/M 个小弧不足 20 字（只有名字） |
| `MINOR_LAYER_THINNER` | 小弧内容合计 ≤ 中弧自身字段合计 |

> `MINOR_LAYER_THINNER` 在 `MINORS_NAMELESS` 已触发时**不再重复报** —— 同一个病的两面，
> 并列只会让报告翻倍（实测 6 个中弧出 18 行），真信号被自己的回声淹没。

实测对旧弧光输出 12 行，全部是真信号（3 个大弧 × 3 条 + 6 个中弧 × 1 条）。

## 4. 解析器改动（含一个必须记住的坑）

支持小弧内容后，`parseArcStructure` 必须**在 `FIELD_LINE` 之前**拦下子项行：

```ts
const bullet = BULLET_LINE.exec(line)
if (bullet && mid && !MINOR_LIST_HEADER.test(bullet[1]!.trim())) { … }
```

⚠️ **`MINOR_LIST_HEADER` 那道闸不能省。** 旧的一行形态
`- 小弧：A（约 8 章）；B（约 9 章）` 也是列表项，若被当成单条小弧，贪婪的 `(.+?)` 会一路
吃到**最后一个**「（约 N 章）」，解析出 `小弧：【首夜敲门】（约 8 章）；【门缝纸条` 这样的
假条目 —— **一次丢掉整条中弧的全部小弧**，且不报错。实测 35 个测试里 10 个当场变红，
才发现是这一处。

这是「解析器静默丢数据」在本文件的第三例（前两例：`Σ` 挂在末条尾、末条带句号）。
**判据 AQ 的补充**：任何「逐条匹配、不匹配就 continue」的解析器，加新模式时必须先写
「新模式会不会把另一种合法模式整条吃掉」这条负向用例。

## 5. 向后兼容

- 旧弧光（小弧只有名字）照常解析：`ArcMinor.text` 为 `undefined`，渲染与区间折算不变；
- 一行形态 `小弧：A（约 8 章）；B（约 9 章）` 仍然可用，也允许每条后面直接跟「：内容」
  （内容里不得出现分号）；
- 投影 `projectArcStructureText` 原样保留本中弧的多行子项 —— 小弧内容随「弧光结构」
  一起进入本批 prompt，不需要在弧位块里再抄一遍。

## 6. 验证

- `tsc --noEmit` 0；
- `arc-position` 35、`arc-node` 26、`arc-cover-report` 11（新增 5 个体检用例）、
  `architecture.command` 全绿；模板契约 62 全绿；
- 真实弧光体检输出 12 行，逐条可点（见 §3.5）。

## 7. 未做 / 待议

- **篇幅比例不均等**（30:45:25 / 40:60 / 小弧差 ≤2 倍）→ 另立 `arc-proportion-calibration.md`，
  作者定为「仅次于当前任务优先级」，暂不实施；
- **转折的章号锚定**：转折继承整个中弧区间（`M1-1/转折 [1,25]`），所以「在第 4 章写掉第 35 章的字」
  在结构位层面依然合法。体检只能看密度，看不到「转折被提前」。下一步可考虑按中弧位置折算
  转折区间（如后 1/3），但那是**猜**，需要作者先定「转折通常落在中弧的哪一段」；
- 「章级」的扩展准则（每章大纲的字数/信息密度下限）尚未设阈值。
