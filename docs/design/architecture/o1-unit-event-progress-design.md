## 0. 一句话结论

旧稿把事件进度挂在**覆盖行**（`#E3`）上，而单元模式的每章输出合同**明令禁止输出「覆盖：」行**；所以改判的实质是：**进度不挂覆盖行，改为独立一行「进度：」，水位按章线性折算、只核声明不核内容、四条不变量全部 fail-open**。

## 2. 目标 / 非目标

**目标**
1. 每章能声明"截至本章末，本单元事件走到第几步"，且声明可被机检。
2. 四条不变量 EV-1..4 有明确判据（越界只提示、不阻断生成）。
3. 满足硬约束：**不新增模板变量、不改请求数、不改 cursor**；旧项目（无「进度：」行）行为与今天完全一致。

**非目标**
- 不判"内容是否真发生了这个事件"（旧稿已知上限，本稿保留并复述）。
- 不改单元模式的 5 段输出合同的其他部分。
- 不新增数据表、不给 `ChapterArcCover` 加字段。

## 3. 功能描述

### 3.1 事件编号规则（沿用，不新造）

1. 输入＝单元维度的事件串文本（单元 `arc` 字段，`CharacterRosterEntry` 之外的结构见 `src/shared/arc-position.ts:34-52`、`:459` 的单元范围）。
2. 切分调用既有 `splitMinorSteps(text)`（`src/shared/arc-position.ts:95-102`）：按 `→` 或 `->` 切，**首项＝起点、末项＝终点，段数 < 2 直接返回 `[]`**。
3. 步序号 `E0…E(M-1)`，`M` ＝ 切分后的段数（`M ≥ 2` 才存在水位）。
4. `M < 2` 或事件串为空 ⇒ **本单元不声明水位**（fail-open，不报错、不阻断）。

### 3.2 每章水位折算（沿用旧公式，分母改「已写章数」）

单元共 `M` 步；`N` ＝**该章落盘时单元内已写章数**（不是计划章数、不是 `maxChapters`），第 `k` 章（`1 ≤ k ≤ N`）末的水位必须落在：

```
[ floor(k·M / N), ceil(k·M / N) ]
```

三条由此推出的性质：
- 上界 − 下界 ≤ 1 ⇒ **每章最多推进 1 步，允许 0 步**（旧稿 `:65`）；
- 第 `N` 章末的上界 = `ceil(M) = M` ⇒ 终态必须走到最后一步（EV-1 的算术来源）；
- **只对已写章判定、未写章不预判**：写到第 6 章时 N=6，第 7–10 章还没有分母，不做任何告警。

**N 的冻结**：每章落盘时把当时的 `N`（＝已写章数）写进快照表（与 C1 同一新 lane，见 C1 稿 §4.5 的 `character_regeneration_snapshots`；O1 侧按"章→N、M、声明值"三列落一行）。这样：
- 作者把单元上界从 10 改到 8，**已写章的分母不变**，不会集体告警；
- 上界改动只影响之后新写的章；
- 事后复核时读得到"当时按几章算的"。

> 为什么不用 `maxChapters`：`src/shared/plot-outline-contract.ts:150-154` 的注释自己写着它是结构派生值、允许实际超出；把它当分母，任何上界改动都会把历史章的合法水位判成越界——那是**判据把工具的错误放大**，不是作者写错。

### 3.3 声明行落点（本稿的核心改动）

单元模式下，在既有 5 段之后追加**第 6 行独立声明**：

```
## 第12章：雨夜
定性：……
选择：……
（正文）
钩子：……
进度：E3
```

规则：
1. **不是覆盖行**，不带「覆盖：」字样，不出现 `V1-U1-Start`/`M1-1` 之类结构编号（合同 `:37` 明令）。
2. **累计语义**：`进度：E3` ＝ 截至本章末已到达第 3 步（含），不是"本章推进了 3 步"（沿用旧稿 `:71-84`）。
3. 位置固定在**最后一行**：放末尾可避免模型把它当正文素材续写；解析只认章末最后一个形如 `^进度：E(\d+)$` 的行。
4. 缺行 ⇒ 未声明（不推断、不按上一章顺延）。
5. 落在**渲染文本**（`synopsis-two-level-suffix.ts` 的 suffix 常量），**不动内置模板**——这是 `synopsisInputsFingerprint` 不变的前提。

**必须同笔改的三处（否则改坏已有合同）**：
1. `ZH_TWO_LEVEL_SUFFIX`（`src/services/prompts/synopsis-two-level-suffix.ts:29`）——该常量第 2 行原文写着「每章按以下顺序输出，**除这些行以外不要加任何说明行**、标签行或注释」（`:30`）。加第 6 行就必须在**同一处**把这句改成"＋「进度：」行"，并写明天度行是唯一允许的附加行。
2. `src/services/__tests__/synopsis-two-level-suffix.test.ts:27-34` 一带的逐字断言（禁「覆盖：」行、禁自造 ID、五行块保留）——加行后要补"含 `进度：E<n>`「且仍不含覆盖行"的断言。
3. `src/services/__tests__/prompt-language-contract.test.ts` 同一批逐字断言。
4. 英文版 `EN_TWO_LEVEL_SUFFIX`（`:135`）必须同步，否则 en-US 项目无该行、EV 判据恒不成立。

这四处是**同一笔提交**，不允许"先加行、断言之后补"——断言是这条改动的护栏，滞后就等于没有护栏。

### 3.4 四条不变量（EV-1..4）

| 编号 | 名称 | 判据（可机检） | 越界处理 |
|---|---|---|---|
| EV-1 | 终态完备 | 单元最后一章的声明 ＝ `M-1` | 提示「本单元事件未走完（E k / E M-1）」，不阻断 |
| EV-2 | 不超前 | 第 `k` 章声明 ≤ `ceil(k·M/N)` | 提示「第 k 章提前推进到 E x（上限 E y）」 |
| EV-3 | 不拖后 | 第 `k` 章声明 ≥ `floor(k·M/N)` | 提示「第 k 章水位落后（下限 E y）」 |
| EV-4 | 不回退 | 相邻两章声明满足 `s(k) ≥ s(k-1)` | 提示「第 k 章水位回退」 |

四条**只核声明、不核正文内容**：正文里到底有没有发生"签下契约"这件事，本稿不做判定（旧稿 `:192-198` 已知上限，保留）。全部 fail-open：**只出提示、不拒绝产出、不重跑**（沿用旧稿 F1–F5 `:250-262` 的处置风格）——因为进度是辅助线索，让它挡住正文等于用弱信号否决强产物。

**判定范围（关键）**：四条只对**已写章**生效，且分母用该章落盘时冻结的 `N`（§3.2）。未写章不预判、不告警；作者改单元上界不影响已写章的判定。EV-1 只在"单元最后一章"已写时才检查——单元没写完就说"终态不完备"是假告警。

### 3.5 注入侧：水位放哪一行（不新增模板变量）

- 复用既有单元位置块 `renderUnitArcPositionBlock`（`src/shared/arc-position.ts:1349-1395`）：该块已经在渲染「卷 / 单元 / 离开状态」与单元内事件内容，**在块尾追加一行纯文本**：`本单元事件进度：已到 E2 / 共 E4（下一章允许推进到 E3）`。
- 该行是**字符串拼接**，不引入新的模板占位符 ⇒ 满足约束①（判据 ⑪「不新增模板变量」）。
- 已声明过的章：读取上一章声明，算出"下一章允许区间"再注入（读时计算，不落第二份真相）。

### 3.6 请求数与 cursor（硬约束②、③）

- 请求数不变：水位不触发额外模型调用，仅改变一次既有请求的文本（沿用旧稿 `:13` 口径）。
- cursor 不变：不改批次大小、不改 `departure state` 推进方式、不改任何 checkpoint 指纹字段。
- 新增的只有：suffix 文本一行 + 解析函数一处 + 提示文案 → **零新请求、零新表、零新变量**。

## 4. 每条：产品上改了什么／体验差异／不选的最坏后果／代价

**O1-声明行（§3.3）**
- 改了什么：单元模式每章输出多一行「进度：E n」；解析出一份"章→水位"序列。
- 体验差异：作者第一次能回答"这个单元我写到第几个事件了"。
- 不选最坏后果：单元内的 4–6 个事件永远是黑箱，写到第 8 章时不知道还剩几个没落地 → 要么事件全挤在末章，要么被悄悄漏掉。
- 代价：小。一行 suffix 文本 + 一个正则 + 一个纯函数折算。

**O1-注入侧水位（§3.5）**
- 改了什么：既有单元位置块末尾多一行"已到 E2 / 共 E4"。
- 体验差异：模型每章都知道自己的位置，不必靠"上一章正文"猜。
- 不选最坏后果：模型每章重新分配事件，前松后紧，末章塞 3 个事件——这正是旧稿要解决的问题。
- 代价：小。但注意：**改的是渲染文本，改模板会让 `synopsisInputsFingerprint` 变化、既有大纲检查点全部失效**（`synopsis-two-level-suffix.ts:26-32`），这条红线要写进卡面。

**O1-不变量提示（§3.4）**
- 改了什么：编辑器里对 4 类越界给提示。
- 体验差异：错位能当场看见，而不是写完 10 章后。
- 不选最坏后果：错位沉默累积，作者要通读整卷才能发现"第 6 章的事件在第 3 章就写完了"。
- 代价：小。四条判据都是纯函数；风险是**误报**（模型声明与上层"重新分配"意图冲突时），故一律 fail-open + 文案写明"仅提示"。

## 6. 不做

1. 不挂覆盖行、不输出结构编号（合同 `synopsis-two-level-suffix.ts:37` 明令）。
2. 不判定"正文内容是否真发生了该事件"（只核声明）。
3. 不新增模板变量（判据 ⑪）、不改请求数、不改 cursor。
4. 不新增表、不给 `ChapterArcCover` 加字段（进度从正文行读，不落库）。
5. 不阻断生成：四条不变量全部 fail-open，只提示。

## 7. 开放问题（交项目总负责人核、主人裁定）

1. ~~N 从哪取~~ **已裁定（项目总负责人 2026-11-24）**：分母＝单元内**已写章数**，按章落盘时冻结进快照表；不用 `maxChapters`（是结构派生、允许超出的名义上界）。见 §3.2。
2. **`进度：` 行名**是否与 `定性：`/`选择：`/`钩子：`风格一致？备选「事件：」「水位：」。选「进度：」的理由：与"事件"区分（事件是内容，进度是位置），且不与 `钩子：` 语义混。
3. 旧项目里已有单元事件串、但已有章节无「进度：」行时，是否给"从第 k 章开始补水位"的一次性入口？本稿不做（缺行＝未声明），若作者需要，另开小卡。
4. 冻结表落地后，作者**把上界调小到已写章数以下**（如已写 8 章、上界改 5）时的 UI 提示：本稿只做"不影响已写章判定"，是否需要在编辑器顶部提示"上界小于已写章数"？倾向提示，但归 S2 卡面定。
