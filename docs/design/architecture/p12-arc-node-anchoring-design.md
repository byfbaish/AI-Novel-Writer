# P12 · 弧光结构位锚定（Arc Node Anchoring）

> 状态：待裁定
> 日期：2026-10-18
> 上级稿：[`arc-delivery-audit-assessment.md`](arc-delivery-audit-assessment.md)（审计结论）
> 相关：[`p11-plan-validity-and-fact-registry-design.md`](p11-plan-validity-and-fact-registry-design.md)（计划有效期）

## 1. 缘起

审计（`arc-delivery-audit-assessment.md`）的结论不是「弧光没兑现」，而是**超额兑现**：

| 弧光结构（中弧 2，约 27–52 章） | 大纲实际落点 | 差异 |
|---|---|---|
| 尝试 2：用记事本笔谈 | **第 2 章** | 提前约 25 章 |
| 转折：主动设计一句谎 → 成功 → 代价落在**鲁传福**头上 | **第 4 章**（借**庞大勇**的嘴） | 提前约 23 章，且承重角色被替换 |

弧光块里已经写着硬规则：「后续中弧的 goal / attempts / turning point **不得在本批出现**」（`arc-position.ts:230-240` 注入的【本批所处弧位】）。规则在，**但不可判**——因为「转折」在数据里只是一句散文。

结果：到第 27 章真正该兑现时，尝试 2 与转折都已被消耗过一遍，只剩「重复」或「失效」两个选择。

## 2. 为什么现在判不出来（不是缺规则，是缺身份）

关键事实：`arc-position.ts` **早就把弧光结构解析成树了**。

- `parseArcStructure()` 产出 `majors[] → mids[] → fields[]`（`ArcMid.fields` 是 `[字段名, 值]` 对）；
- `scaledBoundaries()` 已处理「弧光自报章数 ≠ 全书章数」的等比折算（实测 880 vs 845 也正确）。

但它的定位是**定位辅助**，注释写得很明白（`arc-position.ts:17-18`）：

> 本模块据弧光结构**推算**本批所处的弧位，并把"后续中弧不得提前执行"写成硬约束，随大纲提示词一起注入。它是**定位辅助**，不修改弧光本身。

于是树只被用来「告诉模型你在哪个弧」，**从来没有被用来做「谁消费了哪个结构位」的对账**。缺的不是解析能力，是**结构位的身份**与**消费记录**。

## 3. 关键发现：ID 可以纯函数派生，不需要重跑弧光

弧光文本的格式是**严格**的（实测 150 章项目，3,931 字符）：

```
## 大弧一：睁眼十秒（约 1–52 章）
### 中弧 2：三方上门（约 27–52 章）
- 尝试 2：利用"写下来的不算"，用记事本和纸条跟人笔谈…
- 转折：他第一次主动说了一句精心设计过的谎…
```

三个标题/字段正则都已存在并被实测验证（`MAJOR_HEADING` / `MID_HEADING` / `FIELD_LINE`）。因此结构位坐标可直接由**位置**派生：

| 层 | ID | 例 |
|---|---|---|
| 大弧 | `M<大弧序号>` | `M1` |
| 中弧 | `M<大弧>-<中弧>` | `M1-2` |
| 结构位 | `M<大弧>-<中弧>/<字段名>` | `M1-2/转折`、`M1-2/尝试 2` |

区间来自 `scaledBoundaries()` 的折算结果，**不新增任何数据**。

> **所以这不是「重跑弧光」的工程**：现有项目一行数据都不用改，ID 是派生量。这是本稿与 P11 最大的成本差异——P11 要加列，P12 只要加一个纯函数。

## 4. 设计

### 4.1 `arc-node.ts`：结构位的纯函数视图

```ts
export interface ArcNode {
  /** 稳定 ID：'M1' | 'M1-2' | 'M1-2/转折' */
  id: string
  kind: 'major' | 'mid' | 'field'
  /** 折算后的章号区间（含端点） */
  range: readonly [number, number]
  /** 字段名（kind === 'field' 时有值） */
  field?: string
  /** 该结构位的原文（供 prompt 与报告引用） */
  text: string
  /** 该结构位所属中弧的 name，供人读 */
  midName: string
}

export function listArcNodes(plan: string | null, totalChapters: number): ArcNode[]
export function arcNodesForChapter(nodes: readonly ArcNode[], chapterNumber: number): ArcNode[]
```

实现全部复用 `parseArcStructure` + `scaledBoundaries`，**不新增解析逻辑**（避免第二份真源，判据 K 的教训）。

### 4.2 `covers` 声明

**大纲侧**：章级条目增加一行（仍是 TEXT，正则解析，零 schema）：

```
## 第4章 借嘴
覆盖：M1-2/转折
```

**蓝图侧**：`structured_refs` 已是 JSON 列，增加一个键：

```jsonc
{ "space": "…", "timeRef": "…", "beat": "…", "arcNodes": ["M1-2/转折"] }
```

> 为什么不放 `key_events`：`keyEvents` 是**事件**（发生了什么），结构位是**意图归属**（这一章在兑现弧光的哪一格）。两者语义不同，混在一起会让 `freezeChapterGoals` 的审稿目标变味。

### 4.3 三个不变量（全部机械可判）

| 编号 | 规则 | 级别 | 触发场景 |
|---|---|---|---|
| **INV-1 越界** | `covers` 中每个结构位的 `range` 必须**包含**本章章号 | **error** | 第 4 章声明 `M1-2/转折`（区间 27–52）⇒ 提前使用 |
| **INV-2 重复消费** | 同一结构位不得被两章声明 | **error** | `M1-2/转折` 已在 ch4 消费，第 27 章再声明 ⇒ 超额兑现 |
| **INV-3 漏覆盖** | 本批章号覆盖到的中弧，必须至少有一章声明其某个结构位 | **warning** | 整批跳过某个中弧、无任何章节兑现它 |

**INV-2 是治本项**：它把结构位变成**一次性额度**，与 `keyEvents` 的`freezeChapterGoals` 同一思路——**没有额度概念的结构，一定会被提前花掉**。

`covers` 缺失时 fail-open（不判），但报告显示「本章未声明弧光归属」，覆盖度可统计。

### 4.4 「三条铁律」的唯一定义（判据 AI）

审计发现：该术语在 `characters_arch` 出现 2 次、`plot_structure_plan` 2 次，**从未定义**；唯一候选清单在蒋慕之「能力」里，而大纲自造了另一组，两者只有一条重合。

**修法**：`charactersArch` 步骤在「能力」段必须产出一份编号登记：

```
【规则登记】
R1 每天只有第一句假话成真，零点重置。
R2 写下来的不算；只要没出声，额度不消耗。
R3 …
```

后续各层只允许引用 `R1/R2/R3`，**禁止裸写「三条铁律」**。校验：模板层扫描到「铁律」且其后无 `R\d` ⇒ warning。

这一项比 ID 化更便宜（纯模板 + 一条正则），建议排在最前。

### 4.5 角色弧义务载体（分期，最贵）

现状：`keyEvents` 会被 `freezeChapterGoals` 冻成审稿核对目标（`ch1:keyEvents:N`），**角色弧没有任何对应冻结物**——以整段散文进 prompt，只能靠模型自觉。

建议（**二期**）：每章声明

```jsonc
"arcObligation": { "characterId": "cheng-shi", "fromStage": "A", "moveKind": "主动设计一次引导" }
```

由 `freezeChapterGoals` 一并冻结，审稿链核对「本章是否让该角色从 A 迈了一步」。**一期不做**——它需要角色 ID 体系先稳定。

## 5. 实测：这个项目会被拦在哪

用现有弧光（3,931 字符，150 章）+ 已生成大纲（ch1–5）代入：

| 章 | 声明 `covers`（应然） | INV-1 判定 | 说明 |
|---|---|---|---|
| ch1 | `M1-1/因果` | ✅ 区间 1–26 含 1 | 开篇 |
| ch2 | `M1-2/尝试 2` | ❌ **越界**（2 ∉ 27–52） | 正是「记事本笔谈」被提前 25 章 |
| ch3 | `M1-2/转折`？ | ❌ 越界 | 当前大纲把「搅格」当成转折的一半 |
| ch4 | `M1-2/转折` | ❌ **越界** | 与 ch3 争同一结构位 ⇒ 同时触发 INV-2 |

**审计时靠人工读出的三个结论，在这里变成三条机械报错。** 这就是本稿的价值：不是新增强约束，而是把已有的硬规则变成可执行的。

> 一个附带收益：INV-1/INV-2 能**反向校验弧光本身**。若某批章节按大纲情节确实必须提前使用某结构位，那说明**弧光的章号分配不现实**——这时该改的是弧光，而不是让正文背锅。这是审计稿第 5 条「两份弧光零交叉引用」之外的另一个结构信号。

## 6. 迁移与代价

| 项 | 结论 |
|---|---|
| 弧光数据 | **零改动**，ID 派生 |
| 大纲已有内容 | 可回填 `covers`（逐章人工 1 行，或先用模型批量标注再人工校） |
| 蓝图 | 新生成的才带 `arcNodes`；旧蓝图缺字段 ⇒ fail-open |
| 重跑 | **不需要**。这与 P11 的 `attacks` 一致：缺失即不判 |
| 中英对称 | `covers` 只在模板中作为「一行声明」出现，需同步 en-US 措辞 |

## 7. 不做

- ❌ 把弧光结构改成 JSON（会毁掉作者可读性与可编辑性，且需要重跑）
- ❌ 让代码判断「转折的文学质量」或「承重角色是否合适」（判据 ⑫：只判候选真正依赖的字段；角色替换留给审稿）
- ❌ 强制每章必须有 `covers`（fail-open，先观察覆盖率）
- ❌ 一期做角色弧义务载体
- ❌ 用 ID 重排弧光章节分配（那是创作决策，不是框架职责）

## 8. 验收

1. `listArcNodes` 对实测 150 章弧光产出 `3 大弧 / 6 中弧 / 若干字段`，区间累加等于 150（与 `scaledBoundaries` 一致）。
2. 用 ch1–5 已生成大纲代入，ch2 与 ch4 **必须**报 INV-1。
3. 构造一条「同一结构位两章声明」，**必须**报 INV-2。
4. `covers` 缺失时零报错（fail-open）。
5. `parseArcStructure` 的既有用例全绿（不回归弧位注入）。

## 10. 待裁定

1. `covers` 放在大纲章条目的**首行**还是**末行**？本稿建议首行（紧挨章标题，便于正则与人工核对）。
2. 已生成的 ch1–5 大纲是否**回填** `covers`？本稿建议回填——否则 INV-2 的「已消费」台账从第 6 章才开始，中间是空的。
3. INV-1 是 error（拒绝生成蓝图）还是 warning（仅报告）？本稿建议**首次上线 warning**，观察 1–2 批后转 error——避免一开始就把现有工作流卡死。
4. 「小弧」是否也纳入结构位？现解析器把 `小弧` 放进了 `SKIP_FIELDS`。本稿建议**暂不纳入**（小弧是排期刻度，不是可兑现位）。
