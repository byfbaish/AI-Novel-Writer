# P12 · 弧光结构位锚定（Arc Node Anchoring）

> 状态：待裁定
> 日期：2026-10-18
> 上级稿：[`arc-delivery-audit-assessment.md`](arc-delivery-audit-assessment.md)（审计结论）
> 相关：[`p11-plan-validity-and-fact-registry-design.md`](p11-plan-validity-and-fact-registry-design.md)（计划有效期）

## 1. 缘起

审计（`arc-delivery-audit-assessment.md`）的结论不是「弧光没兑现」，而是**超额兑现**：

| 弧光结构（中弧 2，约 27–52 章） | 大纲实际落点 | 差异 |
|---|---|---|
| 尝试 2：用记事本笔谈 | **第 2 章** | 提前约 25 章 |
| 转折：主动设计一句谎 → 成功 → 代价落在**鲁传福**头上 | **第 4 章**（借**庞大勇**的嘴） | 提前约 23 章，且承重角色被替换 |

弧光块里已经写着硬规则：「后续中弧的 goal / attempts / turning point **不得在本批出现**」（`arc-position.ts:230-240` 注入的【本批所处弧位】）。规则在，**但不可判**——因为「转折」在数据里只是一句散文。

结果：到第 27 章真正该兑现时，尝试 2 与转折都已被消耗过一遍，只剩「重复」或「失效」两个选择。

## 2. 为什么现在判不出来（不是缺规则，是缺身份）

关键事实：`arc-position.ts` **早就把弧光结构解析成树了**。

- `parseArcStructure()` 产出 `majors[] → mids[] → fields[]`（`ArcMid.fields` 是 `[字段名, 值]` 对）；
- `scaledBoundaries()` 已处理「弧光自报章数 ≠ 全书章数」的等比折算（实测 880 vs 845 也正确）。

但它的定位是**定位辅助**，注释写得很明白（`arc-position.ts:17-18`）：

> 本模块据弧光结构**推算**本批所处的弧位，并把"后续中弧不得提前执行"写成硬约束，随大纲提示词一起注入。它是**定位辅助**，不修改弧光本身。

于是树只被用来「告诉模型你在哪个弧」，**从来没有被用来做「谁消费了哪个结构位」的对账**。缺的不是解析能力，是**结构位的身份**与**消费记录**。

## 3. 关键发现：ID 可以纯函数派生，不需要重跑弧光

弧光文本的格式是**严格**的（实测 150 章项目，3,931 字符）：

```
## 大弧一：睁眼十秒（约 1–52 章）
### 中弧 2：三方上门（约 27–52 章）
- 尝试 2：利用"写下来的不算"，用记事本和纸条跟人笔谈…
- 转折：他第一次主动说了一句精心设计过的谎…
```

三个标题/字段正则都已存在并被实测验证（`MAJOR_HEADING` / `MID_HEADING` / `FIELD_LINE`）。因此结构位坐标可直接由**位置**派生：

| 层 | ID | 例 |
|---|---|---|
| 大弧 | `M<大弧序号>` | `M1` |
| 中弧 | `M<大弧>-<中弧>` | `M1-2` |
| 结构位 | `M<大弧>-<中弧>/<字段名>` | `M1-2/转折`、`M1-2/尝试 2` |

区间来自 `scaledBoundaries()` 的折算结果，**不新增任何数据**。

> **所以这不是「重跑弧光」的工程**：现有项目一行数据都不用改，ID 是派生量。这是本稿与 P11 最大的成本差异——P11 要加列，P12 只要加一个纯函数。

## 4. 设计

### 4.1 `arc-node.ts`：结构位的纯函数视图

```ts
export interface ArcNode {
  /** 稳定 ID：'M1' | 'M1-2' | 'M1-2/转折' */
  id: string
  kind: 'major' | 'mid' | 'field'
  /** 折算后的章号区间（含端点） */
  range: readonly [number, number]
  /** 字段名（kind === 'field' 时有值） */
  field?: string
  /** 该结构位的原文（供 prompt 与报告引用） */
  text: string
  /** 该结构位所属中弧的 name，供人读 */
  midName: string
}

export function listArcNodes(plan: string | null, totalChapters: number): ArcNode[]
export function arcNodesForChapter(nodes: readonly ArcNode[], chapterNumber: number): ArcNode[]
```

实现全部复用 `parseArcStructure` + `scaledBoundaries`，**不新增解析逻辑**（避免第二份真源，判据 K 的教训）。

### 4.2 `covers` 声明

**大纲侧**：章级条目增加一行（仍是 TEXT，正则解析，零 schema）：

```
## 第4章 借嘴
覆盖：M1-2/转折
```

**蓝图侧**：`structured_refs` 已是 JSON 列，增加一个键：

```jsonc
{ "space": "…", "timeRef": "…", "beat": "…", "arcNodes": ["M1-2/转折"] }
```

> 为什么不放 `key_events`：`keyEvents` 是**事件**（发生了什么），结构位是**意图归属**（这一章在兑现弧光的哪一格）。两者语义不同，混在一起会让 `freezeChapterGoals` 的审稿目标变味。

### 4.3 三个不变量（全部机械可判）

| 编号 | 规则 | 级别 | 触发场景 |
|---|---|---|---|
| **INV-1 越界** | `covers` 中每个结构位的 `range` 必须**包含**本章章号 | **error** | 第 4 章声明 `M1-1/小弧:第一页报告`（区间 9–16）⇒ 提前 5 章 |
| **INV-2 重复消费** | 同一**一次性**节点（转折）不得被两章声明 | **error** | `M1-2/转折` 已在 ch4 消费，第 27 章再声明 ⇒ 超额兑现 |
| **INV-3 漏覆盖** | 本批章号覆盖到的中弧，必须至少有一章声明其某个结构位 | **warning** | 整批跳过某个中弧、无任何章节兑现它 |

**⚠️ INV-2 的射程只有「转折」（P12-4 修正）**：原稿把「结构位」整体当作一次性额度，但小弧
天然跨 8–9 章（`M1-1/小弧:错位门牌 [1,8]`），那 8 章**都属于它**。按一次性额度实现会逼出
「第 1–7 章写『覆盖：无』、只有第 8 章写 ID」——实测 5 章里 4 章空白，声明失去信息量；
更糟的是第 3 章就声明（提前 5 章收束）**反而看不出问题**，因为「区间内 + 不重复」两条都满足。

修正后两类节点的语义分工：

| 节点 | 语义 | 跨章重复 | 判定 |
|---|---|---|---|
| 小弧 | **归属**（本章属于哪一段） | 正常，区间内每章都写 | 只吃 INV-1（越界即提前消耗） |
| 转折 | **一次性额度**（这一段只发生一次） | 违约 | 吃 INV-1 + INV-2 |

**归属语义的副产品正是「进度」信号**：若某章内容已推进到下一个小弧，模型会去声明
`第一页报告`，INV-1 当场报「提前 5 章」—— 不需要另设「小弧完成度」规则（P12-4 曾拟的
「声明落在区间前 1/3 就提示」因此撤销）。

`covers` 缺失时 fail-open（不判），但报告显示「本章未写「覆盖：」声明」，覆盖度可统计。

### 4.4 「三条铁律」的唯一定义（判据 AI）

**已定位到源头（2026-10-18）**：`project_core.golden_finger` 原文末尾写着

> 「…但**三条铁律**永不解除，每次引导都要付出更高代价。」

——**作者自己用了这个词，却从未列出这三条是什么**。于是角色图谱在蒋慕之的「能力」里造了一份（刚醒十几秒 / 最省事路径 / 第二句抢位），情节大纲又造了另一份（敷衍也算 / 第二句不算 / 零点重置），正文按第三份写。

这不是模板的错，也**不是改模板能治的**：模板只能要求「引用时带编号」，无法让一个源头就没有定义的东西变得有定义。所以修法分两层：

**第一层：数据订正（作者执行，立即生效）**

`golden_finger` 里其实已经写全了三条，只是没有编号。按原文可拆成：

```
【规则登记（R1–R3）】
R1 触发：只有他说出口、且自己明知是假的话，才消耗当天额度并可能成真；写下来、发出去、梦话、比划都不算。
R2 成真路径：成真永远走最省事、最符合现有社会规则的路径；旁人不会觉得异常，只留下细节对不上的漏洞。
R3 额度与失控：一天仅一次；第一句被当面揭穿，或出现第二句抢位，现实就会打架（不是失效，是现实本身开始互相矛盾）。
【进阶路线（不属于铁律）】从"用废话和沉默拖住第一句"，到"以最小代价说谎"，再到"主动制造细节矛盾、把成真引向少伤人的一侧"；每次引导的代价都比上一次更高，三条铁律永不解除。
```

**这三条正好能解释正文里所有的判定分歧**：
- R1 解释了第 2 章「只要没出声，额度就一点不往外漏」（写字条不算）；
- R2 解释了「门牌错位」为什么能成为观察科的证据（旁人只觉得细节对不上）；
- R3 解释了「第一句被揭穿」为什么不是「失效」而是「现实打架」。

**第二层：模板约束 —— 已撤回，不做**

2026-10-18 02:1x 曾给 `character_dynamics` / `plot_structure`（含全局覆盖版、中英双语）加过一条「承重术语只许引用，不许自造」，**作者当场否决并已全部回退**（全局覆盖版由 `*.bak-p12-*` 还原，内置与 en-US 已删净）。

撤回理由，三条都要记住：

1. **三条铁律是小说设定，不是模板问题。** 它的定义权在 `golden_finger`；模板读不到定义，是因为上游没写，不是因为模板缺一条禁令。
2. **约束引用方治不了缺定义的源头。** 在上游没有编号时禁止使用该术语，模型只有两个选择：不用（设定退化）或自造（同错）。R1–R3 依然不存在。
3. **覆盖版是跨项目资产，不能承载单本书的诊断。** 当时的插入段落还带了一行「★ 实测代价（2026-10-18）…」——把内部事故记录永久写进 prompt 正文，既污染提示词，也会污染后续所有新书。

⇒ **唯一该做的是第一层的数据订正**，模板保持原样。

### 4.5 角色弧义务载体（分期，最贵）

现状：`keyEvents` 会被 `freezeChapterGoals` 冻成审稿核对目标（`ch1:keyEvents:N`），**角色弧没有任何对应冻结物**——以整段散文进 prompt，只能靠模型自觉。

建议（**二期**）：每章声明

```jsonc
"arcObligation": { "characterId": "cheng-shi", "fromStage": "A", "moveKind": "主动设计一次引导" }
```

由 `freezeChapterGoals` 一并冻结，审稿链核对「本章是否让该角色从 A 迈了一步」。**一期不做**——它需要角色 ID 体系先稳定。

## 5. 实测：这个项目会被拦在哪

**已用真实数据跑通**（`listArcNodes`，150 章弧光 3,931 字符）：3 大弧 / 6 中弧 / **20 个结构位**。

| 大弧 | 中弧（ID / 区间） |
|---|---|
| M1 睁眼十秒 [1–52] | M1-1 门牌错位 [1–26]、M1-2 三方上门 [27–52] |
| M2 最小代价 [53–103] | M2-1 沉默的报价 [53–78]、M2-2 最省事的那条路 [79–103] |
| M3 档案下面的那一页 [104–150] | M3-1 上一位 [104–127]、M3-2 自担的那一句 [128–150] |

**第 1–5 章全部落在 `M1-1`，可合法兑现的结构位只有三格**：`M1-1/因果`、`M1-1/时序`、`M1-1/转折`。

| 章 | 大纲实际做的事 | 应声明 `covers` | INV-1 |
|---|---|---|---|
| ch1 | 开篇「我马上到」落地 | `M1-1/因果` | ✅ OK |
| ch2 | 记事本笔谈 | `M1-2/尝试 2` | ❌ 越界：该格属 27–52，**提前 25 章** |
| ch3 | 搅「晚九点那格」 | `M1-2/转折` | ❌ 越界：**提前 24 章** |
| ch4 | 借庞大勇的嘴放消息、代价落他头上 | `M1-2/转折` | ❌ 越界：**提前 23 章**，且与 ch3 争同一格 |
| ch5 | — | `M1-1/转折` | ✅（但实际内容未落地，见下） |

**这组数据把「地基不稳」说成了精确形态**：

- **该用的格子没用完**：`M1-1/转折` 的原意是「不说话比说谎更贵；鲁传福第一次替他挡电话、挨第一笔登记」——审计发现这一半至今没落地（鲁传福只有「桥的事别问」）。
- **不该用的格子提前花了**：`M1-2/尝试 2` 与 `M1-2/转折` 被 ch2/ch4 各消耗一次，到第 27 章无格可用。
- **ch4 是一次混用**：「借嘴转嫁代价」同时踩了 `M1-1/转折`（代价落在别人头上）与 `M1-2/转折`（主动设计一次引导）。没有 `covers` 就分不清它到底兑现了哪一格 —— 这正是 INV-2 要防的。

> 一个附带收益：INV-1/INV-2 能**反向校验弧光本身**。若某批章节按大纲情节确实必须提前使用某结构位，那说明**弧光的章号分配不现实**——这时该改的是弧光，而不是让正文背锅。这是审计稿第 5 条「两份弧光零交叉引用」之外的另一个结构信号。

## 6. 迁移与代价

| 项 | 结论 |
|---|---|
| 弧光数据 | **零改动**，ID 派生 |
| 大纲已有内容 | 可回填 `covers`（逐章人工 1 行，或先用模型批量标注再人工校） |
| 蓝图 | 新生成的才带 `arcNodes`；旧蓝图缺字段 ⇒ fail-open |
| 重跑 | **不需要**。这与 P11 的 `attacks` 一致：缺失即不判 |
| 中英对称 | `covers` 只在模板中作为「一行声明」出现，需同步 en-US 措辞 |

## 7. 不做

- ❌ 把弧光结构改成 JSON（会毁掉作者可读性与可编辑性，且需要重跑）
- ❌ 让代码判断「转折的文学质量」或「承重角色是否合适」（判据 ⑫：只判候选真正依赖的字段；角色替换留给审稿）
- ❌ 强制每章必须有 `covers`（fail-open，先观察覆盖率）
- ❌ 一期做角色弧义务载体
- ❌ 用 ID 重排弧光章节分配（那是创作决策，不是框架职责）

## 8. 验收

1. `listArcNodes` 对实测 150 章弧光产出 `3 大弧 / 6 中弧 / 若干字段`，区间累加等于 150（与 `scaledBoundaries` 一致）。
2. 用 ch1–5 已生成大纲代入，ch2 与 ch4 **必须**报 INV-1。
3. 构造一条「同一结构位两章声明」，**必须**报 INV-2。
4. `covers` 缺失时零报错（fail-open）。
5. `parseArcStructure` 的既有用例全绿（不回归弧位注入）。

## 实施记录

### 2026-10-18 · P12-4（小弧改「归属」语义；报告不再互相遮蔽）—— 已实施

**作者原话**：「你说小弧也不是『第一章的事』，是『第 1–8 章的事』，那不就应该覆盖第一吗？但是第一章无覆盖啊？」

**这是设计缺陷，不是作者看错**。P12-3 把「覆盖」实现成**结清**（只有收束那一章才写 ID），
于是 5 章里 4 章写「覆盖：无」；而真正提前 5 章收束的第 3 章反而全绿。改成**归属**：

| 节点 | 语义 | 重复声明 |
|---|---|---|
| 小弧 | 本章属于哪一段，就写哪一段 | **正常**（区间内每章都写） |
| 转折 | 一次性额度，只有真正发生的那一章写 | 违约（INV-2） |

- `arc-node.ts`：新增 `isOneShotArcNode`（只认转折）；`auditArcCovers` 的 INV-2 改为只对
  一次性节点生效；`seen` 记首次章号（小弧会被多次写入）。
- `arc-position.ts`：新增 `minorRanges`（中弧内折算，与 `listArcNodes` **共用**，防两处漂移）；
  `ArcSpan.endMidRange`；可声明清单改为**逐条带区间**输出：
