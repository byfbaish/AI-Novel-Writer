## 1. 它回答什么问题

「这条**本书级**能力能做什么、要付什么代价、什么情况下会被破，这一章能不能用。」

今天这三个问题的答案只活在 `project_core.golden_finger` 的一段自由文本里，而那段文本**从不进正文请求**：
全仓只有 `architecture.command.ts` 调 `withGoldenFinger`，正文链的 `novelConfigFacts` 排除清单**含 `goldenFinger`**。
现有【本书规则】从世界观第 1 维抽 ≤3 条，实测三库都恰好 8 条用满，能力规则挤不进去。

所以这一格不是「再做一个设定库」，而是补上**唯一没有通道的那一半**：一句能在 640 字内被读到、
带「能不能用」判定、且明确说「要付什么」的限制句。

## 2. 形状（13 列）

```sql
CREATE TABLE power_abilities (
  ability_id     TEXT PRIMARY KEY,
  name           TEXT NOT NULL UNIQUE,
  form           TEXT,
  hard_limit     TEXT,
  weakness       TEXT,
  cost_note      TEXT,
  stage_chapter  INTEGER CHECK(stage_chapter IS NULL OR stage_chapter > 0),
  stage_note     TEXT,
  evidence       TEXT,
  evidence_scope TEXT CHECK(evidence_scope IS NULL OR evidence_scope IN ('golden-finger','worldbuilding','chapter')),
  source         TEXT NOT NULL,
  created_at     TEXT,
  updated_at     TEXT
);
CREATE INDEX idx_power_abilities_stage ON power_abilities(stage_chapter);
```

| 列 | 为什么是它 |
|---|---|
| `hard_limit` | 硬限制：永远做不到什么 / 触发的必要前提。三本取样书都写满了，只是写在自由文本里 |
| `weakness` | 弱点：敌人能怎么破。取样里这是**最好填**的一类（「死破绽」「最大的缝」「打架三条件」） |
| `cost_note` | 代价：用一次要付什么。内容上与 `golden_finger` 重复，但**注入链上不重复** —— 那段话今天从未进过正文请求 |
| `form` | 形态短语。**不设 CHECK**：18 个实例里 3 个横跨两到三类，定枚举会替作者切一个切不开的东西 |
| `stage_chapter` / `stage_note` | 从第几章起可用 / 阶段名（开局·中期·后期、境界名）。真实数据里章号几乎永远为空 |
| `evidence` / `evidence_scope` | 逐字引文 + 出处域。**没有出处域就只能伪造章号**（见 §3） |
| `source` | 本期只有 `author`；留 `derived` 是为了以后从定稿抽取时不改表 |

**刻意没有 `character_id`**：角色技能的家是 `characters.abilities`，且已随角色卡进正文
（`generate-draft.command.ts:2171`）。再登一份就是第二套账。代价必须记住：配角「忘了自己有这个技能」
这类 findings **仍然查不出来**（那是角色卡质量，另一期）。

**表名不叫 `abilities`**：`characters.abilities` 是真实存在的列名。同名不同义会让代码搜索、迁移 verify、
便携字段白名单互相冒充，也会让作者以为「角色卡里填过 = 本书规则登记过了」。

## 3. `evidence_scope` 为什么必须有

取样三本书的能力出处 **100% 是设定文本**（`golden_finger` / 世界观第 1 维），**0% 是章号**
（`第[一二三…\d]{1,4}章` 在三库 `golden_finger` + 第 1 维里命中 **0** 次）。

没有这一列，UI 与渲染层只有两种做法：

1. 一律写「来源第 N 章」—— 但 N 不存在，只能编。那是**伪造章号**，与判据 DN 同型，比不写更糟；
2. 一律写「作者登记」—— 丢掉了「这句话出自世界观第 1 维」这条可回查信息。

三档的语义：

| 取值 | 渲染 | 约束 |
|---|---|---|
| `chapter` | `来源第 N 章` | **只有这一档允许出现「来源第 N 章」** |
| `golden-finger` | `作者登记 + 出处：金手指原文` | 渲染行里不得出现任何章号 |
| `worldbuilding` | `作者登记 + 出处：世界观` | 同上 |
| `NULL` | `作者登记` | 不猜出处域 |

`form` 不设 CHECK、`evidence_scope` 设 CHECK，两者不矛盾：前者是**创作自由度**（混合形态真实存在），
后者是**数据完整性**（写错一个值，渲染层只能猜该不该印章号）。

**「不得出现任何章号」也约束阶段列**：`golden-finger` / `worldbuilding` 两档即便作者手填了
`stage_chapter`，行内也只写「作者登记」—— `stage_chapter` 仍是章号，印出来就违反了 G4a 条件 1。
阶段章号**照常参与 `ahead` 过滤**（未来行根本不进本节），只是不显示；阶段名留在登记页
（`stage_note` 与制度 `note`、知情 `evidence` 同一原则：本页可见、不进提示词）。

**已知限制（形状决定，不是实现偷懒）**：13 列里没有单独的「引文章号」列。`chapter` 档的 N 只能取
`stage_chapter`。若作者标了 `chapter` 却没填章号，渲染退回「出处：作者登记」，**绝不编造**。
要彻底分开，得再加一列（改形状），本期不做。

## 4. 三态

| 态 | 条件 | 注入 | 行内写法 |
|---|---|---|---|
| `active` | `stage_chapter ≤ 本章` | ✅ | `自第 N 章起`（**仅 `chapter` / 未标出处域时**；另两档见 §3 末段，不印章号） |
| `ahead` | `stage_chapter > 本章` | ❌ **一律不注入** | （不会出现在节里） |
| `undated` | `stage_chapter IS NULL` | ✅ | `作者登记，未标章号` |

**`undated` 是主路径**：三库「第 N 章」命中 0 次，阶段一律用「开局 / 中期 / 后期」或境界名表达。
所以这一列在真实项目里会长期为空，`ahead` 只是「作者手填章号才有」的开关。

**本期不宣称「解决了剧透」**：过滤逻辑是真的（`readAbilities` 与 `renderAbilitySection` 各滤一次，
有构造数据用例证明未来行没进上下文），但真实项目里不会自然产生 `ahead` 行。它只提供出口。

`undated` 绝不折算成「第 0 章」或「当前章」——未标章号就是未标（判据 DN 同型）。

## 5. 空字段整段省略（对判据 DN 的**刻意例外**）

`hard_limit` / `weakness` / `cost_note` 哪一段为空就**整段不出现**，**不写「未登记」**。

理由：注入文本里的「限制未登记」会被模型读成「**没有**限制」—— 那比不写更糟。缺失提示只放在
登记页（黄条），不进提示词；与制度槽 `note`、知情关系 `evidence` 不进提示词同一原则。

这是对判据 DN「缺失就说缺失」的**唯一刻意例外**，因此：

- 纯函数测试钉「空字段不产生任何字节」（连冒号都不出现）；
- 设计文档写明理由（本节）；
- 面板有黄条，但黄条文案**不进入提交载荷**（有浏览器用例断言）。

## 6. 注入口径

- **位置**：`【知情】` 之后、`【本书规则】` 之前。顺序：事实 → 物品 → 制度 → 知情 → **能力** → 规则。
  能力是「能做什么」，规则是「什么不许做」，约束条款收尾最不易被忽略。
- **上限**：**5 条 / 640 字**；装不下**整条丢弃**，不截半行（截断的限制句会变成一条更宽松的规则）。
- **排序**：`active` 与 `undated` 混排，统一按 `name` **码元序**（`<` 比较，不用 `localeCompare`）。
  不按强度（需派生数值，ADR-0022）、不按出场角色（本表没有 `character_id`）、不按解锁先后（`undated` 无章号可比）。
- **空数组 ⇒ 整节不出现**，材料块逐字节不变（`context-entry-parity` 的五条旧哈希一字未改，
  本期只新增 `{abilities}` 与「六节齐备」两条）。

渲染样例（`undated` 主路径，逐字）：

```
【能力（本书的能力规则：能做什么、要付什么、什么情况下会被破）】
以下是作者登记的能力规则；未登记的用法不在本节范围内，不得据此推定无限制。
- 噬魂推演录（规则·功法·天赋混合；作者登记，未标章号）：硬限制——必须击杀仇敌后方可掠夺功法记忆，每日只能承受一次超越境界的灵力注入；代价——每次吞噬向天道发送一次坐标，雷劫难度随之上升；弱点——蚀毒未清时强注灵力即经脉爆裂
```

## 7. 不做（防下一轮发明）

- ❌ **次数 / 冷却 / 积分 / 强度等级 / 技能树**（ADR-0022）：派生数值会进正文，而那个数字从来没被作者确认过。
  数据里也没有「已用 3 次 / 还剩 2 次」的账；「一天一次」本身就是 `hard_limit` 的原文，不需要我们替作者数。
- ❌ **角色技能登记**：`characters.abilities` 是它的家，已进正文。
- ❌ **自动抽取**：不从 `golden_finger` 或定稿正文里猜「硬限制是什么」。模型的复述不算作者事实。
- ❌ **`form` 的 CHECK / 把混合体拆成多行**：混合是真实形态，拆行会把「这条能力怎么用」断成两半。
- ❌ **给本表加 `character_id`**：加了就与角色卡变成两份账。
- ❌ **在本表存金手指全文**：那是 `golden_finger` 的位置，本表只存摘出来的那一句 + 引文出处。
- ❌ **用本表替换【本书规则】**：两者不互相引用、不互斥。

## 8. 已知限制

1. **样本小**：修仙本 4 章、都市本 A 3 章、都市本 B 0 章。能证明的是**通道事实**（`golden_finger` 不进正文），
   不是效果事实（代价是否真的因此写得更好）。
2. **`stage_chapter` 在真实项目里会长期为空**：`ahead` 不会自然出现；本期不宣称解决剧透。
3. **`chapter` 档没有独立章号列**：只能借 `stage_chapter`；未填则退回「作者登记」。
4. **`cost_note` 与 `resources.cost_note` 同名不同义**：后者是「这种资源换进来要花什么」，
   这里是「用一次这个能力要付什么」。不改名（会与计划 §1.3 冲突），迁移注释与面板里已写明。
5. **`characters.abilities` 的质量不可控**：26/29 条是 `generated`，主角那条最薄（35 字）。
   本表不接管它，也不能替它兜底。
6. **未验证真实注入效果**：本期没有跑生成、没有做 A/B。是否降低「触发条件漂移」，要等实机观察。
7. **`golden_finger` 仍不进正文**：本表只补作者登记的那几句。彻底补需要让金手指进材料块（另一期，
   还要考虑 640 字预算）。
