# P1-1 四格 × 世界观抽取：为什么现在抽不出来，以及该抽哪一格

> 2026-10-26 · 触发：作者把一份**写得齐备**的世界观（制度 / 能力 / 知情 / 空间全有）生成完，发现
> 世界状态的「制度 / 能力 / 知情」三格是空的，且找不到任何「从世界观抽取」的动作。
> 本文回答三件事：① 这是漏做还是设计如此；② 四格该不该抽；③ 抽的话写进哪条通道。
>
> 结论先行：**三格都只有「作者登记」一条写入路径**，`source='derived'` 是留给「从**定稿正文**抽取」
> 的占位（并已明确「另立项」）。所以「世界观写得清清楚楚却不抽」不是 bug —— 是**来源轴不同**：
> 三格的键挂在「定稿章号 + 逐字引文」上，世界观没有章号，挂不上。
> 但**能力**这一格的权威来源确实在世界观第 1 维（设计稿自己承认），它才是该抽的那一格。

---

## 1. 行业里叫什么（先定名，再定方案）

| 我们内部的叫法 | 行业标准名 | 说明 |
|---|---|---|
| 四格（物品 / 制度 / 知情 / 能力） | **continuity tracking**（连续性追踪） | 宿体就是 **story bible**。四类事实：possession / periodic obligation / who-knows-what / power rules |
| 「从已有文本抽出结构化条目」 | **codex / lore extraction**（设定库抽取） | NovelAI Lorebook、Sudowrite Story Bible、Campfire Encyclopedia 都做这件事 |
| 「谁知道哪条事实」 | **knowledge state / information asymmetry** | 键是「事实 × 人物 × 章」 |
| 「谁在捂哪层真相」 | **secrets / dramatic irony 追踪** | 与上一条**不是同一件事**：秘密没有「第几章得知」，只有「几个人知道」 |

行业产品做 codex 抽取时**一律是 extraction → proposal → accept**，不静默写。理由和本项目
「模型的复述不算作者事实」（`p1-1-power-ability-design.md` F 段）是同一条：抽取的产物是**候选**，
不是 canon。这一条决定了本稿方案的形状（§5），也决定「一键抽完自动入库」永远不该做。

## 2. 现状：三条可核对的事实

### 2.1 写入通道只有手填

三个登记面板都是纯 CRUD 表单，全文 grep 不到「抽取 / 生成 / 导入 / 智能」：

- `src/components/editor/CadenceRegistryPanel.tsx`（制度）
- `src/components/editor/KnowledgeRegistryPanel.tsx`（知情）
- `src/components/editor/AbilityRegistryPanel.tsx`（能力）

三处的类型注释写的是同一句：**「来源：本期只有作者登记；留 `derived` 是为了以后从定稿抽取时不改表」**
（`institution-cadence.ts:59`、`power-ability.ts:52`、`knowledge-state.ts` 同段）。

### 2.2 设计稿三处明文写「不做自动抽取」，理由各不相同

| 出处 | 原文要点 | 针对的来源 |
|---|---|---|
| `p1-1-key-items-design.md:112` | 「抽取要解决幂等 / 中断 / 引文定位（W6b 那一整套），另立项」 | 定稿正文 |
| `p1-1-knowledge-state-design.md:172` | 「谁在第几章知道了什么仍由作者登记；**模型说的不算数**」 | 定稿正文 |
| `p1-1-power-ability-design.md:153` | 「不从 `golden_finger` 或定稿正文里猜『硬限制是什么』」 | 金手指 / 定稿正文 |

**注意三处否的都是「从正文猜」，没有一处论证过「从已采纳的世界观抽」。**
这是本稿要补的空白：世界观是另一条来源轴，代价与风险完全不同。

### 2.3 入口其实有，缺的是「工序」不是「页面」

`ProjectTree.tsx` 在「世界观」组里挂了五个登记入口：资源 / 关键物品 / 制度 / 知情 / 能力
（`openBuiltinEditor(...)`，约 :414–:520）。所以「甚至没有抽取的入口」准确表述是：
**有登记页，没有抽取这道工序** —— 作者必须自己把世界观里的句子抄进表单。

## 3. 四道坎：逐格说明「为什么抽不进来」

### 3.1 能力 —— 该抽，卡在预算

- 世界观第 1 维**确实**写了硬限制、代价、体系漏洞（本项目的模板用 ★ 强制：等级表四列必须可判、漏洞必须能被具体利用）。
- 但正文请求里能带的世界观规则只有 **8 条 / 640 字**，且是**轮转分配**：四维各取 2 条
  （`worldbuilding-rules.ts:51` `WORLD_RULES_MAX_ITEMS=8`，:222 轮转）。第 1 维只有 **2 个名额**。
- 能力格设计稿 F5 抽样三本书的结论：**能力出处 100% 是设定文本，0% 是章号**。

⇒ 这一格是**纯抽取红利**：来源轴对得上（世界观 → 本书级规则），价值正是「预算挤不进去的那几条」。

### 3.2 制度 —— 只能抽一半，锚抽不出来

- 世界观第 5 维有**完整周期性事件**（本项目实测那份：点卯 / 开井 / 收工 / 晚课 / 宵禁 / 初一发灵配 / 初一小考 / 十五巡碑坪 / 三十结算 / 季末初八大考 / 十二月三十荐额评定）。
- 但 `institution_cadences` 的判定锚是「**上一次真的发生**在哪一章 / 哪一日」（`institution-cadence.ts:10-24`）。
  世界观没有章号，抽出来的 6 条**全部是 `unknown / anchor-missing`** —— 写完不产生任何判定。
- 也就是说：抽世界观能省掉「名字 + 间隔 + 轴」三项输入，**省不掉最关键的那一项**。

⇒ 有价值但价值有限，且必须诚实标注「锚未定 ⇒ 本章不判」，否则会变成「登记了却不生效」的困惑源。

### 3.3 知情 —— 不是抽取缺失，是**宿体不符**

这是三格里最容易被误判的一格：

- M16 的键是「**事实所在章号 + 逐字引文**」（`knowledge-state.ts` 头部「引用键为什么不用 `continuityStableFactKey`」）。它挂的是**定稿连续性投影里的某条事实**。
- 作者在世界观第 3 维写的「柳长老捂试药残篇 / 周账房捂引纹钉 / 宗主捂九宗大账」是**秘密 + 谁知道**，
  没有章号，也没有「某条定稿事实」可挂。
- 行业里这是 **secrets**（谁隐瞒什么、几个人知道、什么时候会穿），不是 knowledge state（谁在哪一章得知）。
  现有 M16 **装不下**它，抽也抽不进去 —— 缺的是**一个秘密宿体**，不是一个抽取器。

⇒ 这条要单独立项（秘密表：秘密 / 知情者集合 / 被骗者集合 / 揭穿章），并且它比知情格更贴「爽点与悬念」的实际需求。

### 3.4 物品 —— 不该从世界观抽

M14 记的是「**在谁手里**」的换手关系（`p1-1-key-items-design.md`「三件套 + 出处」）。
世界观里的「裂灵石是纹核」是**道具设定**，不是持有关系；从设定抽物品归属等于把静态设定当动态事实。
⇒ 保持现状（作者登记 + 定稿后处理候选）。

## 4. 失败形态归类（为什么不能「抽完直接写库」）

| 形态 | 后果 | 本项目已有的同型教训 |
|---|---|---|
| 抽取即写库 | 第二套事实（模型复述被当成作者确认） | W6：派生数值进上下文被当既定事实（ADR-0022） |
| 抽取只进 prompt、不入库 | 与「已采纳的结构化条目」抢 480 / 640 字预算 | 【制度】480 字 / 知情 640 字 / 能力节预算 |
| 抽不出来时「补齐」 | 编造限制（尤其能力格：写「未登记」会被读成「无限制」，`power-ability.ts:16-21` 已判为刻意例外） | 判据 DN 的例外条款 |
| 静默覆盖同名条目 | 作者手填的那条被模型候选顶掉 | 判据 AO/DG：覆盖版静默遮蔽 |

## 5. 可行方案：抽取 → 草稿 → 逐条采纳

**形状**：一个 `extract-registry-drafts` 工序（不是「一键生成登记」），产物是**未入库的候选草稿**。

```
已采纳的世界观正文
   ├─ 确定性抽取（优先，用模板 ★ 强制结构）
   │    · 第 1 维等级表（四列固定）→ 能力候选：等级名 / 代价 / 卡点
   │    · 第 5 维「周期性事件」段    → 制度候选：名称 / 间隔 / 轴（锚留空）
   └─ LLM 抽取（兜底，只处理确定性抽不到的语义句）
        · 必须带逐字引文（四格都有 evidence 列，天然可核对）
        · 引文必须能在世界观原文里精确命中，否则丢弃该条（不猜）
                    ↓
         候选草稿（内存 / 临时态，不写库、不进 prompt）
                    ↓
         作者逐条采纳 / 编辑 / 丢弃（复用 ThreeWayMerge + diff 面）
                    ↓
              写入 registry（source='derived' + evidence 原文）
```

要点：

1. **不新增写入通道**：采纳仍走 `db:*-upsert`，只是在它前面加一道「候选」态。
   这样 `config-registry-write-paths-assessment.md` 里「五条写入路径只有两条带确认面」的那条缺口不会被扩大。
2. **确定性优先**：等级表、周期性事件段都是模板 ★ 强制结构（`builtin-prompt-templates.ts`
   第 1 维「等级阶梯 · 可判定」、第 5 维「周期性事件」）。能用表格行解析的就不调模型 —— 省 token、可复现、可单测。
3. **引文校验**：抽出的 `evidence` 必须在原文里精确出现（trim 后 `includes`），否则整条丢弃。
   这一条同时挡住「模型改写」和「跨段拼接」。
4. **同名冲突不覆盖**：已存在同名的，候选标 `conflict`，只允许作者选「替换 / 并存（改名）」，默认不动作。
5. **空就是空**：抽不到条目 ⇒ 面板显示「世界观里没找到可登记的能力/制度条目」，而不是生成占位行。

## 6. 分期与代价（建议顺序）

| 期 | 内容 | 价值 | 风险 |
|---|---|---|---|
| **A** | 能力抽取（第 1 维等级表 + 漏洞段） | 高：来源轴正确，且是「预算挤不进去」的补偿 | 低：确定性抽取 + 引文校验 |
| **B** | 制度候选（名称 / 间隔 / 轴，锚留空） | 中：省三项输入，但判定仍 `unknown` | 中：必须显式提示「锚未定 ⇒ 不判」，否则被当成已启用 |
| **C** | 秘密宿体（新表，不是抽取） | 高：第 3 维真正需要的东西 | 高：新 schema + 消费点（写前查阅 / 审稿） |
| — | 物品 / 知情从世界观抽 | **不做** | 来源轴不成立 |

## 7. 待裁定（三条）

1. **期 A 是否现在就做**：它不影响实机验证的读数（不改 prompt、不改 schema），但会加一条新工序与一个候选面。
2. **期 B 的制度候选**：要不要在「锚未定」时就把条目写进 registry（`unknown` 状态全量渲染，
   每章都显示「未知」），还是必须等作者填锚之后才允许入库？
3. **期 C 的秘密宿体**：是并入 M16（给 `knowledge_states` 加一种「全域事实」键），还是新表？
   并入的代价是破坏 M16「键必须可回查定稿」的封闭默认；新表的代价是多一个登记页。

## 附：空间检查的容错（两轮修正后的口径）

### 现象

同一份世界观（10 个空间）报 **7 处待确认**，逐条核对后**没有一处是真问题**：5 条「缺窗口」
（都写在正文的「低频/一次性场景」里）、2 条「约束装不下」（该约束的归属地就是 prompt 里的规则原文）。

### 第一轮（被作者否掉）

把「自评为一次性/低频」的 `no-hours` 直接降级为 `info`。作者当场指出问题，且成立：
**分级声明是模型自己写的**。模型可以给任何空间贴「低频」来免于时间判定 —— 真实数据里
5 个自评低频的空间至少 3 个明显会复发（内门活脉：筑基后必回；长老会议事堂：试药名额议定处；
试药房：主角被灌残篇）。信任这个标签 = 这期检查名存实亡。

### 第二轮（现行）

作者的另一句话给出了正确的轴：**「不是所有地图都有窗口期」**。缺的不是容错，是**第三种表达**。

`entry=` 写满、`hours=` 缺失的行是**二义**的 ——「漏写」与「本来就不适用」长得一模一样，机器永远分不清。
因此给机读行加一个显式取值 `hours=none`（该空间无时段概念：低敏感区、通过型场景），于是三态可分：

| 写法 | 含义 | 检查怎么判 |
|---|---|---|
| `hours=HH:MM-HH:MM` | 有时段 | 参与钟点判定 |
| `hours=none` | **显式声明**无时段概念 | 不报、不参与判定（作者做过决定） |
| 不写 `hours=` | **缺失**（漏写，或作者还没决定） | **报「缺窗口」，要作者二选一** |

关键：**分级（长期舞台 / 一次性）只影响措辞，不再是免检依据**。一次性场景的 `no-hours` 文案会多给
一条更短的路（「若确实没有时段概念就写 hours=none」），但条数照报。

配套改动：
- `space-time-consistency` 认第三值（`noWindow`）—— 避免把 `none` 误报成「按月窗口，需要月历换算」；
- `space-anchor` 认第三值 —— 判 `unknown`（「登记为 hours=none，钟点不判」），不当合规（判据 CL）。

实测同一份世界观：**7 处待确认 → 5 处待确认（每条都是「补窗口」或「写 none」的二选一）+ 2 条设计内提示**。

### 剩下的漏洞在**模板**（待裁定）

第 4 维模板目前写的是「没有时段就**不要写这个字段**（例如只写「车站｜entry=凭票进入」）」——
这句话让「缺字段」同时承担两种语义，模型天然会选最省事的那种（不写）。
最小改法：把这句话改成「没有时段写 `hours=none`」，并在分级声明上给格式（长期舞台必须给窗口）。

⚠️ **撞判据 AO**：作者有 `world_building` 全局覆盖版（N1 完整版），改内置模板会被**静默遮蔽**，
必须同步改覆盖版或先禁用覆盖，否则改完「看起来没生效」。
