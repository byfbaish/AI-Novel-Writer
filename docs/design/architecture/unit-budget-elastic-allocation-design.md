## 0. 一句话结论

**单元要写几章，由这一单元的内容决定；代码只告诉它"现在该松还是该紧"，不给它分配章数。**

判断依据不是"剩余多少"，而是**实际消耗与计划进度线的偏差**：超前了收紧，落后了扩充，贴着线走就按节奏发挥。偏差的账只在**卷内**结清，不跨卷传递。

---

## 1. 为什么放弃前两种方案

| 方案 | 做法 | 失败点 |
|---|---|---|
| **等权折算**（现状 v7） | 150 章 ÷ 28 单元 = 每单元 5.36 章 | 内容只有 3 章的量也被摊到 5 章（注水）；有 8 章的量被压进 5 章（赶） |
| **配比制**（上一轮提议） | 预先给每单元/每段分配章数（后 8 个单元各 9 章） | 前面保守时，后面被"限定"在配额上，内容多也写不满 |
| **弹性配给**（本稿） | 只给**方向**（松/紧/按节奏），章数仍由内容决定 | —— |

前两种的共同错误：**把"计划"当成了"配额"**。计划只能用来当**参照线**，不能用来切蛋糕。

## 2. 机制定义

### 2.1 三个量

```
卷计划额度   budget(v)       本卷计划写多少章
计划已用     plannedUsed(k)  按进度线，到本单元开始时应已用掉的章数
实际已用     actualUsed(v)   本卷内已生成的章数
```

`plannedUsed` 的算法：**卷内按单元均分画进度线**（不是分配章数）：

```
plannedUsed(k) = budget(v) × (j − 1) / m
  j = 本单元在卷内的序号（从 1 起）
  m = 本卷的单元总数
```

> 均分在这里只用于**画一条参照线**。它不约束任何单元写多少章 —— 这是它与配比制的分界。

### 2.2 偏差 Z

```
Z = (actualUsed(v) − plannedUsed(k)) / budget(v)
```

即：**实际消耗相对计划进度的偏差率**，以本卷计划额度为分母。

### 2.3 三档状态与动作

| Z | 状态 | 含义 | 给模型的指令 |
|---|---|---|---|
| `Z > +10%` | **不足** | 本卷超前消耗，余量吃紧 | **收紧**：少开新线、压缩铺陈、合并可合并的场面 |
| `−10% ≤ Z ≤ +10%` | **均衡** | 贴着进度线 | 按节奏发挥，不额外干预 |
| `Z < −10%` | **充足** | 本卷落后于计划，还有余量 | **扩充**：铺细节、开支线、把过程写足 |

**硬规则**：三档只改变**写法**，不减少任何必要情节。收紧 = 把同一个事件写得更紧凑，不是把事件删掉或一句带过。

### 2.4 反馈性质

这是**反馈控制**，不是硬截断：

- 写多了 → Z 变正 → 后面几个单元被要求收紧 → Z 回落
- 写少了 → Z 变负 → 后面被鼓励扩充 → Z 回升
- 卷末自然收敛在计划额度附近，**不需要"最后一章收口"**

### 2.5 实测依据与适用边界（2026-10-19）

状态块到底能不能改变篇幅，已用四组对照实测（详见 [`unit-budget-prompt-ab-test.md`](unit-budget-prompt-ab-test.md) §12；本地 `qwen3.5:9b-128k`，每组 5 次）：

| 内容状态 | 无状态块 | 有状态块 | 状态块作用 |
|---|---|---|---|
| **刚性**（四道关，天然 6–7 章） | 6.8 章 | **3.2 章**（收紧） | **−3.6 章（−53%）** |
| **稀薄**（四字段，天然约 6 章） | 6.0 章 | **8.2 章**（展开） | **+2.2 章（+37%）** |
| **弹性**（写 3–8 章都成立） | 5.6 章 | 5.4 章 | +0.2 章（噪声内） |

三条读法，都直接影响落地：

1. **作用量与内容刚性正相关。** 内容与预算不冲突时，模型按"每单元平均"自己配给，状态块没有活干；冲突时它是主力。**这不是缺陷，正是本设计想要的行为**——它只在需要时用力。
2. **压缩比展开可靠 1.6 倍。** 压缩 = 合并已有场面（刚性组的四道关 5/5 全落地，只是排布变紧）；展开 = 发明内容（模型会自我克制，怕注水、怕越界）。**所以「不足」档的实施优先级高于「充足」档**，而卷末爆额正是「不足」要处理的问题。
3. **均衡档可以不注入。** 该档实测作用在噪声内，注入只会把"按进度应已写 X 章"变成新锚点（见 §4.4 条件注入）。

> ⚠️ 样本量：组内 n=5、单模型（9b）、温度 0.9。结论方向可信（刚性与弹性两组区间不重叠），但**−53% / +37% 这两个倍数不可当常数使用**。

## 3. 卷计划额度的来源

> ⚠️ **本节已被作者裁定取代（2026-10-19）**：卷级额度**不是**输入，而是「模型按材料决定、作者事后否决」的统计量。本节保留作历史记录，现行口径见 [`volume-quota-context-budget-design.md`](volume-quota-context-budget-design.md) §3。

采用**画像默认 + 作者可覆盖**：

| 优先级 | 来源 | 说明 |
|---|---|---|
| 1 | 作者手填 | 项目设置里给每卷一个章数；填了就以填的为准 |
| 2 | 画像默认 | 未填时按平台画像给的建议区间取中值 |
| 3 | 兜底 | 全书总章数 ÷ 卷数（等权） |

> 卷数只有 5–7 个，等权兜底也可接受：真正的差异由**卷内弹性**吸收，不像单元级均分那样致命。

## 4. 生成流程：从「按章号分批」改为「逐单元生成」

### 4.1 现状

```
批次 = 章号区间 [from, to]
  to 由"单元或全书"预先算定（等权折算）
  模型按区间写，写完落在 to
```

问题：`to` 是预先算的，等于提前分配了章数。

### 4.2 目标

```
批次 = 一个单元
  输入：from = 已生成章数 + 1；单元序号 k；本卷预算与 Z 状态
  输出：模型从第 from 章开始写【单元 k】，写到该单元「离开状态」成立为止
  生成后：代码数出实际章数 actual，写 covered_to = from + actual − 1
```

### 4.3 提示词怎么表述（不给 to，给边界）

```
【本次生成范围】
本次只写【单元 k：<单元名>】这一段，从第 <from> 章开始。
写到该单元的「离开状态」成立为止 —— 不要为了凑章数继续写，也不要因为章数少就跳过必要的情节。
写完本单元立即停笔：**不得**进入下一个单元，也不得写"后续概览"以外的任何后续内容。
```

关键差异：**没有"第 from–to 章"这个区间**，只有"从第 from 章起，写完这个单元为止"。

### 4.4 状态块（注入位置：紧跟弧位块）

```
【本卷配给状态 · 单元 3/5】
- 本卷计划：32 章；已写：18 章；按进度此刻应已写：12.8 章
- 偏差：+16.3%（超前）
- 状态：不足 —— 本单元请收紧写法：少开新线，压缩铺陈与过渡，把同一个事件写紧凑。
  **必要情节一个都不能少**；收紧的是笔墨，不是内容。
```

充足时：

```
- 偏差：−14.2%（落后）
- 状态：充足 —— 本单元可以展开：铺细节、开支线、把过程写足。
  但只展开**本单元已有的事**，不得提前使用下一个单元的材料。
```

**条件注入（实测后追加，2026-10-19）**

均衡档（`−10% ≤ Z ≤ +10%`）**默认不注入**本节的整块内容——模板变量留空，由渲染层裁掉。两条理由：

1. 该档实测边际作用在噪声内（§2.5），注入没有收益；
2. 状态块里"按进度此刻应已写 X 章"这行本身会被当成目标（实测中模型会主动做 `剩余章数 ÷ 剩余单元` 的等分），均衡时注入等于多给一个锚。

只有 `|Z| > 10%` 时注入，且**只给方向、不给章数**。

### 4.5 检查点兼容

现有状态机依赖 `synopsis_range = { from, to }`。改为逐单元后：

- `from` 仍然已知
- `to` 在生成完成后由解析得出
- 检查点保存：`synopsis_range: { from, unitIndex }`，`to` 在完成后回填
- 续写（resume）：从 `covered_to + 1` 起，重新定位到"所属单元"，而不是恢复原 `to`

**这是改动风险最高的一块**，必须单独一轮实施并加回归测试。

## 5. 报警（不硬截断）

| 触发 | 时点 | 行为 |
|---|---|---|
| 本卷实际 > 计划 × 1.15 | 卷末（最后一个单元写完） | 报警：本卷超计划 N 章（+X%）。下一卷计划额度不变，偏差不跨卷。可选：上调全书总章数 / 接受 |
| 本卷实际 < 计划 × 0.85 | 卷末 | 提示：本卷写少了 N 章。可选：本卷补单元 / 接受（总章数会少于目标） |
| `budget(v)` 缺失或 ≤ 0 | 生成前 | 回退到等权兜底，并在日志标明"用了兜底" |

**不做**：自动压缩末尾章节、自动删减单元、自动改总章数。

## 6. 极端情况的上限（作者的接受范围）

以当前卷纲为例（7 卷 × 5 单元 × 5 章）：

| 情形 | 全书章数 | 超目标 |
|---|---|---|
| 全部贴线 | 175 | +16.7% |
| 每单元都顶到 +10% 上限（5.5 章） | 192.5 | +28.3% |

作者的判断：**可以接受**。因为偏差只在卷内累积，而每卷最多 5 个单元 × 10% = 50% 的卷内偏差，不会滚成全书指数级。若真出现 192 章，说明"鼓励"没有生效 —— **那是提示词的问题，靠调提示词解决，不靠加硬闸门**。

## 8. 验收

1. **单测**：`planProgress` 三档边界（±10% 附近）、`plannedUsed` 在 j=1 时为 0、卷内 m=1 时不除零。
2. **逐单元生成**：生成单元 1（1–? 章）→ 检查点 `covered_to` 等于实际章数 → 单元 2 从 `covered_to+1` 开始。
3. **状态生效**：人为把卷预算压到很小，令 Z > +10%，确认注入的状态块出现且为"不足"。
4. **不越界**：单元 k 的产出里不得出现单元 k+1 的段间推进内容（用弧位对账查）。
5. **卷末报警**：人为让某卷超 15%，确认报警出现且不阻断。
6. **条件注入**：`Z` 落在 ±10% 内时，渲染后的 prompt 中**不得出现**「本卷配给状态」整段（模板变量为空即裁掉）；`|Z| > 10%` 时该段必须出现且状态与符号一致。
7. **只读预估（E1.5）**：真实项目生成情节大纲时日志出现 ⚖️ 三行，且 `实际章数 − 进度线` 与手算一致；**同一次生成的 prompt 里不得出现该段**（此阶段只打日志）。
