## 1. 缘起：一次真实的剧情断裂

第 2 章与第 3 章的落点，在三层产物里各错一次，且**每一层都不知道上一层已经改过**。

### 1.1 事实（已核验，原文在手）

| 层 | 产物 | 时间 | 原文 |
|---|---|---|---|
| 大纲 | `project_core.synopsis` ch2 | 10-16 前 | 「**下午**有电话进来报当日报价…**晚上九点那一栏，正是他今天站过的位置**」 |
| 正文 | `drafts` ch2 | 10-17 15:25 定稿 | 「掏出手机看了一眼时间。**差一刻九点**」→「**九点那格是望海桥中段。他刚才就站在那儿。**」 |
| 大纲 | `synopsis` ch3 | 10-16 前 | 「**九点前**，他跑到望海桥有摄像头那一截，**站进表上「晚九点」那格**」 |
| 蓝图 | `blueprints[3]` | 10-16 20:58 | keyEvents E2「天亮后…站进作息表上「晚九点」那一格」，`structured_refs` `timeRef = "09:00-10:00"` |
| 正文 | `drafts` ch3 | 10-17 15:30 | 早上 **07:02–07:22** 站在**桥头**摄像头下 |

### 1.2 三处错误，性质各不相同

1. **大纲自己把时间写错了。** 「下午」在桥上，而表上写「晚上九点」——大纲层面就不成立。**是正文把时间挪到 20:45 把这个洞补上了**（判据：先对齐产物时间戳，再谈谁对谁错）。
2. **大纲把「手段」写成了动作。** ch3「站进表上「晚九点」那格」是比喻（占据/污染那个定价位），但写在「九点前」，物理上不成立。蓝图把它字面化（`timeRef=09:00-10:00`），正文再把它执行成「早上七点站桥头」。
3. **那一格在第 2 章就被兑付了。** 20:45 到场 + 停留跨过九点 + 「准得跟钉子似的」+「那格是你自己站进去的」。**已兑付的东西无法事后撤销**；第 3 章不是在「打错格子」，是在**打一个已经交割的东西**。

### 1.3 为什么框架没拦住

模板 `builtin-prompt-templates.ts:959` 原文：

> 以下是**已经定稿的前置章节**……它们是**已经发生的事实**；与上文【全书架构数据池】里的情节大纲（规划）不一致时，**以本节为准**

而 `directory.command.ts:414-420`（批量）与 `:226-231`（单章 `recentBlueprints`）实际填入的是 `keyEventsText(前置蓝图.keyEvents)`。

- 被称作「事实」的，是**计划**；
- 且被**明文授权压制大纲**；
- 真正的事实（`blueprints.notes`，实测 ch1=1821 字、ch2=1875 字，`notes_updated_at=2026-10-17 15:26:05`）**就在同一行数据里，被丢弃**。

英文版 `prompt-language.ts:543-544` 写的是 "Previously validated blueprint **progress**"，反而属实——**中英文语义不对称**。

## 2. 三个可分离的缺口

| 缺口 | 现状 | 为什么必须分开修 |
|---|---|---|
| **A. 计划没有有效期** | `blueprints` 表**无任何状态列**（列：`chapter_number / title / role / purpose / key_events / characters / suspense_hook / user_guidance / notes / notes_updated_at / created_at / updated_at`） | 过期与新鲜在数据层**完全同形**，任何检测器都无从下手 |
| **B. 事实通道未接且被冒充** | `recentBlueprints` 只取 `chapterNumber/title/keyEvents/suspenseHook`；`notes` 被丢弃；模板把计划称为事实 | 加检测器不如先修通道（判据 AA：上游缺数据时，重跑等于复现） |
| **C. 计划不声明攻击目标** | `structured_refs.timeRef` 是**动作时间**（我几点去），不是**被攻击的格的时间**（我要打哪一格） | 没有目标声明，复核第一步就无法起步 |

### 2.1 关键约束：批量蓝图跑在任何正文之前

- trace `20261016-205810-975-蓝图-ch1-5` 生成于 **10-16 20:58**；
- ch1 / ch2 正文分别在 **10-17 12:46 / 15:26** 定稿；
- 实测 `blueprints.notes`：ch1/ch2 有值，**ch3/4/5 均为 0 字**。

⇒ **「把上游换成定稿事实」在批量模式下结构性不可能。** 本稿因此**不**改蓝图生成链的上游，只加「有效期」与「复核」。

### 2.2 批量规模只决定检出率，且第一版判定会漏掉最严重的一档

默认批量 `DEFAULT_PLANNING_ACTION_CHAPTERS = 5`（`src/shared/plot-outline-contract.ts:7`）。设一次预生成 N 章，批内第 1 章定稿后其余 N−1 章即转为过期 ⇒ **复核负担 ≈ N−1**：

| N | 需复核的蓝图 | 形态 |
|---|---|---|
| 5（默认） | 4 | 现状 |
| 20 | 19 | |
| 150（全书一次） | 149 | 「一次性生成所有大纲」的极限 |

**但「过期」这一档在批量模式下会整体失效**：全书批量生成时库内定稿水位也是 0，判据 `max(finalized) > planned_against` **恒为假**，于是每一份「纯假设」的计划都被判为「不过期」并直通。

> 这是本稿 2026-10-18 01:5x 补齐的缺口。作者提问：「如果一次性生成所有大纲，水位为 0，等同于当前第 2、3 章的状态，那还能回避现在这个问题吗？」——**按第一版写法不能**。原判据只覆盖「曾经新鲜、后来过期」，覆盖不了「从来没有新鲜过」，而后者正是批量预生成的全部情形。

## 3. 概念模型：意图 / 状态 分流

### 3.1 分流原则

| | 来源 | 权威 | 可否被下游改写 |
|---|---|---|---|
| **意图** | 大纲（章级 `purpose`） | 唯一 | ❌ 不可 |
| **状态** | 已定稿正文的事实登记 | 唯一 | ❌ 不可（但可**修正手段**） |
| **手段** | 蓝图（`keyEvents` / `structured_refs` / `attacks`） | 派生 | ✅ 必须可重新求值 |

蓝图不是「大纲的投影」，它是 **`f(意图, 状态)` 在生成时刻的求值结果**。求值结果天然有保质期。

### 3.2 「忠于大纲」的正确含义

大纲的 ch3 `purpose` 是「废掉黑市那版作息表上「晚九点桥格」的**定价价值**」——这是**意图**，至今有效。
大纲的 ch3 E2 是「站进表上「晚九点」那格」——这是**手段**，已被第 2 章证伪。

> **忠于大纲 = 保留意图 + 重新求值手段。**
> 执行一个基于过期状态的手段，不是忠于大纲，是忠于一个错误的假设。

### 3.3 唯一的合法汇合点

```
大纲 ──意图──→ 蓝图 ──→ 正文
                  ↑
定稿正文 ──事实──→ 事实登记 ──→ 复核（仅当计划过期）
```

**事实不流向蓝图生成链**（尊重作者的分层要求）；只在**带闸门的复核动作**里修正蓝图的手段。单向、可审计、有触发条件。

## 4. 设计

### 4.1 事实登记（三层 + 一道闸门）

| 层 | 载体 | 用途 | 现状 |
|---|---|---|---|
| **L1 边界** | 定稿收据 `FinalizedSourceIdentity { draftId, finalizationId, chapterNumber, contentHash }` | 只有带收据的正文才算事实 | ✅ 已有（`src/shared/finalized-continuity.ts`） |
| **L2 散文日志** | `blueprints.notes`（章节要点）+ `continuity_facts`（每条带 `evidence` 引文） | 给人看、给模型读 | ✅ 已有；**蓝图链未接** |
| **L3 可判谓词** | `eventClaims / stateClaims / openThreads` | 给代码判 | ❌ 缺 |

**L3 是封闭枚举，不是开放式抽取**——不要求代码理解中文：

```ts
interface EventClaim {
  chapter: number
  window: { start: string; end: string } | null   // "20:45"-"21:10"，null = 未写明
  space: string
  actors: string[]
  kind: 'presence' | 'action' | 'speech'
  quote: string                                    // 必须在定稿正文里逐字存在
}

interface StateClaim {
  key: string          // "slot:望海桥中段@21:00" / "quota:2026-10-17" / "alive:鲁传福"
  value: string        // "settled" / "spent" / "true"
  quote: string
  chapter: number
}

interface OpenThread {
  id: string
  statement: string
  status: 'open' | 'settled'
  settledBy?: string   // quote
}
```

**证据闸门（唯一必须由代码强制的规则）**：
> 每条的 `quote` 必须能在对应章节的定稿正文里**逐字找到**；找不到 ⇒ 拒绝登记。

这条闸门让「代码永不理解中文」成立：模型负责「说出发生了什么」，代码只做**逐字比对**与**规则推导**。

**派生规则（纯机械）**：
- `EventClaim.kind=presence` 且 `window` 覆盖某格钟点 且 `space` 相同 ⇒ 该 `slot` 标 `settled`；
- `quota:<date>` 在当日已有任何 `speech` 类 `EventClaim` ⇒ `spent`。

**落地分三级（避免一次上大件）**：
1. 把 `notes` 接进 `recentBlueprints`，并显式标注「已发生」（零新机制）；
2. 给 `notes` 加机读尾巴，沿用世界观已有的机读行范式：「`- [状态] slot:望海桥中段@21:00 = settled | quote="他刚才就站在那儿"`」（`src/shared/space-time-consistency.ts` 已在解析同族格式）；
3. 再上 L3 结构体与派生规则。

### 4.2 计划水位

`blueprints` 新增一列（走 lane 六步，见 [`notes/data-and-schema.md`](../../../.workbuddy/memory/notes/data-and-schema.md)）：

```
planned_against_finalized_through INTEGER NOT NULL DEFAULT 0
```

含义：**生成该蓝图时，前文已定稿到第几章**。

判定必须分三档，不能只判「过期」。记 `P` = 该列值，`C` = 当前库内定稿水位，`K = chapterNumber - 1`（本章理论上应当接地的章数）：

| 条件 | 档位 | 含义 | 处置 |
|---|---|---|---|
| `C > P` | **stale（过期）** | 生成之后又有新事实落地 | 必须复核 |
| `C == P` 且 `P < K` | **assumed（假设）** | 前 `K − P` 章尚无事实，计划纯属推测 | **必须复核**，并告知作者「这是预生成计划」 |
| `C >= K` 且 `C == P` | **grounded（接地）** | 生成时前文已全部定稿 | 直通 |

派生量 **接地深度** `g = P − K`：

- `g = 0` ⇒ 完全接地；`g < 0` ⇒ 有 `−g` 章是假设。
- 它比布尔值有用：UI 可显示「本章计划：接地 0/2（前 2 章为假设）」，`g` 越负，复核越该强制。
- 全书一次预生成 ⇒ 所有蓝图 `g = −(K)`，**100% 落入 assumed**，不再有「静默直通」的可能。

> 为什么水位必须记在**计划自己**身上，而不是快照上：`settled` 加在 `summary_snapshots` 是「加在没人读的地方」（蓝图链对快照零引用）。**「过期」是计划的属性，不是事实的属性。**

### 4.3 `attacks` 形状（缺口 C）

`BlueprintKeyEvent` 现为 `{ id, event, estimatedUnits }`。建议对**反制/解决类**事件增加可选字段：

```ts
interface BlueprintAttack {
  /** 被攻击的对象。目前只支持「预测格」一种。 */
  kind: 'slot'
  /** 目标格的空间（必须与世界观第 4 维登记名一致） */
  space: string
  /** 目标格的钟点，HH:MM */
  hour: string
  /** 为什么攻击这里会使目标失效（一句，自由文本，仅供人读） */
  rationale: string
}
```

失败时 fail-open：无 `attacks` ⇒ **不判**，但复核报告要显示「本章未声明攻击目标」（判据 ⑫：只判候选真正依赖的字段）。

### 4.4 复核五步（判定归属是核心）

| 步 | 执行者 | 输入 | 判定 |
|---|---|---|---|
| ① 接地判定 | **代码** | `P` / `C` / `K` 三值 | grounded ⇒ 直通；stale 或 assumed ⇒ 进入复核，报告注明档位与接地深度 `g` |
| ② 取攻击目标 | **代码** | `attacks` | 缺失 ⇒ 提示「未声明目标」，不拦 |
| ③ 查结算状态 | **代码** | `attacks.slot` ↔ `StateClaim("slot:<space>@<hour>")` | `settled` ⇒ **拦下**，附证据引文与来源章 |
| ④ 意图留·手段重求 | **模型** | ①本章 `purpose`（原样）②过期事实清单（含引文）③失效旧手段（附失效原因） | 输出新 `keyEvents` + 一行 `why` |
| ⑤ 机械验收 | **代码** | 新 `attacks` | `hour` 必须等于被攻击格的钟点；`space` 必须 **≠** 被攻击格空间 |

**第 ⑤ 步是本设计的关键闸门**：它不判「这个计划好不好」，只判「它有没有资格声称自己在攻击那个格」。实施后，「早上七点站桥头」会因 `hour=07:00 ≠ 21:00` 被直接拒绝。

**判定权与生成权必须分离**（判据 AG）：写计划的同一方判断「计划是否还成立」等于没有复核。

### 4.5 章级大纲「前提」（治本项）

章级大纲条目增加机器可判的**前提声明**：

```
## 第3章
意图：废掉「晚九点桥格」的定价价值
前提：slot:望海桥中段@21:00 = 未结算
```

蓝图生成时**立即校验前提**：不成立 ⇒ 当场拒绝生成并回报「前提已被第 2 章证伪，需重写手段」。

这把「过期」从**创作前**提前到**蓝图生成那一刻**。前提不能保证永远成立（批量生成全书大纲时水位恒为 0，前提全是假设），但**写出来的前提才可被证伪**。

### 4.6 规划视野（`planningHorizon`）—— 唯一能真正「锁死」的开关

上两节都只能**检出**，不能让计划变正确：批量模式下模型看不到未来，`assumed` 档永远存在。要「锁得很死」，只有限制预生成跨度这一条路。

```
planningHorizon: 0 | N     // 单位：章；0 = 严格滚动
```

| 值 | 行为 | 代价 |
|---|---|---|
| `0`（严格滚动） | 生成蓝图的 `P` 必须 `>= chapterNumber - 1`，否则**拒绝**并提示「请先写第 k 章正文」 | 彻底消除 assumed；但失去「排期几章再写」的便利 |
| `N`（默认 3） | 允许预生成 N 章，超出即拒绝 | 复核负担封顶在 N−1；`g` 最差为 −(N−1) |
| `∞`（现状） | 不设上界 | 全书一次生成 ⇒ 几乎每章都要复核 |

**这不是新机制**，只是给现有批量生成加一个上界校验，落点两处：

- `directory.command.ts:321-324` 的 `endChapter` 计算（批量蓝图）
- `architecture.command.ts:2057` 的 `requested` 范围校验（批次大纲）

默认值建议 `N = 3`：够排期，`g` 最差只有 −2，复核可接受。作者若要「锁死」，置 `0` 即可——此档下水位恒 grounded，复核基本不触发，第 2/3 章这类问题在生成时就不可能发生。

> 与 §2.2 的关系：批量规模决定**检出率**，`planningHorizon` 决定**假设深度**。两者是同一件事的两种旋钮，前者事后，后者事前。

## 6. 不做

1. **不把定稿事实接进蓝图生成链**（作者的反对成立：状态不得改写意图）。
2. **不做通用章级因果 / 逻辑自洽检测**（纯因果推理，代码无解）。
3. **不做 `timeRef` 校验器**（`timeRef` 本身失真，在坏字段上加检测器是方法论错误）。
4. **不以「重跑蓝图」当修法**（输入没变 ⇒ 稳定复现同一错误）。
5. **不提前 AC1/AC2/AC3**（射程不同，见 §9.2）。

## 9. 风险与边界

### 9.1 风险

1. **`quote` 逐字匹配脆弱**：正文若在定稿后被编辑，引文会失效。缓解：事实登记与 `contentHash` 绑定，失效即整条作废（不是静默放过）。
2. **`attacks` 是新增输出合同**：会让蓝图链的 JSON 形状变复杂，可能触发既有合同违规率上升。缓解：`attacks` 可选，缺失 fail-open。
3. **水位加列的迁移**：必须走 lane 六步，否则旧库 `UNRECOGNIZED_SCHEMA`（红线 1）。
4. **中英文对称**：模板措辞改动必须同步 `prompt-language.ts`，否则 `prompt-language-contract` 失败。

### 9.2 与 AC 线的边界

AC1/AC2/AC3 查的是**架构五层之间的引用完整性**（角色在图谱里、空间在登记里）。本稿查的是**同一层内「计划 × 状态」的时态一致性**——粒度不同、失败模式不同，不能互相替代。作者已拍板 AC 线顺延到架构定型后，本稿不受该顺延约束。

## 10. 待裁定

1. `attacks` 是否只支持 `kind: 'slot'`，还是要预留 `kind: 'thread'`（攻击一条开放线索）？
2. L3 事实登记由**正文生成链同时输出**（写的时候顺手登记），还是由**定稿后处理**（读完再登记）？本稿倾向前者（模型最清楚自己写了什么），但改变正文链的输出合同，代价更高。
3. 水位判定「过期」后，是**强制复核**还是**仅提示**？本稿建议首次上线**仅提示**，稳定后转强制。
4. `assumed`（预生成计划）档是否与 `stale` 同等对待？本稿建议**同等对待（必须复核）**——它 100% 是假设，风险不低于过期。但若作者觉得「每章都弹」太吵，可退为「首次提示 + 允许『本批不再提示』」。
5. `planningHorizon` 默认取几？本稿建议 `3`；作者若要「锁死」取 `0`。需确认是否允许作者在 UI 上自行调整（若允许，它本身就是一个绕过护栏的口子）。
