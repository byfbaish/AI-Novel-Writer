## 0. 先说结论

**创作侧「条款齐、测量空、口径没接上」。** 十条读者侧维度里，四条已经对齐（章末钩子 / 承诺账 / 卷单元 / 反模式条款），六条半接线，零条缺失（2026-10-24：平台适配由「缺失」升为「半接线」——正文首稿已接，续写轮与章纲链未接）。真正的病灶不是缺条款，而是三件事：

1. **最具体的一份创作规则进不了正文链。** 作者 2026-10-17 手写的「节奏/风格指导」清单（爽点类型轮换、钩子类型轮换、伏笔 60 章内必回收、标题必须含信息）落在 `pacing_guidance` 槽位，而 `withPacingGuidance` **全库只有 `directory.command.ts:442` 一处调用** —— 它只到章纲，正文链根本收不到。同一份清单里还有一句「2–3 章一个小爽点」与模板硬写的「3-5 章一个小高潮」在同一轮 prompt 里打架（`docs/fanqie-guidance-final.md` §3 已记）。（2026-10-24：只补了**作用域说明**（P16-4），没有接线 —— 接线属于 P16-2/C3 的范围。）
2. **创作侧没有任何测量。** 审稿链**刻意**不判文笔与风格（`builtin-prompt-templates.ts:1369`「不报告纯文笔或风格偏好、可选创作建议」），判据 CM 也明确「设计强度 ≠ 一致性」。于是「读者会不会追」这一整条**没有自动反馈回路**，只有作者肉眼 + 离线手测（P8 复验 #3 的「对话占比 20.60% / 连续叙述段 18」是人工数的）。行业里这件事是数据驱动的（§2 B2/B3）。
3. **平台是书的属性，落地要一层层接。** `rhythm_profiles.ts` 定义了 `qidian` / `fanqie` 两档（卷数、单元数、兑现频率都不同）。2026-10-24 的进度：**架构链** ✅（一直有）→ **正文首稿** ✅（P16-5 落地，`next_chapter_draft` 加【节奏推荐】块）→ **章纲链** ❌（只在 `chapter_blueprint_chunk:1044` 硬写「每 3-5 章一个小高潮」，对番茄向的书直接是错的）→ **续写/压缩轮** ❌（不重渲染模板正文，见 P16-2）。「章长」至今由作者手填 `wordsPerChapter`，不随平台折算。

⇒ 本稿**不主张立刻补条款**。要补的是三处**接线**，且每一处都要先过 §5 的护栏问句：**补它是为了让模型别写错，还是为了替作者做创作决定？**

## 1. 方法：四问

沿用 `industry-alignment-and-stage-goals.md` §5，不另造框架。每个维度四项：

1. **行业口径** —— 带 URL + 逐字摘句；无出处标「经验口径（无权威出处）」
2. **本项目承载物** —— `文件:行号`
3. **真实消费方** —— 没有消费方的直接判「半接线」（W6 的教训）
4. **判定** ∈ {已对齐 · 半接线 · 缺失 · 故意不做} + 理由

## 2. 锚点清单

### B1 · 阅文作家专区（官方，已逐字取证）

<https://write.qq.com/portal/community/topic/detail/91461399351449601>《怎样才能写出在起点签约的百万字长篇小说?》

> "三、开篇：黄金三章定生死，编辑和读者只给你3000字机会"
> "1. 第一章：300字内"扔炸弹"，1000字内"亮金手指""

> "3. 节奏：用"爽点-铺垫-爆发"的循环制造"追更依赖""
> "小 节奏（每10-20章）：解决一个小冲突…给读者即时反馈；中节奏（每50-100章）：完成一个阶段性目标…制造"里程碑式爽点"；大节奏（全文）：围绕主线，在30%、60%、90%篇幅处设置"关键转折""

> "主线不能变，但可以"阶段性升级""""支线…必须满足"三个服务"：服务主线进度、服务主角成长、服务人设丰满"

**它支持什么**：开篇留存有明确的**字数窗**（300 / 1000 / 3000）；节奏是**三段嵌套的兑现频率**（小/中/大）；成长要有**阶段性目标**承载。
**它不能支持什么**：这些是**平台编辑经验 + 商业写作共识**，不是可测量定律；"3000 字"是编辑浏览耐心，不是读者留存曲线。

### B2 · 番茄小说官方：作品数据面板（官方，已逐字取证）

<https://fanqienovel.com/docs/8231/90703>《作品数据查看》

> "章节读完率：指N%的读者从第一章持续读到第X章，如果某几章数据出现大幅波动，建议作者优化"

> "追更人数：每日阅读最近更新3天内章节的人数" · "催更人数：每日点击催更按钮的人数"

**它支持什么**：平台把"读者会不会追"**操作化为三个可读指标**（章节读完率 / 追更 / 催更），且**按 50 章一组给趋势图** —— 这正是本项目缺的那层回路。
**它不能支持什么**：不给出任何"合格值"。数值门槛只出现在自媒体（§2 B5），不可引用。

### B3 · 番茄小说官方：作者专区文章《单章到底怎么改?节奏快慢如何调?》（官方，已逐字取证）

<https://fanqienovel.com/writer/zone/article/7626644363652644889>

> "看整体完读曲线和跟读率，哪个章节有明显的下滑点就直接修改。"
> "【章节读完率】…能够反映出读者在阅读本书的时候，具体到哪些章节流失的比较严重。比如说第20章显示折线图下降的非常明显，那你就要从前一章，也就是19章开始修改。"

**它支持什么**：改稿的**触发条件是数据**，不是感觉；且"从流失点的**前一章**改"是一条明确的定位规则。
**它不能支持什么**：它是改稿方法，不是生成方法 —— 不能据此推出"生成时必须满足某个指标"。

## 5. 创作自由度护栏

每个「缺失」必须回答一句：**补它是为了让模型别写错，还是为了替作者做创作决定？** 后者一律进 §7「不做」。

| 缺口 | 防错还是替作者决定 | 结论 |
|---|---|---|
| C1 黄金三章 | **防错**（作者大纲里第 1-3 章常缺"抛主线/立人设"，模型不会自己补） | 可做，但只能写成「本章要让读者知道什么」，不能写成「第 2 章必须激活金手指」 |
| C2 pacing 作用域说明 | **防错**（界面在撒谎） | 改文案，零风险 |
| C3 纸面规则分流 | 混合：标题含信息=防错；钩子类型轮换=**方法提示**（可接受）；伏笔 60 章回收=**替作者决定**（期限是商业经验，不是事实） | 只取前两类；期限类改写成「作者可填的目标区间」 |
| C4 平台画像 | **防错**（同一句"3-5 章"对番茄向的书是错的） | 可做，但必须「作者选了平台才生效」，空值保持中性 |

## 6. 与 P15 的关系（前置复核）

P15「章级情绪极性 / 钩子类型」现为**未立项 · 顺延**（`plans/prompt-assembly-backlog.md:1394`）。它写死三条前置，本稿逐条复核：

| 前置 | 现状（2026-10-24 核实） | 结论 |
|---|---|---|
| 1. P2-1 findings 宿主先建好，且本项是它的**第一个非连续性类试点** | `review_findings` 宿主已建（P2-1 期 1，四类**连续性**语义档：物品/制度/知情/能力）。非连续性类试点**尚未开工** | **部分满足** —— 宿主有了，但"第一个非连续性试点"这个位置还没占 |
| 2. 落点 = 定稿链 `generate_chapter_notes` 顺带产出 → `summary_snapshots` 加列，零新增模型调用 | `summary_snapshots` 现有 `chapter_notes` / `continuity_facts` / `character_state_candidates`（`electron/migrations/baseline-schema.ts:597-609`），**无极性与钩子类型列**；加列 = schema 21 | **可行**，成本 = 一次迁移 + 一次 step 输出扩展 |
