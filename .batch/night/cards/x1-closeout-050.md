# X1（已作废）· 收口卡：把 0.5.0 作为「可用无界面版」发出去，插件二期结项

> 提出：大肥鱼（管家） 2026-11-14
> 背景：主人 11-14「周末可以一直推进；既然方向有误，那就换方向继续；在这个插件上已经花了太多时间，必须要早点结束。」
> 状态：**已作废（2026-11-14）**——主人改口径：内置配置界面 + 会话搜索属核心功能，没有即为残次品，不得投放；0.5.0 暂不发版、不打 tag。本卡仅作档案，**勿再执行**。新增范围见 P22。

## 为什么本期不交付界面（≠ 不做界面）

- 最小核心功能是**投递链路**：watch 能配、能投、重启后还在。界面是配置便利性，不是投递能力；watch 现在就能用，配置写 `cordis.patch.yml` 的 `config.watches` 即可。
- 今晚已连续两次因设置卡把宿主打崩（0.4.0 → fatal、0.5.0 候选 → 槽位被删），第三次仍要先做探针再决定路线；每一次都在同一个非核心功能上。
- 口径边界（主人 11-14 定）：**不交付 ≠ 不做**。README 只许写「当前版本无内置界面，后续版本提供」，**禁止**写成「本插件不做界面」；`client.js`、槽位注册代码、结构化 schema 一律保留在仓库里不删。

## 范围（改动面只限这四件）

1. **WARN 文案改准**：`设置卡未挂载：宿主无 settings 服务（跳过，不影响 watch）` 这句是误判（本版本服务在、槽位没了），改成中性 + 指路：`本版本无内置配置界面，请直接编辑 cordis.patch.yml 的 config.watches`（措辞最终以产品经理中英版为准）。
2. **两份 README 补一段「如何配置」**：`config.watches` 的最小 YAML 样例（`dir` / `targetSessionId` / `done` 三键）+ 「当前版本无内置界面，后续版本提供」；同批把安装行 `#v0.4.0` 改成 `#v0.5.0`（v0.4.0 已公开标注不可用）。
3. **版本号**：定为 **0.5.0**，不升号（npm 上从未发布，latest 仍是 0.3.2，0.5.0 不占号；repo 里 `package.json` 已是 0.5.0，不动）。README 安装行与 tag 一律用 `v0.5.0`，三处必须一致：`package.json` / README 安装行 / tag 名。（0.5.1 方案作废，勿再引用。）
4. **结项单**：见末节。

## 本期不做，但必须保留接入点（扩展性口径）

主人 11-14 纠正：「我要的是最小核心功能早点落地，可扩展性还是要维持的。」

- **设置卡 UI（自定义行渲染 `plugins.row.config` / `.volatile()` 自动表单）**：本期不实现，但**不删挂载路径**。`client.js` 的入口与「探测槽位 → 挂载 / 探测失败仅 warn」这段骨架保留，槽位名集中在 `index.js` 一个常量里，宿主改版只需改常量 + 补渲染，不需要重构。
- **配置 schema 不变**：`config.watches[]` 保持 `{ dir, targetSessionId, done?, exact? }`，UI 永远只是渲染层，不允许出现「只有 UI 能写、yml 不能写」的字段。
- **会话寻址改造**（标题匹配 / cwd 兜底）：本期不做，转 issue #4，但 `targetSessionId` 解析集中在一处函数，便于以后替换成标题/cwd 解析。
- **多播 / 订阅者注册表**：不做，方向已写在 issue #3 与群记忆；配置层不加多目标字段，避免以后改 schema。
- **旧宿主（0.1.1-rc.2）第二条实现路径**：不做。不做能力分支 ≠ 不支持老版本，只是探测失败时只 warn 一次、watch 照常。

## 发版（在改动面之后单独一步）
