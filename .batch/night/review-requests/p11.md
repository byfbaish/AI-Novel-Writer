## D（启动期有限次重扫）判定项

常量：`RETRY_DELAYS_MS = [1000, 5000, 15000]`、`MAX_SCAN_ATTEMPTS = 3`、`MAX_SCAN_WINDOW_MS = 21000`。

**日志可判定性（按 QA 提出的缺口定）**：重扫窗口内每次尝试各写一条 INFO，成功也写，格式含序号与结果，例如
`[dsh-handoff-relay] rescan#1 dir=… result=resolved|not-found`
普通投递成功仍不写日志——INFO 只允许出现在「有限重扫窗口」这一类，最多 3 条/次加载，不得扩散到常规路径。

1. 启动时目标解析不到的文件，在第 1 / 2 / 3 次重扫中任一成功即投出，且**只投一条**；投出后该 watch 不再产生后续 `rescan#` 行。
2. `rescan#` 行总数不超过 3；三次都失败时恰好 3 条，此后 60 秒内日志零新增。
3. 第 2 次成功时日志里**不出现** `rescan#3`。
4. 第 1 次即成功时不出现 `rescan#2`、`rescan#3`。
5. 常规投递（事件触发、稳定触发）成功时仍不写日志，`relay.log` 行数与改动前同语义。
