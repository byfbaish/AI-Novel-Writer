# 缺陷报告：桥接重复投递已读文件

主人让直接报给你们。现象：同一个文件被重复唤醒多次。

## 实测记录
- `how-to-deliver-npm-token.md`：通知两次（第二次我已读完并转达主人后才来）。
- `ask-p6-addressing.md`：**通知三次**。5:52 一次，裁定后 6:53 又来一次；文件 mtime 一直是 5:52，内容一字未改。

另一类：`where-the-files-are.md`、`bridge-handoff-reverse-test.md` 之类只是首次就重复出现。

## 判断
大概是这两个原因之一：
1. 监听器按「稳定 5 秒」判定完成，文件被读、被改 mtime 或 git 操作时会重复触发；
2. 每次 `getupdates` 重放同一条通知（会话唤醒队列没有按文件指纹去重）。

## 建议改法
- 通知里带**绝对路径 + 文件 mtime + 内容 sha256**，接收端据此去重；
- 发送端记一个「已投递指纹」集合，同一指纹只唤醒一次；
- 或者干脆写一个 `.delivered` 标记文件/ledger，唤醒前先查。
