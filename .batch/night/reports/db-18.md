## 3. 登记项（前提成立但配置本身有问题，不改变 PASS）

1. **`vitest.settings-browser.config.ts` 是孤儿配置**：`git grep "vitest.settings-browser"` 在 `docs/` 以外**零命中**，没有任何 `package.json` script 引用它；而它 `:19-24` 白名单的 4 个文件全部存在、且全部落在 `vitest.browser.config.ts:29` 的 `src/**/*.browser.tsx` 里 ⇒ 同一批用例有两条入口，一条还没人用。
2. **两条通路超时口径不一致**：`vite.config.ts:141-142` 把 `testTimeout` 放宽到 20s / `hookTimeout` 30s（注释说明并行下会被放大到 11 倍），而 `vitest.browser.config.ts` 未设超时 ⇒ 浏览器侧仍按默认 5s/10s 判红。同类用例在两条通路上可能一个绿一个红，**这不是配置错误，但是选型时必须知道的口径差**。
3. **`globalSetup` 只在 Node 侧**：`vite.config.ts:135` 的 temp 目录收尸不覆盖浏览器侧（`vitest.browser.config.ts` 无 `globalSetup`）⇒ 浏览器用例留下的 temp 目录不会被整轮清理。
4. **`pnpm test` 全量从未跑过的说法与配置无关**：`run-tests-electron.mjs:24-26` 明确支持 `pnpm test <目录>` / `pnpm test <文件> -t <用例>`，全量只是不传参数。

## 4. 选型建议（给作者的一条，含依据行号）

**默认一律用 `pnpm test <单个测试文件或目录>`（Electron 运行时）；只有目标是 `*.browser.tsx` 时才改用 `--config vitest.browser.config.ts`；`pnpm test:node` 在 worktree 并行期间一律不用。**

依据：`scripts/run-tests-electron.mjs:8`（两个 ABI 127/145）+ `:17-19`（只有 Electron 通路做到「全工程一份 ABI，dev 与 test 可同时跑」）+ `:11-12`（切 ABI 时 `pnpm dev` 持有的 `better_sqlite3.node` 会 `EBUSY`）+ `package.json:27`（`test:node` 每次都先重编）+ `vitest.browser.config.ts:29`（浏览器用例的唯一入口）。

配套两条硬边界（有反例，不是「视情况」）：
- 若目标文件是 `*.browser.tsx` 而用了 `pnpm test`：**一定 0 用例**，因为默认 include 不收（表一 include 行）。
- 若在 `pnpm dev` 开着时跑 `pnpm test:node`：**会因 `EBUSY` 直接失败**，报错与业务无关（`run-tests-electron.mjs:11-12`）。
