# S2 不可归因：被替成一句话的整套机制（方法证据，不是结论）

> 状态：已裁定（2026-11-25）· 产品经理出稿；口径依主人 11-25 裁定与 admin 收口三条
> 用途：只作**方法证据**，供 S3 判据清单引用。**不得**被引用成「字数带对 A 臂无效」，也不得被引用成「模型不遵从」。
> 文件名保留旧名（`band-ineffective`）只因群里已有引用指向该路径，正文标题与结论已按 11-25 裁定改为「整套机制被替成一句话、不可归因」。

## 1. 裁定口径（先写这句，避免误引）

本轮失败原因是 **case 目标不清晰、不可归因**：把「分段预算表／合格线 85%／不足续写／超限压缩」这一整套机制摘掉、只留一句字数带，测到的不是任何一块 prompt 的作用。任何把差异算到某一块 prompt 头上、或算到模型头上的写法，都不成立。

## 2. 现象（3 条样本，`round=AUTH-2026-11-25-R1`，05:39 停跑冻结）

| # | key | 臂 | 净字数 | 相对带（1,009–1,875，目标 1,442） | 终态 |
|---|---|---|---|---|---|
| 1 | `ch05-B1-r1` | B1 | 372 | 低于下限 | `stop` |
| 2 | `ch05-A-r1` | A | 8,430 | 高于上限 | `stop` |
| 3 | `ch10-A-r2` | A | 12,870 | 高于上限 | `length`（`out=10000` 顶 `max_tokens`） |

这三个数只能说明「本轮三条样本的长度分布与臂相关」，**不能**说明任何 prompt 块的作用方向——因为对照组根本不是「同一套机制下的另一块」，而是「整套机制被替成一句话」。

## 3. 机制差异（本轮唯一可下的方法结论）

| 维度 | 真机 ch10 trace（基线） | S2 本轮 payload |
|---|---|---|
| 字数要求 | 分段预算表＋85% 合格线＋不足续写＋超限压缩，四块齐全 | 只有一句 `WORD_BAND_LINE` |
| 调用次数 | 3 次（`scripts/experiments/res-s2-ab-runner.mjs:337-350` 的 `buildPayload()` 是单次） | 单次 |
| 四项机制命中 | 4/4 | **0/4** |

出处：真机 trace 的四项与 8,064 字、3 次调用三个数由 admin 11-25 05:5x 的差异表给出（trace 原件未落在本工作区，引用时写「admin 差异表」不复述为自测）；S2 侧 `6,060` 字符、`【字数要求` 出现 1 次、位于 system 第 `5,926` 字符、`trimEnd().endsWith('即不合格。')=true` 系 developer 与我在盘上核过的原文。

## 4. 由此得到的方法学硬约束（进 S3 判据清单顶部）

> **任何单块 prompt 的对照实验，必须以真机 trace 的完整 prompt 为基线，只把目标块当变量、其余块按同源 mock 原样保留；缺这条的实验一律不受理。**

三条配套（判定时才用，平时不必占注意力）：
1. **基线可核**：基线 prompt 必须能落到盘上（trace 导出的原文或逐段 sha），不能只说「按真机」。
2. **变量可核**：三臂 payload 的 diff 必须只落在目标块上，附逐字 diff 与 sha；除目标块外出现任何差异即判违规。
3. **长度不是变量**：长度带由生成参数保证（`max_tokens` 按字数×tokens/字 折算），不得用 prompt 措辞当控制器——本轮已证该手法不成立，但它属于「机制被替掉」的一部分，不作为「prompt 控字数无效」的结论引用。

## 5. 不要写进报告的三句话

- ❌「字数带对 A 臂无效」——把失败算到错的头上（真正被换掉的是整套机制）。
- ❌「模型不遵从字数要求」——把责任推给模型（同一套 prompt 在真机里是有分段预算的）。
- ❌「A 臂比 B 臂更啰嗦」——n=1 章位、配对 0 对，不能出方向。
