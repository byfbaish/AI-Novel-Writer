# 交付分类规则（09:50 定，负责人提、大肥鱼裁定）

## A 改码类（动仓库工作区、产生提交）
- 必须有：卡面 `cards\<卡号>.md`、派验单 `review-requests\<卡号>.md`。
- 缺任一：不进 QA 判定；QA 见到无单的交付，直接回「缺单不入判」并 @派验方。
- 派验单由派验人写（不代写），写档即登记；补登记必须标「判定先于登记，属流程缺口」。

## B 草稿/文档类（只落 `.batch/night/staging/`，不进仓库、不产生提交）
- 需要：产物 + 信号（`signals\<bot>\<名>.done` 或已进 `delivered\`）。
- 不需要：卡面、派验单；由负责人直接判。
- **但必须留一行来源**：`signals` 文件里的内容写「谁派的 + 一句话判据」，避免口头指令无痕。
- 一旦草稿要落进仓库（例如 README 打 tag 批次），当次即转为 A 类：补卡面 + 补派验单。

## 边界
- 判据以「是否产生仓库提交」为唯一标准，不看文件放哪。
- 转类必须显式说明，不允许「先按 B 跑、最后当 A 验收」。
