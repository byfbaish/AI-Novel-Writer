## 二、开篇前 300 字的三种写法（3 部实测）

| 书名 | 首章字数 | 开篇 300 字写法（我自写标签） | 第一处「异常/冲突」出现在哪 |
|---|---|---|---|
| 惹金枝 | 2,075 | 环境+人物视角：夕照、马车、女主抬眼打量、递信进宅 | 第 300 字附近才点出「故人来见」与「三日后便要抄斩的时家」 |
| 帝王娇宠 | 1,821 | **首句单段场景地标「太极殿。」**，第二段直接进对话冲突（太子要悔婚、皇帝训斥） | 第一段对话即冲突，300 字内已给出「太子厌恶未婚妻」 |
| 二凤伴读 | 1,976 | **先放作者声明**（无 CP/日常向/节奏偏慢/主角团宠），再以时代背景+穿越设定过渡 | 300 字内**没有对话冲突**，靠设定与身世推进 |

**结论 4**：开篇不必非要在 300 字内炸冲突——榜 3 就靠「作者声明 + 设定」过；但**三家都在首章就把「这本书爽在哪」讲明白**（劫法场救人 / 悔婚换嫁 / 团宠团养）。
⇒ 豆包写第 1 章时，**首章必须让读者知道这本书的卖点是什么**，这条比「首句是否冲突」重要。

## 三、章末钩子的形态（4 处实测，含 3 章连读）

**A. 行动承诺 + 具体时点**（惹金枝 第 001 章末）
- 女主与男主谈成交易「成了！」，约定「明日巳时」见面、劫法场救人出城、送到禹县西城门外长亭交给指定人。
- 章末没有疑问句，落在**行动安排 + 具体时点 + 下一个动作**。

**B. 情绪/身世铺垫（弱钩子）**（惹金枝 第 002 章末）
- 回忆养育之恩、「心甘情愿付出代价」、脑补对方身份被揭破时的场面，收在「想了想那个场面，笑出声来」。
- 这章**没有推进新事件**，属于动机交代章的软收尾——说明头部作品也允许一章做纯铺垫，但只做一次。

**C. 承诺 + 相认 + 插科打诨**（惹金枝 第 003 章末）
- 牢里见家人：满门抄斩（连七岁以下、九十以上都不放过），女主在地图上添数笔、折起，留一句「两日后见」；与生母相认（画像伏笔）；收尾是狱卒插科打诨「五天后再来看您」。
- 章末 = **硬倒计时「两日后」** + 情感落点 + 一点轻松调子。

**D. 强情节冲击**（帝王娇宠 第 01 章末）
- 女主被皇帝强吻、失去意识，最后一句落在身体感。
- 章末 = **情感/亲密场面硬钩子**，没有任何行动计划。

**E. 对手视角猜疑 + 当章小目标已闭环**（二凤伴读 第 1 章末）
- 当章小目标达成：小孩把受伤的二公子拉去上药、还盘算去厨房弄吃的；末段切到二公子心里：「不知道他到底是真心疼自己，还是为了留在府中而做出来的表现」。
- 章末 = **小目标闭环（结果已落地）+ 对手/旁人的新疑问**。

## 四、和 `opening-3ch-spec.md` 八个检查点的差异（逐条对表）

| 规格卡检查点 | 市场样本里有没有 | 差异定性 |
|---|---|---|
| 1 章末：最怕失去什么 | 惹金枝有（时家满门性命），帝王娇宠没有（只有情感冲击） | 市场不统一；**规格卡更严，豆包要按卡写** |
| 1 章末：谁在逼他（带人名） | 惹金枝有（皇室/言十安对面势力），帝王娇宠有（太子） | 一致 |
| 1 章末：具体倒计时 | 惹金枝有（三日后抄斩 → 明日巳时 → 两日后）；帝王娇宠、二凤伴读**都没有** | 市场多数不给硬倒计时；**规格卡这一条是额外要求，不能拿样本当借口省掉** |
| 2 章末：小目标闭环结果词 | 二凤伴读第 1 章就有（上药、拉走）；惹金枝第 2 章反而没有（纯铺垫） | 市场松散；规格卡要求必须闭环，照卡 |
| 2 章末：第二障碍带人名+时间 | 三部样本都**没有**做到这么硬 | 规格卡严于市场，照卡 |
| 3 章末：不可撤回的选择 | 惹金枝有（决定劫法场，律法层面已不可撤回） | 一致 |
| 3 章末：代价已可见 | 惹金枝部分有（满门抄斩、救人风险），另两部无 | 规格卡更严 |
| 3 章末：下一章必须回答的信息问题 | 二凤伴读有（是不是真心）；惹金枝弱 | 规格卡更严 |

**结论 5（给豆包的明确口径）**：市场样本**普遍达不到**规格卡的硬标准；规格卡不是「照抄市场」，是「在市场写法之上加硬约束」。**照样稿规格写，不要为了像榜单而降低检查点强度。**

## 五、本轮未采 / 已知限制（别把这张表当全量证据）

1. 正文形态只采了 3 部（惹金枝全 3 章、帝王娇宠第 1 章、二凤伴读第 1 章）；其余 7 部只采元数据。**未采不等于没有**。
2. 番茄阅读页正文用**字体混淆**（HTML 里是私用区码位），程序读不到真字，只能截图肉眼读。采一部 3 章 ≈ 5–8 分钟人工，属于可补项（要补请派，我或 developer 都能做）。
3. 榜单页「最新章节号」与目录实际章数**不一致**（5/8/9/10 尤其：194→202、146→150、166→444、205→397）。本表章数一律以目录接口 `data.allItemIds` 长度为准，不要引用榜单页的章节号。

## 六、给豆包的两句可执行口径（其余照 `opening-3ch-spec.md`）

1. 每章 **1,900–2,300 字**，三章合计约 6,000–6,800 字。
2. 第 1 章**必须让读者知道卖点**（可学「首句场景地标 + 第二段对话冲突」，也可学「先立声明再讲设定」）；章末照规格卡的三个检查点写，**不要**因为榜单样本没做到就省。
