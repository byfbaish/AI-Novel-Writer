## 0. 一句话

外部数据**只能当参考层**：进不了判据，进不了验收门；引用了就必须带来源和口径，否则一律判 N/A。搜索要花真钱，所以默认走显式指定的引擎，不做无目的的全量试跑。

## 1. 适用范围

1. 本 SOP 管三类行为：**检索**（用什么引擎、怎么兜底）、**引用**（外部数据能出现在哪些文件、必须带什么）、**计费**（一次调研大约花多少、怎么避免重复花钱）。
2. 不管代码实现、不管卡面格式（卡面模板归 AI writer总负责人）、不管文学判词（归金牌编辑）。
3. 与卡面冲突时，卡片 §4 验收判据优先；但「引用必须带来源＋口径」是全局硬规则，卡片不能豁免。

## 2. 检索：引擎选择与路由

1. **中文调研默认显式指定引擎**：`advanced_search engine=exa`，`timeRange` 按需给；失败再显式 `engine=bing` 兜底一次。不依赖 `auto` / `multi` 自动路由。
2. **为什么不靠自动路由**：`cordis.patch.yml` 里 `web-search-free` 的 `provider: auto`、`fallbackOrder` 首位虽是 exa，但语言池 `zhPool = bing / baidu / aliyun / anysearch`，**exa 只在 `enPool`**。`auto` 与 `multi_search` 按语言池选引擎，中文查询必然从 bing 起跳，实测会返回 APP 下载页而非资料页。这是配置事实，不是使用习惯问题（developer 11-16 实测）。
3. **禁止裸调 `free_search_test`**：不指定 `engines` 时它会把全部引擎测一遍，直接打到计费引擎。要验证可用性只能显式列出免费引擎（exa / tavily / keenable / firecrawl / parallel / bing / anysearch）。
4. **内置 `web_search` 保持关闭**（`tool-web: disabled: true`），其回退链里的 `deepseek-official` 与 `deepseek-tools` 不得启用——两者都是计费引擎。
5. **能读榜就别搜**：平台榜单、后台页面优先用 CDP / 浏览器直读（零搜索费），只有榜单读不到时才发检索。
6. **改默认路由要负责人点头**：把 exa 加进 `zhPool` 首位属改 profile 配置，影响所有 Bot 的默认路由，当前状态为**待议**——先按第 1 条执行，观察一轮 auto 误落 bing 的实际频次再决定。

## 3. 引用：外部数据的三条硬规则

1. **不可入判据。** 平台指标、榜面数字、作者圈经验值（如追读率 25% / 40%、十万字完读率 16–17% / <10%）**不得**写进卡面判据、验收门、首验报告、文学判词。它们只能出现在「参考/讨论」语境里。
2. **卡面引用外部数据必须写来源＋口径，否则判 N/A。** 来源＝可追溯的 URL 或文档路径＋采集日期；口径＝这个数字是哪个分母（追更 ≠ 在读 ≠ 追读率）、哪个时间窗。缺任一项，验收方直接记 N/A，不做善意推定。
3. **判 N/A 时报告单列一节「外部依据缺失」。** 该节写清缺的是来源还是口径，**不混进八条判据**——八条的分母恒为 8，N/A 只在 §5 验收那栏记，保证跨轮统计不脏。
4. 补充：单一来源的数据一律标「未交叉验证」，在拿到 2–3 个独立来源前只能出现在讨论里，不能出现在结论里。

## 4. 成本：口径与记账

1. **计价口径**：一次搜索约 **¥0.02**。这是估算值，用于事前判断「这次调研值不值」，不作为账单依据。
2. **同一问题只查一次**：同一轮里已有结论的检索不重发；跨 Bot 共享时贴来源 URL 与日期，不要求对方重查。
3. **成本意识顺序**：CDP 直读（¥0）→ 缓存/已有文档 → 显式单引擎检索（¥0.02/次）→ 多引擎并发（成本按次累加，只在需要交叉验证时用）。
4. **记账位置**：调研花销与检索次数记在任务的过程账（如 `.batch/night/reports/time-ledger-1116.md`），一行一次，写明查询词与引擎；不写正文、不写长表。
5. **超预期先问**：单张卡预计超过 10 次检索（≈¥0.2）或需要付费 API / 企业版接口时，先报负责人，不自行开额度。

## 5. 调研产物规范

1. 落 `.batch/night/staging/`，文件名全小写 ASCII 连字符（如 `research-cost-sop-v1.md`），首行标题、第二行元信息（执行方／类型／日期）。
2. 正文必须可追溯：每条外部事实带 URL＋采集日期；推算与推论要显式标注「推论」。
3. 末行写 `<!-- DONE -->`；交付时报**字节数＋行数＋MD5**，供验收方回读比对（报出的数字以文件实测为准，不以自我报告为准）。
4. 要进仓库正式文档（`docs/research/`）属另一动作：须负责人批准，并按文档纪律补状态行与 `docs/README.md` 索引。

## 6. 红线

1. 信号文件（`signals/**/*.done`）一经投出不得原地改写，需要更新另写新文件名——同一路径按新字节／mtime 会再触发一轮唤醒。
2. 同一份文件同一时刻只允许一个执行方写；发现有人已领同一产物，先停手报负责人，不开第二通道。
3. 不得用 `--force` 或改配置的方式绕过检索通道；通道不可用时如实上报，不伪造结果。
