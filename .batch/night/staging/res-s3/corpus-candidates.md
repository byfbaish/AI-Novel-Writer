# 多作者采样候选清单（S3 语料 · 由 admin 采样，本件不抓取）

> 用途：给 admin 的采样环节提供候选作者与书单。**本件只列不采**：不含任何正文、不含 URL、不做抓取。
> 授权：只读研究 + 成文；零模型调用、零生成。落 `.batch/night/staging/res-s3/`（协作介质，不入 `docs/`）。
> 口径依据：`corpus-source-plan.md`（186 行／16,750 B／`6093abc3…aac8`）§3.1–§3.3；`baseline-definition-ruling.md`（`aa1dac76…`）。
> 采样后由 admin 在 `MANIFEST.json` 落 `author / book / chapter / url / fetchedAt / site`，本件的「平台」「可采章数」两栏以 **MANIFEST 实测为准**，本件预测只作排序依据。

---

## 0 选作者的判据（admin 11-25 定，先写死再看名单）

1. **笔法差异要能被读出**，不能全是同一流派的模板文——否则跨作者方差是假的、`K = 作者间/作者内` 会被虚假抬高，平台口径区间跟着失真。
2. 差异必须落在**本课题要检的维度**上（句长分布、段落形态、对话占比、连接词密度、枚举密度、段间衔接），而不是只在设定/题材上不同。
3. 一位作者只能用**一个署名**的作品；同一作者的马甲、合著、改编剧本、同人续写都排除。
4. 译本、AI 生成或 AI 改写文本、平台 AI 聚合页排除。
5. 采样章节必须能**落到原站点页面**（MANIFEST 记 URL），否则无法复核，等于没采。

## 2 采多少、怎么采（交给 admin 的采样环节，我只给数）

- **每位 ≥3 章、总数 ≥20 章、≥5 位作者**（`corpus-source-plan.md` §4 与 ruling 一致）。
- 固定章位：**第 3、6、9 章**（避开第 1 章的作者自我交代与最新章的不稳定），作者按名单顺序取满 5 位为止；某作者第 3/6/9 章不可读时，按第 4、7、10 章顺延并记在 MANIFEST。
- 一章只取**正文段落**，不取作者说、章评、推荐票、广告位、下一章链接。
- 落盘：`.runtime/res-corpus/multi-author-v1/<authorId>/ch<NN>.txt`（`authorId` 用拼音小写 + 序号，如 `maoni-01`，避免出现能被读成「单作者」的名字）；`MANIFEST.json` 每条一行记录，字段 `authorId / author / book / chapter / url / fetchedAt / site / chars`。
- **版权边界**：按 admin 与主人拍的口径执行，本件不预设；如需我改口径，只动本件 §2。

## 3 采样完成后我做什么（复判，不采不抓）

1. 先按 admin 落的 `MANIFEST.json` 核五条（作者数 ≥5、每位 ≥3 章、总 ≥20、每条对应盘上文件、记录含 URL）。
2. 逐章算四条指标（`scripts/measure-ai-flavor-baseline.mjs` 的 ②③④ 口径 + 段长/句长上限），**出逐章读数**，先作者内中位数与四分位，再跨作者 `min–max` + 作者数 n；n=5 不报分位数。
3. 用 `K = D_between / D_within` 与 CV 噪声闸复判清单 §1 的 `transfer` 栏；未复判的行维持 `unknown`（清单 §0.4 已写死，不得升级为 P17 硬判据）。
4. `PS-3 dialogueRatio` 的 `basis` 由「主人内部经验值，待自采实测验证」换成「多作者池实测（n=…）」，实测是多少写多少，**不为维护「25%–40%」凑数**。

## 4 本件明确不做

- 不抓网页、不下载正文、不转载语料（采样归 admin）。
- 不替作者排「谁写得好」——本件只说笔法差异，不作文学评价。
- 不因为某位作者的数值好看就换人补位（换人＝换基线，须整批重采）。
