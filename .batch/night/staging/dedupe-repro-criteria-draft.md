# 去重复现用例 · 判据草案（QA 出，待负责人并入卡面）

范围：只写「怎样算复现、怎样算拦住了」，不写修法。修法由 developer 取证后再定。

## 0. 判重键（建议，供裁定）

主键 = **投递目标（delivered 的子目录/hash）＋ 文件名 ＋ 内容摘要**。
不依赖源路径——源文件搬走后路径消失，按路径记的表匹配不到任何记录（本次现象）。
内容摘要取「正文字节摘要」，不含 mtime；mtime 参与判重会造成同一内容重投被误拦/漏拦。

## 1. 四个用例

| 编号 | 构造 | 期望 | 反例（判不通过） |
|---|---|---|---|
| TC1 | 同一目标、同一文件名、同一内容，间隔投两次（源路径仍在） | 第二次**不唤醒**，只留 skip 日志 | 出现第二次模型调用 |
| TC2 | TC1 的第二次改为「源文件已被移入 delivered 之后」再投（本次现象） | 仍**不唤醒**，只留 skip 日志 | 源路径消失后照发 |
| TC3 | 同一目标、同一文件名、内容改 1 字节 | **必须放行**（唤醒一次） | 被误判为重复而吞掉 |
| TC4 | DONE 与 stable 两通道对同一文件近乎同时触发 | 总共**只唤醒一次** | 两条通知 / 两次模型调用 |

## 2. 可观测判据（每条都要能直接指认）

1. 模型调用次数：以宿主侧实际请求数为准，端点前取一次、结束后取一次，差值必须＝期望值。
2. `delivered/<target>/` 下的新增文件数：必须＝期望值。
3. 日志：跳过时必须有一行，且**同时含** target、filename、digest 三个字段；没有这行 = 判据不成立（「静默跳过」不可验收）。
4. 不得以「用户没收到通知」作证据——通知是结果，不是判据。
