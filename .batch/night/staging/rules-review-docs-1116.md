## 一、冲突（6）

1. **`:16` 1.2 与 `:20` 1.6 是两套地址文法** —— 1.2 要求 `角色 · 群名后缀 | session前8位`，1.6 要求写「主身/群分身」标签，合成的 To 行有两种合法形态，notice 的 From/To 机检（只检 `^From:`、`^To:` 存在）无法区分，谁都不算错。
2. **1.2 的地址文法与名册 v3.6 字段不一致** —— 名册记 `sessionId` + 标题两列，1.2 要求「角色 · 群名后缀」拼接串，名册里没有这个拼接字段，照 1.2 判必须人工拼，无法机检。
3. **`:21` 1.7「重启会让 session id 整批刷新」与实测相反** —— DSH 会话 id 按目录持久，重启只改「是否 live」；今日 4 次轮换（`4f18b03f`→`6acae4d3`、`0103a0ac`→`3286c9d7`、`64419d69`→`51aa9018`、`c64bc312`→`03205043`）全部由新建会话引起，无一次由重启造成。
4. **`:35` 2.6 的发言限流与 notice 同时生效无优先序** —— 两份都写「同议题每 bot ≤1 次」，但一份按「议题」、一份按「轮」，重叠时算一次还是两次没定义。
5. **`:39` 2.10 与 `:40` 2.11 给同一件事两个真源** —— 一个说以台账为准，一个说以群内回执为准，冲突时无裁决顺序。
6. **`:99`–`:104` 的条目缺四列** —— 同一张表里别的条目有「谁写/谁判/依据/失效点」，这六条只有一句祈使句，无法据以判定谁违规。
