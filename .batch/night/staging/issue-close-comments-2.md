## #4 会话重启后是否需要手改 `targetSessionId`

文档已更正，关闭：

- `targetSessionId` 是**持久标识**，按 id 落目录（`~/.dsh/sessions/<workspace>/<uuid>/`）；重启后失效的不是 id 本身，而是「该 id 在当前宿主里是否 live」。
- 重启后 21 秒内 rescan 可转 resolved；超出重扫窗口（3 次 / 21 秒）会停在 `not-found`，直到该目录再有新文件事件。这一「窗口太短」的问题已单独记入 backlog（rescan 延长或改事件驱动），**不在本条范围内**。
- 「重启会改 session id」这个说法是错的，本 issue 保留过的正文即为此更正，已无需继续开着。

版本：`0.5.0`。日期：2026-11-15。
