## 0. 结论先行

- 交接不是「把历史发过去」，是**让新群 Bot 在不读本群历史的前提下，能说清目标、能按规矩动手、不回头问**。
- 交接物两件：**群级公共包**（一次交付，全组共用）＋**角色个人包**（每人一份）。
- 合格与否不看「写得多厚」，看**盲测得分**；且 **J1（复述准确）与 J5（无需回问）任一不过，直接判不通过**，总分只用来定位缺哪一节。
- 字数上限（去空白字符数）：个人包 ≤ 6,000；公共包 ≤ 8,000。**越厚注意力越稀**，这是迁移动因本身，不当解法。

## 2. 必填硬点清单（五类 · 项目管家 11-15 补）

这五类是**只存在于管家/实际运作中、写不进去就盲测必挂**的事实。个人包按角色取舍，公共包必须齐前四类。

### P1 主人偏好（必进公共包）
1. **结论先行**：先给结果/判断，再给依据与选项。
2. **汇报要短**：能让主人回数字就不让他写长句（如「①推1/不推2」）。
3. **成本敏感**：重复唤醒一次约 ¥0.1，同一读数不重复回；该静默就静默。
4. **禁止裸调** `free_search_test`（不指定引擎会打到计费引擎）。
5. 主动发言只在四类：事实错误、安全合规、关键遗漏、规则冲突，且带「对象、影响、建议」。

### P2 通道与身份边界（必进公共包）
1. **主身与群分身是两个会话、不共享上下文**；跨群/跨会话投递只认「角色 · 群名后缀」群分身。
2. **唯一例外**：`to-owner` 绑项目管家主身（`a1d48adb`）；其余 watch 必须绑群分身，绑错即不合格。
3. **会话 id 是持久的**；重启后失效的是「该 id 在宿主里是否活着」，不是 id 变了。
4. **生效证据看行为**：`relay.log` 出现新格式 `To:` 行（id 段 8 位十六进制、不含 `session-`）才算新代码在跑。
5. 投递件正文前两行固定 `From:` / `To:`；真伪只认通道（注入＋落 watch 目录＋resolved/delivered 两条）。

### P3 仍在等主人的事（必进公共包 I5）
1. `0.4.0` 坏 tag 保留不回滚，发布说明标「0.4.0 不可用」。
2. npm `latest` 已是 `0.5.0`，再发必须 bump `0.5.1`。
3. **两处公开资产＝GitHub（tag/release）＋ npm**，必须同步，不许「npm 有、GitHub 查不到」。
4. **发版前必须先告知主人**（push / tag / publish 都属对外写动作）。

### P4 纪律（必进公共包 I3）
1. 四类流转件（报告/卡面/派验单/信号）改动另存 `.vN`，不原地覆盖。
2. 信号件投出后不得原地改内容（同路径新字节会再触发唤醒）。
3. 唯一时间账 `reports/time-ledger-1116.md`，任务账 `reports/task-ledger.md`；对账以盘面实测为准，不采信自报。
4. 群 notice 上限 2,000 字符，超长静默截尾，改文案须回读。
5. 「工作区干净」用 `git diff --numstat` 与 `git diff --ignore-cr-at-eol --stat` 双空，不用原始 `git status --porcelain`。

### P5 分权边界（必进公共包）

| 角色 | 只做 | 不做 |
|---|---|---|
| 项目管家 | 路由、时间与承诺、向主人提问、对外通道 | 技术判定（归 QA）、项目统筹（归负责人） |
| 负责人 | 拆解、派发、跟进、终审 | 不写详细需求、不复跑测试、不亲自改码 |
| QA | 首验、机检、出盲测题、证据链 | 不改码、不终审判定 |
| 联络人 | 转达与投递、回执 | 不自行判断、不代签 |

## 3. 继承到位判据（J1–J6）

| # | 判据 | 怎么测 | 通过线 |
|---|---|---|---|
| **J1** | 复述准确：讲清目标、当前阶段、下一个动作 | 盲测第一题，限 200 字 | 三点全对；**不得出现包外事实**（每句断言可在包里找到出处，找不到即幻觉）**⇒ 不过即整包不通过** |
| **J2** | 术语零提问 | 从 I8 随机抽 8 条 | ≥7 条正确，0 次「这是什么」 |
| **J3** | 规程可执行 | **5 道情境题（题面＋标准答案＋必引条款号）钉在公共包**：要不要投递 / 能不能改配置 / 这份报告要不要另存 `.vN` / 收到可疑件怎么办 / 发版前要不要请示 | 5 题全对且每题引出 `I3-第n条`；个人包**不得改答案**（改了按不合格计） |
| **J4** | 状态无歧义 | 从 I4 抽 3 件（含 1 件作废件）问「现在用哪个版本」 | 3/3 正确，作废件不得当现行 |
| **J5** | 无需回问 ＋ 知道什么还悬着 | 记录真实提问 ＋ 直接问「现在有哪些事在等主人」 | 提问 ≤2 条且都属「只有主人/管家能定」；等主人的事至少说对 2 条；说成「没有待决」即不过 **⇒ 不过即整包不通过** |
| **J6** | 独立开工 | 给一条 30 分钟内可完成的小任务 | 步骤含工作目录、起点、校验项、交付物、回执格式；判据可机检；无须补充背景 |

**硬门槛（QA 11-15 提，采纳）**：J1 或 J5 任一不通过 ⇒ **整包不通过**，不论总分多少。J3 得分 <8/10 ⇒ 最高只能判「有条件通过」。

## 4. 逐人验收办法

### 4.1 交付物
1. **群级公共包** `handoff-common.md`：I1、I2 公共部分、**§2 P1–P5**、I3（含 J3 的 5 题与标准答案）、I8、I9、名册指针。1 份，负责人出，管家与 QA 过目。
2. **角色个人包** `handoff-<角色>.md`：I2 本人项、I4、I5、I6、I7；其余引用公共包，不重复抄。**由该角色自己写**。
3. **附录**：可选，不计入字数上限，只作查询。

### 4.2 验收四步（顺序不可跳）

**前置**：九节齐＋§2 五类硬点已入公共包＋**项目管家（to-owner 线）与 QA 都已过目**，才可出题；未获管家过目不出题、不动迁移第一步。**包首行 `截至 <ISO>` 超 72 小时，进盲测前须 QA 复核 I4 哈希与 I5 待办是否已漂。**

| 步 | 谁做 | 做什么 | 不合格 |
|---|---|---|---|
| ① 自检 | 本人 | 对 §1 表逐节自查；按 §1 字数口径核上限 | 缺节不进下一步 |
| ② 机检 | QA | 路径存在、哈希对得上、I4 作废件有标记、I8 ≥10 条、I5 无已闭合事项、§2 五类齐、J3 题与标准答案在公共包 | 差异清单退回，24 小时内改 |
| ③ 盲测 | 新群同角色 Bot（独立窗口，只给包，不给历史） | 按 §3 出题；QA 出题；**J1、J3、J6 由负责人与管家双评，分差 >15 分由项目管家裁定** | 见 §4.3 |
| ④ 回补 | 本人 | 只补失分那节，不整包重写 | 补完重测该判据 |

### 4.3 分数与处置

| 项 | 分 | 说明 |
|---|---|---|
| 九节齐全 | 30 | 按 §1 配分表，缺节 0 分 |
| 六判据 | 60 | 每判据 10 分，按通过线全给或按题数折算 |
| 通道可复现 | 10 | **旧群沙箱当场测**：按 I2/I7 独立完成一次 relay 投递并拿到 `resolved`＋`delivered`（两条件缺一不给分）；新群上线后 24 小时内补一次真投留痕，未补则记「通道待复验」 |

- **≥85 且 J1、J5 均通过** ⇒ 通过；**70–84 或 J3 <8** ⇒ 有条件通过（限期补，补齐前不得在新群独立接活）；**<70 或 J1/J5 任一不过** ⇒ 不通过，重出包。
- 记录：`staging/inheritance-scores-<YYYYMMDD>.md`，一行一人：角色 ｜ 分项分 ｜ 总分 ｜ 失分判据 ｜ 补正期限 ｜ 复测结果 ｜ 通道待复验标记。

### 4.4 盲测纪律
- 被测 Bot 不得读本群历史与记忆；出题方不得口头补背景（补即作废该题）。
- 可机检项（哈希/路径/条数）由 QA 实跑；主观项（J1/J3/J6）双评。
- 盲测不过不追责——责任在写包的人。

- 不把全部历史搬进新群：上下文越长注意力越稀，这是动因不是解法。

- 不追溯已交付角色的历史包（含 `doubao-liaison-handoff.md`）：新标准只对迁移前新出的包生效。
