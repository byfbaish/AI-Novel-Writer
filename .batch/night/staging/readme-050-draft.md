## B3 删掉「重启后 id 会变、要重新接线」（全文三处）

当前写法是错的：会话 id 是**持久标识**（会话按 id 落盘）；重启影响的只是「该 id 在当前宿主里是否已加载」，启动期重扫会在 21 秒内把多数不上的补回来。全文不得再出现「重启会改 id / 需重新接线」。

### B3-a `README.md:149-152`、`README.zh-CN.md:129-131`（Install 末尾那段）

现在（EN）：

```
Restart the host so the bundle and its config are loaded. A watch's target must
resolve to a session that currently exists: with `targetSessionId` this means
re-wiring it after every restart, because session ids change when the host
restarts. `targetTitle` avoids that — its title survives restarts.
```

改成（EN）：

```
Restart the host so the bundle and its config are loaded. A watch's target must
resolve to a session that exists. Session ids are stable — they are not
regenerated by a restart; what changes is whether that session is loaded in the
current host, and a failed target is retried for up to 21 seconds after startup
(see "Startup rescan"). Use `targetTitle` if the session may be renamed or
replaced: the title follows the session, an id does not.
```

现在（中）：

```
重启宿主，让 bundle 与配置生效。每条 watch 的目标必须指向当前存在的会话：
用 `targetSessionId` 时，宿主重启后会话 id 会变化，每次重启后都需要重新接线；
改用 `targetTitle` 就没有这个问题——标题跨重启不变。
```

改成（中）：

```
会话 id 是持久标识——重启不会重新生成 id；变的只是「这个会话在当前宿主里加载了没有」，
```

## B4 设置卡一节（改写 + 补入口）

**位置**：`README.md:234-245`（整节替换）、`README.zh-CN.md:200-209`（整节替换）

改成（EN）：

```markdown
## Settings page

From `0.5.0` the plugin contributes a card to the host's plugin settings page.
(`0.4.0` never shipped a usable build — install `0.5.0`.) The card is an editor
only: `watches` in `cordis.patch.yml` remains the single source of truth at
runtime.

**Where it is:** open the plugin in the host (`Plugins → Installed → open
dsh-handoff-relay`), then scroll to the README page's bottom and click the
component name listed under "Included components". The settings card is opened
from there — it is not a top-level menu item.

- Each watch is one row with three columns: **directory / target session /
  completion rule**.
- The target session is chosen from a picker, not typed. The picker lists 10
  sessions by default, with "show more" to expand, and takes a search term.
  Rows show the session's title and its directory, so two sessions with the same
  title in different projects are distinguishable.
- Saving writes the whole `watches` array back into `cordis.patch.yml` and
  leaves the rest of the file untouched.
- The `exact` switch means: off (default) = the stored title is matched as a
  substring; on = the whole title must be equal. The card writes `exact: true`
  for any row picked from the session picker.
- Saving does **not** hot-reload the running relay. **Restart DSH for the new
  watches to take effect** — this release has no live reload.
- On a host that does not provide the settings row, the card renders read-only
  and says so; editing `cordis.patch.yml` still works.
```

改成（中）：

```markdown
## 设置页

从 `0.5.0` 起，插件会在宿主的插件设置页里提供一张卡片。（`0.4.0` 没有可用的
发行版，请装 `0.5.0`。）卡片**只作编辑通道**：运行期的唯一真相仍然是
`cordis.patch.yml` 里的 `watches`。

**入口在哪：** 在宿主里打开本插件（`插件 → 已安装 → 打开 dsh-handoff-relay`），
然后滚到 README 页面最下方的「包含的组件」，点那里的组件名即可进入设置卡。
它不是顶层菜单项。

- 每条 watch 一行，三列：**目录 / 目标会话 / 完成规则**。
- 目标会话用**选择器**选，不用手填。选择器默认列 10 条，可「查看更多」展开，
  并带搜索框。列表项显示会话标题与其目录，同名但不同项目的会话能分开。
- 保存时把整个 `watches` 数组写回 `cordis.patch.yml`，文件里的其它内容保持不动。
- `exact` 开关的含义：关（默认）= 存的标题做包含匹配；开 = 标题必须完全相等。
  凡在选择器里选定的行，卡片一律写 `exact: true`。
- 保存**不会热更新**正在运行的 relay。**重启 DSH 后新的 watches 才生效**——
  本版本不做热更新。
- 宿主没有提供这一条目时，卡片以只读形式渲染并说明原因；改 `cordis.patch.yml` 仍然有效。
```

## B5 绑定规则（新增小节，两处都加）

**位置**：放在配置字段之后、加粗警告之前（`README.md:229` 之后、`README.zh-CN.md:196` 之后）

新增（EN）：

```markdown
### How a target is resolved

1. `targetTitle`, compared exactly when `exact: true` and as a substring
   otherwise. It is resolved afresh before every delivery.
2. If the title matches nothing (or more than one session) and
   `targetSessionId` is also set, that id is tried.
3. If still not exactly one session, nothing is delivered and a warning names
   the watch and the reason.

`exact` is only about title comparison. There is no `cwd` fallback and no
contains-both rule: a title that matches two sessions is never guessed.
```

新增（中）：

```markdown
### 目标如何解析

1. 先看 `targetTitle`：`exact: true` 时要求标题完全相等，否则按包含匹配。
   每次投递前都重新解析。
2. 标题命中 0 条（或多条）且同时给了 `targetSessionId` 时，再用这个 id。
3. 仍然不能唯一定位到一个会话，就不投递，并写一条点名该 watch 与原由的告警。

`exact` 只影响标题比较。不做 `cwd` 兜底，也不做「两边都算命中」：一个标题命中
两个会话时，插件不猜。
```

同时改 `watches` 字段说明里「恰好选一个」：

- `README.md:193-198` 的 `` each entry needs `dir` plus exactly one of `targetSessionId` and `targetTitle` `` → `` each entry needs `dir` plus at least one of `targetSessionId` and `targetTitle` (giving both is allowed: title first, id as fallback) ``
- `README.zh-CN.md:168-171` 的「在 `targetSessionId` 与 `targetTitle` 中**恰好选一个**」→「必须给出 `dir`，并至少给出 `targetSessionId` 与 `targetTitle` 中的一个（两个都给也可以：标题优先，id 兜底）」

- EN: `targetSessionId` → `Id of the session to notify. Ids are stable across restarts. Give with or instead of targetTitle: it is used when the title does not resolve to exactly one session.`
- EN: `targetTitle` → `Session title to match; substring unless exact is true. Resolved before every delivery; falls back to targetSessionId when it matches zero or several sessions. No cwd fallback.`

## B6 投递落点（新增一节）

**位置**：放在 `## Startup rescan` 之后、`## Config` 之前

新增（EN）：

```markdown
## Where a delivered file goes

On a successful delivery the source file is **moved** out of the watched
directory, into the plugin's own data area under the profile:

```
<profile>\dsh-handoff-relay\delivered\<dir key>\
```

So "the file is gone from `dir`" is the normal, expected state — do not read an
empty watched directory as "nothing happened". To check that a delivery
happened, look at `delivered\`, or at the notification the target session
received. The plugin never deletes a delivered file.
```

新增（中）：

```markdown
## 投递后文件落在哪

投递成功后，源文件会被**移出**被监控的目录，落到 profile 下插件自己的数据区：

```
<profile>\dsh-handoff-relay\delivered\<目录键>\
```

所以「文件从 `dir` 里消失」是正常状态，别把空目录读成「什么都没发生」。要核实
投递，看 `delivered\`，或看目标会话收到的通知。插件不会删除已投递的文件。
```

## B7 去重（新增一节）

**位置**：接在 B6 之后

新增（EN）：

```markdown
## Duplicate suppression

The same file — same path, same byte size, same `mtimeMs` — wakes the target at
most once, even across plugin reloads and host restarts: delivered snapshots are
persisted in the plugin's data area (`dedupe.json`). A skipped duplicate leaves
one INFO line in `relay.log` and nothing else. Changing the file (size or mtime)
makes it a new item again.
```

新增（中）：

```markdown
## 重复抑制

同一个文件——同路径、同字节数、同 `mtimeMs`——最多只唤醒目标一次，跨插件重载和
宿主重启都成立：已投递快照会持久化在插件数据区的 `dedupe.json` 里。被跳过的重复件
只在 `relay.log` 里留一行 INFO。文件内容一变（字节数或 mtime 变），就算新的一条。
```

## B8 已知项（新增一节）

**位置**：`## License` 之前

新增（EN）：

```markdown
## Known limitations in `0.5.0`

- `dedupe.json` is never pruned; it grows with each distinct delivery. Pruning
  is planned for `0.6.0`.
- A duplicate that is skipped is not moved out of the watched directory, so the
  file stays where it is and keeps being skipped.
- Saving the settings card needs a host restart to take effect (no live reload).
- On a host without the plugin settings row, the card is read-only.
- When the target session is not open, the file stays undelivered, remains in
  the source directory, and one warning is logged; it is delivered automatically
  once that session is open. The plugin never starts a session by itself.
```

新增（中）：

```markdown
## `0.5.0` 已知限制

- `dedupe.json` 不做剪枝，会随不同投递条数增长；剪枝计划在 `0.6.0`。
- 被判定为重复而跳过的文件**不会**被移出监控目录，它会留在原地继续被跳过。
- 设置卡保存后需要重启宿主才生效（不做热更新）。
- 宿主没有插件设置条目时，卡片是只读的。
- 目标会话未打开时，文件保持未投递、留在源目录并记一条 warn；等该会话打开后会自动补投。插件不会主动拉起会话。
```
