# 裁定：工作方式回到标准 Git 流程（2026-11-17 13:45）

## 一、为什么改（依据）
今天 11:00–12:50 的群里，63 条消息中 51% 在复述三元组、67% 在纠错改口径，并集 78%。
跟班取证结论：**不是纪律问题，是产物形态问题**，三条叠加——
1. 同一事实存多份副本：`.batch/night` 内 826 个 md 有 8 组字节完全相同（升版零改动）；`model-policy.mjs` 仓库内 8 份、3 种内容。
2. 三元组（字节／md5／行数）写在文件正文里，且这些文件由「整份重写」的脚本产出 ⇒ 换一版全链路作废，人人重报重算。
3. 机检拿「行数」当判据，而末行无换行使 `wc -l` 与 `awk NR` 恒差 1（`build-v68.py` 明写 `no trailing newline kept`）⇒ 指标本身不确定。更有 `fix-ledger-v7.mjs` 为躲机检把「已堵住」改成「已经堵住」。
唯一没出问题的 `ledger-pending-entries` 恰恰是唯一「只维护现行件、不标 vN」的那一份——方向已被反向证明。

## 二、规则（即日生效）
1. **版本只由 git 承担**：分支、提交、tag。文件正文与文件名**一律不得带版本号**（禁 `.vN`、禁「v68」这类编号）。历史要看就 `git log`。
2. **一份事实一处存放**：其余位置只放指针（路径＋commit sha 前 8 位），不放副本。
3. **三元组退出文件正文**：交付件不写「字节／md5／行数」。要证明「你看的就是这份」用 `git show <sha>:<path>` 或 `sha256sum` 当场算，不许抄。
4. **汇报格式**：群里只报 `<commit sha 前8位>` ＋ PR 号 ＋ 一句话结论。不再报字节、md5、行数。
5. **流程**：一卡一分支 `card/<卡号>`；提交信息带卡号；QA 预审 → 项目总负责人终审；合并后删分支。对外发布、以及要合并进主人指定分支，**必须报主人**。
6. **收口标准改判据**：以「内容判据通过」为完成，不以「大家的数字一致」为完成。数字不一致但内容无误时，一次比对即结案，写一行归因，不再循环。
7. **产物归属**：协作介质（卡面、裁定、会签、台账清单、名册、评审请求）入住 `.batch/night/{cards,org,reports,review-requests,roster,staging}`，已加入版本控制（提交 `35ff9aa7`，分支 `card/git-track-ops-1117`）。信号／桥接／草稿／取证／归档、临时脚本仍不入库；**脚本一律放 `/scripts/`**。
8. **末行换行**：所有含中文正文的 md 一律以单个换行结尾，由 pre-commit 统一，不再靠人工注意。
